# 매칭 방식과 사용자 파라미터

2026-10-04 추가: 두 커스텀 형상의 표시 점수는 `방향 점수 × (1 − 감점 비중 × 추가 윤곽비율)`이다. 기본 감점 비중1이며 학습 영역 안에 새로 생긴 윤곽을 감점한다. 방향 점수와 추가 윤곽비율은 결과 상세에 따로 표시한다. OpenCV NCC는 그대로다. 점수는 불량 확률이나 영역 전체 픽셀 동일성이 아니다.

| 실행/점수 설정 | 범위·기본값 | 영향 |
|---|---|---|
| 후보 예산 프리셋 | 기본 후보 예산/확대 후보 예산/사용자 설정, 기본은 기본 후보 예산 | 후보2048/8192, 원본 검증64/256, 축소 검증256/1024. 모두 자세 정밀화 켬. 합격점수/결과한도는 유지. 누락이 큰 빠르게 프리셋은 제거 |
| 실행 장치 | CPU 기본 / GPU 전처리+CPU 검색 · CUDA | 커스텀 형상 전용. ILGPU CUDA가 평활화·Sobel 미분, CPU가 정규화·검색·검증. 결과에서 실제 adapter·처리량·전송 포함 시간 확인. NVIDIA CUDA 장치 필요, 실패 시 CPU로 자동 전환하지 않음 |
| CPU 병렬도 | 1~16, 앱의 새 형상 설정은 논리 프로세서 수의 절반을 1~4로 제한한 값 | 기준 장비에서는4. 후보/검증 병렬 작업 수이며 읽기·모든 단계를 같은 수로 병렬화하지 않음. 논문·기하 방식의 사용자 설정은 각각 유지 |
| 검사 시간 한도 | 0~600초, 기본0 | 0 무제한. 도달 시 안전한 연산 종료 후 경고/취소. 강제 종료 시각 아님 |
| 추가 윤곽 감점 비중 | 0~1, 기본1 | 0은 기존 방향 점수만 사용, 1은 추가 윤곽비율을 모두 반영 |
| 윤곽 대응 허용 거리 | 0.5~8 원본px, 기본3 | 추가 윤곽 설명 여부와 기하 대응 허용 거리. 너무 크면 차이를 허용 |

오른쪽 **검사 도구 → 일반 도형 찾기**는 학습 없이 채워진 삼각형·직각 사각형·원·대칭 십자가를 찾는다. **도형 샘플 → 도형 검출**로 확인할 수 있다. 자동 Otsu/수동 문턱0~255, 명암 극성, 도형별 선택, 최소/최대크기6~512px, 윤곽 근사비율.005~.04, 최소점수0~1, 최대결과1~1000, 시간 한도를 조절한다. 열린 선/테두리만/붙은 도형/부분 가림은 지원하지 않는다. 실제 원본 윤곽을 표시하고 잘림·한도 초과는 경고한다. 패턴 검사와 동시에 실행하지 않는다.

GPU가 항상 빠르지는 않다. 이전 DX12 전처리의 CPU4.21초/GPU4.51초 측정은 교체 전 기록이다. 새 CUDA 구현의 검증과 측정은 [휴대 가능한 검사 검증](portable-inspection-validation.md)을 따른다. 후보 예산을 초과하면 우선 검증할 위치·자세를 분산하지만 생략 후보가 존재한다는 경고를 유지한다. 예산 확대도 모든 입력의 완전한 검출을 보장하지 않는다.

각 방식은 별도의 모델과 설정을 보관한다. 처음 선택한 방식에는 ROI 하나로 학습해야 한다. 다른 방식으로 갔다 돌아오면 해당 모델과 설정이 복원된다. 이미지를 바꿔도 모델은 남지만 결과는 지워진다. 앱을 종료한 뒤 보존하는 저장 기능은 아직 없다.

최소 점수와 각도·배율·허용비율 등은 소수점으로 입력할 수 있다. `0` → `0.` → `0.7` → `0.72`처럼 한 글자씩 입력해도 소수점과 후행0을 유지하며, 유효한 숫자는 즉시 설정에 반영된다. 같은 입력 방식은 일반 도형 검출의 숫자 필드에도 적용된다. 빈칸·잘못된 문자열은 입력 오류로, NaN·무한대·허용 범위 밖 값은 설정 오류로 실행을 막는다. 패턴 방식을 바꾸면 잘못 입력한 문자열은 선택한 방식의 저장된 숫자로 복원한다.

| 방식 | 검색과 검증 |
|---|---|
| OpenCV · 템플릿 매칭 | CCOEFF_NORMED 명암 상관. 학습 당시 각도·크기를 유지한 위치 검색. 회전/배율을 새로 측정하지 않음 |
| 논문 기반 · 형상 매칭 | 방향 응답맵 피라미드 후보, 연속 gradient 검증, 자세 정밀화. 회전·균일 배율 지원. 논문 전체 재현은 아님 |
| 기하 형상 · 자체 구현 | 논문 기반 후보 엔진에 원본 윤곽 대응·RMS 거리·불필요 윤곽 검증 추가. Cognex SDK/PatMax 복제 구현은 아님 |

## 공통 검색 설정

| 항목 | 기본값 / 범위 | 영향 |
|---|---|---|
| 최소 최종 점수 | .72 / 0~1 | OpenCV는 명암 상관, 커스텀 형상은 방향 유사도에 추가 윤곽 감점을 반영한 값. 방식 간 점수를 같은 정확도로 비교하지 않음 |
| 최대 결과 수 | 세 방식 모두 256 / 1~1000 | 앱 초기값. 각 방식의 사용자 값은 독립 보관. 학습 개수와 무관하며 추가 결과가 생략되면 경고 |
| 최대 검색 후보 수 | 2048 / 1~100000 | NMS/검증 이전 후보 예산. 부족하면 검색 불완전 경고. 증가 시 시간·메모리 증가 |
| 최대 검출 중복 비율 | .3 / 0~1 | 검출 외접 영역의 IoU가 이 값을 넘으면 중복으로 제거. 낮추면 더 강하게 제거 |
| 선택 ROI 안에서 기준점 검색 | 해제 | 켜면 선택 도형 안에 기준점이 있는 결과만 허용. 끄면 전체 이미지 |

개수가 부족하면 먼저 상태의 **출력 상한**과 **후보 예산** 경고를 구분한다. 점수를 무조건 낮추면 오검출과 후보 수가 늘어난다. 최대 결과 수를 늘려도 후보 예산 경고가 사라진다는 보장은 없다.

## 형상 학습 설정 — 변경 후 다시 학습

| 항목 | 기본값 / 범위 | 영향 |
|---|---|---|
| 최소/최대 회전 편차 | -180~180° / 전체 폭 최대 360° | 학습 ROI 방향 기준 편차. 결과는 이미지 기준 절대각 |
| 템플릿 각도 간격 | 10° / 0 초과~45° | 작을수록 촘촘하지만 학습 템플릿과 검색 비용 증가 |
| 균일 배율 검색 | 해제 | 켜면 최소/최대 배율과 간격 적용 |
| 최소/최대 배율 | .9~1.1 / 0 초과~8 | 학습 크기에 대한 균일 배율. 최소≤최대 |
| 템플릿 배율 간격 | .1 / 0 초과 | 작은 간격은 템플릿 수 증가 |
| 명암 극성 무시 | 해제 | 밝고 어두움이 뒤집힌 윤곽의 방향 허용 |
| 최대 학습 특징 수 | 160 / 12~512 | 선택하는 방향 특징 수. 대응 비율 분모와 연산량에 영향 |
| 최소 학습 명암 경사 | 8 / 0 초과 | 에지 특징 선택 기준. 높이면 약한 윤곽 제외 |
| 최대 학습 템플릿 수 | 2048 / 1~16384 | 각도×배율 샘플 예산. 초과하면 범위/간격 조정 안내 |

피라미드는 원본 ROI 크기에 따라 자동 조정하고 모델 요약에 실제 단계 수를 표시한다. 큰 학습 ROI에도 임의 단계 값을 강제로 적용하는 옵션은 제공하지 않는다.

## 형상 검색 고급

| 항목 | 기본값 / 범위 | 영향 |
|---|---|---|
| 최소 후보 점수 | .65 / 0~1 | 후보 단계 통과 기준. 최종 점수와 별도 |
| 최소 방향 지지율 | .6 / 0~1 | 방향이 일치하는 특징의 최소 비율 |
| 최대 형상 검증 후보 수 | 64 / 1~4096 | 일반 검색의 정밀 검증 후보 한도 |
| 최대 축소 검증 후보 수 | 256 / 1~4096 | 큰 이미지 피라미드에서 원본 검증으로 넘기는 후보 한도 |
| 검출 위치·자세 정밀화 | 켬 | 후보 위치·각도·배율을 연속 정밀화. 끄면 정밀화 미확정으로 사용자 확인 판정 가능 |

## 자체 기하 검증

| 항목 | 기본값 / 범위 | 의미 |
|---|---|---|
| 대응 허용 거리 | 3px / .5~8px | 원본 픽셀 기준 에지 대응 거리 |
| 최소 윤곽 특징 검출비율 | 0 / 0~1 | 선택 학습 특징 중 실제 에지가 대응한 최소 비율. 물체 면적 비율 아님 |
| 위치 오차 제한 | 해제, 3px RMS / 0 초과 | 대응 에지 거리 RMS 상한. 정답 위치 오차·치수 공차 아님 |
| 불필요 윤곽 제한 | 해제, .3 / 0~1 | 학습 도형 내부 에지 중 모델 윤곽으로 설명되지 않는 비율 상한 |

기본값은 기하 품질을 계산만 한다. 대응이 없거나 정밀화가 미확정이면 사용자 확인으로 표시한다. 기준을 켜면 해당 조건 미달 후보가 제외된다. 실제 생산 이미지의 허용 기준은 별도로 검증해야 한다.

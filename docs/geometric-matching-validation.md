# 전통적 기하 패턴 매칭 1차 확장 — 합성 검증

2026-10-04. 공개 논문에 기반한 기존 C# 형상 검색에 실제 에지의 대응 비율·위치 오차·불필요 윤곽 평가를 추가하고, 명시적으로 선택하는 정밀 검사 조건을 검증했다. Cognex PatMax의 소스를 포팅하거나 내부 알고리즘을 재현한 결과가 아니며 상용 제품 동등성은 검증하지 않았다.

## 조건과 고정 기준

- 장비: 사용자 기준 PC의 AMD Ryzen 5 5600H, Windows 10.0.26200, .NET 10.0.12, 논리 프로세서 12개. 알고리즘은 CPU에서 실행했다. 전원·온도·백그라운드 부하는 고정하지 않았다.
- 입력: 자체 제작 Gray8 193×181. 학습 영상 96×96, 비대칭 C 모양 획과 내부 원형 특징. 모델 160개 특징, 피라미드 3단계, 회전 -180~180°/간격 5°, 균일 배율 0.8~1.2/간격 0.1, 총 365개 자세 템플릿.
- 양성 13건: -179.4~179.4° 범위 중 서로 다른 9개 비정수 각도와 0.8~1.2배 조합, 대비 50%, 가림, 주변 획, 가림+주변 획+대비 50%. 정확한 각도 목록은 원시 JSON에 있다.
- 가림은 원래 도형 경계 상자 39×42의 오른쪽 25%다. 모델 특징의 25% 또는 물체 면적의 25%가 가려졌다는 뜻이 아니다. 주변 획은 영상 배경에 추가하며 목표 도형을 지우지 않는다.
- 음성 3건: 빈 영상, 주변 획만 있는 영상, 수직·수평 획은 비슷하지만 내부 원형 특징이 없고 오른쪽이 닫힌 직사각형. 명암 반전 영상은 극성 유지에서 거부, 극성 무시에서 검출하도록 2건을 더해 총 18건이다.
- 고정 합격 기준: 양성은 정확히 1개 검출, 위치 오차 ≤0.75px, 주기성을 고려한 각도 오차 ≤1.5°, 배율 절대 오차 ≤0.025. 음성은 검출 0개. 모든 사례에서 후보/검증/결과 개수 예산 경고가 없어야 한다.
- 기존 임계값은 후보 방향 점수 0.65, 최종 방향 점수 0.72, 방향 지지율 0.60으로 유지했다. 위치·각도·배율 기준과 음성 정답은 실패 후 완화하지 않았다.

영상 생성은 매칭 구현과 별개인 역변환과 4×4 면적 샘플링을 사용한다. 가림·주변 획·명암 변화·음성 입력은 별도 fixture에서 만든다. 구현: `tests/VisionAlgorithm.Tests/RobustGeometricScene.cs`, `RobustGeometricMatchingTests.cs`.

## 기본 정책과 정밀 정책

| 설정 | 기본 | 이 검증의 정밀 정책 |
|---|---:|---:|
| 최대 거친 후보 | 2048 | 4096 |
| 최대 최종 검증 후보 | 64 | 256 |
| 에지 대응 허용 거리 | 3px | 3px |
| 최소 특징 검출비율 | 0 | 0.75 |
| 최대 대응 위치 오차 RMS | 제한 없음 | 1px |
| 최대 불필요 윤곽 비율 | 1 | 0.75 |

정밀 정책은 전역 기본값으로 바꾸지 않았다. 대응 비율은 선택한 학습 특징의 에지 대응 비율이고, 위치 오차는 대응 에지 사이 거리의 RMS다. 불필요 윤곽 비율은 변환된 학습 영역 내부 에지 중 학습 윤곽으로 설명되지 않는 비율이다. 점수와 면적 검출률 또는 제품 치수 공차로 혼용하지 않는다.

가림 정답은 방향 점수 약 0.831이고 유사 직사각형 음성도 약 0.831이어서 점수만 높여 두 경우를 분리할 수 없었다. 새 평가의 calibration 측정에서 양성의 최소 대응 비율은 0.85625, 최대 위치 오차는 0.53288px, 최대 불필요 윤곽 비율은 0.69537이었다. 유사 직사각형은 대응 비율 0.84375, 위치 오차 1.19348px, 불필요 윤곽 0.19615였다. 따라서 이 입력군에서는 **위치 오차 1px 제한**이 유사 음성을 구분한다. 최소 비율 0.75·불필요 윤곽 0.75는 가림·넓은 학습 영역의 배경을 허용하는 명시적 조건이다. 이것은 이 합성 입력으로 정한 초기 설정이며 독립 현장 검증으로 일반화하지 않는다.

앱에서 같은 정책을 사용하려면 오른쪽 **기하 검증 · 원본 윤곽 확인**을 펼쳐 **후보 검증 확대 (4096 / 256)**를 켠다. 대응 허용 거리 `3`, 최소 윤곽 특징 검출비율 `0.75`를 넣고 **위치 오차 제한**을 켜 `1`을 입력한다. **불필요 윤곽 제한**을 켜 `0.75`를 입력한다. 기본 최종 점수 `0.72`, 최소 방향 지지율 `0.6`은 유지한다. 해당 학습 범위를 재현할 때는 학습 설정의 각도 `-180 / 180 / 5`, 균일 스케일 `0.8 / 1.2`로 다시 학습한다. 이 작은 합성 모델의 365개 템플릿 수를 큰 ROI에도 그대로 보장하지 않는다.

## 결과와 예산 진단

| 실행 | 18건 중 모든 기준 합격 | 실패 내용 |
|---|---:|---|
| 기하 품질 평가 추가 전 / 기본 | 15 | 주변 획·복합은 정확한 위치를 찾았지만 후보 예산 경고, 유사 도형은 오검출·검증 예산 경고 |
| 기하 품질 평가 추가 후 / 기본 | 15 | 기존 점수·예산을 유지하여 위 한계가 그대로 드러남 |
| 기하 품질 평가 추가 후 / 정밀 | 18 | 없음 |

정밀 정책의 양성 및 극성 무시 검출 전체에서 최대 위치 오차 0.18028px, 각도 오차 0.26862°, 배율 오차 0.00625였다. 검색 중 가림은 남겨 둔 분모로 평가하며 반환한 품질 값도 대응 비율≥0.75, 위치 오차≤1px, 불필요 윤곽≤0.75를 회귀에서 확인한다.

별도 병목 계측은 최대 후보 100000·최종 검증 4096으로 **한 번만** 실행했으며 합격 기준 변경용이 아니다. 주변 획은 잘림 전 거친 후보 2239개→검증 후 후보 54개, 복합은 2219→55개였다. 기본 최대 2048을 초과하므로 경고가 맞다. 유사 도형은 거친 후보 365개→검증 후 160개라 기본 최종 검증 64개를 넘는다. 유사 후보를 근거 없이 제거하거나 경고를 숨기지 않고, 정밀 정책의 별도 예산으로 해당 입력을 끝까지 처리했다. 기본 정책의 예산 경고가 계속 노출되는 회귀 2건도 별도로 보존했다.

## 시간 측정

동일 프로세스 안에서 사례별 1회 워밍업 후 3회 측정한 중앙값(ms)이다. 영상 생성·학습은 시간에서 제외하고, 원본 전처리·후보 검색·검증·정밀화·결과 억제를 포함한다. 순차 실행이며 통계적 성능 우위를 증명하는 실험이 아니다.

| 사례 | 추가 전 기본 | 추가 후 기본 | 추가 후 정밀 |
|---|---:|---:|---:|

정밀 정책은 더 많은 후보를 처리하므로 주변 획과 복합에서 느려졌다. 위 6개 정밀 사례의 `EstimatedWorkspaceBytes`는 약 1.18~1.28MB지만 이것은 전체 피크 메모리가 아니다. 반복 측정의 managed 할당량은 약 5.6~26.2MB이며 임시 배열, GC, working set을 구별해야 한다. 원시 JSON에는 각 반복 시간·할당량과 단계별 시간이 있다.

## 앱 통합과 회귀

전체 자동 테스트 491개(Core182/앱123/Canvas100/Algorithm86), skip0와 저장소 포맷 검사 PASS. 독립 리뷰에서 공개 정밀화 호출의 이전 Geometry 재사용 문제를 발견해 RED 재현 후 무효화했으며 상위 matcher는 최종 pose에서 재평가한다. 근거: `artifacts/geometric-solution-tests.log`, `geometric-format-verify.log`, `geometric-refine-quality-red.log`.

별도 배포 `artifacts/publish-geometric`의 실제 RTX3060 Laptop/DX12 debug 검사 smoke는 exit0 PASS다. 8K 합성 칩16개, 회전 폴리곤, 실제 WPF 품질 옵션·검사 중 입력 잠금, 원본 품질값, OpenCV와 기존 표시 회귀를 확인했다. 두 패턴 검사91.9ms(단일 실행)의 RMS는0.000/0.328px, 특징 대응160/160, clutter0이었다. 회전 패턴의 Rejected 정밀화는 CHECK로 유지한다. `artifacts/geometric-runtime-final/artifacts/inspection-smoke.log`와 `inspection-geometric-quality-app.png`가 근거이며 PNG는 WPF+GPU readback 진단 캡처다. OS 앱 창 스크린샷은 사용자 Escape로 화면 조작이 중단되어 새로 촬영하지 않았다.

## 남은 검증

실촬영 8K/24K, 다양한 부품군, 조명·반사·초점·노이즈 분포, 25% 이상의 특징 가림, 기울임·비균일 배율·비강체 변형, 실시간 검사 FPS, 상용 PatMax와 동일 데이터 비교는 **NOT_RUN**이다. 이 보고서의 작은 합성 18건 통과를 현장 검출률이나 8K/24K 처리속도로 표현하지 않는다. 설정은 동일 합성 입력으로 calibration했으며 독립 holdout 데이터 검증이 추가로 필요하다. 전체 솔루션·앱 GPU 검증은 상위 작업에서 별도로 기록한다.

# 방향키 이동 · 검사 화면 잠금 · 선택 없는 ROI 위치 보기

2026-10-16. 메인 TeachingToolWpf와 독립 DX12/WPF MVVM·Vulkan·wgpu·Skia 샘플에 적용한다. 기존 `VisionCanvas.Sample`도 같은 공통 입력과 탐색 UI를 사용한다.

## 사용법

1. ROI를 선택하고 캔버스에 포커스를 둔다. 방향키는 **원본 이미지 좌표 1px**, Shift+방향키는 **10px** 이동이다. 화면 이동 도구에서도 선택 ROI를 이동할 수 있지만 진행 중인 드래그/그리기 초안 중에는 막는다. 확대율과 DPI에 따라 화면에서 보이는 이동 거리는 달라진다. Ctrl/Alt 조합은 이동으로 사용하지 않는다.
2. 단일 ROI, 복수 선택, 그룹과 반복 셀은 기존 이동 제약을 따른다. 부모와 자식을 함께 선택해도 자식은 한 번만 움직인다. 각 키 입력은 기존 Undo/Redo 한 건이며 경계 때문에 실제 이동이 없으면 이력을 추가하지 않는다. 숫자 입력칸·버튼·목록에서 사용하는 키는 ROI 이동으로 가로채지 않는다.
3. **검사 화면 잠금**을 켜면 캔버스의 키, 클릭/더블클릭, 선택, 그리기, 이동/크기/회전, 마퀴, 가운데 버튼/Space 이동, 휠과 미니맵 탐색을 막는다. 진행 중인 드래그·다각형 초안은 취소한다. 메인 앱과 샘플의 편집/탐색 명령도 비활성화된다. 다시 체크를 해제하면 사용 가능하다.
4. 잠금은 영상 공급과 렌더링을 중단하지 않는다. 검사 결과나 외부 코드가 게시하는 문서/장면도 계속 표시할 수 있다. 운영체제 창 닫기나 외부 검사 제어를 금지하는 보안 잠금은 아니다. 이 설정은 편집 이력·저장 문서에 포함하지 않는다.
5. **ROI 위치 보기** 목록에서 대상을 고르면 해당 ROI의 회전을 포함한 경계가 여백과 함께 화면에 맞춰진다. 캔버스의 편집 선택, ROI 값과 Undo/Redo는 유지된다. **ROI 맞춤**은 같은 대상을 다시 보여 주고, **전체 보기**는 이미지 전체로 돌아간다. 원래 편집용 ROI 목록은 기존 선택 기능을 유지한다.

로딩/붙여넣기 준비 중의 일시적인 편집 제한과 검사 잠금은 구별한다. 준비 중에는 기존 취소 버튼과 Esc를 사용할 수 있고, 검사 잠금에서는 캔버스 키를 모두 막는다. 잠금 해제 버튼 자체는 계속 사용할 수 있다.

반복100,020,001셀은 목록에서 **배치 한 행**이다. 셀 전체를 목록 객체로 만들지 않는다. 목록은 펼칠 때 문서의 행 버전이 달라진 경우에만 다시 만들며, 프레임·pan/zoom·기하 이동마다 전수 생성하지 않는다. 대규모 일반 ROI 목록을 처음 펼치는 비용은 아직 별도로 측정하지 않았다.

## 다른 검사 앱에서 사용하기

Core는 WPF나 렌더러에 의존하지 않는다. 외부 결과 목록도 원본 좌표 영역을 넘겨 선택 없이 탐색할 수 있다. 문서/UI를 소유한 실행 문맥에서 호출한다.

```csharp
// 전체 사용자 입력 차단. 앱의 외부 편집 명령도 같은 상태에 바인딩한다.
input.IsEnabled = false;
// 직접 HWND 컨트롤만 사용할 때의 전체 입력 차단. 영상 게시와 렌더링은 계속된다.
viewport.IsInputEnabled = false;

// ROI ID 또는 반복 배치 ID로 화면 맞춤. 편집 선택·이력은 바꾸지 않는다.
bool shown = session.FocusRoi(roiId, layout.Width, layout.Height);

// 검사 결과 영역 또는 반복 배치의 특정 셀을 직접 표시할 수도 있다.
session.FocusBounds(resultBoundsInImagePixels, layout.Width, layout.Height);
session.FitImage(layout.Width, layout.Height);
```

없는 ID, 유효하지 않은 크기/경계 또는 진행 중인 편집 preview에는 탐색 메서드가 `false`를 반환하고 상태를 바꾸지 않는다. 위 Core 메서드는 프로그램의 표시 요청이므로 사용자 입력 잠금과 독립적이다. 제공한 UI는 잠금 중 목록 탐색도 차단한다.

`ViewportNavigationViewModel` + `ViewportNavigationBar`가 여러 호스트의 잠금 체크박스·독립 탐색 목록·명령을 공유한다. VM은 문서와 `InteractionController`, `ViewportLayout`을 받고, View는 바인딩·목록 펼침·포커스 판별만 맡는다. 기본 `Dx12Viewport`를 상속하는 Vulkan/wgpu/Skia는 같은 HWND 입력 차단을 사용한다. 렌더러별 장치·셰이더·영상 버퍼 수명은 변경하지 않았다.

## 검증과 한계

- Core: 방향키 이동·부모 경계·부모/자식 중복 방지·Undo/Redo·잠금 전환 중 preview 취소·선택 없는 회전 ROI 맞춤·없는 ID/0크기 거부. 전체401건 통과.
- 공통 Canvas: 잠금으로 휠/키가 우회하지 못하는 회귀, 바인딩, 선택/이력 보존, 현재 기하로 다시 맞춤, 삭제 대상 처리,1억 반복셀의 단일 행/개별 이동·이력 검증. 전체248건 통과.
- 실제 DX12 하드웨어/WARP 창: 네이티브 방향키, WPF 목록 선택과 목록 방향키의 ROI 비변경, 잠금/해제, 로딩 중 Esc 취소. 잠금 중7680×4320 Gray8 프레임을50→180으로 바꿔 렌더러 캡처 픽셀 확인. MVVM 전체21건 통과, 기존 ken32 선택 시험1건 건너뜀.
- 실제 Vulkan/Skia/wgpu 창: 키와 포인터/휠 차단, 잠금/해제 후 다시 이동, 선택 없는 ROI 맞춤/전체 보기, 잠금 중 새8K 프레임 표시를 확인했다. Vulkan16건/Skia29건/wgpu19건 통과. 기존 ken32/성능 선택 시험은 각각1/2/1건 건너뛰었으며 최종 결과는 아래 TRX에 기록했다.
- 메인 WPF의 키·명령·목록·비동기 preview 준비 관련40건 통과. 위 중복 없는 관련 테스트 합계774건 통과, 기존 선택 시험5건 건너뜀. 기존 독립 DX12 샘플의 `--smoke --output artifacts/canvas-navigation/legacy`도 종료 코드0으로8K/24K·편집/이력·파일 실패 원자성·렌더 오류 없음 확인.
- 처음 만든 DX12 영상 검증의 “전체 픽셀 중1/3 이상” 조건은 가로로 긴 뷰포트의 맞춤 여백을 고려하지 않아 실패했다. 실패 캡처에서 영상 값50이 정상임을 확인하고, 화면 중심의 실제 영상 RGB를 비교하도록 고쳤다. 제품 기준을 완화한 성능 판정이 아니다.
- 잠금 조건을 반전하는 변이 실험에서 새 회귀 테스트가 실패함을 확인한 뒤 원본 코드를 복원하고 Core 전체를 다시 통과했다.

재현 명령은 `dotnet test tests/<프로젝트>/<프로젝트>.csproj --no-restore -m:1 -nodeReuse:false -p:UseSharedCompilation=false`다. 실제 HWND/GPU 테스트는 로컬 Windows 데스크톱에서 실행한다. 이번 환경의 샌드박스에서는 VSTest와 testhost가 연결되지 않아 허용된 로컬 실행으로 검증했다.

증거: `artifacts/canvas-navigation/*.trx`, `artifacts/canvas-navigation/Automatic/navigation-ui.png`, `Software/navigation-ui.png`, 두 폴더의 `locked-frame-50.png`/`locked-frame-180.png`, `artifacts/canvas-navigation-mutation.log`. WPF UI 캡처는 네이티브 영상 영역을 포함하지 않으므로 영상은 별도 렌더러 캡처로 검증한다.

이번 검증은 실제 카메라 수집·지속60FPS·장시간 메모리 안정성·전체1억 객체 할당·현장 검사 정확도를 입증하지 않는다. ken32 성능 재측정이나 기존 성능 결과의 변경도 없다. 새 의존성, 진단용 제품 코드, 커밋·푸시 없이 로컬 수정·검증만 진행했다.

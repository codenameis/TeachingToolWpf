# 대량 복제·미니맵 검증 · 2026-10-02

약 7,000개 복사/붙여넣기에서 확인한 계층 검색 비용과 필터 GPU 슬롯 고갈을 수정했다. 사용자 경로인 **300개 → 전체 선택·복사·붙여넣기 → 600개 → 반복**을 19,200개까지 검증했다. 우하단 미니맵으로 전체 이미지/현재 영역을 표시하고 클릭·드래그로 이동한다. 설계는 [ADR-007](decisions/0007-bulk-paste-and-minimap.md), 원시 수치는 [JSON](data/clipboard-minimap.json)을 따른다.

## 조건과 재현

Windows x64, .NET 10 Release, Ryzen 5 5600H/RAM 32 GB/RTX 3060 Laptop을 사용했다. 실제 앱이 보고한 GPU 전용 메모리는 5.9 GiB, 당시 예산은 5.1 GiB였다. 8,192×8,192 합성 이미지에서 평면 격자, PCB 부품/패드 계층, 동일 위치/크기의 완전 중첩 ROI를 사용했다. 실제 사용자의 수동 300개 형상은 제공받지 않았으므로 같은 조작 순서의 합성 재현이다.

ROI 초기 생성 후 마퀴와 ViewModel의 Ctrl+C/Ctrl+V 명령 경로를 사용했다. 각 명령 후 UI 레이아웃을 반영하고 100ms 대기했다. 최종 실행은 DX12 debug layer를 켰다. 아래 값은 **각 배치의 단일 진단 실행**이며 정식 워밍업/60초×3회 p95/p99 측정이 아니다. 입력 이벤트 반환·작업 완료·UI 응답 간격은 서로 다른 값이다.

```powershell
dotnet build TeachingToolWpf.slnx -c Release --no-restore
dotnet test TeachingToolWpf.slnx -c Release --no-restore
bin/Release/net10.0-windows/TeachingToolWpf.exe --clipboard-check --clipboard-repeat --clipboard-layout pcb --clipboard-report artifacts/clipboard-check-pcb.json --gpu-debug
bin/Release/net10.0-windows/TeachingToolWpf.exe --clipboard-check --clipboard-filter --clipboard-report artifacts/clipboard-check-filter.json --gpu-debug
bin/Release/net10.0-windows/TeachingToolWpf.exe --smoke --gpu-debug
```

`--clipboard-layout`은 `flat`, `pcb`, `overlap`을 지원한다. `--clipboard-repeat` 없이 실행하면 7,000개에서 시작한다. 보고서의 `stage=complete`, `error=null`, 프로세스 종료 0을 함께 검사한다. 진단 캡처는 요청한 제출 버전 이후이며 이미지 개요가 준비된 프레임을 저장한다.

## 수정 전후

동일 위치의 7,000개를 14,000개로 붙여넣는 동기 경로는 약 **2,167.73ms → 309.49ms**로 줄었다. 두 값은 모두 DX12 debug layer를 끈 동일 진단의 개별 관찰이다. 변경 ROI마다 교차 자식 후보를 반복 열거하지 않고, 대량 변경에서는 전체 ROI의 최소 포함 부모를 한 번씩 찾는다. 부모 판정이나 이력 정확성을 생략하지 않았다.

별도 7,000개 Binarize 미리보기 시험에서는 기존 코드가 `GPU 타일 슬롯이 소진되었습니다` 오류 후 렌더 스레드를 종료했다. ROI마다 texture descriptor를 사용한 것이 원인이었다. 결과를 페이지 atlas로 묶어 수정했고 최종 실행에서 필터 등록 → 취소 → 14,000개로 붙여넣기 → Undo/Redo → pan → GPU 캡처까지 완료했다. 사용자가 원래 필터를 켰는지는 확인되지 않았으므로 이 오류를 사용자 사례의 유일한 원인으로 단정하지 않는다.

## 최종 반복 복제

각 단계 직전에 현재 ROI 전체를 마퀴로 선택하고 복사했다. 아래 값은 작업 준비·확정·레이아웃을 포함한 완료 시간(ms)이다. 필터 처리 완료와 GPU 표시 지연은 포함하지 않는다.

| 복제 결과 | 평면 | PCB 계층 | 완전 중첩 |
|---|---:|---:|---:|
| 300 → 600 | 45.58 | 48.78 | 49.59 |
| 600 → 1,200 | 41.54 | 52.96 | 46.94 |
| 1,200 → 2,400 | 82.39 | 95.75 | 68.35 |
| 2,400 → 4,800 | 128.51 | 202.38 | 110.61 |
| 4,800 → 9,600 | 234.14 | 489.86 | 211.08 |
| 9,600 → 19,200 | 425.27 | 1,587.69 | 357.25 |

UI에 16ms 간격의 Dispatcher timer를 두고 이벤트 간격과 작업 마지막 구간의 최대값을 기록했다. OS 타이머 해상도/스케줄링을 포함하므로 CPU 점유 시간이나 실제 디스플레이 지연과 같지 않다.

| 최종 붙여넣기 | 최초 명령 반환(ms) | 전체 완료(ms) | 최대 UI 응답 간격(ms) | 작업 중 timer 처리 횟수 |
|---|---:|---:|---:|---:|
| 평면 9,600 → 19,200 | 5.39 | 425.27 | 99.06 | 13 |
| PCB 9,600 → 19,200 | 5.91 | 1,587.69 | 83.22 | 61 |
| 중첩 9,600 → 19,200 | 5.49 | 357.25 | 76.05 | 12 |
| Binarize 등록 7,000 → 14,000 | 9.56 | 314.98 | 84.98 | 9 |

기하·계층 준비 중 UI가 응답했으나 확정/목록 갱신 등에서 짧은 지연은 남는다. “전체 붙여넣기가 6ms”, “항상 60 FPS”로 해석하면 안 된다. 준비 시작 20ms 후 Esc를 예약한 취소 시험은 배치별 약 47–58ms에 끝났고 기존 ROI 참조·이력을 유지하며 편집 가능 상태로 복귀했다. 협력적 취소이므로 큰 계층 계산 내부에서 취소 응답이 늦어질 수 있다.

## 정확성과 실제 GPU 검증

- Release 솔루션 빌드 경고/오류 0. Core **60개**, Imaging/WPF **32개** 통과.
- 7,000개 중첩 붙여넣기의 ID 유일성·형상/설정·부모 관계·단일 Undo/Redo, 비동기 취소와 Redo 보존을 검사했다. 반복 복제 진단은 매 단계 ROI/선택 개수, 최종 취소, Undo 선택 복원과 Redo ROI 값 일치를 검사한다.
- atlas는 7,000개 출력과 가로/세로로 긴 혼합 출력에서 페이지 수·픽셀·UV·원래 순서를 검증했다. 실제 RTX에서 7,000개 미리보기의 렌더 종료 오류가 재발하지 않았다.
- 미니맵은 정사각 8K, 긴 24K, 가로로 긴 이미지의 좌표 왕복·종횡비·가시 영역·경계 제한, Draw 도구 입력 차단, 클릭/잡은 위치 유지 드래그, 취소/resize, ROI·선택·이력 보존을 검사했다.
- 실제 HWND 메시지와 RTX/DX12 debug smoke에서 **8K 정적, 24K 정적, 8K 라이브**의 미니맵 클릭·드래그·캡처 상실 취소를 확인했다. GPU readback 이미지 `minimap-8k.png`, `minimap-24k.png`, `minimap-live.png`도 확인했다. 미니맵은 전체 원본이며 필터 미리보기는 주 화면 ROI에만 표시된다.
- 최종 배포 실행 파일에서도 편집·그룹·목록·한글 속성·필터·미니맵·8K 라이브·렌더 재시작 smoke 종료 코드 0. 로그에 D3D12 경고/오류가 없었다. 미니맵의 세 캡처도 배포본에서 다시 생성해 확인했다.
- 클릭과 드래그를 구분하는 조건을 일시 반전해 회귀 테스트 실패를 확인한 뒤 복원했고 전체 Core 테스트가 다시 통과했다.
- 독립 코드 리뷰에서 비동기 스냅샷/확정, atlas 소유권/순서, 미니맵 입력·좌표·GPU 수명, 캡처 버전 경합을 검토했다. 원칙 예외는 없다.

## 남은 범위

이번 검증은 실제 Windows/GPU에서 실행한 자동 진단이다. OS 물리 마우스로 전체 조작을 다시 수행한 E2E와 실제 카메라는 미검증이다. 혼합 DPI 모니터 이동은 기존 미검증 항목으로 유지한다. 라이브 미니맵은 256×160 표시 목표로 기존 프레임 준비기를 재사용하지만 축소 배수 상한 16 때문에 8K에서는 더 큰 축소 texture를 만들 수 있다. 최대 갱신 2Hz이며 추가 CPU 축소 비용이 있다.

수백만 ROI의 전체 선택·초기 구축·이력 확정이 무지연이라는 보장은 하지 않는다. 복잡한 실제 PCB의 깊은 중첩, 장시간 라이브 동시 부하, 전체 명령의 추가 UI 분할은 후속 과제다. [이전 대량 ROI 측정](roi-scalability.md)의 미완료 범위를 유지한다.

# PCB fiducial 형상 검출

후속 성능 기록: [합성 생성 비용을 제외한 CPU/CUDA 측정·최적화](primitive-detection-performance.md). 아래33.987/41.905초는 생성 비용이 포함된 당시 기록이며 순수 검출 시간으로 사용하지 않는다.

2026-10-16. 일반 도형 검출의 후속 작업이며 패턴 매칭과 별도다. `main`에서 로컬 수정·검증만 수행한다. 사용자가 제공한 [7PCB 참고 그림](https://www.7pcb.com/images/blog/fiducial-mark.png)을 기준으로 더블스퀘어를 대각선의 같은 정사각형 두 개로 해석했다. 동심 사각형 두 겹은 기존 사각 테두리/내부 도형 경로다.

## 지원과 판정

기존 삼각형·사각형·원·십자가·도넛·사각 테두리에 다음을 추가한다. 모두 기본 선택 상태이며 별도 학습 없이 검출한다.

| 선택 | 형상과 개수 | 방향의 대칭 |
| --- | --- | --- |
| 마름모 | 네 변 길이가 같은 볼록 사각형. 정사각형은 사각형도 켜면 사각형으로 한 번만 집계 | 비직각 마름모는 긴 대각선, 180° |
| # 마크 | 직교하는 두 세로 획과 두 가로 획, 중앙 사각 구멍 한 개 | 90° |
| 더블스퀘어 | 크기·자세가 같은 정사각형 두 개의 대각선 배치. 모서리 접촉 또는 작은 간격 지원 | 두 중심 연결 방향+45°, 180° |
| 별 (5각) | 규칙적인 다섯 꼭짓점과 다섯 골을 가진 채워진 별 | 72° |
| 별표 (6·8방향) | 같은 폭의 3개/4개 직선 획이 중심에서 교차 | 60°/45° |

더블스퀘어는 사각형 하나당 결과를 중복 생성하지 않는다. 크기는 두 조각을 합친 이미지 축 바깥 폭/높이, 면적은 두 실제 이진 윤곽 면적의 합, 중심은 두 중심의 중점이다. 모서리에서 연결된 경우에는 원본의 한 윤곽을 유지한다. 떨어진 두 조각은 `contour`와 `additionalContours`로 보존하며 각각 닫힌 선으로 표시한다. 빈 구멍인 `innerContours`와 구별한다. 세 사각형의 연쇄처럼 가능한 짝이 여러 개면 묶지 않는다.

회전한 원본 윤곽을 이상 형상과 양방향으로 비교하고 면적·구멍·대칭/획 구조를 함께 확인한다. 작은 픽셀 계단/3×3 median의 모서리 둥글어짐만 제한된 거리로 허용한다. # 방향은 전체 둘레의 4차 모멘트와 직선 방향으로 구하며 약한 모멘트는 직선 방향을 사용한다. 초기 자세 검증에 실패하면 ±3° 안에서 재검증하며 면적/전체 윤곽 조건은 유지한다. 점수는 기하 일치 척도이며 검출 확률이 아니다.

기존 결과 수 0(전체), 점수 .8, 크기 허용 범위 6~512px(기본 12~256px), 2Mpx 원본 창과 최대 네 작업, 명암/마스크/취소를 유지한다. CPU+CUDA도 같은 분류를 쓰며 CUDA는 median 전처리만 수행한다. 크기 범위 내 모든 픽셀 크기에서 모든 복잡한 마크가 보인다는 뜻은 아니다. 작은 획이 이진화로 사라지면 복원하지 않는다.

## 검증

- 독립 래스터 fixture: 추가 5종 × 크기 .6/1/1.5 × 0~179° 1도 간격 = 2,700조건. 밝고 어두운 전경, ±6 잡음, 행 padding. 중심 오차 ≤1px, 대칭 각도 오차 ≤3°, 종류/개수/점수/구멍/조각 확인. 단순 짧은 직선 추정에서 발생한 작은 #의 3.06° 초과를 전체 둘레 방향으로 수정했다.
- 8방향 별표: 세 크기 × 0~44° = 135조건. 더블스퀘어 간격 0/1/2px × 0~177° 3도 간격 = 180조건.
- 손상 형상 거부, 기존 타원/T/L/I/다중 구멍 거부, 종류 필터, 정사각형 이름 중복 방지, 복합 크기, 세 사각형 모호성, 두 조각/빈 간격 마스크.
- 창 소유권 경계에서 중복 없는 복합 검출, 병렬/직렬 결과 동일, ROI가 두 조각을 모두 포함하는지 검사. CLI JSON 왕복, WPF 필터/표시, Canvas에 조각 사이 가짜 연결선 없음.
- 실제 NVIDIA CUDA에서 CPU와 중심·각도·점수·면적·모든 윤곽·잘림/한도 결과 동일 비교.

최종 자동 검사는 알고리즘53·검사 서비스/CLI21·실제CUDA13·WPF VM12·Canvas13 = **112건 PASS**다. Release 앱/CLI/평가 도구 빌드와 변경21개 C# 파일의 공백·명명·스타일 검사가 통과했다. 형식 도구의 워크스페이스 로딩 경고는 남았으나 대상 파일 위반은 없다. 기존 저장소 전체 형식 위반은 이 작업에서 고치지 않았다.

### 실제 WPF 조작

Computer Use로 Release 앱에서 PNG를 열고 일반 도형 찾기를 선택했다. 1024×1024의16개를 CPU 첫529.8ms/CUDA 첫769.4ms로 검출하고 결과 텍스트의 종류·중심·점수·면적이 동일함을 대조했다. 화면에 #의 안팎 윤곽과 더블스퀘어의 두 조각을 확인했다. # 선택 해제 후14개, 복원+CPU 재검사 후16개/46.4ms였다. 최종 각도 보정·복합 라벨 위치·표시 명칭이 반영된 별도 Release 앱에서도16개/CPU510.0ms와 표시를 다시 확인하고 열어두었다. 시간은 화면에 표시된 서비스 시간이며 실제 버튼→물리 표시 지연은 아니다. [접근성 상태 증거](data/pcb-fiducial-ui-validation.json).

실행 로그와 CPU/CUDA 32K 측정 원시는 [검증 묶음](data/pcb-fiducial-validation.zip)에 보존한다.

### 32K 전수 측정

32,768×32,768, 16,384개, 위치를 흔든 256px 셀, 0~89° 회전, 1,849 원본 창. 합성 패턴 생성은 알고리즘과 독립적이며 창 경계에 걸친 도형도 포함한다. 원본 크기 약 96px인 마크를 사용했다.

| 조건 | 개수 | 누락/중복/종류 오류 | 최대 중심 오차 | 최대 대칭 각도 오차 | 서비스 시간(빌드·테스트 종료 후) |
| --- | ---: | --- | ---: | ---: | --- |
| CPU | 16,384 | 모두 0 | 0.0388px | 1.1225° | 33.987초 |
| CPU + RTX 3060 CUDA | 16,384 | 모두 0 | 0.0388px | 1.1225° | 41.905초 |

종류별 개수는 마름모 2,731, # 2,732, 더블스퀘어 2,731, 5각 별 2,730, 6/8방향 별표 합계 5,460이다. 최종 구현의 CPU 세 실행과 CUDA 세 실행의 중심·각도·점수·면적·외곽/구멍/추가 조각 전체 해시는 `1F664E81DFD686EC1F6ED150897DCD86A83D95A545D7BCFA8B57E16F1BC50488`로 같다. 잘림/불완전 경고도 없다.

위 측정의 읽기 시간은 CPU 28.151초, CUDA 32.534초이며 대부분 합성 마크를 픽셀로 만드는 비용이다. 이를 실제 PNG/카메라 입력 성능으로 해석하지 않는다. 실제 검색 작업의 병렬 누적 시간은 CPU 20.930초, CUDA 29.394초다. CUDA는 장치 준비 528.3ms, 업로드 1.087초, 커널/대기 2.309초, 다운로드 .780초다. **이 조건에서 GPU가 더 느렸으며**, 아주 빠른 32K 검사 목표를 달성했다고 표현하지 않는다. 프로세스 peak working set은 CPU 약303MiB, CUDA 약337MiB이며 GPU VRAM 계측값이 아니다.

앞선 최종 구현 반복은 CPU34.412/41.699초, CUDA65.405/36.779초였다. 일부 구간에서 빌드·테스트가 겹쳤으므로 이 시간으로 가속률을 주장하지 않고, 위 표는 모두 끝난 뒤 새 프로세스를 순차 실행한 값이다. 개발 PC의 다른 앱/열 상태까지 통제한 벤치마크는 아니다. 작은 #의 각도 오차를 줄인 전체 둘레 방식은 이32K 크기에서 최대 각도 오차가 기존 .866°에서1.1225°로 증가했다. 검출 개수와 정밀 각도 합격을 구별하며 모든 크기의 각도가 일괄 개선됐다고 표현하지 않는다.

각도 후속 보정 전8K 1,024개에서는 윤곽 거리 검사/독립 합성 생성의 반복 LINQ 할당을 순서가 같은 루프로 바꾼 전후 해시가 동일했다. 첫 실행 서비스 시간 3.627→1.469초, 누적 managed 할당 약2.04GB→0.27GB다. 테스트 영상 생성 최적화가 포함되어 있으므로 전부 제품 검출기 개선으로 귀속하지 않는다.

## 재현

```powershell
dotnet test tests/VisionAlgorithm.Tests -c Release --filter "FullyQualifiedName~PcbFiducialDetectionTests|FullyQualifiedName~PrimitiveShapeDetectionTests"
dotnet test tests/VisionCompute.Tests -c Release --filter FullyQualifiedName~CudaPrimitiveDetectionTests
dotnet test tests/VisionInspection.Tests -c Release --filter "FullyQualifiedName~PrimitiveShapeDetectionIntegrationTests|FullyQualifiedName~RecipeRunnerTests"
dotnet run --project tools/PrimitiveDetection.Evaluation -c Release -- 32768 0 1 --pcb
dotnet run --project tools/PrimitiveDetection.Evaluation -c Release -- 32768 0 1 --pcb --gpu
dotnet run --project tools/PrimitiveDetection.Evaluation -c Release -- 1024 0 0 --pcb --preview
```

`--preview`는 2048px 이하 입력을 `artifacts/pcb-marks-preview.png`로 저장한다. `--pcb`의 독립 형상 생성과 타일 읽기도 서비스 시간에 포함되므로 실제 파일 디코딩/카메라 입력 시간과 구별한다. `DetectionWorkMilliseconds`는 병렬 창의 누적 작업 시간이며 벽시계 시간이 아니다. CPU/GPU 시간은 같은 입력·옵션·결과 해시와 함께 해석한다.

## 남은 범위

일반 패드와 fiducial의 기하 모양이 같으면 영상 형상만으로 용도를 구별할 수 없다. 실제 기판에서는 검색 ROI 또는 기존 템플릿 매칭으로 대상을 제한할 수 있다. 특정 제조사의 모든 변형, 비직교 문자형 #, 임의 개수의 별, 가림/손상/반사/저대비에서 전부 인식한다는 보장은 하지 않는다. 기판 정답 라벨에 대한 누락/오검출률, 물리 위치 교정, 정밀 각도 허용 오차 및 버튼→화면 32K 시간은 별도 검증 대상이다. 합성 전수 개수를 현장 전수 검출로 표현하지 않는다.

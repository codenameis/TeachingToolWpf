# 대량 PCB ROI 성능 검증

2026-10-02. DX12를 유지하면서 선택/기하/목록의 전체 순회를 줄였다. 수백만 ROI의 모든 작업이 지연 없이 끝난다는 결과는 아니다. 특히 초기 생성·계층 구축과 전체 문서를 바꾸는 명령은 별도 비용이다.

## 조건과 측정 범위

- Ryzen 5 5600H, RAM 32 GB, RTX 3060 Laptop GPU. 앱 보고: VRAM 5.9 GiB, GPU 예산 5.1 GiB. .NET SDK 10.0.401, Windows x64, Release, 성능 실행은 GPU debug 꺼짐.
- 8192×8192 합성 정적 이미지, viewport 877.33×540 DIP, DPI 150%. 외부 카메라나 실제 PCB 검사 데이터는 아니다. 노트북 전원/열 상태를 통제한 실험실 측정은 아니다.
- 평면 ROI 격자와 `부품 부모 1개 + 패드 자식 8개` 격자. 수용 대상 총수는 부모와 패드를 합한 값이다. 마지막 부품은 총수에 맞춰 일부 패드만 갖는다. ID는 무작위이며 위치/크기는 고정이다.
- 실제 WPF 창·바인딩·DX12 렌더 스레드가 실행되는 화면 밖 진단이다. 입력 컨트롤러/명령 처리 후 `UpdateLayout`까지의 UI 시간과 UI 스레드 할당을 측정한다. OS 물리 마우스부터 모니터 발광까지의 지연은 아니다.
- 각 조작 5회 워밍업. 기존 비교는 10회 샘플/실행을 3회 반복, 대량 시험은 30회 샘플. 기존 비교는 `(i×97)%N`, 대량은 문서 전역에 균등 분산한 ROI를 선택한다. p50은 정렬 샘플의 상위 중앙값(짝수 개일 때 두 중앙값 중 큰 값), p95는 nearest-rank다. 전후 모두 같은 계산이다.
- `select`는 ID를 지정한 선택 명령, `click`은 포인터 Down/Up, `drag`는 Down/Move/Cancel, `commit`은 단일 선택/소폭 이동/Undo, `rename`은 이름 변경/Undo다. 다중 선택 표의 값은 **2개 선택**이며 200만 개 전체 선택 시간이 아니다. 전체 보기에서 매우 작은 ROI 클릭은 정확한 최소 면적 hit 규칙을 따르므로 지정한 격자 ID와 이웃 후보가 같다고 가정하지 않는다.
- 전체 보기에서는 6 DIP 이하 BVH 집합을 요약 표시한다. 확대 시험은 원본 좌표 대비 4 DIP/px(이 장비 표시 600%)에서 가시 후보에 분산 접근한다. 단일 선택은 실제 형상으로 표시한다.

## 1,550 / 3,550개 전후 반복 비교

수정 전 `8e221ed` 배포본과 최종 코드 `f837cce`를 각각 독립 프로세스로 3회 실행했다. 측정 중 테스트/빌드/프로파일러를 함께 돌리지 않았다. 아래 p50/p95는 **각 실행 백분위 3개의 중앙값**이며 30개 샘플을 합쳐 다시 계산한 백분위가 아니다. 단위 ms.

| 입력 | 클릭 p50 전 → 후 | 클릭 p95 전 → 후 | drag p95 전 → 후 |
|---|---:|---:|---:|
| 1,550 평면 | 14.78 → 2.63 | 120.19 → 3.54 | 209.25 → 4.82 |
| 1,550 PCB | 6.25 → 1.50 | 9.89 → 2.19 | 237.62 → 2.11 |
| 3,550 평면 | 31.88 → 1.73 | 34.55 → 2.50 | 95.23 → 2.07 |
| 3,550 PCB | 12.78 → 1.43 | 14.26 → 2.32 | 174.92 → 2.32 |

3,550 평면 클릭 중앙값은 약 18.4배 개선됐다. PCB drag p95의 실행별 범위는 수정 전 167.15–185.60ms, 후 2.17–2.57ms였다. 평면 drag는 수정 전 5.82–335.05ms로 변동이 매우 컸고, 후 1.80–2.72ms였다. 짧은 10회 샘플의 p95는 최댓값이므로 장시간 지연 보장으로 해석하지 않는다. UI 스레드 클릭당 평균 할당의 실행 중앙값은 3,550 평면 4,348,198 → 76,003바이트, PCB 6,065,604 → 82,180바이트다. 렌더/작업 스레드 할당은 포함하지 않는다.

각 실행의 전체 조작 집계·장비·오류·원본 SHA256은 [보존한 측정 자료](data/roi-scalability.json)에 있다. 원본은 로컬 `artifacts/roi-before-repeat-{1,2,3}.json`, `artifacts/roi-after-isolated-{1,2,3}.json`이다. 백만 단위 실행은 같은 성능 경로를 사용하는 최종 단계 코드이며, 이후 4,096개 이하 목록 정책과 진단 시나리오 보강은 백만 단위 경로를 바꾸지 않는다.

최초 일괄 생성·계층·목록 구축은 평면 100만 **15.07초**, 200만 **31.43초**, PCB 100만 **21.39초**, 200만 **49.00초**였다. 확대 실행에서 200만 구축은 평면 32.96초/PCB 47.68초였다. 전체 보기 연속 실행의 최대 샘플 Private Bytes는 약 **3,790 MiB**였다. 이미지/이력/CLR/WPF를 포함한 프로세스 값이며 GPU VRAM이나 ROI 데이터 단독 크기가 아니다.

## 병목별 근거와 유지한 변경

1. 무이동 클릭에서도 계층/이력을 재계산: 기하가 바뀌지 않은 편집을 일찍 종료하고 동일 선택 알림을 생략했다. 초기 3,550 평면 클릭 p50 40.75ms가 이 단계에서 3.02ms로 줄었다.
2. 매번 전체 ROI 검색/자식 구성/변경 비교: 공유 불변 BVH·자식 색인·변경 ID 기반 이력으로 교체했다. 작은 편집의 경로만 복사하며 이전 렌더 스냅샷은 유효하다.
3. 렌더 전체 순회: BVH 가시 영역과 화면 크기별 요약으로 바꿨다. 선택도 정확한 후보 검색을 사용한다. 명령/도메인의 ROI 수를 줄인 결과가 아니다.
4. WPF unresolved 선택 순회: 백만 ROI 분산 시험에서 선택 p50 102.87ms, 클릭 86.00ms, drag 222.70ms였다. 직접 인덱스 단일 선택 적용 후 각각 2.00/2.29/2.34ms로 줄었다. 다중 선택과 전체 목록 관리까지 제한하기 위해 512개 페이지를 추가했다. 페이지 이동은 추가적인 UI 갱신 비용을 가진다.
5. 속성 TextBox의 긴 대기: 임시 구간 계측에서 이름/X/Y 갱신에 각각 수십 ms가 관찰됐다. `dotnet-trace 10.0.745401`의 스택에는 `TextStore.RequestLock → GrantLockWorker → DispatcherSynchronizationContext.Wait` 경로가 있었다. 표시/편집을 분리한 후 3,550 PCB drag p95가 154.15ms에서 6.23ms로 감소했다(동일 50회 분산 샘플). 한글과 표준 TextBox 입력은 포커스 시 유지한다.

512개 페이지를 모든 문서에 적용한 중간 버전은 3,550개 단순 선택 p95가 5–14ms로 증가했다. 최종 버전은 4,096개까지 한 가상화 목록을 유지하고 그 이상만 페이지를 사용한다. 단일 선택은 ID 인덱스로 바로 조회하며 전체 페이지를 훑지 않는다. 중간 버전 수치를 최종 개선으로 숨기지 않는다.

기각한 실험: GDI 라벨 경로는 PCB drag p95 183.69ms로 개선되지 않아 제거했다. 비활성 필드의 IME 플래그 변경도 167.04ms로 개선되지 않아 되돌렸다. 강제 GC/입력기 전역 차단/Undo 생략은 적용하지 않았다. 지연 팩터리 체인의 장기 메모리 보존은 별도 리뷰에서 찾아 수정했다.

## 정확성과 남은 범위

백만 ROI 일괄 명령도 두 fixture 모두 성공했다. 삭제/Redo는 빈 문서, Undo는 모든 ID·이름·기하·부모·필터 값과 백만 개 선택의 정확한 복원을 검사했다. 아래는 각 1회 실행의 전체 UI 시간이며 백분위가 아니다.

| 백만 ROI 명령 | 평면 | PCB |
|---|---:|---:|
| 전체 선택 | 3.59초 | 2.31초 |
| 전체 삭제 | 1.76초 | 5.40초 |
| 삭제 Undo | 3.14초 | 5.66초 |
| 삭제 Redo | 0.63초 | 2.15초 |
| Redo 후 다시 Undo | 3.93초 | 6.84초 |
| 이미지 문서 상태 교체 | 0.61초 | 0.52초 |
| 이미지 문서 상태 Undo | 3.30초 | 4.29초 |

이 시험의 이미지 교체는 도메인 이미지 참조/ROI/선택/뷰 이력 검사이며 파일 I/O를 포함하지 않는다. 실제 파일 재개방은 기존 smoke·[반복 이미지 교체 검증](memory-replacement-validation.md)에 별도로 있다. 원시 결과는 `artifacts/roi-million-bulk.json`. 대량 명령 동안 UI 점유가 남아 있으므로 이 결과를 무정지 전체 편집으로 표현하지 않는다.

- Core 52개, 영상/WPF 29개 테스트 통과. 큰 이동의 색인·메타데이터 조회, 전수 포함 비교, 스냅샷 수명/동등성, 페이지 선택, 비활성 속성 필드 Value 패턴을 포함한다.
- 실제 RTX DX12 debug smoke: 목록 페이지, 숨은 선택의 일반 클릭 해제, pan 페이지 보존, 포커스/한글 값 Apply/Undo, HWND 포인터/Del, 복제, 그룹/연쇄 삭제, OpenCV Binarize/Edge, 이미지 교체/복원, 라이브 시작/정지·렌더 재시작 통과. D3D12 오류 미관찰. 한글 문자열 입력/바인딩은 검증했지만 물리 IME 조합 입력을 자동 검증한 것은 아니다.
- 수백만 개 전체 변경은 선형 비용과 이력 메모리가 필요하다. 기본 이력 200명령/추정 1 GiB이며 초과하는 한 명령은 원자적으로 거부한다. 백만 개 전체에 필터를 동시에 적용하는 실시간 검사 성능은 검증하지 않았다.
- 초기 구축은 아직 UI를 오래 점유한다. 깊은 중첩, 모든 ROI가 겹치는 적대적 배치, 백만 이상 영역의 동시 변형, 실제 PCB/CAD 데이터, 8K 라이브와 200만 ROI의 동시 지속 부하는 추가 검증 대상이다.
- CPU 처리/레이아웃 수치와 GPU/Present/프레임 간격은 구분한다. 정적 입력의 프레임 간격에는 의도적인 20ms 샘플 간격·유휴 대기가 포함되므로 이를 FPS 역수로 계산하지 않는다. 확대 화면 캡처에서 부모/패드와 선택 핸들/이름이 표시됨을 확인했다.

## 재현

```powershell
dotnet build .\TeachingToolWpf.slnx -c Release --no-restore
.\bin\Release\net10.0-windows\TeachingToolWpf.exe --roi-benchmark --roi-counts 1550,3550 --roi-samples 10 --roi-legacy-operations --roi-report artifacts\roi-small.json
.\bin\Release\net10.0-windows\TeachingToolWpf.exe --roi-benchmark --roi-counts 1000000,2000000 --roi-samples 30 --roi-distributed --roi-single-batch --roi-capture --roi-report artifacts\roi-fit.json --metrics artifacts\roi-fit-frames.csv
.\bin\Release\net10.0-windows\TeachingToolWpf.exe --roi-benchmark --roi-counts 2000000 --roi-samples 30 --roi-distributed --roi-single-batch --roi-detail --roi-report artifacts\roi-detail.json
.\bin\Release\net10.0-windows\TeachingToolWpf.exe --roi-benchmark --roi-counts 1000000 --roi-samples 5 --roi-distributed --roi-single-batch --roi-bulk --roi-report artifacts\roi-bulk.json
```

`--roi-single-batch`는 한 번의 AddRange로 구축한다. 생략하면 10만 개 단위로 나누어 구축하고 그 사이 Dispatcher를 양보한다. 구축 시간 비교에는 이 옵션을 일치시켜야 한다. 장비/배율/입력/반복 횟수/오류 필드는 JSON에 남는다. 아키텍처와 검토 근거는 [ADR-006](decisions/0006-large-roi-interaction.md), [품질 검토](quality-review.md)를 따른다.

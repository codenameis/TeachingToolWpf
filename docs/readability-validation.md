# 코드 가독성 정리와 검증

2026-10-02. 사람이 입력·편집·렌더 흐름을 따라갈 수 있도록 핵심 경계를 정리했다. 기능 추가나 그래픽 API 변경은 없다. 읽기 시작점은 [코드 읽기 안내](code-guide.md)에 있다.

## 바뀐 표현과 유지한 동작

| 경계 | 정리한 내용 | 유지한 계약 |
|---|---|---|
| Controls | 메시지·키·커서·창 스타일 명명, signed 좌표/휠 해석, DPI 변환 분리 | focus→capture→Down, Up→capture 해제, 취소·오류·종료 순서 |
| ROI GPU 데이터 | 숫자 인덱스 대신 `RoiDrawConstants` 필드, 셰이더 변수·코너 계산 명명 | 128바이트 배치, 형상 32바이트·역할 4바이트, 같은 좌표/색/두께 |
| ROI 그리기 | 캐시 조회/생성, 역할만 업로드, 비가시 캐시 제거를 함수로 구분 | 같은 블록/LOD/역할 버전, fence 이후 해제, 회전 중 형상 재사용 |
| EditorSession | 미리보기 materialize→해제→시작 상태 복원→이력 확정 순서 명시 | 실제 변경 없는 편집, 실패·취소·Redo·현재 viewport 보존 |
| Presentation | 큰 선택의 준비, 마지막 요청 적용, Mouse Up 대기와 목록 갱신 명명 | 단일 worker, 최신 요청 하나, 오래된 결과 거부, 기존 임계값 |
| GPU 수명 | 프레임 완료 번호·해제 예약, 전송 공간 정렬/최소 크기, 캡처 버전 조건 명명 | GPU 완료 전 재사용 금지, 동일 512B/64KiB 정렬·4MiB 최소 블록 |
| 셰이더 컴파일 | `ShaderCompiler.CompileFile`로 파일/바이트 전달/진단 수명 경계 명시 | 같은 shader profile·진입점, 컴파일 오류 전파·blob 해제 |

새 데이터 타입은 값 타입이며 상수/필드 이름을 붙이기 위해 매 프레임 힙 객체를 추가하지 않는다. 큰 ROI 자료구조, 화면 밀도 LOD, Command/Memento, 렌더 스레드와 WPF 경계는 유지한다. 기존 알고리즘 전체를 교체하거나 새 범용 렌더 추상화 계층을 만들지 않았다.

`.editorconfig`를 추가하고 변경한 C# 파일에 SDK 공백 포매터를 적용했다. 자동 서식과 의미 있는 함수/필드 이름을 함께 사용한다. 문장 수를 줄이기 위해 부작용을 한 줄로 압축하지 않는 규칙을 AGENTS.md에도 남겼다.

## 자동 검증

- Core **158개 통과**: 계층·변형·이미지 경계·이력·취소·원자성.
- Imaging/WPF **123개 통과**, 전체 **281개 통과**. 기존 검증을 제거하거나 실패 기준을 완화하지 않았다.
- 새 GPU 계약 검증 6개: 모든 필드의 바이트 오프셋, 관리 객체 참조 없음, 네 가지 선택/그림자 조합의 이전 float 배열과 바이트 완전 일치, instance/role stride.
- 새 입력 경계 검증 13개: 음수 XY, signed16 경계, 64비트 포인터 상위 비트 무시, ±0.5 휠 입력, 키 flag와 휠 값 분리.
- 새 셰이더 컴파일 검증 7개: 실제 ROI/이미지 VS·PS 네 진입점, 한글 주석을 가진 두 shader profile, 잘못된 소스의 진단 보존. GPU 생성 없이 실제 D3DCompiler로 검사한다.
- Release 솔루션 빌드 **경고 0·오류 0**.

초기 단계의 한 테스트 실행은 새 GPU 타입으로 이행하던 도중 옛 `WriteRoleStyles` 호출과 맞지 않아 컴파일 단계에서 중단됐다. 테스트의 색/두께 조건을 유지한 채 새 필드를 검사하도록 연결한 이후 전체 suite가 통과했다. 제품 오류를 숨기는 호환 메서드나 테스트 제외는 추가하지 않았다.

첫 RTX 실행에서는 한글 HLSL 주석을 추가한 뒤 소스 끝부분이 잘리는 컴파일 실패를 발견했다. 기존 문자열 경로는 변환된 네이티브 문자열에 문자 수를 길이로 전달한다. 이 전달 방식은 [Vortice 공식 컴파일러 소스](https://github.com/amerkoleci/Vortice.Windows/blob/main/src/Vortice.D3DCompiler/Compiler.cs)에도 나타난다. 로컬 3.8.3에서 실제 ROI VS/PS와 한글 주석 예제가 실패하는 것을 먼저 재현했다(7개 중 4개 실패). `ReadAllBytes`와 바이트 span overload로 정확한 길이를 전달하고 성공/실패 양쪽 blob을 해제하도록 수정한 뒤 7개와 전체 suite가 통과했다. 한글 주석 제거로 문제를 숨기지 않았다. 최초 실패 로그와 red 테스트도 원시 자료에 보존한다.

## 실제 GPU와 성능 비교

최종 RTX 3060 Laptop GPU/DX12 debug/150% DPI smoke는 종료 0, `completed=true`, 새 오류 0이다. 포인터·설정 패널·색/두께·자식 분리·Undo/Redo, 미니맵, 필터, 이미지 교체, 라이브와 렌더 재연결이 통과했다. 미선택 역할·부모 선택·자식 분리의 세 PNG는 변경 전 캡처와 SHA-256이 완전히 같았으며 실제 캡처도 확인했다. 실제 물리 마우스부터 모니터까지의 지연 측정은 아니다.

리팩터링 전 검증 배포본(`roi-style-final`)과 수정 배포본(`readability-release`)을 각각 20만 ROI 평면/PCB로 3회 실행했다. Release, GPU debug off, 고정 8192² 합성 이미지, 워밍업 2회+입력 180회, DPI 150%, 기존 LOD/중복 표시 정책을 유지했다. PCB는 부모 22,223개를 선택해 자손 포함 20만 개에 영향을 준다. 아래는 실행별 통계의 최솟값–최댓값이며 시간 단위는 ms다.

| 배치 | 전 callback p50 | 후 callback p50 | 전/후 입력 할당 p50 | 전 frame 간격 p95 | 후 frame 간격 p95 |
|---|---:|---:|---:|---:|---:|
| 평면 | 0.1965–0.2179 | 0.2032–0.2222 | 3,584 / 3,584 B | 21.1294–21.4383 | 21.5952–24.8583 |
| PCB 부모 | 0.1899–0.2103 | 0.2149–0.2430 | 3,632 / 3,632 B | 21.0375–21.2164 | 21.1583–24.7303 |

12개 실행 모두 정확한 Undo/Redo와 반복 회전 구간 ROI 업로드 0 B를 확인했다. callback은 모델 preview가 존재한 입력(`DisplayedMeasured`)만 사용하며 전체 프레임 시간과 다르다. GPU 제출 단계의 PCB p50은 전 0.3310–0.3447, 후 0.3291–0.3461이었다. CPU 클럭·전력·열·OS 스케줄링을 고정하지 않았고 위 실행은 전/후를 시간대로 묶었다. 따라서 프레임 간격 편차가 코드에서 생겼는지 확인하기 위해 PCB 전/후를 번갈아 추가 측정했다. 초기 준비·확정·Undo/Redo 완료 비용은 반복 callback과 별개로 원시 자료에 남겼다. 이전부터 남아 있던 지연이 해결됐다고 주장하지 않는다.

교차 실행은 각 3회, 순서를 후→전 / 전→후 / 후→전으로 바꿨다. 같은 시기에 이전판도 프레임 간격이 길어졌고 아래처럼 범위가 겹쳤다. 추가 6회도 정확한 Undo/Redo, ROI 업로드 0 B다. 전/후 입력 할당 p50은 모두 3,584–3,632 B로 같은 범위였다.

| PCB 교차 실행 | callback p50 | callback p95 | 프레임 간격 p95 | GPU 제출 CPU p50 |
|---|---:|---:|---:|---:|
| 이전판 | 0.2034–0.2380 | 0.3220–0.3677 | 21.0449–22.3482 | 0.3766–0.4077 |
| 수정판 | 0.2195–0.2292 | 0.3255–0.3905 | 21.5271–22.5870 | 0.3721–0.3983 |

기존 재사용/할당 특성이 유지됨을 확인했다. 작은 시간 차이 전부의 원인을 확정하거나 모든 장비에서 동일 성능을 보장하는 시험은 아니다. 원시 자료·실행 스크립트·실패/성공 로그·캡처·바이너리 해시는 [검증 자료 묶음](data/readability-validation.zip)에 있다. 압축을 풀고 `scripts/Summarize-RoiRotation.ps1`에 `readability-before-*-r*.json`, `readability-after-*-r*.json`, `readability-interleaved-*-r*.json`을 전달하면 요약을 재생성할 수 있다. 통계와 LOD의 정확한 의미는 [회전 성능 기록](rotation-performance.md)을 따른다.

## SOLID·GRASP 검토

| 원칙 | 이번 변경의 근거 |
|---|---|
| SRP | 입력 해석, 편집 확정, GPU 전달 값·자원 수명 책임을 구분 |
| OCP | 표시 palette와 기존 입력/영상 계약 유지, 새 기능 분기 없음 |
| LSP | 기존 취소·실패·이력 동작 유지, GPU 표현 교체는 바이트 계약 검증 |
| ISP | 새 범용 인터페이스 없이 소비자 전용 값 타입만 추가 |
| DIP | Core에 WPF/Win32/DX12 의존성을 추가하지 않음 |
| Information Expert | 좌표 메시지는 Controls, 문서 확정은 Core, GPU 배치는 전달 타입이 설명 |
| Creator | 문서·작업·GPU 자원의 기존 생성/소유/해제 주체 유지 |
| Controller | VM은 요청 연결, Session은 편집 확정, 렌더러는 그리기 담당 |
| Low Coupling | 불변 장면과 명시적 바이트 전달 경계 유지 |
| High Cohesion | 관련 단계를 의미 있는 함수로 묶고 무관한 책임은 이동하지 않음 |
| Polymorphism | 기존 도구/영상 계약 유지, 명명만을 위한 상속·전략 추가 없음 |
| Pure Fabrication | 기술 책임인 입력 해석·작업 준비·GPU 전달/캐시를 도메인에서 격리 |
| Indirection | 기존 어댑터와 명명된 GPU 전달 값이 외부 API 연결을 담당 |
| Protected Variations | 입력 bit 해석과 C#/HLSL 배치를 경계 테스트로 보호 |

승인된 원칙 예외는 없으며 이번 정리에도 예외를 적용하지 않았다. `unsafe`, GPU fence, 셰이더와 BVH의 전문적인 내용 자체가 사라진 것은 아니다. 필요한 경계에 유지하고 이름·주석·읽기 안내로 설명한다. 실제 저사양 GPU, 물리 모니터 지연, 현장 PCB+8K 라이브 동시 부하와 기존 최초 준비/대량 확정 지연은 이번 가독성 작업의 완료 기준과 구분한다.

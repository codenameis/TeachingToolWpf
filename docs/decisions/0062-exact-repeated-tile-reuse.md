# ADR-062: 반복 모듈의 동일 픽셀 맵 재사용

상태: 채택, 2026-10-16. 사용자가 요청한 현재 상태는 `f86e32d`로 `origin/main`에 푸시했다. 이후 성능 변경은 로컬 수정·검증이다. [실측](../cpu-matching-repeated-modules.md).

## 문제

전체 8K에서 드문드문 배치한 8개 대상과 기본 샘플의 반복 모듈 256핀은 비용이 다르다. 기존 공간 캐시는 위치가 다르면 같은 픽셀로 같은 방향/거리 맵을 다시 만들었다. Line2D의 SIMD 행 누적은 공유 버퍼 때문에 순차 실행했고, NCC는 같은 자세에서도 표본마다 영상 포함 여부를 다시 확인했다.

## 결정

- Line2D/Chamfer의 원본·중간 지역 맵만 같은 검사 안에서 공유한다. 영역 크기와 halo를 포함한 모든 Gray8 픽셀이 같아야 한다. 해시가 같아도 `SequenceEqual`로 확인한다. 좌표별 탐색·보정·검증은 모두 수행한다.
- `PyramidSearch`의 `reuseIdenticalTiles`는 기본 false다. 입력 픽셀과 템플릿에만 의존하는 읽기 전용 전략만 명시적으로 허용한다. 외부 전략의 기본 동작과 순차 계약을 보존한다.
- 위치 캐시의 기존 최대 32항목·맵 크기 추정 512MiB 상한은 늘리지 않는다. 동일 위치의 타일은 기존 조회를 쓰며, 새로운 위치에서만 픽셀 해시/비교를 수행한다. 이는 프로세스 전체 메모리 상한은 아니다.
- Line2D는 행마다 풀에서 빌린 독립 누적 버퍼를 `finally`에서 반환한다. `IRowScore.SupportsParallelRows` 기본값은 false이며 Line2D만 true로 지정한다. 기존 최대 4작업과 행 내부 SIMD/float 누적 순서를 유지한다.
- NCC의 표본 경계 범위 재사용은 희소 8K에서 이득이 있었지만 밀집 조건에서 개선을 확인하지 못해 원복했다. 동일 타일 공유 실험도 보정 단계가 느려져 제거했다. NCC 구현은 체크포인트 그대로다. 원본 픽셀을 사용하는 NCC와 준비된 방향 맵을 사용하는 두 방식을 같은 캐시 정책으로 강제하지 않는다.

## 보존 조건

점수 0.75, 후보 2048, 출력 256, 각도·배율·해상도·검색 영역을 유지한다. 결과·점수·평가 횟수·잘림 플래그의 전후 동일성을 확인한다. 실제 촬영 모듈이 닮았다는 이유로 같은 픽셀이라고 가정하지 않는다. 노이즈나 결함으로 한 픽셀이라도 다르면 맵을 새로 준비한다. 이전 프레임의 검사 결과는 재사용하지 않는다.

새 반복 모듈 진단에서 드러난 기존 후보 잘림과 Sub-NCC 위치 오차는 합격으로 바꾸지 않는다. 125/80ms 달성과 별도로 기록한다.

# ADR-042: 메인 문서의 반복 ROI·부분 선택·클립보드

- 날짜: 2026-10-13
- 상태: 사용자 승인 범위 구현. 엄격한 60FPS 성능 수용은 별도 [검증 기록](../main-editor-repeated-roi-validation.md)을 따른다.
- 승인: [구체적인 범위](../../tasks/main-editor-billion-roi-scope.md)에 대한 사용자 답변 **“공통 문서 확장까지 진행”**. `main` 로컬 변경·검증만 하며 커밋/푸시하지 않는다. 설계 원칙 예외 없음.

## 문제

ADR-041의 별도 시험 창은 사용자가 원한 메인 편집기의 부분 선택·복붙을 제공하지 못했다. 일반 `ImmutableDictionary<Guid, Roi>`에 1억 개를 펼치면 개별 객체/이력/선택 배열을 모두 만들어야 한다. 일반 ROI 30만 개에서도 15만/20만 선택 시 ID 검증, 불변 해시 집합 생성, 선택 BVH의 ID 경로 재구축, 자손 집합 중복 생성이 지연을 만들었다.

## 결정

1. 기존 `DocumentState`에 `RepeatedRois`와 `RepeatedSelection`을 추가한다. 일반 ROI 저장·계층은 유지한다. 반복 ROI의 정체성은 `(BatchId, Index)`이며 부분 편집 후에도 변하지 않는다. `RoiCount`/`SelectionCount`는 두 표현을 합한 `long`이다.
2. `RoiCellSet`은 정렬된 반개구간들의 합집합이다. 전체 100,020,001개는 구간 하나, 세로 절반은 최대 10,001개 구간이다. `RepeatedRoiBatch`의 불변 part는 셀 집합과 공통 pose를 공유한다. 부분 이동/회전은 선택·비선택 part를 나누며 셀 전체를 열거하지 않는다. 개별 형상은 기존 격자의 수정값으로 저장한다.
3. 같은 셀 열 범위의 인접 행을 occupied block으로 합친다. 실제 형상/수정값의 경계로 이미지 제약과 선택을 계산한다. 렌더러는 이 블록만 그려 WARP의 전체 화면 중복 처리와 픽셀별 10,001개 선택 범위 검색을 제거한다. 회전 후 부분 선택의 수천 개 미세 계단은 축소에서 점유 요약 셀로 합쳐 같은 픽셀의 중복 처리를 줄인다. 요약은 부분 경계를 셀 단위로 근사할 수 있으며 확대는 정확한 개별 윤곽/블록을 사용한다. 작은 단일 블록의 실제 외곽을 보존하고 두께가 블록 바깥으로 나가는 범위도 그린다. 실제 도형·hit·이력은 표시 LOD로 대체하지 않는다.
4. `EditorSession`, 준비/취소/게시, `RoiClipboard`, `DocumentEdit`의 기존 흐름에 반복 배치 변경을 포함한다. 복사는 선택 부분의 불변 자료를 공유하고 붙여넣기는 새 배치 ID와 배치 pose를 만든다. 일반 ROI와 혼합해도 생성 순서·원자적 Undo/Redo·이미지 변경 복원·오래된 준비 결과 거부를 유지한다. 이력 예산은 지연 생성될 블록/기하/BVH 저장 비용도 예약한다.
5. 메인 버튼·viewport·마퀴·더블클릭/Alt 클릭·이동/회전·목록·속성·단축키가 같은 문서를 사용한다. 목록은 반복 배치 한 행을 표시하며 1억 행을 펼치지 않는다. 일부 셀 선택 상태에서 Ctrl로 다른 행을 추가해도 기존 셀 범위를 보존한다. 단일 셀의 위치·크기·각도는 기존 속성 패널과 같은 이력을 사용한다.
6. 일반 선택은 `RoiIdSet`의 불변 FrozenSet 기반과 작은 추가/제거 delta를 사용한다. 대량 포함 조회와 bulk 생성 비용을 줄이고 Ctrl 단일 토글의 전체 복사를 피한다. 외부 소비자가 `DocumentState.Selection`을 `ImmutableHashSet<Guid>`로 명시 선언했다면 새 `RoiIdSet`/`IReadOnlySet<Guid>` 계약으로 조정해야 한다. 기존 컬렉션 식·열거·집합 동작은 유지한다.
7. 선택 BVH는 불변 노드를 공유하고 ID→경로 표를 실제 변경 시점까지 지연한다. 자식이 없는 문서는 자손 집합을 재생성하지 않으며 큰 선택의 사실 확인은 순차 문서 조회와 빠른 membership을 사용한다. 특정 CPU 명령·코어 수·모델에 맞춘 분기는 추가하지 않는다.

## 기능 경계와 비용

반복 ROI는 선택·부분/전체 복사·붙여넣기·삭제·이동·회전·단일 크기/위치/각도·Undo/Redo를 지원한다. 일반 ROI의 그룹 계층·이름/검색 범위 메타데이터·필터·마스크·검사는 반복 셀에 구현하지 않았다. 혼합 선택에서 일부만 조용히 적용하지 않도록 명령을 막고 속성 패널에 지원 범위를 표시한다. 기존 일반 ROI 기능은 유지한다. 이 후속 결정이 ADR-041의 **메인 버튼이 별도 창을 연다**는 설명을 대체한다. 이전 창은 과거 CLI 성능 시험 재현용으로 남는다.

압축 효과는 반복 구조에 의존한다. 반복된 부분 편집으로 part/구간/개별 수정이 많아지면 준비·표시 비용이 늘어난다. 모든 형상을 다르게 편집한 1억 개나 임의의 조각난 선택에도 같은 속도라고 보장하지 않는다. 검증하지 않은 현장 문서·24K 파일·별도 저사양 CPU의 성능을 이번 8K 고정 입력 결과로 대신하지 않는다.

## 검토

| 원칙 | 적용/검증 |
|---|---|
| SRP | 셀 집합/배치 기하, 편집·이력, WPF 표현, DX12 업로드/표시의 기존 소유 경계 유지 |
| OCP | 기존 문서에 반복 표현 추가. 영상 I/O·검사 알고리즘이나 장치 전략 교체 없음 |
| LSP | 일반/반복 혼합의 선택·클립보드·취소·이력 동등 계약 검사. 지원하지 않는 부가 편집은 명시 차단 |
| ISP | 무관한 새 인터페이스 없음. 기존 viewport 입력·준비/게시 계약 재사용 |
| DIP | Core에 WPF/DX12/검사 공급자 의존성 없음. 앱이 연결하고 렌더러가 GPU 자원 소유 |
| Information Expert | 집합 계산은 RoiCellSet, 셀 기하·포함/제약은 반복 part, 도메인 이력은 Core 소유 |
| Creator | EditorSession이 유효한 배치/이력 생성, Pipeline이 업로드 arena 생성·해제 |
| Controller | UI는 편집 요청 전달. 셀 이동·클립보드 규칙은 Session/도메인에 배치 |
| Low Coupling | 불변 DocumentState/RenderScene 경계. 검사·디코더 변경 없음 |
| High Cohesion | 공통 문서 확장은 기능별 partial 파일, 반복 저장은 반복 전용 타입에 제한 |
| Polymorphism | 기존 입력/장치 계약을 유지. 변형점 없는 일반화 인터페이스 추가 없음 |
| Pure Fabrication | 집합 저장·이력 비용·GPU 수명은 각 기술 책임으로 분리 |
| Indirection | 앱 조립과 렌더 scene으로 WPF·Core·DX12 직접 결합 방지 |
| Protected Variations | CPU/WARP와 GPU는 같은 문서·입력·이력 사용. 플랫폼/장치 변화가 셀 정체성을 바꾸지 않음 |

독립 리뷰에서 혼합 붙여넣기 순서, 미포함 override의 크기 검증, 이력 캐시 비용 누락, 축소 override 재편집, 작은 부분 배치 요약 누락, Alt 순환/최근접 선택, 두께 설정/외곽 잘림을 찾아 수정하고 회귀를 추가했다. 원칙 예외는 사용하지 않았다.

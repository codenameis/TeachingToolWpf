# ADR-010 — 공통 강체 변환으로 유지하는 ROI 회전 preview

상태: 적용, 자동 회귀·실제 RTX 통합 검증 완료. 2026-10-02. 실행 조건·수치·남은 지연은 [회전 성능 기록](../rotation-performance.md)에 둔다. [ADR-001](0001-quality-and-edit-history.md)의 설계 원칙, [ADR-008](0008-retained-roi-rendering.md)의 GPU 버퍼 수명, [ADR-009](0009-responsive-bulk-editing.md)의 준비/확정 경계를 유지한다. ADR-008/009에서 기존 형상 생성 경로로 남겨 두었던 회전 preview를 이 결정으로 대체한다. resize는 이번 변경의 대상이 아니다.

## 문제

기존 회전은 포인터 Move마다 선택 ROI와 자손의 새 형상을 만들고 불변 ROI 맵을 갱신했다. 이미지 밖으로 나가는 입력은 허용 변형을 찾는 최대 40단계 경계 탐색에서도 전체 형상을 반복 생성했다. 수만 개를 선택하면 입력 한 번의 기하 계산·맵 복제·할당이 UI 지연과 GC를 유발하고, 렌더러도 매번 바뀐 형상을 업로드해야 했다.

회전 중에는 선택된 집합 모두에 같은 회전 중심과 각도가 적용된다. 각 ROI 값을 매 입력마다 확정할 필요는 없다. 목표는 이 공통성을 이용해 반복 입력 비용을 줄이면서 이미지 경계, 자손 단일 변형, 정확한 확정 형상과 한 번의 Undo/Redo를 유지하는 것이다. ROI 수를 줄이거나 편집 기능을 제거하는 방식으로 성능을 맞추지 않는다.

## 결정

### 불변 선택과 공통 변환

`RoiTranslationSelection/Preview`를 `RoiTransformSelection/Preview`로 일반화한다. 선택 객체는 시작 문서, 중복을 제거한 실제 영향 집합, 움직이는 ROI와 정지 ROI의 공간 인덱스, 선택 bounds를 공유한다. 선택된 조상이 있는 자손은 별도의 변형 루트로 처리하지 않는다. 영향 집합의 각 ROI에는 공통 변환을 정확히 한 번 적용한다.

영향 집합의 소비 계약은 `IReadOnlySet<Guid>`다. 전체 선택이면 기존 불변 `Selection`을 재사용한다. 자손을 확장해야 하면 `Subtree`가 만든 임시 `HashSet`을 선택 객체가 소유하는 `FrozenSet`으로 한 번 고정한다. 기존 `HashSet` → `ImmutableHashSet` 변환에서 지속적 갱신용 트리 노드를 만들던 비용을 줄이며, 제스처 중 집합을 갱신하는 기능은 필요하지 않다. 읽기 전용 인터페이스로 가변 집합을 감추는 방식이 아니라 실제 불변 구현을 보관한다. 소비자는 집합의 포함·동등성·개수에 의존하고 열거 순서를 도메인 우선순위로 사용하지 않는다.

`RigidTransform2D`는 이미지 좌표의 회전 중심, 누적 각도와 이동량을 가진 Core 값이다. `Apply`, `ApplyVector`, `InverseApply`와 bounds 변환이 점·방향·가시 영역의 정의를 공유한다. `default`와 `Identity`는 모두 항등 변환이며 기본 cosine은 1, sine은 0이다. 시계 방향 양수, 원점 좌상단·+Y 아래쪽이라는 기존 좌표 계약을 유지한다.

회전 드래그 중 `EditorSession.State.Rois`와 CPU 공간 인덱스는 시작 문서를 유지한다. 각 샘플은 `TransformPreview`의 공통 변환만 바꾸고 변경을 알린다. 현재 형상이 필요한 렌더러·호버·선택 핸들·속성 패널·필터는 모두 같은 `preview.Geometry(roi)` 또는 이에 대응하는 GPU 변환을 사용한다. 확정되지 않은 형상을 조회하는 소비자가 원래 ROI 맵을 현재 화면 형상으로 오인하지 않도록 preview를 명시적으로 전달한다.

문서의 viewport만 바뀌어도 불변 선택과 공간 인덱스는 재사용할 수 있다. 캐시의 시작 문서가 예전 viewport를 갖는 것은 허용하지만, 편집 확정은 현재 viewport를 별도로 보존한다. 캐시에서 얻은 시작 viewport를 현재 탐색 상태에 덮어쓰지 않는다.

### 이미지 경계와 연속 회전

선택·회전 중심·이미지 규격이 같으면, 시작 각도 0에서 각 방향으로 처음 이미지 경계를 벗어나는 각도를 한 번 계산하고 `RotationRange`로 캐시한다. 이후 샘플은 이 연속 허용 구간으로 요청 각도를 제한한다. ROI 네 꼭짓점의 회전 궤적과 이미지 네 변의 교차를 사용하며, 화면 AABB만으로 최종 포함 여부를 판단하지 않는다.

BVH에서는 바깥쪽으로 보수적으로 보정한 노드 bounds로 후보를 가지치기하고, 필요한 잎에서는 실제 회전 사각형 꼭짓점을 검사한다. 이는 고정 횟수로 각도를 샘플링하거나 이전 40단계 형상 복제를 반복하는 방식이 아니다. 해석적으로 얻은 경계 각도를 안쪽으로 보정한 뒤 실제 bounds가 수치 오차 여유까지 만족하는지 검사하고, 필요하면 최초 준비에서만 최대 48회 bounds 조회로 안전한 끝점을 좁힌다. 전체 ROI 맵을 반복 생성하지 않는다. `double` 계산과 수치 오차 처리는 기하 계층에 둔다. 첫 준비의 최악 비용은 여전히 ROI 수에 비례할 수 있으며, 결과를 캐시했다고 준비 비용이 사라지는 것은 아니다.

최종 요청 각도의 형상만 이미지 안에 있다고 해서 중간의 금지 각도 구간을 건너뛰지 않는다. 예를 들어 180도 결과가 이미지 안이어도 그 전에 최초 경계 이탈이 있으면 그 지점에서 멈춘다. 접촉만 하고 밖으로 나가지 않는 경우와 실제 이탈을 구별한다.

제스처는 연속 포인터 벡터 사이의 각도를 누적해 `atan2`의 ±180도 분기에서 한 바퀴 반대 방향으로 뛰지 않게 한다. Shift는 누적 요청 각도를 15도 단위로 맞춘 뒤 같은 경계 제한을 적용한다. 따라서 이미지 경계가 15도 배수보다 먼저 나타나면 최종 허용 각도는 15도 배수가 아닐 수 있다. 저장·표시할 개별 ROI 각도는 기존 `[0, 360)` 정규화를 따른다.

### GPU 버퍼와 가시성

기존 `(불변 BVH 블록 참조, LOD)` 키와 32바이트 중심/축 인스턴스 형식을 유지한다. 회전 샘플은 인스턴스를 다시 쓰지 않고 draw 상수의 cosine/sine과 블록 원점만 갱신한다. 정지 집합에는 항등 변환, 움직이는 집합과 선택 윤곽에는 같은 강체 변환을 적용한다. 블록 요약 표시도 같은 변환을 받는다.

도메인과 CPU 변환은 `double`이다. CPU는 블록 원점을 공통 변환한 뒤 뷰포트 좌표로 바꾸고, GPU에는 그 화면 원점과 블록 기준 상대 `float` 중심·축을 전달한다. 셰이더는 상대 중심과 두 축을 회전한 결과를 화면 원점에 더한다. 24K 또는 더 큰 절대 이미지 좌표를 그대로 `float`로 변환해 정밀도를 잃지 않는다. 선과 핸들의 DIP 두께는 기존 계약을 유지한다.

움직이는 공간 인덱스를 조회할 때는 뷰포트 이미지 영역의 네 꼭짓점을 공통 변환의 역변환으로 보내고 그 AABB를 검색한다. 회전 전에 화면 밖이던 ROI가 화면 안으로 들어오는 경우도 후보에 포함한다. 이 AABB는 보수적인 후보 영역이며 정확한 형상 렌더링·편집 규칙을 대체하지 않는다.

hover와 단일 선택 핸들은 preview 형상을 사용한다. 다중 선택의 표시 박스는 시작 선택 bounds의 네 꼭짓점을 공통 변환한 박스이며, 회전 핸들의 방향도 함께 회전한다. 회전 중 매 샘플 전체 선택 형상의 AABB를 다시 만들지 않는다. 확정 후에는 새 문서의 선택 bounds를 사용한다.

GPU 리소스 생성·소유·해제는 렌더 스레드에 남고 기존 fence 이후 재사용/retire 규칙을 유지한다. 새 가시 블록, LOD 변경, 캐시 퇴출 뒤에는 업로드가 필요할 수 있으므로 모든 회전에서 업로드가 항상 0이라고 보장하지 않는다.

### 라벨·필터·속성

라벨은 기존 화면 밀도와 겹침 제거에 더해 공간 인덱스 조회당 최대 1,024개 후보만 지연 열거한다. 화면에 배치하는 라벨은 기존 최대 256개다. 큰 ROI가 서로 겹쳐 BVH 밀도 축약이 작동하지 않아도 모든 후보를 배열로 만들고 정렬하지 않도록 한다. 예산 안 후보는 문서 순서로 정렬하고 선택 라벨을 먼저 배치한다. 공간 순회는 결정적이지만 예산 밖까지 포함한 전역 최소 순서의 라벨을 항상 보여 준다고 보장하지 않는다.

이 예산은 화면을 가리는 이름표 장식에만 적용한다. ROI 윤곽, 정확한 히트 테스트, 선택, 계층, 필터 등록, 편집과 이력에서 ROI를 누락하지 않는다. 전체 이름은 기존 목록과 속성 패널에서 확인한다. 가시 후보를 찾는 BVH 탐색 자체의 최악 실행 시간을 상수로 보장하는 예산도 아니다.

회전이 바뀌면 역변환 가시 영역으로 라벨 후보를 갱신하고 preview 형상에 맞춘 위치·각도 텍스트를 사용한다. 평행 이동/근거리 pan의 기존 캐시는 유지하되 표시 형상의 화면 교차와 클램핑을 확인한다. 텍스트 래스터화와 GPU 라벨 캐시의 기존 예산은 그대로이며 모든 다중 선택 라벨이 매 프레임 즉시 준비된다고 보장하지 않는다.

필터 요청은 불변 preview를 참조하고, debounce 이후 단일 작업자에서 회전 ROI의 현재 영상 영역을 추출한다. 결과에 들어 있는 형상에는 이미 변환이 적용되어 있으므로 렌더러가 한 번 더 회전하지 않는다. 취소/버전 검사를 통해 이전 각도의 늦은 필터 결과를 버린다. 속성 패널의 절대 각도와 부모 상대 각도도 같은 preview 형상으로 계산한다. 원본 이미지와 필터 등록 값은 회전 미리보기만으로 변경하지 않는다.

### 준비되지 않은 선택의 첫 입력

부모 선택 직후에는 자손 집합·이동/정지 공간 인덱스·회전 한계가 아직 준비되지 않을 수 있다. 문서가 4,096개 ROI를 초과하고 이 캐시가 준비되지 않았으면 Presentation의 `RoiPreviewPreparation`이 불변 시작 문서와 preview epoch를 잡고 `EditPreparation.Run`에서 준비한다. 준비 여부 조회는 `Lazy.IsValueCreated`를 확인하며 UI에서 지연 계산을 시작하거나 기다리지 않는다. 이미 준비된 선택과 작은 문서는 기존 동기 preview를 사용한다. 최초 이동량/각도가 0이면 작업을 시작하지 않는다.

coordinator는 제스처마다 최신 포인터 요청 하나를 유지하고 준비 안내를 한 번 표시한다. 작업 진입은 하나의 취소 가능한 gate로 직렬화한다. 취소를 즉시 반영할 수 없는 지연 계산이 남아 있어도 그 준비 함수가 종료되기 전 다음 제스처의 준비 함수를 동시에 실행하지 않는다. 대기 요청이 취소되면 준비 함수에 진입하지 않고 종료한다. Dispose는 취소를 요청하고, 실행 중 작업과 대기 요청의 종료 뒤 gate를 해제한다.

UI continuation은 preview 활성 여부, epoch, ROI/선택 맵 참조와 이미지가 같은지 검사한 뒤 최신 요청만 적용한다. 취소 후 같은 문서로 다시 시작해도 이전 epoch의 결과를 게시하지 않는다. 마우스를 먼저 놓으면 기존 `RunEditAsync`가 편집 대기 상태를 소유하고 `FlushAsync` 후 `PreparePreviewAsync`로 최종 요청을 확정한다. 이 동안 pan/zoom은 유지하며 Escape는 동일한 편집 취소 경로를 사용한다. 준비 오류는 상태로 보고하고 실패한 요청을 정상 편집으로 확정하지 않는다. 이는 첫 계산의 총 비용을 제거하는 변경이 아니라 UI 입력에서 분리하고 동시 실행량을 제한하는 변경이다.

### 한 번의 확정과 정확한 이력

마우스를 놓을 때 실제 ROI 값을 한 번 생성하고 하나의 Command/Memento 이력으로 확정한다. 영향 ROI가 256개를 초과하는 변경은 기존 단일 worker 준비 경계에서 형상·계층·이력·필요한 목록/인덱스를 준비한 뒤 UI에서 검증하고 게시한다. 작은 편집은 같은 Core 규칙의 동기 경로를 유지한다. 준비 중 pan/zoom은 허용하고 결과 확정 시 현재 viewport를 보존한다.

전체 문서에 공통 강체 변환을 적용하고 포함 tolerance가 일정한 좌표 범위 안이면 기존 계층을 보존한다. 일부 집합의 변형이나 좌표에 따른 tolerance 변화가 가능한 경우에는 기존 최소 완전 포함 부모 규칙으로 확정 시 재판정한다. 성능을 위해 수동 부모를 강제하거나 자손의 변형을 생략하지 않는다.

준비 결과는 소유 세션, mutation revision, preview epoch와 사용 여부를 검증한다. 다른 preview 샘플, 선택/문서/이미지 변경, 취소 후 재시작 또는 이미 사용한 결과는 옛 준비 결과의 확정을 허용하지 않는다. 취소·실패·실제 변경 없는 조작은 이력을 추가하거나 Redo를 제거하지 않는다. `Escape`와 캡처 상실은 시작 형상과 선택으로 돌아가며 별도 탐색의 현재 viewport는 보존한다.

Undo/Redo는 기록된 형상·ID·부모 관계·이름·필터·선택을 정확히 복원하고 계층을 다시 추정하지 않는다. 원본 이미지나 GPU 리소스를 명령마다 복제하지 않는다. 회전 범위와 공간 캐시는 불변 입력에 종속되고 ROI·선택·이미지가 바뀌면 새 입력의 캐시를 사용한다. 캐시 재사용을 이유로 오래된 편집 결과의 검증을 생략하지 않는다.

### 전체 강체 변환 확정의 BVH refit

회전 샘플의 비용을 줄인 뒤에는 확정 단계의 공간 인덱스 재구성이 별도 병목으로 남았다. 20만 ROI CPU 진단 3회에서 관찰한 비용은 공간 인덱스 준비 약 757ms/47.7MB, 형상 적용 약 339ms, `DocumentEdit` 준비 약 57ms였다. 이는 refit 도입 전 병목을 찾기 위한 측정이며 refit 적용 후 결과나 성능 목표 달성 수치가 아니다. 재현 조건과 비교 결과는 [회전 성능 기록](../rotation-performance.md)에 둔다.

전체 문서의 ROI에 같은 강체 변환이 적용되면 ID 집합과 공간적 이웃 관계를 보존할 수 있다. `RoiSpatialIndex.RefitGeometry`는 기존 잎의 ROI 배치와 ID 경로를 유지하면서 새 ROI 값으로 잎 배열을 만들고, 아래에서 위로 새 노드를 구성한다. 좌표 정렬과 재분할을 반복하지 않는다. bounds뿐 아니라 최대 면적, 히트 우선순위와 라벨 대표 ROI도 새 값에서 다시 계산한다. 기존 메타데이터 overlay를 새 형상에 섞지 않고 전달된 전체 불변 맵의 값을 사용한다.

기존 노드나 잎 배열을 수정하지 않으므로 이전 스냅샷의 조회 결과와 렌더 버퍼 참조는 유지된다. 새 인덱스는 불변 ID 경로만 공유하며, 이후 `WithChanges`의 이동·추가·삭제는 기존 경로 계약을 그대로 따른다. API는 ROI 개수, 모든 기존 ID의 존재와 키/값 ID 일치를 검사한다. 잘못된 입력이나 취소로 중단되면 이전 인덱스가 부분 갱신되지 않는다.

적용 경계는 내부 `WithRigidRois`와 `RoiSnapshot.IsRigidUpdate`로 표시한다. 실제 영향 집합이 전체 문서일 때만 회전 적용 경로가 이 표시를 만든다. `DocumentEdit`는 해당 표시와 직전 ROI 맵의 참조 일치를 함께 확인해 Undo/Redo에서도 refit을 선택한다. Undo/Redo는 역회전을 계산하지 않고 기록된 정확한 ROI 값들을 복원한 뒤 그 값으로 인덱스를 갱신한다. 부분 편집, ID 추가·삭제와 일반 변경은 기존 `WithChanges` 또는 재구성 경로를 사용한다. 이 표시는 계층 검증을 생략할 권한이 아니며, 포함 tolerance와 부분 변형에 따른 기존 재부모화 규칙은 별도로 유지한다.

refit도 전체 ROI를 한 번 읽고 새 잎/노드를 할당하므로 O(N) 시간·메모리가 남는다. 회전된 분할의 AABB 겹침에 따라 이후 검색 효율이 새로 정렬한 인덱스와 다를 수 있어 확정 시간만으로 전체 성능을 판단하지 않는다. 확정 후 노드 참조가 바뀌므로 GPU 캐시의 재업로드도 발생할 수 있다. 드래그 중 기존 버퍼 재사용과 확정 후 인덱스 교체는 서로 다른 단계다. 라벨 후보 예산은 refit 여부와 무관하게 유지한다.

직접 `RefitGeometry` 호출은 노드마다 취소를 검사한다. 현재 snapshot의 지연 인덱스 생성 경로는 이 토큰을 전달하지 않으므로 worker 취소가 진행 중인 refit 한 번의 종료까지 지연될 수 있다. 준비 결과 게시 전의 취소·revision·epoch 검증으로 취소되거나 오래된 결과의 확정을 막지만, 취소 응답 시간이 즉시라는 보장은 하지 않는다.

## 대안과 결과

기존 전체 형상 복제를 작업 스레드로 옮기기만 하면 샘플마다 O(N) 할당과 오래된 작업의 취소 부담이 남는다. GPU에서만 회전하고 CPU 소비자에 preview를 전달하지 않으면 표시·필터·속성의 정의가 달라진다. 선택 bounds만으로 회전 한계를 정하면 실제 사각형보다 과도하게 제한할 수 있으며, 목표 각도의 포함만 검사하면 중간 경계 이탈을 허용한다. 따라서 공통 변환, 실제 꼭짓점의 최초 이탈 구간, 명시적 preview 소비와 한 번의 확정을 함께 적용한다.

새 렌더러나 외부 의존성, 범용 변환 플러그인 시스템은 추가하지 않는다. 기존 State 제스처, Command/Memento, Observer, 불변 스냅샷과 GPU 어댑터의 책임을 확장한다. 회전 한계의 최초 준비와 확정·Undo/Redo에는 여전히 큰 입력에 비례하는 작업이 남는다.

## 클린 코드·SOLID·GRASP 검토

점/방향/역변환은 `RigidTransform2D`, 경계 이탈은 기하와 공간 인덱스, 영향 집합은 `RoiTransformSelection`, 편집의 시작/취소/확정은 세션, GPU 상수와 리소스는 렌더러에 둔다. UI가 각 ROI의 기하를 직접 갱신하지 않고 소비자마다 회전 규칙을 새로 정의하지 않는다.

| SOLID | 이번 변경의 근거 |
|---|---|
| SRP | 변환 수학·경계 제약·세션 이력·작업 준비·GPU 표시·라벨 예산을 각각의 변경 이유에 따라 분리한다. |
| OCP | 기존 이동 preview를 공통 강체 변환으로 확장하고 렌더/필터 소비자가 같은 계약을 사용한다. Core에 WPF/DX12별 회전 분기를 추가하지 않는다. |
| LSP | 새 상속 대체 구현은 없다. 동기·비동기 확정은 같은 변환, 이미지 경계, 취소/실패 및 복원 계약을 유지한다. CPU와 GPU 표현의 일치도 별도 검증한다. |
| ISP | preview는 영향 선택과 공통 변환만 전달한다. 영상 소스·GPU 리소스 계약에 도메인 회전 메서드를 강제하지 않는다. |
| DIP | Core의 순수 값/편집 계약이 기준이며 WPF·DX12·OpenCV 소비자가 이를 사용한다. Core에서 UI·셰이더·필터 구현을 참조하거나 서비스 로케이터로 조회하지 않는다. |

| GRASP | 이번 변경의 근거 |
|---|---|
| Information Expert | 실제 꼭짓점과 BVH bounds를 가진 기하 인덱스가 회전 이탈 한계와 refit의 bounds/조회 메타데이터를 계산하고 선택 객체가 영향 집합과 캐시를 관리한다. |
| Creator | 세션이 preview와 준비 편집을 만들고 공간 인덱스는 이전 스냅샷을 보존하는 새 노드를 만든다. GPU 파이프라인이 자신의 버퍼·상수를 생성/관리하며 도메인 값이 GPU 수명을 소유하지 않는다. |
| Controller | 제스처와 ViewModel은 회전 요청·진행·취소를 연결하고 세션이 상태와 이력 확정을 통제한다. |
| Low Coupling | UI/worker/렌더 사이를 불변 문서와 명시적 preview·준비 결과로 연결하며 가변 ROI 컬렉션을 공유하지 않는다. |
| High Cohesion | 변환 연산은 하나의 값 타입에, 이미지 제약은 기하에, 라벨 예산은 렌더 장식에 모아 무관한 규칙을 혼합하지 않는다. |
| Polymorphism | 기존 제스처 State와 영상/렌더 어댑터 계약을 유지한다. 강체 변환 값에는 실제 대체 구현 요구가 없어 새 상속 계층을 만들지 않는다. |

## 검증과 한계

회귀 검증은 항등/default 변환, 큰 좌표의 GPU 상대 float와 도메인 double 꼭짓점 일치, 역변환 가시 후보, 라벨 진입/이탈과 각도, 핸들 정합성, 큰 중첩 ROI의 라벨 예산, 부모/자손 단일 변형, 최초 경계 이탈과 접촉, 180도 분기 누적, Shift, 취소/no-op, viewport 보존, 준비 결과의 stale/중복 사용 거부와 정확한 Undo/Redo를 대상으로 한다. CPU에서 셰이더 수학을 비교하는 테스트와 실제 DX12 셰이더 실행 검증은 구분한다.

refit 회귀 검증은 새로 구성한 인덱스와의 bounds·교차 조회·히트 결과 비교, 이전 스냅샷의 값 보존, 면적/순서/이름 변경에 따른 조회 메타데이터 갱신, 후속 `WithChanges` 이동·삭제·추가, 다른 ID 집합과 키/값 불일치 거부, 빈 입력 및 이미 취소된 토큰을 포함한다. 편집 통합에서는 전체 회전의 정확한 Undo/Redo와 준비 결과의 stale/취소 게시 거부를 함께 확인한다. 직접 refit의 취소 테스트가 snapshot 지연 생성 중 즉시 취소까지 증명하는 것은 아니다.

최초 선택 준비는 게이트로 순서를 제어하는 STA 테스트로 worker 실행과 UI 적용, 최신 요청 우선, 준비 완료 후 동기 경로, 취소/동일 문서 재시작, Mouse Up 선행과 pan 보존, Escape 및 오류 전달을 검증한다. 취소를 무시하고 계속 실행되는 준비 함수가 있는 상태에서도 다음 준비 함수의 최대 동시 실행은 하나이며, 대기 취소와 Dispose가 작업 종료 전에 gate를 해제하지 않는지도 확인한다. 테스트는 임의 시간 대기를 사용하지 않는다.

자손 집합 구현의 회귀 검증은 부모/자손 중복 제거, 선택 변경 뒤 이전 영향 집합의 불변성, 전체 선택 집합 재사용과 빈 집합을 포함한다. 2026-10-02 최종 자동 회귀 검증은 Core 158개와 Imaging 69개, 총 227개 통과를 확인했다. 실제 RTX의 최종 Release 회전 시험 10개와 DX12 debug native smoke(회전 버튼·OpenCV 회전/취소·이력·미니맵·라이브)가 통과했다. 실행 조건과 남은 지연은 [회전 성능 기록](../rotation-performance.md)에 별도로 기록한다.

성능은 고정 입력·워밍업·반복 측정으로 callback, layout, UI 할당/GC, Dispatcher 지연, 준비/확정 시간, 렌더 CPU/GPU, 업로드량을 분리해 기록한다. 4만 개에서 개선된 한 조건의 결과를 모든 수십만 ROI 분포, 실제 저사양 GPU 또는 목표 FPS 달성으로 확대 해석하지 않는다. 최초 캐시 준비, 새 가시 블록, 경계 근접·큰 중첩·계층 분포, 동시 필터와 라이브 영상의 비용은 별도 확인 대상이다. 실제 수치와 미검증 범위는 [회전 성능 기록](../rotation-performance.md)을 따른다.

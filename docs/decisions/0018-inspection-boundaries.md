# ADR-018 — 검출 도형과 검색 범위 표시

날짜: 2026-10-04. 사용자가 검사 완료 후 검출 박스·폴리곤이 맞지 않는다고 보고했고, 패턴 검색 범위를 점선으로 구분하도록 요청했다.

## 원인과 결정

형상 모델의 `Bounds`는 마스크의 픽셀 AABB를 학습 각도 기준으로 변환한 중복 검출 제거용 사각형이다. 이를 표시 경계로 재사용하면 회전한 학습 ROI의 실제 윤곽을 잃으며 원·삼각형·오목 폴리곤도 사각형으로 표시한다. OpenCV 표시도 학습 crop의 축 정렬 사각형을 사용해 같은 문제가 있다. 기존 긴 좌표 라벨은 인접 검출 경계까지 가린다.

- 학습이 성공하고 작업의 유효성이 확인될 때 모델과 학습 `RoiGeometry` 불변 스냅샷을 함께 보관한다. 방식별로 따로 보관하고, 실패·취소·늦은 학습 결과는 기존 모델과 도형을 교체하지 않는다. ROI 편집·선택·이미지 교체가 등록 모델의 도형을 변경하지 않는다.
- 형상 표시에는 학습 도형의 로컬 꼭짓점을 검출 기준점·이미지 기준 절대각·균일 배율로 변환한다. OpenCV는 학습 도형의 크기와 각도를 유지하고 기준점의 평행 이동만 적용한다. 알고리즘의 NMS 경계와 검색 계산은 변경하지 않는다.
- 검출 윤곽은 닫힌 실선, 검색 범위는 화면 DIP 간격의 점선으로 표시한다. 전체 이미지 검색은 이미지 경계, 선택 ROI 검색은 실제 ROI 윤곽을 사용한다. 선 대비를 보완하되 기존 OK/NG/WARN/CHECK 판정색은 유지한다.
- 캔버스의 개별 라벨은 번호와 점수로 줄이고 상세 위치·각도·배율은 오른쪽 결과에 유지한다. 표시 도형은 학습 ROI를 검출 자세로 옮긴 영역이며 자동으로 분할한 제품 외곽 또는 결함 윤곽을 뜻하지 않는다.
- 기존 표시 토글·결과 위치 맞춤·선택 유지·입력 변경 무효화·편집 이력을 유지한다. 검사 결과는 ROI 문서에 추가하지 않는다.

## 검증

Release 빌드와 전체 자동 검증 **422개 PASS**(Core 182 / 앱 103 / Canvas 100 / Algorithm 37), skip 0. 근거는 `artifacts/inspection-boundary-solution-tests.log`다. 회전 사각형·삼각형·원·오목 폴리곤, 학습 후 ROI 변경·이미지 교체, 재학습 실패/취소/늦은 결과, OpenCV 고정 각도, 검색 중 경계 표시를 확인했다. Canvas 테스트는 배율/DPI와 무관한 8 DIP 대시/5 DIP 공백, 화면 밖 구간의 선 생성 제한, 모서리·닫는 변·클리핑의 위상, 라벨과 검출 실선 순서를 확인한다.

RTX 3060 Laptop / DX12 debug에서 실제 파일 reader→학습→검사→GPU 캡처 smoke **PASS(exit 0)**, 렌더 오류 없음. `artifacts/boundary-runtime/artifacts/inspection-smoke.log`에 8K 합성 칩 16개, 기존 형상 2개, OpenCV 1개, 특징점·선택 유지·미검출 회귀를 기록했다. 새 오목 6각형 학습/검색은 640×400 합성 PNG에서 X419.875/Y230.125, 20.156°, 1.2000배, 점수 .999의 패턴 1개를 60.9 ms에 검출했다. 알려진 정답에 대한 꼭짓점 오차 1.5px 미만, GPU 결과의 닫힌 6개 변, 검색선의 대시/공백 89/31개 표본 및 18회 전환이 확인됐다. 배율 상한에서 정밀화가 `Rejected`인 결과는 CHECK/Gold로 유지한다. 합성 데이터의 단일 실행 수치를 현장 정확도/속도 근거로 사용하지 않는다.

`artifacts/boundary-runtime/artifacts/inspection-polygon-boundaries-app.png`를 직접 확인했다. 검색 점선 사이에는 기존 파란 선택 ROI 실선과 핸들이 보존되며, 별도 Gold 실선은 회전·배율을 적용한 학습 폴리곤의 오목 꼭짓점을 유지한다. 이 파일은 실제 WPF UI와 DX12 readback을 합친 **진단 캡처**다. OS가 캡처한 앱 창 스크린샷과 구별한다.

최종 `Format-Code.ps1 -Verify`와 배포 빌드는 PASS다. 수정 배포본을 실제 창으로 실행하고 마우스로 칩 ROI를 그린 뒤 학습·검사를 수행했다. 8K 합성 칩 16개/OK, 짧은 라벨·실선 검출 박스·전체 검색 점선을 직접 확인했다. OS 앱 창 캡처는 `artifacts/actual-app-screenshot-20261004/inspection-boundaries-window.jpg`이며 검사 완료 상태로 앱을 유지했다. 자세한 실행 증거는 [작업 목록](../../tasks/todo.md)에 기록한다.

## 설계 원칙 검토

| 원칙 | 이번 변경의 적용 |
|---|---|
| SRP | 모델 수명은 VM, 표시 도형 변환은 앱 adapter, 선과 라벨 배치는 Canvas |
| OCP | 기존 표시 좌표 계약 안에서 실제 윤곽을 전달하며 알고리즘 분기를 Canvas에 추가하지 않음 |
| LSP | 학습 서비스 계약 유지, 실패·취소·늦은 결과를 테스트 대역으로 확인 |
| ISP | 표시 수정 때문에 학습/검색 서비스 인터페이스를 확장하지 않음 |
| DIP | Canvas는 값 좌표만 받고 알고리즘/판정 공급자를 참조하지 않음 |
| Information Expert | 학습 ROI를 가진 앱이 도형을 보관하고 화면 변환은 Canvas가 담당 |
| Creator | 학습 성공 게시 지점에서 모델과 도형을 함께 교체 |
| Controller | UI 버튼은 기존 VM 명령 경로를 유지 |
| Low Coupling | 내부 NMS 사각형과 표시 경계를 분리 |
| High Cohesion | 검색 계산·ROI 편집 규칙을 표시 수정에 섞지 않음 |
| Polymorphism | 기존 실제 공급자와 테스트 대역의 계약을 유지하며 새 변형 계층은 만들지 않음 |
| Pure Fabrication | 표시 adapter와 painter가 각각 변환·렌더 기술 책임을 소유 |
| Indirection | 알고리즘 결과와 GPU 사이에 기존 typed adapter 유지 |
| Protected Variations | 알고리즘 내부 마스크/NMS 경계 변경이 화면 도형을 바꾸지 않음 |

새 의존성과 설계 원칙 예외는 없다.

# ADR-024 — 원본 읽기·후보 계산 최적화와 소수점 편집

- 날짜: 2026-10-04
- 상태: 구현·전체 회귀·반복 성능 측정·배포 앱 검증 완료
- 요청: 느린 GPU/대용량 형상 검사 개선, 매칭 기준값의 소수점 입력 수정.

## 재현과 결정

GPU는 CUDA 평활화·Sobel을 실행하며 전체 검색은 GPU 작업이 아니다. 동일 원본 PCB에서 8K 읽기 약 2초, 후보 계산 약 1.6초가 확인됐다. CPU 병렬도는 종전의 최종 검증에만 적용되어 실제 후보 정밀화와 대용량 원본 crop 처리는 직렬이었다. 입력은 8192×8192(256핀), 24576×8192(768핀), 학습 핀 하나, ±180도, 최소 점수 .72, 추가 윤곽 감점 1이다. 합성 정답과 실촬영 검출률을 구별한다.

1. 원본 Gray8 변환을 행 단위로 처리하고 축소 전 crop 복사를 제거한다. 원본 16 MiB LRU는 유지하고, 정확히 같은 2×2 평균을 적용한 축소 타일을 별도 4 MiB LRU 안에서 재사용한다. 화면 LOD는 검사에 사용하지 않는다.
2. 원본 정밀화 crop을 공간 순서로 읽고 결과는 기존 후보 순서로 복원한다. CPU 작업만 병렬화하며 reader는 한 소유자가 순차 접근한다. 병렬 batch의 원본 픽셀 합은 2 Mpx까지다. 기존 2 Mpx 초과~8 Mpx 단일 crop은 혼자 실행한다.
3. 방향 후보의 연속 정밀화를 고정 결과 슬롯에 병렬 실행한다. 후보 큐·필터·정렬·동점·NMS·예산 경고를 유지한다. 고정 배율의 동일 자세 재계산을 생략하고 실제 소비자가 없는 상위 레벨의 NMS/edge 저장을 생략한다. 임계값·검색 범위·검증 수를 낮추지 않는다.
4. 장치 공급자는 동시 호출 지원을 요구하지 않는다. 검사 소유의 직렬 어댑터가 `Prepare`·diagnostics·해제를 보호한다. 모든 CPU worker가 끝난 뒤 reader/provider를 해제한다. GPU 오류를 CPU 성공으로 숨기지 않는다.
5. 앱의 새 형상 설정은 CPU 논리 코어 절반, 최소 1/최대 4를 사용한다. 사용자는 1~16을 조절할 수 있다. OpenCV 및 라이브러리 기본값 1은 유지한다. 기존 사용자 설정을 강제로 바꾸지 않는다.
6. 숫자 필드별 변환기가 입력 문자열을 보존한다. `0.` 또는 `0.720`을 입력해도 숫자 source의 round-trip이 소수점·후행 0을 지우지 않는다. 잘못된 문자열은 WPF 검증 오류로 남기고 실행을 막는다. 범위/NaN/Infinity는 기존 typed 검증을 통과해야 한다.

## 검증 기준

변경 전후 full-image 검출을 정답 위치 1 px 및 전체 match record(점수·pose·지지·정밀화·품질)의 정확한 동등성으로 비교한다. CPU 1/CPU 4/CUDA 결과, 후보·출력 상한 경고, 원본 읽기 단일 소유, 취소 후 worker 종료·해제, 픽셀 형식/stride/홀수 경계/캐시 예산을 확인한다. 실제 WPF 키 입력과 검사 완료 화면을 확인한다. 최종 실측·테스트 증거는 [검증 기록](../matching-throughput-validation.md)에 남긴다.

전체 746개 회귀, 포맷 검사, 별도 게시물의 통합 검사와 실제 앱 직접 조작을 통과했다. CPU 4의 반복 검사 중앙값은 8K 2149.90 ms, 24576×8192 입력 6532.94 ms다. 실제 앱 단일 실행의 256개 검출/3117.7 ms는 이 반복 측정과 구별한다. CUDA는 같은 최종 CPU 설정보다 느렸으며 CPU 기본을 유지한다.

병렬 단계 진단 합계는 작업별 경과 시간의 합이며 서로 겹친다. 전체 `WallMilliseconds`와 같은 것으로 표시하거나 전체 시간을 분해한 비율로 해석하지 않는다. CUDA diagnostics는 전처리만 측정하며 초기화·전체 검색·종료 시간과 구별한다.

## 설계 원칙 검토

| 원칙 | 적용 |
|---|---|
| SRP | 원본 읽기, 후보 실행 배치, 장치 직렬화, 숫자 편집 책임 분리 |
| OCP | 기존 공급자 계약을 유지하며 CUDA/대체 구현을 어댑터로 보호 |
| LSP | 공급자에 새 동시 호출 의무를 부과하지 않음; 취소·소유권·실패 계약 회귀 |
| ISP | 기존 작은 이미지/전처리 계약 유지, 미사용 기능 추가 없음 |
| DIP | Algorithm은 WPF·DX12 미참조, 검사 조립 시 공급자 주입 |
| Information Expert | 타일 변환/축소는 reader, 후보 순서/좌표 복원은 검사 배치가 소유 |
| Creator | 검사 실행이 배치·장치 어댑터를 만들고 수명 종료 책임을 가짐 |
| Controller | UI는 설정·명령만 전달, 계산은 검사 서비스에서 실행 |
| Low Coupling | 숫자 문자열을 알고리즘에 전달하지 않으며 플랫폼 타입 추가 없음 |
| High Cohesion | 공간 읽기·병렬 계산·원래 순서 복원을 전용 타입에 응집 |
| Polymorphism | 기존 ITileSource/IImagePreprocessor의 실제 대체 구현 유지 |
| Pure Fabrication | 제한된 캐시와 직렬 장치 어댑터가 기술 책임을 담당 |
| Indirection | 앱 조립 및 장치 어댑터로 외부 장치와 업무 정책 직접 결합 차단 |
| Protected Variations | 숫자 편집/CPU 실행 방식이 이미지 좌표·모델·판정 계약을 바꾸지 않음 |

원칙 예외를 적용하지 않는다. 기존 변경과 사용자가 편집한 작업은 유지한다.

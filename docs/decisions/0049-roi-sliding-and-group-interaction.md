# ADR-049: 복수 선택 회전 제거·벽 슬라이딩·대량 그룹 입력

2026-10-15 사용자 요청. 현재 main에서 로컬 수정·검증만 진행한다. [ADR-048](0048-roi-boundary-motion-and-nested-selection.md)의 경계 제한과 중첩 선택을 유지하면서 아래 동작을 변경한다.

- 주황색 복수 선택에서는 회전 핸들과 회전/각도 초기화 명령을 제공하지 않는다. 실제 그룹 하나 또는 ROI 하나의 회전은 유지한다. 여러 ROI의 선택·이동·복사·삭제·통합 이력은 그대로다. Core의 프로그램식 복수 변환 API는 제거하지 않는다.
- 부모 벽을 향해 드래그하면 먼저 연속 이동 경로의 접촉 위치를 구한다. 남은 이동을 실제 벽 방향으로 투영하고 모든 고정 부모와 이미지 경계에 대해 다시 검증한 위치로 이동한다. 회전된 벽·원·오목 다각형을 실제 형상으로 판정한다. 접선 후보 중 요청 위치에 가장 가까운 유효 후보를 고르며 막힌 모서리는 통과하지 않는다.
- Shift 축 고정 중에는 슬라이딩하지 않는다. 원래 축과 다른 벽 방향으로 흐르는 것을 막기 위해 입력의 `allowSlide`를 기존 비동기 미리보기의 최신 요청에도 보관한다. `InteractionController` 생성자의 translation 콜백은 `Action<PointD, bool>`로 바뀌며 두 번째 인수는 이 값이다. 앱 호출부와 테스트·매뉴얼을 함께 갱신한다.
- 미리보기의 직전 위치부터 경로를 검사하며 확정 시 같은 결과를 사용한다. Undo/Redo, 빠른 포인터의 금지 구간 통과 방지, 기존 밖의 독립 ROI 편입 예외와4단계는 유지한다. 경계 오차를 늘리는 대신 다각형 꼭짓점 이동의 끝점 포함도 검사한다.
- 단일 항목을 고를 때 자손 전체의 변환 자료까지 준비하지 않는다. 선택을 즉시 게시하고 실제 이동/회전 때 기존 preview worker가 자료를 준비한다. 대량 영역/복수 선택의 worker 경로는 유지한다.
- 큰 단일 그룹의 강체 변환에서 영향 ROI가4096개 초과이고 문서의 절반을 넘으면 기존 BVH 배치를 재사용하고 경계만 갱신한다. ID·계층·순서가 그대로이며 별도의 공간 색인이나 캐시를 추가하지 않는다. 전체 재구축과 실제 질의 결과·Undo/Redo를 비교한다.

기하 후보 계산은 `RoiMotionBounds`, 부모 간 공동 제한은 `RoiGroupBounds`, 입력 선택은 `InteractionController`, UI 명령과 즉시 선택 여부는 ViewModel에 둔다. View 코드에 도메인 규칙을 추가하지 않는다. 새 패키지와 설계 원칙 예외는 없다.

수만 ROI 측정에서는 입력 처리 시간, 선택/편집 완료, 프레임 제출 간격, DXGI 표시 카운터, GC를 구별한다. 정적 구간의 렌더 생략을 프레임 드롭으로 계산하지 않으며 첫 표시와 최초 준비 지연은 별도 기록한다. **60FPS와 모든 프레임16.67ms 이내 기준을 낮추지 않는다.** 결과·남은 미달·재현 명령은 [검증 기록](../group-interaction-validation.md)에 둔다.

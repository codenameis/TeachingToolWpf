# ADR-008 — ROI GPU 버퍼 재사용과 이동 preview

상태: 적용. 2026-10-02. [측정 보고서](../retained-roi-performance.md).

## 문제

ROI 변경은 이미 한 번의 문서 게시로 묶였지만, 렌더러는 탐색할 때마다 ROI의 선/그림자 정점을 CPU에서 생성했다. 이름표 후보 전체 순회·정렬과 WPF 텍스트 래스터화도 반복했다. 32,940개 평면 ROI의 기존 paint p95는 482.52ms였다. 이미지 경계에 걸린 1만 개 이동은 40단계 제한 탐색마다 전체 형상을 복제해 입력당 548–993ms와 약 320MiB 할당을 만들었다.

## 결정

1. BVH의 불변 하위 트리를 최대 2,048개 단위 GPU 블록으로 사용한다. 변경되지 않은 노드의 **참조 동일성**과 LOD 단계로 default-heap instance buffer를 재사용한다. 구조체는 중심/축/요약 플래그 32바이트다. pan은 상수만 변경하고, zoom은 필요한 LOD 단계의 버퍼만 준비한다. DX12 `DrawInstanced`가 네 변을 생성한다. CUDA나 Vulkan 전환은 하지 않는다.
2. 이미지 좌표는 계속 `double`이다. CPU에서 블록 중심을 뺀 상대 좌표와 축만 GPU `float`로 변환한다. 현재 화면의 블록 원점도 `double`로 변환한 후 전달한다. 완전히 동일한 윤곽은 블록 안에서 표시만 합치며 ID·선택·필터·계층·이력은 합치지 않는다. 작은 집합의 기존 화면 요약을 유지하고 확대하면 개별 윤곽을 그린다.
3. GPU 버퍼는 upload arena에서 한 번 업로드한다. 슬롯 재사용/캐시 제거는 fence 이후다. 비활성 버퍼는 실제 committed 할당량과 보유 도메인 객체 추정량(원본 ROI당 256바이트)을 합산한 128MiB 예산으로 제거한다. 현재 가시 버퍼는 보호하므로 예산을 초과할 수 있다. 예산 값은 순수 VRAM 사용량이 아니다.
4. 일반 클릭은 BVH에 저장한 최소 면적/최신 순서 우선순위로 가지치기하며 정확한 회전 포함 판정을 수행한다. Alt 순환 선택은 기존 전체 hit 순서를 유지한다. 선택 요약(첫 ROI, 그룹 여부, 필터 혼합/등록 목록)은 불변 문서/선택별로 한 번 계산한다.
5. 이동 드래그는 `RoiTranslationSelection`과 이동량으로 표현한다. preview 중 `EditorSession.State`는 확정 전 불변 문서다. 렌더·이름표·속성·필터가 명시적인 `TranslationPreview`를 사용한다. 이미지 경계는 선택 bounds의 허용 이동 비율로 제한한다. 마우스를 놓을 때에만 형상을 한 번 생성하고 한 이력으로 확정한다. 전체 ROI의 공통 이동은 포함 관계가 보존되어 계층 재판정을 생략하고, 일부 이동은 기존 규칙으로 재판정한다. 취소와 no-op 종료도 필요한 UI 갱신을 통지한다.
6. 필터 요청은 불변 이동 preview를 참조한다. UI에서 ROI 배열을 복제하지 않고 100ms 요청 합치기 이후 단일 작업자가 표시 위치의 형상을 계산한다. 취소/버전 검사와 원본 불변성은 유지한다.
7. 이름표는 화면 밀도(120×32 DIP) 단위의 대표 후보를 BVH에서 찾고 실제 겹침을 제거한다. 대표는 큰 면적 우선으로 부모를 자식보다 우선한다. 기존 최대 256개, 선택 우선, 전체 이름을 목록/속성에서 읽는 규칙을 유지한다. 64 DIP 이하 근거리 탐색에는 배치를 재사용하되 매번 화면 교차와 경계 고정을 확인한다. 이동 preview도 이동/정지 집합을 각 표시 위치에서 조회한다.
8. 새 일반 ROI 이름표 텍스처 생성은 프레임당 2개 또는 누적 2ms 이후 다음 프레임으로 넘긴다. 단일 선택 이름표와 HUD는 즉시 생성한다. 기다리는 이름표가 있으면 렌더 요청을 한 개 합쳐 다시 깨우고, 완료되면 정지한다. 캡처는 해당 장면의 이름표 준비를 기다린다. 텍스트 캐시는 실제 GPU 할당 32MiB/512개 LRU이며 현재 프레임 사용 항목은 보호한다. 줌 중 이름표가 점진적으로 나타날 수 있으나 ROI 윤곽과 입력은 기다리지 않는다.

## 유지되는 계약과 한계

기하/히트 테스트/계층은 표시 요약과 독립적이다. 부모 자손 단일 변형, 연쇄 삭제, Undo/Redo, 이미지 경계, 필터 등록은 유지한다. WPF와 DX12 타입을 Core에 넣지 않았다. Strategy/Adapter, State, Command/Memento, Observer와 불변 스냅샷의 책임을 유지하며 설계 원칙 예외는 없다.

변형 확정과 대규모 생성·선택·삭제·복원에는 여전히 ROI 수에 비례하는 작업이 있다. 회전/resize는 기존 형상 preview 경로다. 수백만 개의 모든 명령이 일정 시간에 끝난다는 뜻이 아니다. 실제 측정과 남은 지연은 성능 보고서에서 별도로 공개한다.

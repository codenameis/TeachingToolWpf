# ADR-045: ROI 4단계 계층과 명확한 이름

2026-10-15 후속 [ADR-047](0047-view-responsibilities-and-group-bounds.md)이 아래 결정 중 그룹의 생성 후 자유 편집과 별도 자식 버튼 설명을 대체한다. 그룹은 상위 실제 도형 안에서 이동·회전·크기를 변경하며, 일반 리프의 자유 편집·4단계·색상·이력 규칙은 유지한다.

2026-10-14. 사용자 확정: `RootGroup → ModuleGroup → RoiGroup → Roi`를 포함해 최대 4단계, 단계별 색상 설정, **그릴 때만** 부모 내부 제한, 로컬 수정·검증만 진행한다. ADR-014의 부모 밖 자식 **그리기**와 부모가 있는 ROI의 재그룹화 허용은 이 결정으로 대체한다. 생성 후 이동·회전·resize의 명시적 ParentId 유지 계약은 보존한다.

## 결정

2026-10-14 후속 [ADR-046](0046-parent-reuse-and-mvvm-viewport.md): 부모 하나 + 독립 ROI 그룹화는 새 ROI를 만들지 않고 기존 부모에 연결한다. 부모 여러 개를 선택한 상위 그룹 생성과 구별하며, 중첩된 부모도 연결 대상으로 허용한다.

- 부모 선택 없이 독립 ROI를 그린다. 자식 그리기는 선택한 부모의 실제 도형 안에 완전히 포함되어야 한다. 회전 사각형·원·삼각형·오목 폴리곤의 기존 기하 포함 판정을 재사용한다. 경계를 넘는 드래그는 확정하지 않으며 실패로 이력/Redo를 바꾸지 않는다. 폴리곤은 실패한 초안을 수정·취소할 수 있다.
- 기존 독립 ROI는 `연결할 자식 지정 → 부모 선택 → 선택 부모에 연결`로 편입한다. 사용자 답변에 따라 편입에는 공간 포함 제한을 추가하지 않는다. 이미 부모가 있는 ROI, 자기 자신/자손 연결, 5단계는 거부한다. 형상·ID를 유지하며 하나의 준비/게시/Undo 트랜잭션으로 처리한다.
- 그룹화는 선택된 조상이 없는 유효 루트들에만 적용한다. 유효 루트가 이미 다른 부모 아래 있으면 거부한다. 선택된 부모의 자손은 함께 이동하는 구성원이며 중복 재그룹화하지 않는다. 독립 부모 그룹들도 다시 묶을 수 있다.
- 자식 추가·배치 추가·그룹화·편입·붙여넣기에서 4단계를 검사한다. 과거/외부에서 직접 만든 더 깊은 DocumentState는 목록에서 `초과 계층`으로 식별하되, 새 5단계 편집을 허용하지 않는다.
- 별도의 그룹 상속 계층을 만들지 않는다. 기존 `Roi/ParentId/IsGroup` 문서에서 하위 계층 높이를 계산한 `RoiSnapshot.GroupLevels`를 사용한다. 리프는 0, ROI 그룹은 1, 모듈 그룹은 2, 루트 그룹은 3이다. 중간 단계를 생략한 연결도 가능하다. 계층 변경으로 역할이 달라지며, 이름은 사용자 값을 보존하고 목록 종류/속성 설명/색상을 갱신한다.
- 계층 높이 캐시는 형상 편집·pan/zoom에서 재사용하고 기존 준비 worker에서 평가한다. GPU 역할 캐시도 같은 버전을 사용하며 두 버전·약한 참조 정책을 유지한다. 원본 이미지나 ROI 형상을 복제하는 새 경로는 없다.
- 기존 독립/자식/부모 표시 슬롯에 모듈/루트 두 슬롯을 추가한다. 설정 화면에서 기본·단일 선택·다중 선택 색과 두께를 변경한다. 기본 4단계 색은 녹색·분홍·파랑·주황으로 구분한다. DX12 상수는 5색상과 두께 벡터를 담는 176바이트이며 셰이더와 C# 배치를 함께 검증한다.
- 검색범위 타입 선택은 기본 여유 20px로 즉시 저장한다. 일반 타입 복귀도 즉시 저장한다. 이름/위치/여유 숫자의 입력 중간값은 함께 확정하지 않는다. 숫자는 `변경 적용`으로 저장하며 Refresh는 이력을 만들지 않는다.

## 명명

`RoiGrouping → RoiGroupEditor`, `CudaCandidateScoring → CudaCandidateScorer`, `CrosshairLayerBinding → CrosshairLayerLink`, `RoiListBinding → RoiListSelectionLink`, 내부 `Pending → PreviewOperation`, `InputTiming → InputMetrics`로 책임을 드러낸다. `IsGroupingRoi/IsGrouping → IsGroupRoi/IsGroup`, 선택 ROI ID·셀·중심/각도·선택 동기화 상태도 구체적으로 이름을 붙였다. 상태를 뜻하는 `IsRunning/IsDragging`, 프레임워크 `Binding`, 기존 namespace의 전문 용어는 단순 문자열 제거 대상으로 삼지 않는다.

새 의존성·원칙 예외는 없다. 공개 `IsGroupingRoi`를 사용하는 외부 호스트는 `IsGroupRoi`로 이름을 바꿔야 한다. 저장소 내 참조·바인딩·테스트는 함께 갱신했다. [검증과 한계](../roi-hierarchy-validation.md).

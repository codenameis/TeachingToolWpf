# ADR-002: 외부 조작 버튼과 부모 생성형 그룹화

## 상태와 날짜

2026-10-01 결정, 2026-10-02 구현. 외부 수동 버튼과 그룹화의 의미는 사용자 확정 요구다. 새 부모 생성, 그룹 해제, 연쇄 삭제와 각각의 Undo/Redo를 자동 테스트 및 실제 HWND 앱 실행에서 검증했다. 기존 설계 원칙 및 부모 연쇄 삭제 결정은 유지한다.

## 배경

사용자는 샘플 앱에서도 이미지 수동 교체, zoom, panning, ROI 추가, 그룹화 버튼이 뷰포트 밖에 있어야 한다고 요청했다. 그룹화의 의미를 확인한 결과, 선택한 ROI들을 감싸는 새 부모 ROI 생성을 선택했다.

## 결정

1. WPF 툴바와 속성 패널에서 기본 기능을 조작한다. 이미지 열기/교체, 확대/축소/배율/Fit/1:1, 이동 도구/방향 이동, 선택 도구, ROI 추가/삭제, 그룹화/해제, 0도 초기화, Undo/Redo를 제공한다. GPU viewport와 겹치지 않게 배치한다.
2. 버튼과 단축키·포인터는 같은 응용 명령을 호출한다. WPF ICommand/CanExecute는 UI 어댑터이며 기하·계층·편집 이력 규칙을 중복 구현하지 않는다.
3. 그룹화는 선택한 회전 ROI를 감싸는 사각형 부모를 생성한다. 별도 논리 그룹/선택 집합 모델은 추가하지 않는다. 생성된 부모에는 이름표가 붙고 기존 부모의 변형·삭제 규칙이 적용된다.
4. 기존 완전 포함 관계를 유지한다. 선택 외 ROI의 추가 포함도 반영해 알리고, 기존 계층과 충돌하여 일부 선택 ROI가 새 부모 아래에 들어가지 않는 상태는 적용하지 않는다. 자세한 원자적 검증과 안내는 계획 6.5절을 따른다.
5. 그룹 해제는 그룹화로 생성한 부모만 제거하고 자손의 형상을 보존한다. 삭제 명령은 부모와 전체 자손을 삭제한다. 서로 다른 명령으로 명확히 표시하고 각각 Undo/Redo한다.

## 대안과 영향

- 단축키·마우스 제스처만 제공하는 구성은 사용자가 요구한 외부 버튼을 충족하지 못하므로 채택하지 않는다.
- 여러 ROI를 함께 편집하는 별도 논리 그룹은 사용자가 선택한 의미와 달라 채택하지 않는다.
- 포함 여부와 상관없이 ParentId를 강제 설정하는 방식은 기존 완전 포함 불변식을 깨므로 사용하지 않는다.
- 그룹 해제를 삭제 명령의 옵션으로 숨기지 않는다. 삭제의 연쇄 동작은 그대로 유지한다.
- 그룹화/해제는 생성 부모 메타데이터와 영향받은 관계·선택까지 이력에 기록한다. 구현·검증 작업 T08A와 T10A를 추가한다.

## 검증

버튼만으로 파일 열기, 탐색, ROI 생성, 그룹화, 변형, 해제, 삭제, Undo/Redo 흐름을 시작할 수 있어야 한다. 클릭 가능한 상태와 실행 결과를 검증하고, 단축키와 결과·이력이 동일한지 확인한다. 회전 형상, 선택된 부모/자식, 선택 밖 추가 포함, 기존 부모와 충돌, 실패 원자성, 그룹 해제 후 위치 보존을 테스트한다.

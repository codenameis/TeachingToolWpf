# ADR-029 — 작은 논문 형상의 세부 획 검증과 검사 시간 로그

- 날짜: 2026-10-05
- 범위: 사용자가 보고한 kensa의 18V 검출 실패와 검사 병목 로그. OpenCV와 자체 기하의 점수 정책은 유지한다.
- 상태: 구현·회귀 검증. 125/80 ms 목표와 후보 예산을 포함한 완전 검색 수용은 미달.

## 재현과 결정

`kensa.png`(1024×1536)의 좌상단 전압 글자 ROI 중심 `(194.5,371)`, 크기 `19×12`를 사용했다. 사용자가 학습한 정확한 ROI 수치는 받지 못했으므로 이 ROI가 사용자 입력과 같다고 주장하지 않는다. 기본 ±180°, 고정 배율, 최소 점수 .72, 후보 2048/검증 64를 유지했다. 학습 결과는 원본 한 단계·26개 특징이다. 기존 구현은 전체 검색에서 118개를 반환했고 다른 인쇄 문자도 높은 점수를 받았다. 전압 글자 한 개의 선택된 자세는 180°였다.

1. 논문 서비스만 `UseFineDetailValidation`을 학습에 지정한다. 기하 모델은 제외한다. 원본 한 단계만 남고 실제 마스크 내부의 유효 3×3 stencil 수가 4096 이하인 작은 모델에만 원본 Sobel 세부 자료를 보관한다. 큰 모델 또는 다단계 모델은 기존 경로를 유지한다. 예산 초과 시 부분 자료를 사용하지 않는다.
2. 평활화·방향 응답 후보 생성은 유지한다. 최종 검증에서 미세 획의 위치를 원본 Gray8로 보정한다. 무부호 후보의 180° 모호성은 학습 회전 범위 안의 반대 방향도 평가해 해결한다. 고정 배율·회전/영역 제약·취소를 보존한다. 이 작은 모델에는 point-to-line 대신 세부 획 보정을 적용하며 point-to-line 수렴을 주장하지 않는다. 기존 사용자 확인 판정은 유지한다.
3. 원본 gradient 벡터의 최소제곱 설명 에너지 `D = positive(dot)² / (modelEnergy × sceneEnergy)`를 사용한다. 극성 무시에서는 점별 내적의 절댓값을 합한다. 밝기 offset과 균일 gain에 불변이며, 마스크 밖을 stencil의 유효 대상으로 쓰지 않는다. 이는 자체 추가 검증이며 특정 논문 전체 재현·OCR·상용 동등성을 뜻하지 않는다.
4. 최종 점수는 `방향 점수 × (1 − w × 추가 윤곽 에너지 비율) × (1 − w × (1−D))`다. `D`가 없는 모델은 기존 식이다. `w=0`은 기존 방향 점수를 유지한다. 최종 반환 pose에서 방향·지지·윤곽·세부 점수를 다시 계산한다. 세부 일치도를 결과에 별도 표시하고 기존 윤곽 개수/에너지 비율에 섞지 않는다.
5. 원본 세부 검증용 전처리 스냅샷은 필요한 경우에만 Gray8 복사본을 소유한다. 작업 픽셀 한도(검색 2 Mpx/단일 정밀화 8 Mpx), LRU, 단일 reader 소유권을 유지하고 복사본을 `EstimatedBytes`에 포함한다. 공개 사전 전처리 API에서 세부 모델을 사용하려면 `retainOriginal:true`가 필요하다.

## 로그가 답하는 질문

- 어떤 원본 크기·학습 ROI·학습/검색 조건으로 실행했는가?
- 장치 준비, 서비스, 원본 읽기, 후보/검증, 결과 게시 중 어디서 시간을 쓰는가?
- 0개/일부 검출은 정상 종료인가, 예산 잘림·취소·시간 초과·오류인가?
- 결과 게시와 해당 overlay의 GPU 표시 제출은 언제 끝났는가?

논문 검사 명령 경계에서 run ID와 시작 시각을 만든다. 모델 ID·source generation·ROI·특징 수·조건·완료 상태를 같은 스냅샷에 기록한다. 실제 경과 단계와 병렬 worker 누적은 분리한다. 서비스 await는 작업 대기/reader 종료/UI 복귀를 포함하고, 서비스 내부 시간과 동일시하지 않는다. 장치 준비를 명령 전체 시간에서 빼지 않는다. 준비 실패의 장치 시간은 0 대신 미측정이다.

최근 20회를 세션 메모리에 보관하며 화면은 마지막 검사를 보여 준다. `로그 JSON 저장`으로 전체 스냅샷을 내보낸다. 디스크 기록·JSON 직렬화를 검사 작업에 넣지 않는다. 종료 시 자동 보존하지 않는다. 파일 경로·원본 픽셀은 로그에 기록하지 않는다. 로그 파일을 서버로 전송하지 않는다.

표시 계측은 기존 공급자 비의존 overlay ID/Present/fence 이벤트에 연결한다. 같은 ID만 갱신하고 오래되거나 알 수 없는 ID를 최신 검사에 연결하지 않는다. 이 시간은 실제 클릭 도착, WPF 패널 렌더/DWM 합성, 물리 화면 scan-out의 완료를 인증하지 않는다.

## 설계 검토

설계 원칙 예외는 없다.

| 원칙 | 적용 확인 |
|---|---|
| SRP | 세부 모델/검증, 서비스 단계 시간, 로그 스냅샷, WPF 저장 대화상자 책임 분리 |
| OCP | 명시적 논문 학습 옵션과 선택형 세부 자료로 확장; 기존 방식 기본값 유지 |
| LSP | 같은 원본·극성·pose 범위·취소·점수 범위·소유권 계약 검사 |
| ISP | 기존 좁은 서비스/표시 완료 계약 사용; 불필요한 로그 공급자 인터페이스 미추가 |
| DIP | 알고리즘은 Gray8만 소비하고 WPF/Canvas를 참조하지 않음 |
| Information Expert | gradient 설명 에너지는 세부 모델, 단계 시간은 해당 실행 소유자가 계산 |
| Creator | trainer가 불변 학습 자료, 전처리가 원본 복사, VM이 실행 로그 생성 |
| Controller | VM은 실행/게시 연결, View는 파일 대화상자만 담당 |
| Low Coupling | Canvas는 기존 overlay ID만 통지하며 검사 정책을 모름 |
| High Cohesion | 세부 획 수식과 좌표 변환은 한 모델, 로그 형식은 별도 타입에 응집 |
| Polymorphism | 기존 CPU/CUDA scorer와 검사 service 대체 계약 유지 |
| Pure Fabrication | 로그 DTO/보관과 단계 계측은 ROI 도메인 외부에 둠 |
| Indirection | MainWindow가 표시 이벤트와 검사 로그를 연결 |
| Protected Variations | GPU/파일 공급자 변화가 세부 모델과 로그 스키마에 직접 의존하지 않음 |

성능·정확도·미검증 범위는 [검증 기록](../kensa-text-and-logs-validation.md)을 따른다.

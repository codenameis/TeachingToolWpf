# ADR-063: 전체 후보 검사와 원본 자세 기준 중복 제거

상태: 구현·로컬 검증 완료, 2026-10-16. 검증 데이터의 정확도는 PASS, CPU125ms/CUDA80ms는 FAIL이다. 사용자 요청은 Sub-NCC 위치 오차48개와 후보 잘림의 원인 수정, 같은 검색 조건의 Kensa/8K 전체 위치·각도 검증, 이후 속도 개선이다. 기존 CPU+CUDA 경로는 유지한다.

## 원인

Sub-NCC의 작은 원판 표본은 긴 핀의 일부와 사선 배경을 혼동한다. 원본8K에서 올바른 후보보다 약30px 이동한 봉우리 점수가 높았으며, 원본 전체 내부 픽셀을 보기 전에 중복 제거가 정상 후보를 없앴다. 두 원본 픽셀 회귀에서29.822/30.072px 오류를 재현했다.

세 방식의 기존 전역 우선순위 큐는 원본 검증 전에 후보2048개만 남겼다. 실제로 후보를 버렸으므로 Warning은 올바른 보고였다. 경고만 숨기거나 점수를 조정해 해결할 수 없다.

## 결정

- 전역 모든 위치·각도·배율의 후보 점수 계산과 기존 임시 문턱/최종 점수0.75를 유지한다.
- `CandidateLimit`은 세 CPU 방식에서 **한 번에 정밀 검사할 후보 묶음 크기**다. 기본2048을 유지하고 가득 차면 검사한 뒤 다음 후보를 계속 처리한다. 더 약한 후보도 버리지 않는다. 다른 기존 알고리즘의 예산 의미는 바꾸지 않는다.
- 위치가 가까운 후보의 중복 제거는 모든 원본 정밀 보정·검증 뒤에 적용한다. 중간 단계에서는 X/Y/각도/배율이 정확히 같은 자세만 합친다. 정밀 보정은 seed 점수를 다시 계산하므로 이 합침은 다른 위치 가설을 제거하지 않는다.
- `CandidateCount`와 `CandidateBatches`를 기록한다. 모든 묶음을 처리해야 정상 반환하며 취소/실패는 부분 성공으로 반환하지 않는다. 결과 상한 `MaximumMatches`와 `MatchLimitExceeded`는 그대로 유지한다.
- 자세 캐시는 기존 용량 안에서 오래된 항목을 빼고 새 자세를 보관한다. 처음 채운 몇 각도만 남긴 채 이후 자세를 매 점수 계산마다 다시 만들던 비용을 줄인다. 입력 픽셀·점수 계산·표본·보정 범위는 바꾸지 않는다.
- 동일 픽셀 맵 캐시는 여러 위치가 같은 맵을 가리켜도 한 항목으로 센다. 기존 맵 수/추정 용량 상한을 유지하며, 맵 퇴출 시 위치 별칭을 비워 퇴출된 맵을 붙잡지 않는다. 픽셀 전체 비교는 유지한다.
- 병렬 후보 작업은 같은256px 구역을 연달아 계산하되 결과를 원래 후보 번호에 저장한다. 계산 순서만 바꾸고 결과 정렬·점수 누적·평가 횟수는 유지한다.
- CUDA 방향 보간은 CPU와 같은 중간 반올림을 보존한다. 전체 후보 처리 뒤 드러난 Chamfer603/607개 차이를 점수/동점 허용 오차로 숨기지 않고, float 곱셈 반올림과 double 곱셈/덧셈의 결합 방지로 수정한다. 방향 점수 격자 테스트는 기존1e-7 오차 허용에서 정확한 동등성으로 강화한다.

이 변경은 총 처리 후보 수와 평가 횟수를 늘릴 수 있다. 이전 잘린 실행과 결과/평가 횟수가 모두 같다고 주장하지 않는다. 성능 최적화의 동일성 기준은 **정확도 수정 후 전체 후보를 검사하는 실행**이다.

## 검증 범위

기존 `kensa.png`1024×1536의48개는 검색과 별도의 OpenCV ECC 정합 기준에 대해 위치·각도를 비교한다. 모든 라벨이 있어도 물리 교정 정답은 아니다. 앱8K8192×8192의256핀은 생성기 정답을 사용한다. 제한 영역 회귀·희소8K·회전/배율/잡음 데이터도 유지한다.

CPU125ms/CUDA80ms는 검사 버튼→표시 시간으로 판단한다. 묶음 처리로 생기는 추가 비용을 숨기지 않으며 GPU 장치 준비·전송과 CPU 정밀 검증을 포함한다. 작업 결과는 [검증 기록](../cpu-matching-full-search-accuracy.md)에 갱신한다.

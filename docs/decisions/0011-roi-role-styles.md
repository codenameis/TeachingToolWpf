# ADR-011 — 실제 계층 역할에 따른 ROI 색상과 독립 선 두께

2026-10-02. 상태: 적용, 자동 회귀·실제 RTX UI/GPU 통합 검증 완료. 실제 결과와 측정 한계는 [역할 스타일 검증](../roi-style-validation.md)에 기록한다. [ADR-001](0001-quality-and-edit-history.md)의 설계 원칙과 [ADR-008](0008-retained-roi-rendering.md)의 GPU 버퍼 수명을 유지하며 승인된 원칙 예외는 없다.

## 문제와 결정

부모·자식·독립 ROI를 화면에서 구별하고 세 역할의 선 두께를 각각 조정한다. 스타일을 각 ROI에 저장하거나 형상·이력에 섞지 않는다. WPF 패널이 앱 표시 설정을 편집하고, UI에서 확정한 불변 `RoiStylePalette`를 `RenderScene`으로 전달한다. 세션 간 저장은 이번 범위가 아니다. 문서 Undo/Redo는 스타일 설정을 되돌리지 않는다.

역할은 확정된 문서의 실제 관계에서 결정한다. 실제 자식이 하나라도 있으면 `Parent`, 자식은 없고 부모가 있으면 `Child`, 둘 다 없으면 `Default`다. 자신도 다른 ROI 아래에 있는 중간 부모는 `Parent`다. `IsGroup`은 역할 판정 기준이 아니므로 일반 사각형도 다른 ROI를 완전히 포함하면 부모 색을 쓴다. 마지막 자식이 빠져나가면 부모 역할을 잃고, 관계 복원 시 다시 부모 역할이 된다. 드래그 중 계층은 재판정하지 않고 확정/Undo/Redo로 게시된 관계를 따른다.

기본 부모 선은 분홍색 `#F472B6`, 선택 부모는 흰 라벨과의 대비를 위한 진한 분홍색 `#D63384`다. 일반·자식은 기존 회청색, 선택 시 기존 파란색을 유지한다. 단일 선택의 핸들 연결선·각도/이름 표시도 해당 역할의 선택 색을 사용하며 다중 선택 공통 핸들은 파란색이다. 선택은 색상 외에도 핸들·두께·라벨·목록 표시로 구분한다.

`RoiStrokeStyle`은 일반/선택 색과 기본 두께를 보관하며 기본 두께는 0.5–8 DIP의 유한값으로 제한한다. 세 역할의 기본값은 각각 1 DIP, 선택 윤곽은 해당 값에 0.5 DIP를 더한다. 이미지 확대율과 무관한 DIP를 렌더 타깃 DPI로 변환한다. 세 입력칸을 모두 검증한 뒤 한 번에 적용하며 하나라도 잘못되면 기존 palette를 유지하고 입력 오류를 표시한다. Reset은 기본 palette로 복원한다. Apply/Reset은 ROI나 이력을 수정하지 않는다.

## 렌더·캐시 경계

기존 32바이트 형상 instance를 유지하고 같은 GPU 소유 리소스 안의 별도 역할 데이터에 instance당 4바이트 역할을 둔다. 인스턴스 N개의 payload는 형상 32N바이트+역할 4N바이트이며 실제 committed 할당량은 기존 캐시 예산 규칙으로 계산한다. 동일한 가시 블록/LOD에서 palette 변경은 상수만 바꾸므로 형상/역할 업로드가 없다. 문서 Children identity가 바뀔 때 역할을 다시 평가하고 역할 배열이 같으면 복사하지 않으며, 달라진 경우에만 4N바이트 역할을 업로드한다. `UploadedBytes`는 실제 형상/역할 복사의 합계다. 역할 데이터의 생성·캐시 제거·재사용 역시 렌더 스레드와 기존 fence 수명 규칙을 따른다.

palette 게시의 no-op 판정은 세 두께만이 아닌 색·선택 색·두께를 포함한 전체 불변 값의 동등성을 사용한다. 현재 UI가 두께만 편집하더라도 이후 색 값 변경이 게시에서 누락되지 않도록 한다.

역할 캐시의 계층 버전은 `WeakReference<object>`로 보관한다. 버전 확인만 필요한 캐시가 이전 `Children` 맵 전체를 강하게 붙잡아, 형상 블록 재사용 기간만큼 과거 계층 수명을 연장하면 안 된다. 현재 문서가 제공하는 버전과 참조 동일성을 비교하고 약한 참조의 대상이 없어졌으면 다시 평가한다. 역할 배열의 소유권과 GPU fence 규칙은 그대로 유지한다. 캐시가 회수된 계층 데이터를 역참조하거나 과거 문서를 복원하는 저장소로 동작하지 않는다.

완전히 같은 형상의 표시 중복 제거에서는 `Parent > Child > Default`를 우선한다. 도메인 ID·선택·필터·히트·계층은 합치지 않는다. 화면 밀도 LOD가 여러 ROI를 요약한 instance는 중립적인 `Default` 스타일을 쓴다. 따라서 요약 윤곽의 색을 개별 ROI 역할의 완전한 표시로 해석하지 않는다. 확대 시 개별 역할이 나타난다.

## SOLID·GRASP 검토

| 원칙 | 이번 변경의 적용과 경계 |
|---|---|
| SRP | 설정 입력 검증, 문서 역할 판정, GPU 그리기/수명을 별도 책임으로 둔다. |
| OCP | 색·두께 변경은 불변 palette 값으로 처리한다. 고정 세 역할을 위한 불필요한 플러그인 체계는 추가하지 않는다. |
| LSP | 스타일 값은 동일한 유한값·범위 계약을 지킨다. 표시 변경이 기존 편집/이력/취소 계약을 바꾸지 않는다. |
| ISP | 소비자는 palette와 필요한 역할 값만 받는다. 관련 없는 편집/영상 기능을 스타일 인터페이스에 묶지 않는다. |
| DIP | Core에 WPF/DX12·색상 설정을 넣지 않는다. 표시 DTO로 UI와 렌더를 연결하고 GPU 객체는 전달하지 않는다. |
| Information Expert | 실제 부모/자식 정보는 문서 snapshot에서 얻고 포함 판정을 렌더러에서 다시 구현하지 않는다. |
| Creator | 설정 모델이 유효한 palette를 만들고 렌더 소유자가 역할 GPU 데이터를 생성·해제한다. |
| Controller | UI는 Apply/Reset을 설정 모델에 전달한다. ROI 이동/Undo는 기존 응용 명령을 사용한다. |
| Low Coupling | 불변 palette·문서 snapshot 경계로 연결하며 GPU가 WPF 입력칸을 읽지 않는다. |
| High Cohesion | 색/두께 규칙을 스타일 값에 모으고 계층 편집과 섞지 않는다. |
| Polymorphism | 기존 입력·렌더 계약을 유지한다. 단순한 세 역할 값에 사용처 없는 상속 구조는 추가하지 않는다. |
| Pure Fabrication | 역할 스타일과 GPU 역할 캐시는 표시 책임으로 분리하고 도메인 ROI에 표시 상태를 추가하지 않는다. |
| Indirection | `RenderScene`과 설정 명령이 UI 입력·GPU 실행 사이의 명시적 경계가 된다. |
| Protected Variations | palette 변경은 편집 형상/이력과 격리되고 렌더 자원 변화는 기존 fence 소유 경계 안에 둔다. |

## 검증과 제외 범위

역할 우선순위·범위 검증·세 입력의 원자적 적용·문서 이력 독립성을 포함해 Core 158개+Imaging/WPF 97개, 총 255개가 통과했다. Release 빌드 경고·오류는 0이다. 실제 RTX smoke에서 설정 패널의 입력칸/적용 버튼을 거쳐 자연 포함 부모/자식/독립 ROI의 2/3/4 DIP, 선택 색, 자식 분리, 정확한 Undo/Redo와 Reset을 검증하고 캡처를 확인했다. 수치 설정의 도메인 검사와 픽셀 색/두께 시각 검사를 구분한다.

소유권 회귀 검증은 `NoInlining` 팩터리에서 문서와 역할 캐시를 만든 뒤 캐시와 계층의 약한 참조만 반환한다. 테스트에서 캐시는 살아 있는 상태로 GC를 실행하고 이전 계층이 회수되는 것을 확인했다. JIT의 지역 변수 수명 때문에 문서가 우연히 남는 경우와 캐시의 실제 강한 참조 누수를 구분하기 위한 검증이다.

20만 평면/PCB 부모 선택의 반복 회전 측정 구간에서는 ROI 업로드 0B를 관측했다. 이는 palette 적용 순간의 실측과 다르다. 최종 smoke의 render CSV가 GPU 재시작으로 다시 만들어져 적용 timestamp 구간이 남지 않았으므로, 스타일만 변경한 순간의 GPU 업로드 0B를 실측 결과로 주장하지 않는다. 해당 재사용은 구현 경로와 캐시 회귀로 검증했고 실제 측정의 공백은 검증 기록에 남긴다.

새 색상 편집기, 세션 간 설정 저장, 임의 역할 추가, LOD 요약의 개별 역할 전부 표시, 저사양 GPU에서의 새 성능 목표는 이번 범위가 아니다. 성능 개선을 주장하려면 palette만 변경했을 때의 형상 재업로드·역할 변경 비용을 별도 측정한다.

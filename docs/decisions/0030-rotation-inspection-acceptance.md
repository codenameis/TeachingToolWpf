# ADR-030: 논문 형상 탐색 각도와 회전 합격 범위 분리

- 날짜: 2026-10-05
- 상태: 구현·현재 PCB ROI 검증 완료. CPU125/CUDA80 ms 성능 수용은 FAIL.
- 범위: 논문 형상 앱의 선택형 회전 검사. 알고리즘 점수·OpenCV·자체 기하 방식은 변경하지 않는다.

## 문제와 재현

사용자는 켜진 앱에서 180° 뒤집힌 대상이 불량으로 나오지 않는다고 보고했다. 앱에서 읽은 학습 ROI는 중심 `(760.793,598.841)`, 크기 `110.787×245.01`, 각도0°, 검색 범위0~10°다. 기존 8K 속도 fixture의 짧은 핀 ROI와 다르다.

원본 샘플 한 주기 2048²에서 좁은 각도로 검색하면 아래쪽8핀이 약0°·점수0.935~0.996으로 검출된다. 밝은 핀은 대칭에 가깝고, 방향 특징 점수는 명암 경사의 크기를 정규화한다. 추가 윤곽 에너지 감점만으로 이 후보를 배제하지 못한다. 특징 최소 대비 비율을0으로 바꿔도 이 fixture의 선택 특징·결과는 동일했다. 비율0 재학습만으로 완전한 형상/방향 비교를 보장하지 않는다.

같은 학습 ROI를 전체360°로 탐색하면 아래8핀을 약±180°로 선택한다. 기존 앱은 그 각도를 표시했지만 학습 방향과 비교한 회전 불량 정책은 없었다. 좁은 검색 범위를 합격 범위처럼 사용하는 것으로는 회전 불량 검사를 대체할 수 없다.

## 결정

1. 논문 모드에 `회전 불량 검사 · 변경 후 재학습`을 제공한다. 기존 동작을 보존하기 위해 기본은 꺼짐이다. 켜면 실제 학습 탐색 범위는 학습 방향 대비 -180~180°다. 기존 좁은 검색 범위 입력은 보관하고 편집을 비활성화한다. 끄면 보관했던 검색 범위로 돌아가며 다시 학습해야 한다.
2. 정상 허용 편차는 독립 `RotationAcceptance`에 저장한다. 초기값0~10°는 이번 사용자의 현재 입력을 기준으로 한 구현 기본값이며 생산 합격 조건의 최종 확정을 뜻하지 않는다. 정상 범위만 바꾸면 재학습 없이 결과를 무효화하고 재검사한다. 모드 사이에서 섞지 않는다.
3. 각도 차이는 모델의 학습 기준각을 빼고 주기를 처리한다. -180°와180°는 같은 방향이며 170~190°처럼 주기 경계를 넘는 구간도 지원한다. 경계의1e-9°는 부동소수 오차용이며 측정 허용 공차를 숨겨 추가하지 않는다.
4. 검색 완료 결과에서 허용각 밖 검출은 NG/Tomato, 목록과 캔버스 라벨에는 판정·학습 대비 각도를 표시한다. 점수는 변경하지 않는다. 개별 회전 NG가 하나라도 있으면 전체 NG이며 다른 미확정 항목은 별도 CHECK로 보존한다.
5. 후보 잘림·출력 상한·검색창 없음은 WARN이 우선한다. 회전 관측 불가 또는 유효하지 않은 각도는 CHECK다. point-to-line의 `Rejected`는 검증된 후보 pose로 복귀한 상태이므로 회전 관측 가능한 반환각이 명백히 허용각 밖이면 회전 NG를 적용한다. 정상 허용각 안에 있는 정밀화 미확정 결과는 기존 CHECK를 유지한다.
6. 최근20회 검사 로그에 정상 각도 구간과 회전 NG 수를 보관한다. 불완전 검색의 NG 수는 미판정(null)이다. 기준 변경 중 도착한 오래된 결과는 기존 epoch 검사로 폐기한다.

## 검증과 한계

[8K 검증 기록](../rotation-inspection-validation.md)을 따른다. 현재 ROI에서는 CPU·CUDA 모두256개를 찾고 역방향128개 전부 NG로 표시한다. 0~10°에서는 정방향의 작은 음수 측정각까지 제외하여 총192개NG, ±10°에서는 역방향128개만NG/정방향128개OK다. 설정을 자동 완화하지 않았다.

회전 검사를 끈 좁은 탐색에서는 앞의0° 오인식이 그대로 가능하다. 이것은 임의의 대칭 형상을 구분하는 알고리즘 수정이나 전체 형상 동일성 보증이 아니다. 완전히 대칭인 ROI는 전체각 탐색으로도 방향을 결정할 수 없다. 실제 비대칭 단서가 포함된 ROI가 필요하며 다른 현장 입력의 정확도는 NOT_RUN이다. 동일 장면에 대해 전체각 탐색 시간이 늘 수 있으며 기존125/80ms 목표를 변경하지 않는다.

## 설계 원칙 검토

| 원칙 | 확인 |
|---|---|
| SRP | 주기·허용 구간은 RotationAcceptance, 합격 정책은 InspectionDecision, 표시 변환은 Presentation, 자원/탐색은 기존 서비스다. |
| OCP | 기존 판정에 선택형 정책을 전달하고 정책이 없으면 기존 동작을 유지한다. |
| LSP | 서비스 인터페이스·취소·소유권 계약을 바꾸지 않는다. 전체각은 기존 유효 학습 옵션이다. |
| ISP | 새로운 서비스 메서드나 사용하지 않는 인터페이스를 강제하지 않는다. |
| DIP | 정책은 앱 검사 계층에만 있으며 Algorithm/Core/Canvas에 WPF 판정 의존성을 추가하지 않는다. |
| Information Expert | 각도 주기와 범위는 그 값을 소유한 정책이 계산한다. |
| Creator | 기존 모드 상태가 학습 설정과 검색 정책을 보유한다. |
| Controller | VM은 불변 설정을 전달하고 판정 규칙은 InspectionDecision에 위임한다. |
| Low Coupling | Canvas는 이미 계산된 색·문구만 받는다. |
| High Cohesion | 회전 바인딩/문구는 Rotation partial, 정책은 작은 별도 타입에 둔다. |
| Polymorphism | 기존 IShapeMatchingService를 그대로 사용한다. 실제 변형이 없는 새 인터페이스는 만들지 않는다. |
| Pure Fabrication | 허용각 정책과 진단 실행을 ROI 도메인 밖에 둔다. |
| Indirection | 기존 표시 adapter가 모델/판정과 렌더러 사이를 연결한다. |
| Protected Variations | 모드별 독립 상태와 기존 원본/자원 계약을 보존한다. ROI·Undo/Redo 상태 불변을 회귀 테스트했다. |

성능상 설계 원칙 예외는 없다. 새 의존성·무제한 작업·자동 외부 전송은 없다.

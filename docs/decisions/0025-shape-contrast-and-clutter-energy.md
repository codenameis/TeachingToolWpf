# ADR-025 — 형상 학습의 대비 선택과 추가 윤곽 에너지 검증

- 날짜: 2026-10-04~05
- 상태: 구현, 최종 검증 중
- 요청: 논문 기반 형상과 자체 기하 형상의 검출·정합성·속도 저하 재검토.

## 재현

이전 성능 검증은 작은 핀의 고정 배율 검색에 치우쳤다. 8192×8192 원본 PNG에 배경 무늬의 위치와 회전·배율이 다른 동일 형상 16개를 넣으면 두 방식 모두 후보 16개를 원본 검증에 전달했으나 최종 검출은 1개였다. 후보·출력 한도 경고는 없었다. 임계값을 낮추거나 검증 후보를 잘라 해결하지 않는다.

학습 산포는 전체 후보의 공간 면적으로 간격을 정했다. 넓은 학습 배경의 약한 윤곽이 강한 대상 윤곽의 특징 자리를 차지했고, 배경이 달라지면 방향 점수까지 하락했다. 또한 추가 윤곽의 개수 비율은 많은 약한 무늬와 실제 강한 구조 차이를 같은 무게로 취급했다.

## 결정

1. 학습의 선택 특징 후보에 `MinimumFeatureContrastRatio`를 적용한다. 각 피라미드 단계의 최대 gradient 강도에 대한 비율이며 기본 .2, 범위 0~1이다. 0이면 종전처럼 모든 유효 윤곽 후보를 사용한다. 변경 후 재학습하며 두 형상 방식의 값을 따로 보관한다. OpenCV에는 적용하지 않는다.
2. 전체 원본 학습 윤곽과 실제 도형 마스크는 그대로 보관한다. `ClutterRatio`와 `MaximumClutterRatio`는 전체 윤곽으로 설명되지 않는 장면 에지의 **개수 비율**이라는 기존 계약을 유지한다. 픽셀까지 같은 학습 이미지가 약한 윤곽 제거 때문에 탈락하지 않아야 한다.
3. 최종 감점은 별도 `ClutterEnergyRatio`/`ClutterPenaltyRatio`를 사용한다. 실제 마스크 안의 gradient 강도 제곱 합에서 설명되지 않는 에너지의 비율이다. 최종 점수는 `DirectionScore × (1 − ClutterWeight × ClutterPenaltyRatio)`이다. 원래 개수 비율은 진단과 명시적 기하 제한으로 남는다.
4. 에너지 설명은 거리·방향뿐 아니라 조명 gain 보정 후 대비 차이를 두 배까지 허용한다. 강한 학습 윤곽에서 고르게 고른 최대 128개의 위치·방향 대응 강도비 중앙값으로 gain을 구한다. 추가 결함의 최대 강도를 전역 조명 변화로 흡수하지 않는다. 대응이 없으면 gain 1을 사용한다. 전체 윤곽 개수 설명에는 이 강도 조건을 적용하지 않는다.
5. 방향 정밀화의 변환 특징 캐시는 실험 후 **원복**했다. 정확한 점수·자세 동등성은 통과했지만 강제 Rebuild로 분리한 binary의 전체 검사 시간에서 이득이 재현되지 않았다. 추가 수명·버퍼 복잡도를 제품에 남기지 않는다. 처음의 동일 DLL 비교는 무효로 기록했다.

## 의도된 한계

대비 선택은 약한 실제 세부도 제외할 수 있다. 강한 사각형과 낮은 대비 E 문자를 함께 학습하는 통제 입력에서 기본 .2는 E 누락을 구별하지 못했다. 이런 세부를 검사하려면 비율을 낮추거나 0으로 설정한 뒤 다시 학습해야 한다. 전체 픽셀 동일성이나 결함 확률을 보장하는 점수로 표현하지 않는다. 잡음과 의미 있는 저대비 구조를 자동 분류하는 기능은 구현하지 않았다.

GPU는 기존 CUDA 전처리이며 검색·정밀화는 CPU다. 이번 변경으로 전체 GPU 검색이나 상용 PatMax 동등성을 주장하지 않는다. 합성 PNG 정답을 실제 현장 검출률로 표현하지 않는다.

## 검증

변경 전 RED, 동일 noisy 학습의 원시 개수 판정, 명암 변화, 추가 강한 윤곽, 마스크 구멍, 저대비 세부 옵션 0, 회전·배율·서브픽셀·얇은 윤곽, 정답 8/오답 88 장면을 확인한다. 실제 파일의 16개 정답은 위치 1px·각도 1도·배율 .01 이내를 요구하고 중복·미할당도 검사한다. CPU 1/4 및 두 방식에서 첫 검색과 반복 검색을 구별하며 읽기·학습은 검사 wall time에 섞지 않는다. 전후 자료와 최종 실행 증거는 [검증 기록](../shape-regression-validation.md)에 남긴다.

## 설계 원칙 검토

| 원칙 | 적용 |
|---|---|
| SRP | 학습 후보 선택, 윤곽 소유, 기하 검증, 점수 합성, UI 표현 책임 유지 |
| OCP | 기존 typed 설정에 선택 비율을 추가하고 공급자 의존성은 추가하지 않음 |
| LSP | 기존 개수 비율·마스크·취소·모델 소유 계약 유지, 자기일치 회귀로 확인 |
| ISP | 기존 작은 공개 계약을 유지, 새 서비스 기능 강제 없음 |
| DIP | Algorithm에 WPF·DX12·Canvas 참조 없음 |
| Information Expert | 원본 윤곽·대비 기준은 모델, 설명·gain은 품질 계산이 소유 |
| Creator | 학습기가 모델의 불변 윤곽·대비 기준을 생성하고 소유 |
| Controller | 앱은 설정·실행·결과를 연결하며 알고리즘 규칙을 직접 계산하지 않음 |
| Low Coupling | 기존 원본 이미지·typed 결과 경계 유지 |
| High Cohesion | 윤곽 설명의 개수·강도 결과를 같은 공간 조회에서 계산 |
| Polymorphism | 기존 전처리 공급자 대체 계약 유지, 새 가짜 공급자 없음 |
| Pure Fabrication | 기술 성능 측정은 benchmark로 분리, 효과 없는 캐시 실험은 원복 |
| Indirection | 앱 어댑터가 결과 값을 표시하고 Canvas는 공급자 비의존 overlay만 받음 |
| Protected Variations | 개수 제한과 에너지 감점의 의미를 별도 필드로 보존 |

설계 원칙 예외는 적용하지 않는다.

# ADR-012: 사각형 전제 제거와 도형별 ROI

날짜: 2026-10-03. 사용자 요청: ROI를 사각형으로 전제하지 않고 폴리곤·원·삼각형을 추가한다. 원칙 예외 없음.

## 결정과 동작

- `RotatedRect`를 공통 값 `RoiGeometry`로 교체한다. 중심·양수 크기·절대 각도와 불변 `RoiShape` 전략을 가진다. 사각형은 기본 생성값일 뿐 ROI 계약의 전제가 아니다. Core는 WPF/OpenCV/DX12를 참조하지 않는다.
- 도형 전략은 로컬 포함·support·면적을 제공한다. 사각형, 원, 삼각형, 단순 폴리곤을 지원한다. 원은 너비=높이=지름, 폴리곤은 정규화한 불변 꼭짓점 배열을 보유한다. 평행 이동·회전·resize·복사·Undo/Redo에서 같은 전략을 보존한다. 삼각형 초기값은 상단 꼭짓점/하단 밑변의 이등변삼각형이다.
- `FrameCorners`는 사각 편집 프레임의 8개 핸들 및 필터 패치 매핑에만 사용한다. 실제 경계·그룹 범위·이미지 제한·마퀴는 도형의 정확한 Bounds를 사용한다. 원을 회전해도 그 자체의 범위는 커지지 않는다. 부모 회전에 따른 중심 이동과 자손 회전은 유지한다.
- BVH 후보 검색은 자식 형상 위의 점을 사용한다. 오목 폴리곤의 프레임 중심이 도형 밖에 있어도 올바른 부모를 찾는다. 최종 포함은 원/원의 거리, 원/다각형의 꼭짓점 또는 변까지 거리, 사각 부모의 정확한 support, 다각형/다각형의 모든 변 구간 판정으로 결정한다. 오목 홈을 가로지르는 변은 자식으로 인정하지 않는다. 면적 우선·ID 동률·경계 접촉·같은 면적 제외 규칙은 유지한다.
- 회전 허용 구간은 사각형/다각형의 실제 꼭짓점, 원 중심과 반지름만큼 줄인 이미지 경계로 최초 이탈을 구한다. 회전용 BVH support도 도형 전략을 사용한다.
- 왼쪽 도형 선택을 `ROI 추가`와 `그리기`에 공통 적용한다. 폴리곤 즉시 추가는 오각형이다. 자유 폴리곤은 점 클릭 → 완료/Enter/첫 점 클릭, 마지막 점 제거는 점 취소/Backspace, 전체 초안 취소는 취소/Escape다. 초안은 문서·이력을 건드리지 않는다. 이미지 변경/도구 전환/창 크기 변경 및 드래그 중 캡처 상실도 초안을 폐기한다. 성공한 확정 한 번만 이력에 기록하고 선택 도구로 복귀한다.
- 자기 교차·비인접 변 접촉·인접 변 되접힘·중복 점·0 면적·비정상 좌표를 거부한다. 구멍 없는 단순 폴리곤을 지원하며, 생성 후 개별 꼭짓점 편집·타원·구멍이 있는 복합 도형은 후속 범위다. 기존 프레임 핸들/수치로 폴리곤 전체를 resize/이동/회전할 수 있다.
- 원 resize는 반대쪽 핸들을 유지하고 두 축을 같은 지름으로 확정한다. 소수 연산으로 최소 .01 px 아래에 떨어지지 않게 최종 크기를 제한한다. 수치 편집에서 너비/높이 하나를 바꾸면 지름에 반영하고 둘 다 변경하면 너비를 우선한다.

## 렌더와 필터

`RoiInstance` 32바이트/역할 4바이트 계약을 유지한다. 사각형과 원은 한 instance, 삼각형·폴리곤은 변당 한 instance를 사용한다. 원은 pixel shader에서 화면 반지름과 선 두께를 사용해 해석적으로 그린다. 선분은 동일 보관 버퍼·역할 색상·공통 강체 변환·fence 수명을 사용한다. hover/그리기 초안의 원 가이드는 128개 선분이며 정확한 도메인 판정은 이 근사를 사용하지 않는다.

필터는 기존 회전된 로컬 패치를 처리하고 worker에서 픽셀 중심의 도형 마스크를 만든다. 마스크가 있는 atlas 페이지는 RGBA, 사각형만 있는 페이지는 기존 Gray8이다. 영역 밖 alpha는 0이므로 원본이 보존된다. 단일 실행/최신 대기·4Mpx/1024px/라이브 최대 5Hz 계약은 유지한다. 원본/이력에 결과 픽셀을 보관하지 않는다.

꼭짓점 배열은 불변으로 공유한다. 이력은 폴리곤 점의 바이트를 보수적으로 포함한다. BVH 노드가 꼭짓점 추정 바이트를 합산해 렌더 캐시에서 요약 노드의 전체 점을 다시 순회하지 않고도 CPU 유지 비용을 계산한다. 실제 GPU 할당과 CPU 추정은 구별한다. 기존 사각형의 빠른 Bounds 경로를 유지한다.

## 검증

- Release 솔루션 빌드: 경고/오류 0. Core 174개, Imaging/WPF 129개 통과.
- 반지름 hit/계층, 오목 홈을 가로지르는 변 거부, 프레임 중심이 밖인 오목 자식, 동일 도형 보존, 이미지 경계 resize/회전, 작은 이미지로 복사, 부모 연쇄 삭제/선택 복원/Undo/Redo/새 분기, 폴리곤 취소·실패·소스 변경, 소수 좌표 원 resize를 자동 검증했다.
- GPU 선분/원 instance와 역할 개수·좌표, 필터 픽셀/투명 alpha를 자동 검증했다. 원 내부 판정 조건을 반전한 변이 시험에서 관련 테스트 실패를 확인하고 원본을 복원했다.
- 실제 NVIDIA GeForce RTX 3060 Laptop, VRAM 5.9 GiB, DXGI budget 5.1 GiB, DPI 150%에서 `--smoke --gpu-debug` 종료 0. 로그상 DX12 warning/error 없음. 도형 ComboBox 바인딩, HWND 메시지 기반 원/삼각형/폴리곤 입력, 지름 적용, 혼합 회전·그룹/연쇄 삭제·Undo, OpenCV 마스크를 확인했다. [캡처와 로그](../data/roi-shapes-validation.zip).
- 캡처 `shapes-app.png`, `shapes-outline.png`, `shapes-filter.png`에서 각 실제 윤곽과 폴리곤 홈의 원본 보존을 확인했다. 이 시험은 직접 HWND 메시지 기반이며 물리 마우스 전체 E2E와는 구분한다.
- 최종 `artifacts/publish`를 작업 디렉터리로 한 동일 debug smoke도 종료 0. 배포된 네이티브 DLL/셰이더 및 새 UI를 확인했고, 첨부 ZIP은 이 최종 배포 실행의 로그·캡처다.
- 혼합 도형 수백만 개의 정식 성능/장시간/실제 카메라 시험, 개별 점 수가 매우 많은 폴리곤의 입력 지연은 미검증이다. 폴리곤 유효성/쌍별 포함은 점 수에 따라 비용이 증가한다. 이번 결과로 과거 사각형 대량 측정이나 8K FPS 목표를 새 도형 전체의 달성 결과로 확대하지 않는다.

## 설계 검토

| 원칙 | 이번 변경의 근거 |
|---|---|
| SRP | 도형 규칙은 기하, 입력 초안은 Interaction, 필터 마스크는 Imaging, GPU 수명은 Rendering |
| OCP | 실제 변형인 도형을 RoiShape 전략으로 분리. 도메인 포함 쌍/렌더 primitive의 명시적 분기는 각 소유 경계에 제한 |
| LSP | 같은 형상 값 계약으로 유한 크기/오류/이미지 제한/변형 보존 검증. 원의 지름 제약은 명시적으로 검증 |
| ISP | 로컬 포함·support·면적/윤곽만 도형 계약에 두고 UI·파일·GPU 메서드를 강제하지 않음 |
| DIP | Core는 플랫폼에 의존하지 않으며 앱 조립과 기존 영상/렌더 계약 유지 |
| Information Expert | 반지름·꼭짓점을 가진 기하가 포함/경계/면적을 계산 |
| Creator | 기하 생성자가 유효성, EditorSession이 생성/이력, GPU 소유자가 버퍼 수명을 담당 |
| Controller | WPF는 도구/명령을 연결하고 도형 입력은 Interaction/EditorSession에서 처리 |
| Low Coupling | 불변 RoiGeometry와 마스크 결과로 UI/영상/GPU 경계 연결 |
| High Cohesion | 폴리곤 수학·기하 변형·픽셀 마스크 책임을 각각 분리 |
| Polymorphism | RoiShape 전략으로 원과 다각형의 로컬 포함/support/면적 구현 |
| Pure Fabrication | 기존 공통 이력/BVH/atlas 유지, 폴리곤 기술 비용도 해당 소유자에 배치 |
| Indirection | ViewModel/입력/렌더 adapter가 플랫폼 API와 Core를 연결 |
| Protected Variations | FrameCorners와 실제 Outline을 구별해 사각 UI 프레임이 도메인 형상을 규정하지 않음 |

기존 MVVM·Command/Memento·State·Composite를 재사용하고 도형에 Strategy를 적용했다. 성능을 이유로 정확성·이력·원칙을 완화하지 않았다. 승인 요청이 필요한 원칙 예외는 없다.

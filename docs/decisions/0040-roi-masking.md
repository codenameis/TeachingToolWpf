# ADR-040 — ROI 마스크 편집과 검사 제외

상태: 2026-10-06 사용자 요청에 따라 구현. 현재 `main`에서 로컬 변경만 진행한다.

## 결정

ROI 안의 검사 제외 부분을 사각형·타원으로 그린다. 마스크는 자식 ROI가 아닌 `Roi.Masks` 불변 값이며 ROI 프레임 좌상단 기준0–1 좌표로 저장한다. 이동·회전·크기 변경·복사에서 상대 위치를 유지하고 실제 ROI 도형과의 교집합만 적용한다. 그룹 부모에는 추가하지 않는다. 초기 버전은 ROI당 최대64개이며 목록의 수치 편집과 삭제를 제공한다.

`RoiMaskViewModel`/패널은 입력 초안을, Core gesture/session은 포인터 초안·확정·이력을 담당한다. 한 드래그는 한 명령이며 Esc/캡처 상실/대상 변경은 초안을 버린다. 사선 음영·활성 버튼·목록·상태 설명을 함께 제공한다. 표시 토글은 문서와 검사 적용을 바꾸지 않는다. 선택 ROI 하나의 마스크 합집합을 GPU에서 한 번 채워 겹침에 따라 불투명도가 누적되지 않게 한다. WPF를 HWND 위에 겹치지 않는다.

사용자는 UI뿐 아니라 학습·검사 연결도 요청했다. 다음 의미를 구분한다.

- **학습:** 원본 픽셀 중심에서 `ROI 안 AND 마스크 밖`을 기존 학습 마스크로 전달한다. NCC의 유효 픽셀과 형상 모델의 특징/전체 윤곽/품질 마스크에 적용한다. 전부 가린 학습은 오류다.
- **선택 ROI 검사:** 제외 영역과 겹치는 대상을 결과에서 제외한다. 마스크로 잘린 대상을 남은 부분으로 재점수화하지 않는다. NCC는 실제 학습 유효 픽셀, 형상은 실제 학습 마스크와 전처리/보간 지지 여유4px, 일반 도형은 실제 채워진 윤곽과 median 여유를 확인한다. 일반 도형의 자동 임계값/자동 명암 선택에서도 제외 픽셀을 뺀다. 원본 픽셀을 검게 칠해 인공 경계를 만들지 않는다.
- **전체 이미지 검사:** 모델에 저장된 학습 마스크를 사용한다. 문서의 모든 ROI 마스크를 합쳐 전역 제외 영역으로 만들지는 않는다.

`MaskRegion`/`RoiExclusion`은 VisionGeometry의 중립 값이다. 앱이 원본 ROI와 마스크를 VisionInspection에 넘기며 검사/알고리즘은 Canvas·WPF를 참조하지 않는다. 서비스에 선택적 exclusion 인수를 추가했고 구현체·테스트 대역을 갱신했다. 이 인터페이스를 직접 구현하는 외부 호스트는 새 인수가 필요하다.

학습 ROI의 마스크가 달라지면 저장 모델은 보관하되 재학습 전 검사를 막는다. Undo로 동일 마스크를 복원하면 모델을 다시 사용할 수 있다. 실행 중 변경은 기존 epoch/취소 경계로 늦은 결과를 버린다. 보기 토글은 학습을 무효화하지 않는다.

## 비용과 한계

Core는 불변 배열을 공유하고 이력 추정에 항목당64바이트를 추가한다. 마스크 렌더 업로드는 프레임별 arena를 사용하며 첫 사용 시 두 슬롯 합 최소8MiB가 추가된다. fence가 끝난 슬롯만 재사용하고 renderer 종료에서 해제한다. 마스크 표시 때문에 전체 문서를 매 프레임 순회하지 않는다.

제외 래스터는 원본 crop 크기만큼 필요한 경우에 생성한다(기존 형상 검색2Mpx/정밀화8Mpx, NCC16Mpx 상한 유지). 학습 마스크는 전체 윤곽 모델의 소유 버퍼를 공유하고 해당 모델이 없는 경로만 복사한다. 재사용 가능한 전처리 결과는 제외 마스크 사본을 소유하므로 호출자가 입력 버퍼를 재사용해도 결과가 변하지 않는다. 사본 생성 시간과 소유 메모리를 전처리 진단에 포함하며 마스크만을 위해 원본 픽셀을 보관하지 않는다. 축소 후보 검색은 원본 명암을 유지하고 마스크 최종 제외는 원본 정밀화에서 수행한다. 마스크 영역의 후보가 후보 예산을 쓸 수 있으며 기존 불완전 검색 경고를 유지한다.

이번 기능은 기존 전체60FPS 또는 검사 CPU125ms/CUDA80ms 목표 달성 근거가 아니다. 자유 폴리곤/브러시, 기존 마스크의 캔버스 핸들 편집, 모든 ROI 마스크 동시 표시는 후속 범위다. [사용법·검증](../roi-masking.md).

## SOLID와 GRASP 검토

| 원칙 | 확인 |
|---|---|
| SRP | WPF 초안, 편집/이력, 기하, GPU 수명, 검사 adapter 분리 |
| OCP | 선택적 값 인수로 검사 확장, Core에 공급자 분기 없음 |
| LSP | null exclusion의 기존 동작, 원본/취소/검증 계약 유지 |
| ISP | 작은 기하 값 전달, 광범위 서비스 계약 추가 없음 |
| DIP | 앱이 중립 기하 전달, Canvas/Core에 검사·CUDA 참조 없음 |
| Information Expert | 기하가 포함, session이 문서, reader가 원본 crop 소유 |
| Creator | session이 이력 생성, 렌더 pipeline이 GPU 생성/해제 |
| Controller | 버튼/포인터가 같은 session 명령 사용 |
| Low Coupling | WPF 객체/문서/렌더 자원을 검사에 전달하지 않음 |
| High Cohesion | 마스크 UI, gesture, GPU pipeline 각각 한 책임 |
| Polymorphism | 기존 CPU/CUDA 전처리·검사 대체 계약 유지 |
| Pure Fabrication | GPU 수명·이력은 해당 기술 서비스에서 처리 |
| Indirection | 앱 adapter와 원본 reader가 편집/영상/알고리즘 연결 |
| Protected Variations | shader·WPF·OpenCV 타입을 기하/Core에서 격리 |

설계 원칙 예외 없음. 불완전 검색이나 미검증 하드웨어를 성공으로 표시하지 않는다.

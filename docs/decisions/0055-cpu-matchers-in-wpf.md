# ADR-055: 세 CPU 템플릿 매칭 방식의 WPF 연결

상태: 사용자 요청으로 구현, 로컬 수정·검증만. 2026-10-16.

기존 선택에 Line2D/Sub-NCC/Directional Chamfer를 추가한다. ADR-054의 독립 라이브러리를 VisionInspection이 프로젝트 참조하고 App이 원본 reader를 사용하는 서비스를 VM에 주입한다. Canvas/편집 도메인은 변경하지 않는다. 삭제된 기하 모드 값2를 재사용하지 않고4~6을 추가한다.

각 방식은 독립 템플릿·학습 ROI·검색 설정을 유지한다. 사각형 ROI를 원본1px 간격으로 펼쳐 학습하고 실제 사용한 정수 크기를 표시한다. 검색 각도는 학습 ROI에 대한 편차, 결과는 영상 기준 절대 각도다. 픽셀 인덱스와 Canvas 좌표의0.5px 차이는 어댑터에서 처리한다.

검색 ROI는 기준점의 허용 영역이다. 회전·최대 배율을 포함하는 주변 원본을 읽고 실제 도형의 중심 판정을 최종 NMS/출력 상한 전에 적용한다. 라이브러리의 선택적 predicate는 기하/WPF 의존성을 만들지 않는다. 후보 예산 소진을 성공으로 숨기지 않는다.

기존2Mpx 검색·512px 템플릿 한도, 원본·취소·오류 계약을 유지한다. 마스크/비사각형 학습은 명시적 오류다. 모델은 세션에서만 유지한다. 검색 각도는 제품 회전 OK/NG 허용각이 아니며 새 방식의 결과는 사용자 확인/불완전 경고로 표시한다.

[사용법·실측·원칙 검토](../cpu-matching-wpf.md). Kensa 원본18V/부품, 그 crop의 알려진 회전과179° 합성 형상을 동일 점수0.75로 비교한다. 명령/원본 읽기/검색/게시/Present fence와 다음 WPF Rendering을 기록한다. 물리 입력 메시지 대기·scan-out은 별도이며125ms 달성을 선언하지 않는다. Chamfer 원본 부품의 추가 오검출을 보존한다. 설계 원칙 예외 없음.

# ADR-056: CPU 매칭의 정확도 우선 보정과 계산 재사용

상태: 사용자 요청으로 구현, 로컬 수정·검증만. 2026-10-16.

사용자는 성능 목표보다 정확한 검출을 먼저 확보하고 이후 속도를 다듬도록 확정했다. 현재 WPF에 연결한 Line2D/Sub-NCC/Directional Chamfer가 대상이다. CPU125ms/CUDA80ms 목표를 달성했다고 선언하거나 삭제하지 않으며, 기존 PoseMatch 전체 탐색 경로는 변경하지 않는다.

Kensa의 같은 부품4개를 찾는 제한 영역에서 Chamfer는8개를 반환했다. 단방향 template→scene 거리만 쓰면 조밀한 다른 윤곽도 높은 점수를 얻는다. 별도의 합성 체크무늬가0.8517점을 얻는 재현으로 이를 확인했다. 또한 원본 거리 단위가 템플릿 크기에 따라 최대3px까지 증가해 다른 크기의 칩에도 관대했다.

Chamfer의 최종 원본 검증에 scene→template 방향 거리 지지율을 추가하고 두 방향의 조화평균을 사용한다. 역변환한 템플릿 내부에서만 평가하며 crop 미분 경계2px를 제외하고 영상 gradient 크기로 가중한다. 원본 공간 거리 단위는0.6~1px로 제한하고, coarse 레벨의5px 허용은 유지한다. 점수0.75, 각도/배율 범위, 후보 예산, NMS와 검색 ROI를 줄여 결과 개수를 맞추지 않는다. 기하 모드나 NCC 검증을 새로 혼합하지 않는다.

공통 피라미드는 최종 pose에서 `IScoreLevel.Verify`를 호출한다. 기본 구현은 기존 pose 점수이며 Chamfer만 추가 검증을 구현한다. 최종 검증은 실제 검색 도형 중심 판정·NMS·출력 상한보다 앞에 있다. Line2D와 Sub-NCC의 점수 의미는 유지한다. Chamfer 점수는 이전 버전과 의미가 달라졌으므로 같은 수치를 직접 품질 개선량으로 비교하지 않는다.

정확도 수정 이후에만 다음 재사용을 적용한다. 불변 영상의 전체 crop은 같은 인스턴스를 반환하고, coarse 응답 버퍼는 모든 행을 덮어쓰며 재사용한다. pose 계산은 한 검사/레벨 안에서 정확히 같은 double 각도·배율만 캐시한다. 캐시는 템플릿 면적에 비례하는1~128개 상한을 두고 넘는 값은 그대로 계산한다. 영상별 준비를 검사 이전으로 옮기거나 검색 해상도·평가 수를 줄이지 않는다. 캐시는 실행 간 공유하지 않아 수명과 동시 실행을 격리한다.

회귀 기준은 개수뿐 아니라 누락/오검출0, 위치1px·각도1°·배율0.03 이내, 후보/출력 잘림 없음이다. Kensa 제한 영역의 수작업 정답과 알려진 합성 변환, 수정 후 생성한 추가 검증을 구별한다. 전체 현장 데이터 정답과8K 전체 탐색 완료로 해석하지 않는다. [재현·실측·SOLID/GRASP 검토](../cpu-matching-accuracy.md). 설계 원칙 예외 없음.

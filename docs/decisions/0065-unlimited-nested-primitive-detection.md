# ADR-065 — 전체 개수·중첩 도형·32K CPU/CUDA 검출

- 날짜: 2026-10-16
- 상태: 로컬 구현·검증. 커밋/푸시 없음.
- 범위: 학습 없는 일반 도형 검출. 패턴 매칭/PoseMatch의 검색 정책은 변경하지 않는다.

## 요구

사용자는 도형 개수 제한 제거, 32K 영상의 CPU 전용 및 GPU 사용 검사, 정확도 우선 최적화를 요청했다. 이어 원 안의 원·사각형 안의 사각형과 도넛을 추가하도록 요청했다.

## 결정

1. `MaximumResults=0`을 전체 결과의 기본값으로 쓴다. 양수의 명시적 출력 상한은 유지하고 초과하면 불완전으로 보고한다. 기존 1,000개 설정 상한과 내부 4,096개 윤곽 절단을 제거한다. 실제 가능한 개수는 메모리와 실행 시간의 제약을 받는다.
2. 기존 원본 2 Mpx 창, 최대 도형 폭+4px 여백, 중심 소유권, 창별 Otsu/수동 이진화와 명암 방향을 유지한다. reader는 한 작업자가 소유하고 최대 네 창을 병렬 계산한 뒤 원래 순서로 합친다. 원본 버퍼를 재사용하고 OpenCV 입력의 불필요한 복사를 제거한다. 표시 LOD나 축소 입력을 쓰지 않는다.
3. CUDA는 선택형 `IPrimitivePreprocessor`로 주입한다. 기존 ILGPU로 CPU와 같은 정수 3×3 median 및 복제 경계를 수행한다. 이진화·윤곽·분류는 공통 CPU 경로다. 검사 하나가 장치·버퍼를 소유하고 병렬 호출은 장치 내부에서 직렬화한다. 준비·전송·계산·수신을 구분하며 GPU 사용 불가를 CPU 성공으로 대체하지 않는다.
4. CComp의 외곽과 직접 자식 구멍을 보존한다. 원형 외곽+원형 구멍 한 개는 `Ring`, 사각 외곽+사각 구멍 한 개는 `RectangleFrame`이다. 구멍 안에 떨어져 있는 전경은 독립 도형이다. 빈 구멍은 검출 개수에 넣지 않는다. 여러 구멍·다른 종류의 구멍·해석 불가능한 구멍은 해당 외곽의 지원 도형 분류를 거부한다.
5. 반환 중심·각도는 바깥 도형 기준, 면적은 바깥 윤곽 면적-구멍 윤곽 면적이다. `InnerContours`를 원본 좌표로 보존하고 Canvas의 알고리즘 중립 표시 계약과 CLI JSON에 전달한다. 안팎 윤곽은 각각 닫힌 선으로 그리며 서로 연결하지 않는다. 동심도·동일 두께·안팎 각도 일치의 제품 판정은 추가하지 않는다.
6. 마스크가 실제 물체 또는 median이 참조하는 경계 여백과 겹치면 그 도형을 제외한다. 구멍 깊숙한 곳의 마스크는 바깥 테두리를 제외하지 않으며 내부의 독립 도형에는 별도로 적용한다.
7. 픽셀 계단으로 누락되던 회전 십자가/사각형은 원본 변의 직선 맞춤을 사용한다. 모서리가 분할된 사각형은 네 긴 변·기존 직각/면적 기준·전체 경계 거리 2px를 모두 확인한다. 원의 반경은 압축된 꼭짓점만 보지 않고 각 변을 균일 표본화한다. 십자가 각도는 원본 면적의 4차 모멘트로 구한다. 기존 최소 점수 .8, 크기 6~512px와 면적/직각/원형성 기준을 낮추지 않는다.
8. 결과 객체와 표시 윤곽은 전부 유지하되 오른쪽 결과 문구는 256개씩 표시한다. 페이지 이동은 재검사를 하지 않는다. 옵션/입력 변경·취소·실패는 기존 늦은 결과 거부를 유지한다.

## 대안과 제약

- 원본을 작은 영상으로 축소하거나 후보/결과를 잘라 속도를 맞추는 방법은 누락 위험 때문에 사용하지 않았다.
- 모든 윤곽을 독립 검출로 세면 도넛 구멍이 중복 집계되므로 외곽/구멍 계층을 사용한다. 외곽만 검색하면 내부 독립 도형을 놓치므로 CComp의 두 단계 구성을 유지한다.
- 현 장비의 CUDA median은 전송 비용 때문에 합성 32K에서 CPU보다 느리다. 기본값은 CPU이며 GPU 실가속 달성으로 표현하지 않는다.
- 32×22px 작은 사각형은 이진화/median 후 미세 각도가 소실되어 최대 2° 오차가 관측됐다. 면적 2차 모멘트 실험은 큰 도형의 각도까지 악화해 원복했다. 전수 개수와 정밀 각도 합격을 구별한다.
- 원본 전체를 정답으로 라벨링하지 않은 `ken32.png`의 도형 개수를 현장 검출률로 표현하지 않는다. 서비스 시간은 실제 버튼→표시/카메라 FPS가 아니다.

검증·실측·재현 명령은 [32K 검증 기록](../primitive-detection-32k.md)에 둔다. CComp 계층의 근거는 [OpenCV 공식 문서](https://docs.opencv.org/4.13.0/d9/d8b/tutorial_py_contours_hierarchy.html)다.

## PCB fiducial 후속

사용자가 참고 그림을 제공하고 #·마름모·더블스퀘어·별을 요청했다. 공통 분류기에 기하 검증을 추가하며 정사각형은 기존 사각형 이름을 우선한다. 더블스퀘어는 대각선 두 정사각형으로, 떨어진 조각을 `AdditionalContours`에 보존한다. 접촉한 경우 원본의 단일 윤곽을 유지한다. 점수·크기·원본 창·CPU/CUDA 정책은 그대로 두고 [PCB 검증과 한계](../pcb-fiducial-detection.md)를 따른다. 일반 패드와 fiducial의 의미 구별이나 모든 제조사/촬영 조건의 인식 보장은 추가하지 않는다.

## 생성 시간 분리·학습하기 쉬운 최적화 후속

사용자는 합성 생성 시간을 제외해 먼저 측정하고 정확도를 유지한 CPU/CUDA 개선을 요청했다. 외부 평가 도구에서 원본을 미리 만들고, 서비스에 읽기/초기화를 제외한 실제 검출 경과 시간을 추가한다. 병렬 창의 누적 시간과 혼동하지 않는다. 기하 표본·거리 함수·기준·수치 누적 순서는 유지하며 이전 일치 변 우선 검사와 획별 회전 계산 재사용만 적용한다. CUDA는 동기 전송 계약을 확인해 연속 입력의 복사와 중복 대기를 제거한다. 결과 캐시·전역 설정·새 전략 인터페이스는 추가하지 않는다. 느린 pinned host 버퍼 실험은 원복했다. [실측·전수 동일성·단계별 코드 안내](../primitive-detection-performance.md)를 따른다.

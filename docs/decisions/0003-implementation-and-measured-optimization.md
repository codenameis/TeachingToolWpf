# ADR-003: 구현 경계와 측정에 따른 최적화

2026-10-02 · 적용됨. 사용자 요청의 클린 코드/SOLID/GRASP 예외는 없으며 사전 승인 절차를 유지한다.

## DX12 및 책임 분리

Vortice 3.8.3, DXGI flip discard, 2개 back buffer, direct queue 1개와 HwndHost를 사용한다. RTX 3060에서 실제 실행/입력/debug layer를 확인했다. Windows 전용 WPF라는 요구에 맞춘 선택이며 Vulkan과 속도 비교한 결과는 아니다. Core는 WPF/DX12/NetVips 참조가 없다.

`RenderWorker`는 스냅샷 소비와 실행 순서를 담당한다. 장치/표시, texture 수명, 업로드 arena, mesh, label, timestamp를 별도 클래스로 분리했다. UI 입력/명령은 `EditorSession`을 거쳐 `DocumentEdit`의 sparse before/after 기록으로 확정한다. 프레임·타일 포트와 텍스트/프레임 준비 어댑터는 실제 변형 지점이다.

## ROI 저장과 이력

초안의 부모 local 좌표 저장 대신 이미지 좌표의 중심·크기·각도와 ParentId를 기준값으로 둔다. 재부모화는 기하를 변경하지 않고, 부모 이동·회전은 유효 선택 루트의 subtree에 한 번 적용한다. 반복 재부모화에서 좌표 변환 오차를 줄이고 Undo로 정확한 값을 복구하기 위한 선택이다. 포함 판정은 부모 로컬에 변환한 자식 4개 꼭짓점으로 한다. BVH는 후보만 거르며 정확한 최종 판정을 대체하지 않는다.

부모 resize는 자식 크기와 부모 기준 상대 위치를 유지한다. 핸들 반대점을 고정하여 부모 중심이 이동하면 자식도 같은 변위를 받는다. 자동화 테스트와 속성 패널 경로를 이 계약으로 일치시켰다. 드래그 중에는 기존 관계, 확정 후에는 최소 포함 부모를 적용한다.

명령당 전체 이미지를 복사하지 않는다. 삭제/그룹/수치 편집도 동일한 이력을 사용한다. 현재는 자동 저장/레시피 직렬화를 제공하지 않는다. 라이브는 문서 이미지 위의 미리보기이며 시작/정지는 편집 이력이 아니다. 정지 후 마지막 원본 lease는 zoom 및 렌더러 재연결을 위해 유지한다.

## 파일 읽기와 텍스트

WIC 단일 비트맵 대신 NetVips 3.2.0 / native 8.18.6을 사용한다. 최초 순차 변환 후 디스크 `.v` 피라미드에서 512px 영역만 CPU로 가져온다. manifest는 마지막에 쓰고 staging 디렉터리를 이동한다. Windows에서 네이티브 연산 캐시가 해제된 `.v` 파일 매핑을 계속 잡아 staging 이동을 막는 문제를 재현하여 연산 캐시를 껐다. 디스크 캐시와 GPU LRU가 재사용을 담당한다. 원본 경로·크기·수정 시각을 버전으로 삼으며 내용 전체 해시 보장은 아니다.

텍스트는 `ITextRasterizer`를 통해 렌더 STA가 독립 WPF FormattedText를 만들고 GPU label texture로 캐시한다. UI Visual을 렌더 스레드가 읽지 않는다. 직접 DirectWrite glyph atlas는 지금 필요한 수준보다 구현/검증 비용이 커 채택하지 않았다. 동일 텍스트/DPI를 매 프레임 래스터화하지 않으며 256개 태그 표시 제한과 충돌 억제를 둔다. 네이티브 라이선스 고지는 배포에 포함한다.

## 실측 후 최적화

1. 렌더 이벤트가 겹쳐도 동일 스냅샷/프레임/타일이면 다시 그리지 않는다. 정지 시 event를 기다린다.
2. 업로드 버퍼는 back buffer별로 재사용하고 fence 완료 후 reset한다. row pitch가 같으면 한 번에 복사한다.
3. 8K 전체 RGBA 업로드에서 GPU 작업이 약 20ms까지 걸리는 것을 측정했다. 가시 영역과 현재 배율에 맞춘 파생 프레임만 업로드하되 CPU의 전체 원본은 유지한다.
4. NetVips로 매 라이브 프레임을 줄이는 시험은 CPU 병목이 커 채택하지 않았다. `BoxResampler`의 AVX2 및 scalar area averaging으로 교체했다. 4개 픽셀 형식, 1/2/4/8/16 배율, 홀수 크기/경계에서 두 경로의 바이트 동등성을 검증한다.
5. 계층의 모든 쌍 검사를 BVH 후보 검색으로 바꿨다. 무작위 회전 ROI 테스트로 brute force와 같은 결과임을 검증한다. 현재 렌더 culling/hit test는 전체 순회이므로 BVH 렌더 가속까지 구현했다고 표현하지 않는다.

최적화는 책임 경계 안에 두었으며 Undo/Redo, 원본 픽셀, 포함 규칙 또는 설계 원칙을 제거하지 않았다. 결과·조건·미달/미검증 목표는 [성능 기록](../performance-baseline.md)을 따른다.

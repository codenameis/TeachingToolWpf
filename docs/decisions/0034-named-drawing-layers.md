# ADR-034: 이름 있는 표시 레이어와 임시 마우스 영역

- 날짜: 2026-10-06
- 상태: 사용자 구현 승인, 검증 결과는 [기록](../drawing-layers-validation.md)을 따른다.
- 후속: 앱의 크로스헤어 중심/범위와 표시 설정은 [ADR-035](0035-configuration-and-image-crosshair.md)로 구체화했다. 레이어 API 계약은 유지한다.

## 요구와 결정

사용자는 검사 결과를 이름 있는 레이어에 Add/Remove(id)/Clear하고, FPS 게임처럼 화면 중앙에 고정된 가이드도 독립적으로 관리하기를 요청했다. ROI 생성·다중 선택 중 마우스로 지정한 영역만 반투명하게 채운다.

`Dx12Viewport.Layers`가 생성 순서의 레이어와 ID를 소유한다. Image 좌표와 Screen DIP 좌표를 생성 시 고정하고 불변 그래픽 DTO를 받는다. 레이어 이름·내용은 ROI 문서에 들어가지 않는다. 기존 `RenderScene.Inspection`은 기본 `Inspection` 레이어로 연결하여 외부 호스트와 기존 검사 완료 계측을 유지한다. 단순 탐색은 지운 검사 결과를 복원하지 않고 새 결과만 교체한다.

레이어는 논리적인 표시 묶음이며 별도 전체 화면 텍스처가 아니다. 순서 있는 불변 트리와 ID 색인을 사용해 변경된 경로만 갱신한다. 도형 윤곽은 항목 생성 시 준비한다. AddRange/ReplaceAll은 검증 성공 후 한 번 게시한다. UI가 수정하고 렌더 스레드가 불변 스냅샷을 읽는 기존 경계를 유지한다.

드래그 영역은 `InteractionOverlay.DragArea`의 화면 DIP 사각형이다. 실제 ROI 윤곽·포함 판정·선택 판정에 대신 사용하지 않는다. 하나의 반투명 quad를 그리며 확정/취소 시 소멸한다. 폴리곤 점 입력과 완성된 ROI 내부는 이번 범위가 아니다.

## 범위와 대안

공개 타입은 Line/Shape/Text/Crosshair/기존 ResultOverlay 묶음이다. 사용자 렌더 콜백·플러그인·독립 swap chain·WPF 반투명 오버레이는 도입하지 않는다. 기존 성능용 ROI 캐시·페이지·배치·이력은 유지한다. 사용자 레이어는 hit test나 Undo에 참여하지 않는다. 레이어 자체 삭제·임의 z-index·외부 UI용 편집 도구는 추가하지 않는다.

검사 서비스가 직접 Canvas를 참조하지 않는다. 판정과 버전/오래된 결과 거부는 호스트가 계속 소유한다. 자동 이미지 교체 정리는 호스트 정책이며, 기본 검사 경로의 무효화는 그대로 유지한다. 성능을 위한 설계 원칙 예외는 없다.

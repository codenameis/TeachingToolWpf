# ADR-001: 설계 원칙 준수와 필수 편집 이력

## 상태

사용자 확정 요구사항은 수용됨. 2026-10-02 구현 및 테스트를 진행했고 구체적인 경계는 [ADR-003](0003-implementation-and-measured-optimization.md), 수치는 [성능 기록](../performance-baseline.md)을 따른다. 설계 원칙 예외 승인은 없고 예외를 적용하지 않았다.

## 날짜

2026-10-01

## 배경

최소 8K 실시간 영상과 24K급 완성 이미지를 다루는 WPF 티칭 툴에는 GPU 성능과 편집 상태의 정확성이 함께 필요하다. 사용자는 클린 코드, 디자인 패턴, SOLID, GRASP를 모두 준수하고 성능상 불가피한 원칙 예외는 먼저 사람에게 질문할 것을 요구했다. Undo/Redo는 필수이며 부모 ROI 삭제는 모든 자손 삭제를 포함한다.

## 결정

1. 설계 원칙을 모든 기능·리팩터링의 검토 기준으로 삼는다. 구체적인 SOLID 5개·GRASP 9개 책임 기준은 [AGENTS.md](../../AGENTS.md#필수-설계-원칙과-성능-예외-절차)에 둔다. 실제 문제에 적합한 패턴을 사용하며 형식적인 패턴 남용은 피한다.
2. 성능 문제는 기준 장비인 Ryzen 5 5600H / RAM 32 GB / RTX 3060 Laptop 6 GB에서 재현·측정한다. 원칙을 지키는 대안을 우선한다.
3. 원칙의 불가피한 예외를 제안할 때는 측정 조건/수치, 대상 원칙·경계, 대안과 한계, 최소 예외 범위, 예상 이득·위험, 검증·복원 방법을 사용자에게 제시한다. 명시적 승인 전에는 해당 변경을 적용하지 않는다. 침묵을 승인으로 간주하지 않는다.
4. 첫 ROI 편집 이전에 Command/Memento 기반 이력을 마련하고 모든 편집 경로를 연결한다. Undo/Redo는 선택 기능이나 성능에 따라 제거할 기능이 아니다.
5. 부모 삭제는 확정된 하위 트리를 중복 없이 한 번에 삭제한다. 하나의 Undo로 원래 ID·형상·이름·계층·순서·선택을 복원하고 Redo로 같은 집합을 다시 삭제한다. 단순 겹침 관계의 타 ROI는 포함하지 않는다.
6. 이력은 복원에 필요한 값과 소스 참조를 보관한다. 원본 이미지·GPU 객체를 명령마다 복제하지 않는다. 취소·실패·no-op는 문서 및 이력 위치를 유지한다.

## 검토한 대안

- 성능을 우선해 에이전트가 임의로 원칙을 완화: 사용자의 사전 질문 요구와 맞지 않아 채택하지 않는다.
- 모든 디자인 패턴을 일괄 도입: 책임과 무관한 복잡성이 생기므로 문제에 적합한 패턴과 명시적인 적용 이유를 사용한다.
- Undo/Redo를 마지막에 부착: 편집 경로가 이력을 우회하기 쉬우므로 기반을 먼저 만든다.
- 부모만 삭제하고 자손 보존: 이전 초안의 동작이며, 부모와 자손을 함께 삭제하라는 사용자 확정 요구로 교체한다.
- 매 명령마다 전체 문서와 원본 이미지 복제: 대용량 입력에 불필요한 메모리/복사 비용이 생기므로 영향받은 상태의 전후 기록을 사용한다.

## 결과와 검증

- 첫 ROI 편집 앞에 이력 기반 T04A를 둔다. 이후 추가 요구를 포함한 최신 작업 수와 검사 항목은 [todo.md](../../tasks/todo.md)를 따른다.
- 사용자 제공 하드웨어를 기준으로 성능을 측정하며 실제 선택 adapter와 노트북 전원/열 조건을 기록한다.
- 일반 이미지 파일 열기와 대용량 타일링을 구현한다. RAW는 시험 데이터로 사용할 수 있지만 카메라 라인 수집·조립은 이번 범위가 아니다.
- 관계 복원, 다중 명령 원자성, 새 명령 뒤 Redo 제거, 이력 예산 경계 및 소스 재개방 실패를 검증한다.
- 승인된 예외가 생기면 새 ADR에 사용자 결정·범위·근거·검증·복원 방식을 기록하고 이 문서와 지침에서 연결한다. 현재 예외 승인 기록은 없다.
- 2026-10-03 도형 확장은 [ADR-012](0012-roi-shapes.md)에 공통 기하·Strategy·이력 보존과 SOLID 5개/GRASP 9개 검토를 기록했다. 원칙 예외는 적용하지 않았다.

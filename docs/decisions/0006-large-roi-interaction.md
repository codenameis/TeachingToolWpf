# ADR-006 — 대량 PCB ROI의 검색·표시·편집 비용 분리

상태: 2026-10-02 적용. 설계 원칙의 예외 없음. 실측은 [ROI 성능 보고서](../roi-scalability.md).

## 문제와 결정

1,550–3,550 ROI에서 클릭만 해도 전체 계층·목록·이력 비교가 실행되었다. 백만 ROI 시험에서는 WPF `SetSelectedItems`의 항목 위치 확인이 전체 목록을 순회했다. 속성 TextBox의 반복 갱신에는 별도로 TSF 입력 서비스 대기가 관찰되었다. CPU 전체 사용률만으로 GPU 부족이라고 판단할 수 없었다.

- 선택과 뷰 변경은 ROI 스냅샷의 BVH·자식 색인을 공유한다. 기하 편집은 변경 ID와 BVH 경로만 복사하고, 대량 편집은 한 번에 색인을 재구축한다. 이름·필터·부모 메타데이터는 현재 값 맵으로 조회하며 이전 스냅샷을 변조하지 않는다.
- 계층은 변경 ROI, 기존 직접 자식, 새 영역과 겹치는 후보만 재평가한다. 정확한 회전 사각형 포함 판정과 최소 부모·ID 동률 규칙은 유지한다. Undo/Redo는 기록된 값으로 복원하며 재판정하지 않는다.
- 지연 색인은 이전 `Lazy` 팩터리를 재귀적으로 붙잡지 않는다. 이전 값을 먼저 평가하고 구조를 공유한다. 캐시 채움은 문서 동등성·해시를 변경하지 않는다.
- 포인터·마퀴·렌더링 모두 BVH 후보 검색을 사용한다. 화면에서 한 변 6 DIP 이하인 BVH 집합은 요약 영역으로 그리며 안내를 표시한다. 확대하면 개별 윤곽으로 전환하고 단일 선택 ROI는 항상 정확한 윤곽·핸들을 그린다. 원본 ROI 데이터, 포함·선택 판정은 간소화하지 않는다. 라벨은 겹침을 제거하고 화면당 최대 256개다.
- 왼쪽 목록은 4,096개까지 단일 가상화 목록, 그 이상은 512개 페이지로 표시한다. 하나를 새로 선택하면 해당 페이지로 이동하고, pan/zoom은 사용자가 고른 페이지를 보존한다. 페이지 이동은 선택을 바꾸지 않는다. Ctrl 추가 선택은 다른 페이지의 선택을 보존하고 일반 클릭은 전체 선택을 교체한다. 목록 메타데이터 캐시는 UI 스레드만 소유하며 렌더에 전달하지 않는다.
- 속성 필드는 비활성 상태에서 `TextBlock`으로 값을 표시하고 포커스 진입 시 표준 `TextBox`에 편집값을 연결한다. 입력·한글·숫자·접근성 Value 패턴·공통 편집 명령은 유지한다. 입력기 비활성화나 전역 GC 강제 호출은 사용하지 않는다.
- 이력 추정치는 명령 생성 시 한 번 계산한다. 기본 상한을 200개/1 GiB로 조정해 백만 단위 삭제·이미지 교체를 취소할 공간을 확보한다. 선할당이 아니며 오래된 완전한 명령부터 제거한다. 한 명령이 상한을 넘으면 변경 전에 거부하고 기존 상태/Redo를 보존한다. 원본 이미지·GPU 객체를 이력에 복사하지 않는다.

## 대안과 검증

스레드 수 증가와 Vulkan 전환은 현재 병목의 해결 근거가 없어 적용하지 않았다. WPF 라벨을 GDI로 바꾸는 실험과 비활성 TextBox의 IME 플래그 변경은 동일 조건에서 긴 지연을 줄이지 못해 되돌렸다. WPF 라벨 어댑터는 그대로다.

회전 포함 판정의 전수 비교, 원본 BVH 경계를 벗어난 이동, 이전 스냅샷 보존, 이름 갱신, 2,000회 Undo/Redo 및 지연 색인의 수명 테스트를 추가했다. 첫 변이 실험에서 기존 테스트가 큰 이동을 놓쳐 해당 테스트를 보강했고, 조건 반전이 실패하는 것을 확인한 뒤 소스를 복원했다. 페이지 밖 선택의 잘못된 삭제 위험과 pan의 페이지 되돌림은 별도 검토에서 발견하여 수정하고 실제 WPF smoke에 포함했다.

초기 구축·대량 선택·전체 삭제/복원·깊거나 과도하게 겹친 계층은 일반 단일 ROI 편집과 별도 비용이다. 수백만 개의 모든 작업이 한 프레임 안에 끝난다는 보장은 하지 않는다.

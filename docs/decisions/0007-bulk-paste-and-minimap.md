# ADR-007 · 대량 붙여넣기와 미니맵

- 상태: 적용, 2026-10-02
- 요구: 약 7,000개 복제 후 화면 정지 수정. 300개를 전체 선택·복제해 두 배씩 늘리는 경로 검증. 전체 이미지와 현재 위치를 표시하고 클릭/드래그로 이동하는 미니맵.
- 기존 기준: [ADR-001](0001-quality-and-edit-history.md), [ADR-005](0005-filter-registration-and-roi-copy.md). 원칙 예외는 없다.

## 대량 붙여넣기

많이 겹친 ROI를 붙여넣을 때 변경 ROI마다 교차하는 자식 후보를 다시 열거하던 비용을 줄인다. 변경이 64개를 넘고 전체의 1/8을 넘으면 전체 ROI에 대해 부모 후보를 한 번씩 평가한다. 최종 판정은 기존 회전 사각형의 완전 포함과 최소 면적 규칙이다. 동일 크기 중첩을 부모 관계로 바꾸지 않는다.

복사 집합이 256개를 넘으면 UI에서 불변 문서·복사 값·순서를 확보하고 `RoiPaste`가 작업 스레드에서 새 ID와 계층을 준비한다. 결과는 UI로 돌아와 문서·이미지·순서가 그대로인지 검사한 후 한 명령으로 확정한다. 준비 중 변경된 pan/zoom은 보존한다. 오래된 결과·취소·실패는 문서와 이력을 바꾸지 않는다. UI는 진행 상태와 Esc 취소를 제공하고 편집 명령의 중복 실행을 막는다. 취소는 협력적이며 진행 중 계층 계산이 반환된 뒤 적용될 수 있다.

이력 생성·UI 갱신은 여전히 UI 스레드에서 수행하므로 전체 명령에 0ms 지연을 보장하지 않는다. 복사·전체 선택·백만 단위 일괄 명령의 남은 비용은 별도로 보고한다. GPU/CUDA로 기하 계산을 옮긴 변경이 아니다.

## 필터 미리보기 GPU 수명

ROI마다 텍스처 descriptor를 만들던 구현은 수천 개 필터 결과에서 공유 슬롯 2,048개를 소진해 렌더 스레드를 종료시켰다. Gray8 결과를 최대 2,048×2,048 페이지로 묶고 각 ROI는 페이지와 UV를 참조한다. 패킹 순서와 그리기 순서를 분리해 겹친 ROI의 기존 표시 순서를 보존한다. 페이지의 단일 소유자는 `GpuFilterPreview`이며 교체 시 fence 이후 해제한다. ROI 개수나 필터 결과를 임의 생략하지 않는다. 기존 ROI당 1,024px·전체 약 4Mpx 미리보기 예산은 유지한다.

## 미니맵

Core의 `MinimapLayout`을 GPU 표시와 입력에서 공유한다. 우하단 패널에서 원본 종횡비를 유지한 전체 이미지와 현재 가시 영역을 표시한다. 클릭은 해당 위치로 중심을 이동하고, 현재 영역을 잡아 드래그하면 잡은 위치를 유지한다. 이미지 경계에서 이동을 제한하고 배율·ROI·선택·이력을 보존한다. Esc/캡처 상실/창 크기 변경은 진행 중 이동을 취소한다. 패널에서 시작한 입력이 뒤쪽 ROI를 생성·편집하지 않도록 우선 처리한다.

미니맵은 기존 DX12 표면에 마지막으로 그린다. WPF 오버레이를 사용하지 않는다. 정적 이미지는 기존 최저 해상도 타일을 공유한다. 라이브는 기존 프레임 준비기를 이용한 전체 화면 축소본을 최대 초당 2회 갱신하고 렌더 소유의 재사용 텍스처 두 개를 사용한다. 원본 채널 수를 보존한다. ROI 필터와 선택 장식은 미니맵 원본을 가리지 않는다. 뷰포트가 320×240 DIP보다 작으면 패널을 숨긴다.

진단 캡처에는 제출 버전을 기록해 요청보다 오래된 장면을 저장하지 않게 한다. 이미지 개요가 준비되어야 저장한다. 타일 실패/첫 프레임 미도착은 호출측 timeout으로 진단한다.

## 검증

[실측·검증 기록](../clipboard-minimap-validation.md)에 고정 입력, 반복 복제 경로, 실제 RTX/DX12 검사, 미니맵 회귀와 남은 제약을 기록한다. 성능 목표를 실측 결과로 대체하지 않는다.

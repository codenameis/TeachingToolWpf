# ADR-037: ROI 확대 상세화의 프레임별 준비

- 날짜: 2026-10-06
- 상태: 구현, 성능 수용 여부는 [검증 기록](../group-cold-validation.md) 참조

## 근거

20만 ROI를 그룹화한 뒤 첫 확대에서 렌더 제출183.91ms 중 패킹176.84ms가 발생했다. 해당 프레임의 GC 정지 누계 증분은0ms였다. 반복 탐색이 빨라지는 현상은 확대 단계별 GPU 표시 캐시가 준비되는 과정과 일치한다. Undo/Redo에서는 계층 역할 재계산도121.51/178.02ms의 렌더 제출에 영향을 줬다.

## 결정

- `RoiPipeline`은 한 프레임의 새 LOD 준비에4ms를 배정한다. 중간에 단일 블록 처리를 끊지 않으므로 **프레임 시간의 상한 보장은 아니다**. 한 프레임에 최소 한 블록은 진행한다.
- 예산을 쓰면 **같은 불변 공간 블록 identity**의 기존 LOD를 현재 viewport와 rigid preview 변환으로 그린다. 다른 형상/문서의 블록을 대신 사용하지 않는다. 준비된 블록부터 요청 LOD로 교체한다. 최초 표시처럼 기존 블록이 없으면 기존 동기 경로로 모든 형상을 준비한다.
- 상세화 중에는 확대된 요약 윤곽이 잠시 보일 수 있다. CPU hit/도메인 형상/선택/검사 입력/Undo 데이터는 바꾸지 않는다. 캐시가 준비되면 기존 알고리즘과 동일한 LOD를 사용한다. 이미지 타일이나 검사 해상도를 낮추지 않는다.
- 보류된 상세화는 렌더 요청을 다시 발생시킨다. 포인터가 멈춰도 완료하며, 대기가 끝나면 정적 프레임 생략을 재개한다. 캡처와 검사 결과 표시 완료 신호는 상세화가 끝난 프레임까지 기다린다.
- 직전 LOD 별칭은 기존 GPU 블록만 가리킨다. 퇴출 시 별칭을 제거/교체하고 기존 fence 이후 해제 규칙을 유지한다. 원본 중복 복사는 추가하지 않는다.
- 렌더 스레드의 `RoiRoleLookup`은 계층에서 ID→역할만 만든다. 필요할 때만 갱신하며 확대 단계마다 불변 문서 트리를 반복 조회하지 않는다. 중첩 부모 우선순위는 기존 규칙과 같다.
- 각 GPU 블록은 현재/직전 역할 배열 두 벌까지만 보관해 Undo/Redo에 재사용한다. 계층 키는 약한 참조이므로 옛 문서를 붙잡지 않는다. 역할 조회 용량과 두 배열의 보수적 비용을 기존 캐시 예산에 포함한다.
- 검색 경계의 Spatial/Moving/Stationary 지연 색인은 기존 편집·preview worker에서 준비한다. 준비 완료 판정에 검색 색인도 포함한다. 취소는 작업 경계에서 확인하며 공유 Lazy에 취소 token/예외를 저장하지 않는다.

## 설계 검토

원칙 예외와 새 라이브러리 의존성은 없다. 기존 불변 스냅샷·GPU 캐시·Command/Memento·Observer 흐름을 유지한다.

| 원칙 | 확인 |
|---|---|
| SRP | Core는 검색 색인 준비, Canvas는 표시 LOD/역할/GPU 수명만 담당한다. |
| OCP | 도형별 패킹·검사 공급자 계약을 변경하지 않는다. |
| LSP | GPU/WARP에 같은 데이터와 완료 조건을 사용한다. 성능을 같다고 보장하지 않는다. |
| ISP | 공개 Canvas/영상/검사 API에 설정이나 준비 메서드를 추가하지 않는다. |
| DIP | Core에 Canvas/WPF/GPU 참조를 추가하지 않는다. |
| Information Expert | BVH는 불변 블록을 제공하고 렌더 캐시가 LOD 준비·재사용을 결정한다. |
| Creator | GPU 페이지 생성·fence 해제는 기존 소유자에 둔다. |
| Controller | UI 편집 명령과 원자적 게시/취소 경로를 유지한다. |
| Low Coupling | 불변 identity와 작은 역할 값만 공유하고 worker에 GPU 객체를 넘기지 않는다. |
| High Cohesion | 역할 조회만 작은 내부 타입으로 분리하고 범용 작업 큐/프레임워크를 만들지 않는다. |
| Polymorphism | 신규 변형 지점이 없어 새 인터페이스가 필요하지 않다. 기존 도형 처리를 보존한다. |
| Pure Fabrication | 렌더 캐시와 기존 편집 준비 서비스가 기술 책임을 소유한다. |
| Indirection | 앱은 기존 준비/제출 경계로 연결되고 renderer 내부 캐시를 조작하지 않는다. |
| Protected Variations | double 도메인 형상과 GPU float 표시 경계를 유지한다. |

## 한계와 복원

처음 등장한 형상 블록, 큰 단일 폴리곤 블록, 계층의 첫 역할 표 작성, GC와 UI 게시 비용은4ms로 제한되지 않는다. 모든 조작의60FPS 보장이 아니라 확인된 연속 확대 준비 정지의 완화다. GPU 완료와 실제 모니터 표시 지연을 CPU 제출 시간으로 대신하지 않는다.

되돌릴 때는 이번 상세화/역할 캐시와 준비 완료 조건만 한 묶음으로 복원한다. ADR-036의 검색 ROI·그룹 이름 기능이나 이전 GPU 페이지 배치 최적화를 제거하지 않는다. 작업 시작 시 기존 변경은 `artifacts/group-cold-20261006/preexisting.patch`에 별도 보관했다.

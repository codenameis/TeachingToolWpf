# ADR-064: 검색 ROI 자동 지정과 크기 제한 없는 CPU 입력

상태: 구현, 로컬 검증. 2026-10-16. 사용자는 패턴 매칭의 검색 ROI 자동 지정과 전체 이미지 선택 시 크기 제한 해제를 요청했다. 추가 커밋·푸시는 하지 않는다.

## 결정

- 여섯 패턴 모드 모두 ROI 검색을 기본으로 한다. 모드별로 사용자가 선택한 전체 검색은 유지한다.
- 학습이 성공하면 앱의 문서 소유자가 해당 리프 ROI의 검색 여유를 확인한다. 없는 경우에만 가로·세로 양쪽20px를 기존 `SetProperties` 명령으로 지정한다. 기존 값·학습 형상·마스크는 유지한다. 실패·취소·늦은 학습 결과는 문서를 바꾸지 않는다. 변경은 Undo/Redo 한 건이다.
- 검색 여유가 이미지 밖으로 나가면 원본과 겹치는 부분을 검사한다. 실제 ROI 포함 판정은 유지하며 학습 ROI의 원본 경계 검증은 완화하지 않는다.
- CPU 세 방식의 서비스는67,108,864픽셀 이하에서 기존 연속 버퍼 경로를 유지한다. 초과하면 `IGrayImageSource`와 `FindWindowed`를 사용한다. 전체 영상의 `GrayImage` 생성과 영상 크기를 이유로 한 거부를 없앤다. 개별 읽기·맵 메모리 예산은 유지한다.
- 축소 피라미드는 검색 원점 기준의 반복2×2 평균과 단계별 반올림을 유지한다. 고정 배치/이전 영상/예상 위치를 사용하지 않는다.
- 축소 단계의 모든 각도·배율·위치를 작은 창으로 순회한다. 템플릿 반경·최대32px 거리 전파·미분/봉우리 이웃 여백을 읽고 창 내부 후보만 수집한다. angle/scale/y/x 순서로 후보 묶음을 넘긴다. 창별 최종 NMS나 결과 제한은 하지 않는다.
- 후보 원본 보정과 검증은 기존 공통 단계를 사용한다. 마지막 전역 NMS 이후에만 기존 `MaximumMatches`를 적용하고 초과 여부를 알린다. 점수·표본·후보 묶음 크기와 검색 각도/배율은 변경하지 않는다.
- 읽기는 reader 잠금 아래 직렬화한다. 병렬 계산과 선택형 CUDA 격자 계산을 유지하고 취소 시 부분 결과를 성공으로 반환하지 않는다. `ReadMilliseconds`는 창 읽기를 합산하고 `SearchMilliseconds`에서 제외한다. 단계별 시간은 그 단계에서 발생한 읽기를 포함한다.

## 비용과 한계

창 여백 점수 계산과 맵 재생성 때문에 연속 경로보다 평가 횟수와 시간이 늘 수 있다. 후보·원본 검증 결과 전체가 대량으로 발생하면 결과 메모리와 시간도 증가한다. 영상 크기 상한 해제는 무한 메모리, 일정 시간 완료,125/80ms 달성을 뜻하지 않는다.

OpenCV·논문 형상·PoseMatch는 기존 창 검색 경로를 유지한다. 각 방식의 학습 조건·마스크 지원·결과/후보/작업 예산은 그대로이며, 기존 불완전 검사 경고를 숨기지 않는다. 특히 PoseMatch의 최대 창 수는 사용자 작업 예산이다.

## 검증

[검증 기록](../cpu-matching-windowed-input.md)에 경계·축소 위상·큰 논리 영상·원본 읽기·CUDA·문서 이력 및 실제 ken32 실행 범위를 구분한다. 작은 합성 검증이나 알려진 자기 위치 한 곳을 ken32 전체 정답으로 표현하지 않는다.

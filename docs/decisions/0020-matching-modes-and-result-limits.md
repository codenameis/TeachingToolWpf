# ADR-020 — 매칭 방식별 모델·설정과 OpenCV 출력 제한

- 날짜: 2026-10-04
- 상태: 구현 및 자동/실제 DX12 통합 검증 완료
- 사용자 요청: 남겨둔 OpenCV 일부 검출 현상 확인, OpenCV/논문 기반/자체 기하 방식 분리, 사용자 파라미터 확대.

## 재현과 원인

실행 중인 사용자 앱을 직접 확인했다. 8192×8192 기본 검사 이미지에서 핀 하나를 학습했고 모델 crop은 107×130이었다. 최소 점수 .72, 최대 결과 수 16, 전체 이미지 검색이었다. 16개 결과와 16개 검색 창을 처리한 뒤 `OK · 정상`이 표시되었다.

동일 모델에서 최대 결과 수만 1000으로 올리자 **256개**를 검출했다. 검사 10,169.4ms, 읽기 933.9ms, 검색 창 16개였다. 기존 16개 결과는 8,115.3ms였다. 둘 다 사용자 앱의 단일 실행이며 속도 개선 비교가 아니다. 학습 ROI 속성 표시값은 중심 (759.518,546.178), 크기 105.827×129.459, 각도 0°였다. `artifacts/opencv-user-state`에 전후 접근성 텍스트와 실제 OS 창 스크린샷을 보관한다.

검색 창 순회는 끝까지 수행했으나, 마지막 NMS가 최대 결과 수에서 끝나 추가 결과 생략 사실을 반환하지 않았다. 동점은 Y→X 순서여서 위쪽 일부만 검색하다 중단한 것처럼 보였다. 학습 모델 한 개는 검출 개수 한 개를 의미하지 않는다.

## 결정

1. `MatchLimitExceeded`는 NMS 후 출력 상한보다 한 개 더 많은 독립 검출이 존재할 때만 true다. 정확히 상한 개수이면 경고하지 않는다. 전체 생략 개수를 추가 계산하지 않는다.
2. 후보 예산 소진의 `Truncated`와 출력 상한을 구분한다. 어느 쪽도 정상/제품 NG로 판정하지 않으며 Orange 경고와 해결 안내를 제공한다. 동시에 발생하면 두 이유를 모두 표시한다. OpenCV뿐 아니라 형상의 일반·피라미드 최종 NMS에도 적용하고, 내부 검색 창에서 생략된 결과는 검색 불완전으로 전달한다.
3. OpenCV 앱 기본 최대 결과 수는 256, 사용자 범위는 1~1000이다. 형상 방식의 기본 16개와 독립적이다. 상한을 늘려도 후보 예산이 부족하면 경고를 유지한다.
4. 앱 방식은 `OpenCV · 템플릿 매칭`, `논문 기반 · 형상 매칭`, `기하 형상 · 자체 구현` 세 가지다. 각각 학습 모델·ROI 스냅샷·학습/검색 설정을 보관한다. 방식 변경은 결과를 무효화하고 진행 중 작업을 취소한다. 현재 방식의 모델 해제는 다른 방식에 영향을 주지 않는다.
5. 논문 기반 모드는 기존 방향 응답맵 피라미드→연속 방향 검증→자세 정밀화이며 전체 기하 모델을 생성하지 않는다. 자체 기하 모드는 같은 후보 엔진에 원본 윤곽 대응비율·거리 RMS·clutter 검증을 추가한다. Cognex PatMax 소스나 SDK를 구현한 것으로 명명하지 않는다. 두 방식이 후보 검색 코드를 공유한다는 사실도 명시한다.
6. 추가 사용자 설정과 범위는 [파라미터 안내](../matching-parameters.md)를 따른다. 학습 설정 변경 시 모델은 보존하되 다시 학습하기 전까지 검사를 막는다. 서비스 자동 피라미드 값 대신 사용자가 학습한 설정 스냅샷과 비교한다. 원래 값으로 복귀하면 기존 모델을 다시 사용할 수 있다.
7. 표시 LOD, Canvas, ROI 이력, 상용 SDK 경계는 유지한다. 세션 종료 후 모델/설정 저장은 이번 변경에 포함되지 않는다.

## 검증과 품질

출력 제한 회귀는 추가 결과/정확한 상한/중복 후보/여러 검색 창을 구분한다. 모드별 학습·조건 전달·변경 취소·늦은 결과 폐기·모델 해제 및 원래 설정 복귀를 검사한다. 실제 앱 smoke는 사용자 ROI를 재현해 16개 경고→256개 정상과 16개 칩별 핀 16개를 검증한다. 최종 수치는 [todo](../../tasks/todo.md)에 기록한다.

전체 542개 테스트 및 Format Verify PASS. 재학습 차단을 제거한 변이는 관련11개 테스트가 실패했고 즉시 원복 후21개 모드 회귀를 통과했다. 실제 DX12 debug smoke는 출력 상한16의 Warning과 상한256의256개 Pass, WPF 숫자 파싱/범위 차단·값복구·모드전환, 기존 형상/기하/폴리곤/판정색을 통과했다. 수정 배포본 핀256개 검사는9,610.9ms 단일 실행이며 성능 최적화나 현장검출률 근거가 아니다.

SOLID: SRP는 NMS 진단·서비스 전달·판정·UI를 분리한다. OCP는 기존 후보 엔진을 공유하는 명시적 모드 확장이다. LSP는 취소·원본 좌표·오류 계약을 유지한다. ISP는 기존 작은 서비스 계약을 유지한다. DIP는 알고리즘이 앱/Canvas를 참조하지 않는다.

GRASP: Information Expert는 NMS가 생략 여부를 계산한다. Creator는 모드 상태가 해당 모델/설정을 소유한다. Controller는 ViewModel이 실행을 조정하고 수치 계산은 서비스에 둔다. Low Coupling은 결과 값으로 표시 경계를 유지한다. High Cohesion은 학습/검색/표시 책임을 partial과 상태 타입으로 나눈다. Polymorphism은 기존 형상/템플릿 서비스 계약을 유지하며 불필요한 공급자 체계를 만들지 않는다. Pure Fabrication은 모드 상태가 ROI 도메인의 오염을 막는다. Indirection은 앱 어댑터를 유지한다. Protected Variations는 OpenCV 타입을 공개하지 않고 원본 이미지 reader 수명을 보존한다. 원칙 예외는 없다.

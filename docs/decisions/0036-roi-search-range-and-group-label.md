# ADR-036: ROI 검색 범위와 그룹 부모 이름 표시

- 날짜: 2026-10-06
- 상태: 구현, 검증 상태는 [사용법과 검증](../roi-search-range.md) 참조

## 요청과 해석

일반 ROI를 검색 범위가 있는 ROI로 전환하고 검색 범위를 숫자로 수정한다. 검색 경계는 빨간 점선이다. 부모는 그룹만 담당하며 오른쪽 속성에서 한글 이름과 캔버스 이름 표시 여부를 지정한다.

검색 범위는 ROI 로컬 가로·세로 축의 **양쪽 여유(px)** 두 값이다. 기본값은 각각20px, 유한한0 이상의 값을 받는다. 실제 ROI는 기존 사각형·원·삼각형·폴리곤을 유지하며, 검색 경계만 중심·각도를 공유하는 확장 사각형이다. 좌우 또는 상하 비대칭 여유, 별도 검색 경계 마우스 편집은 이번 범위에 넣지 않는다.

## 결정

- 불변 `Roi.SearchRange`의 null 여부가 일반/검색 타입이다. `Roi.IsNameVisible`은 기본true다. 기존 `SetProperties` 호출은 이 값을 보존하고 확장 오버로드가 형상·이름·타입·여유·표시를 하나의 Command/Memento로 확정한다. 음수/NaN/무한대/확장 크기 오버플로는 게시 전 거부한다.
- 실제 자식이 있거나 `IsGroup`인 ROI는 그룹 부모다. 학습과 선택 영역 검사 입력에서 제외하고 검색 경계를 표시하지 않는다. 자식 없는 독립 ROI의 검사는 보존한다. 일반 ROI가 부모가 되면 기존 검색 설정은 휴면 상태로 보관하며, 마지막 자식이 없어지면 재사용한다. 그룹화로 생성한 `IsGroup` 부모는 자식이 없어도 그룹이다.
- 이름 숨김은 선택 중에도 적용한다. ROI 윤곽·선택 핸들·트리 이름·자식 표시에는 영향을 주지 않는다. 부모 표시 이름은 기존 이름 필드에서 바꾼다.
- 검색 경계는 ROI 이동·회전을 따르고 크기 변경 시 같은 픽셀 여유를 유지한다. 복사/붙여넣기(작은 이미지로 축소 포함)도 입력한 픽셀 여유를 보존한다. 검색 범위는 이미지 밖까지 표시할 수 있고 ROI 이동 제한은 기존 실제 윤곽 기준이다. 이미지 밖의 검색 요청은 기존 검사 서비스의 범위 검증을 따른다.
- 패턴 학습은 실제 ROI, ‘선택 영역 검사’는 확장 검색 경계를 사용한다. OpenCV/두 형상 방식/일반 도형에 같은 입력 규칙을 적용한다. 전체 이미지 검사와 독립 모델 보관은 유지하며 ROI에 검사 객체나 결과를 넣지 않는다.
- `RoiSnapshot.SearchSpatial`은 파생 검색 형상만의 BVH다. 검색 경계만 화면에 들어오는 경우도 표시하고 실제 ROI hit/변형 범위는 바꾸지 않는다. 변경 ID와 직접 부모를 갱신하며 메타데이터 변경은 형상 블록 identity를 보존한다. 이전 Lazy/문서의 재귀 체인을 붙잡지 않는다. 이동·회전 preview의 두 색인은 선택별로 재사용한다.
- 기존 GPU instance/배치/캐시를 사용한다.128바이트 draw 상수의 예약 슬롯 하나를 검색 패스 flag로 쓰고, HLSL에서8 DIP 선/5 DIP 공백을 만든다. 이름 밀도 제한과 미세 ROI 요약은 기존 정책을 따른다. 매 프레임 전체 ROI 복사나 CPU 대시 선분 생성을 추가하지 않는다.

## 설계 검토

성능 원칙 예외는 없다. MVVM과 기존 Command/Memento·불변 스냅샷을 확장하며 새 의존성을 추가하지 않았다.

| 원칙 | 확인 |
|---|---|
| SRP | 검색 여유는 Core 값, 입력 초안은 속성 VM, 표시는 Canvas, 검사 연결은 앱에 둔다. |
| OCP | 기존 ROI 도형과 검사 서비스 계약을 유지하고 선택 입력·GPU draw 패스를 확장한다. |
| LSP | 기존 속성 API가 새 메타데이터를 보존한다. GPU/WARP에 같은 셰이더·상수 계약을 사용한다. |
| ISP | 검사 실행 API나 영상 계약에 검색 편집 메서드를 추가하지 않는다. |
| DIP | Core/Canvas에 검사 공급자·WPF 참조를 추가하지 않는다. |
| Information Expert | 여유 확장은 RoiSearchRange, 부모 판정은 DocumentState, 공간 조회는 Snapshot/BVH에 둔다. |
| Creator | EditorSession이 검증·확정하며 기존 렌더러가 GPU 버퍼를 소유한다. |
| Controller | WPF는 VM을 통해 편집 명령을 전달한다. |
| Low Coupling | 이력에는 값만 저장하고 검사/렌더 실행 객체를 넣지 않는다. |
| High Cohesion | 검색 색인 구현만 RoiSnapshot partial로 묶는다. |
| Polymorphism | 새 공급자/도형 다형성을 만들 필요가 없다. 기존 geometry·service 계약을 보존한다. |
| Pure Fabrication | 기존 이력/BVH/GPU 캐시의 기술 책임을 재사용한다. |
| Indirection | 앱의 검사 VM이 실제 ROI/확장 범위를 서비스 입력으로 변환한다. |
| Protected Variations | 픽셀 여유의 double 값과 GPU float 상수 경계를 분리한다. |

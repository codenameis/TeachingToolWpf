# ADR-047: 전체 View 책임 정리와 그룹 도형의 포함 제한

후속 [ADR-048](0048-roi-boundary-motion-and-nested-selection.md)이 일반 리프 자유 이동과 끝점만의 포함 판정을 대체한다. 부모 밖 리프 편입은 사용자 확정으로 유지한다. 아래는 이 결정 당시의 기록이다.

- 상태: 채택, 2026-10-15 사용자 후속 요청
- 범위: 로컬 수정·검증. 커밋·푸시 없음.
- 선행: [ADR-045](0045-roi-hierarchy-and-explicit-names.md), [ADR-046](0046-parent-reuse-and-mvvm-viewport.md)

## 요청과 결정

사용자는 모든 View의 코드 비하인드를 같은 MVVM 기준으로 확인하고 기존 기능을 유지하도록 요청했다. 그룹이 상위 그룹을 벗어날 수 없다는 의미는 **ROI 그룹·모듈 그룹의 이동·회전·크기 변경을 상위 도형 안으로 제한**하는 것으로 직접 확인했다. 일반 ROI의 생성 후 자유로운 편집은 유지한다.

1. 앱의 View 11개와 공통 FilterPanel을 확인한다. RepeatedRoiWindow의 구현체 조립은 App, 로딩 취소·오류·성능 표시 상태는 RepeatedRoiViewModel, 진단 실행은 RepeatedRoiRun으로 옮긴다. ShapeMatchingPanel은 WPF 파싱 오류만 VM에 전달하고 학습/검색 가능 여부는 기존 VM 명령, 오류 안내 표시 여부는 바인딩으로 결정한다.
2. View에는 InitializeComponent, DataContext/컨트롤 연결, 포커스·Dispatcher·WPF 검증 오류 추출, 파일/설정창 표시, UI 구독 해제를 남긴다. 실제 WPF 객체와 화면 수명이 필요한 책임이며 업무 규칙을 넣지 않는다. 한 화면만을 위한 새 범용 이벤트 계층이나 MVVM 패키지를 추가하지 않는다.
3. `RootGroup → ModuleGroup → RoiGroup → Roi`의 최대4단계를 유지한다. 상위 그룹이 있는 모든 그룹은 상위의 실제 도형에 완전히 포함되어야 한다. 이동·회전 미리보기/확정, 동기/준비된 편집, 핸들/숫자 크기 변경에 같은 규칙을 적용한다. 상위 그룹만 줄일 때도 남아 있는 하위 그룹을 배제할 수 없다.
4. 일반 리프 ROI는 생성 후 부모 밖으로 이동·회전·크기 변경할 수 있고, 기존 독립 리프의 편입도 포함 제한을 추가하지 않는다. 부모 아래 새 ROI를 그릴 때의 기존 엄격한 포함 규칙은 유지한다. 그룹 편입과 리프의 그룹 승격은 새 그룹 경계를 검증하고 실패 시 문서/번호/이력을 변경하지 않는다.
5. `RoiGeometry.Covers`는 같은 경계까지 허용하는 실제 도형 포함 판정이다. 기존 `Contains`는 더 작은 자식이라는 그리기 조건을 유지한다. `RoiGroupBounds`가 계층 규칙을 담당하며 ViewModel·WPF·렌더러가 포함 여부를 별도로 판정하지 않는다. 선택 전체에 같은 변환 비율을 적용해 상대 위치를 보존한다.
6. 그룹 해제는 선택한 그룹 껍질을 제거하고 그 자식들을 원래 상위로 연결한다. 최상위 그룹 해제 시 자식은 독립한다. 하위 그룹과 자손은 유지하고 Undo/Redo로 복원한다. 명시적 `IsGroup`뿐 아니라 자식 연결로 형성된 실제 그룹에도 명령을 적용한다.
7. 별도 `자식 추가/그리기` 버튼·명령을 없애고 `ROI 추가/그리기`로 통합한다. 그룹 하나를 선택했으면 그 안에 연결된 ROI를, 일반 ROI·무선택·다중선택이면 독립 ROI를 만든다. R 단축키도 같은 명령을 사용한다. `부모 추가/부모 그리기`는 유지한다.

## 적용 경계

이 결정은 ADR-045의 생성 후 자유로운 편집 설명 중 **그룹**에 대한 부분과 ADR-046의 별도 자식 버튼 설명을 대체한다. 기존 문서·통합 이력·그룹 색상·이미지 경계·4단계 제한은 유지한다. 저장된 기존 문서나 과거 이력을 열 때 도형을 자동 변경하는 마이그레이션은 추가하지 않는다.

경계 제한은 게시되는 각 도형의 포함 여부를 검사한다. 오목 도형 내부에서 포인터가 이동한 연속 경로 전체에 대한 충돌 시뮬레이션은 아니다. 각도0 초기화처럼 정확한 값이 필요한 명령이 경계를 위반하면 기존 상태를 유지하고 오류로 알린다.

전체 View별 유지 이유, SOLID5/GRASP9 검토와 실행 증거는 [검증 기록](../views-mvvm-and-group-bounds.md)에 둔다. 새 의존성이나 설계 원칙 예외는 없다.

# ADR-017 — 기본 칩 검사 피드백과 패턴 샘플

날짜: 2026-10-04. 사용자가 시작 기본 이미지의 칩 하나를 학습·검사했을 때 결과가 보이지 않고 느리다고 보고했다. 별도 패턴 매칭 이미지도 버튼으로 열기를 요청했다.

## 재현과 결정

기본 이미지는 8192×8192 합성 PCB다. 칩의 평평한 내부만 선택한 512×512 ROI(중심 1024,1024)와 1280×700 ROI에서는 학습에 필요한 윤곽이 부족해 학습이 실패했다. 기존 UI는 실패 원인을 긴 패널 아래에 표시하고 캔버스에는 일반 경고만 표시했다. 학습이 실패하면 검사 버튼이 비활성화되어 사용자가 반응을 확인하기 어려웠다. 테두리·핀을 포함한 ROI는 16개 칩을 검출했다. 사용자 조작의 정확한 ROI/선택 방식은 제공되지 않았으므로 모든 미검출의 원인을 이것으로 단정하지 않는다.

- 학습·검사 중에는 GPU 배너와 패널 상단 상태/진행 막대를 표시한다. 진행 상태에는 검출 위치나 정상/불량 판정을 넣지 않는다.
- 학습 실패는 캔버스에서 명시하고, 원인·재학습 방법은 패널 상단에 표시한다. 윤곽 부족은 테두리·핀을 포함하도록 안내하며 에지 기준을 완화하거나 가짜 모델을 만들지 않는다. 이전 모델이 있으면 실패 시 유지 사실을 알린다.
- 이미지·설정 변경으로 작업을 무효화할 때 처리 중 안내도 지운다. epoch/token 검증, 취소, 늦은 결과 폐기, 편집 이력 분리를 유지한다.
- 상단 **패턴 샘플**은 기존 검사 검증에서 사용하던 자체 제작 640×400 PNG를 연다. 자산은 앱의 `Assets/pattern-matching.png`이며 빌드/배포에 동봉한다. 일반 파일과 동일한 `ImageCoordinator.ReplaceAsync`를 사용해 ROI 초기화, 모델 보존, 실패 원자성, 이미지 Undo/Redo를 유지한다. Canvas에 검사 전용 분기를 추가하지 않는다.
- 왼쪽 도형 전체를 ROI로 잡아 학습한다. 오른쪽 도형은 20° 회전·1.2배 크기이므로 **형상 매칭 → 배율 검색 켜기 → 최대 배율 1.2 이상 설정 → 학습**이 필요하다. 이미지 열기 버튼이 사용자의 검사 설정을 암묵적으로 바꾸지 않는다. OpenCV 기본 템플릿은 고정 각도/배율이므로 왼쪽 원본 형태만 검출한다.

## 원본 정밀화 비용 개선

기존 큰 이미지 경로는 이미 검색한 후보 주변의 원본 crop마다 gradient 피라미드와 전체 방향 응답맵을 모두 만들었다. 원본 정밀화는 후보의 위치가 정해져 있으므로 `PreparedSearchImage.CreateForRefinement`에서 gradient만 만들고 각 단계의 연속 위치·각도·배율 최적화와 마지막 point-to-line 정밀화를 수행한다. 전체 후보 검색은 기존 응답맵 경로를 유지한다.

최종 점수·지지율·ROI 포함·작업 메모리·후보 예산은 유지한다. 기존 응답맵의 국소 위치 탐색을 생략하므로 수렴 가능한 초기 오차 범위까지 모든 입력에서 동등하다고 주장하지 않는다. 축소 seed 주변의 비정수 위치·회전·배율 및 실제 큰 이미지 경로를 회귀 검증한다. 현장 영상 정확성은 별도 평가가 필요하다.

### 동일 입력 3회 비교

Ryzen 5 5600H / RAM 32GB / Windows x64 / .NET 10 Release, CPU 형상 검색. 기본 8192², ROI 중심 (1024,1024), 1600×1120, 회전 ±180°/입력 간격 10°, 배율 1, 점수 .72, 최대 결과 16, 전체 이미지 검색. 각 프로세스에서 3회 연속 학습/검색했고 아래 시간은 검색의 원본 읽기·검증을 포함한다. 전원/열 상태는 고정하지 않았다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 3회 검색 시간 ms | 4980.2 / 4549.3 / 4567.4 | 3725.1 / 3449.5 / 3460.7 |
| 검색 중앙값 ms | 4567.4 | 3460.7 |
| 전처리 중앙값 ms | 2244.3 | 1130.1 |
| 프로세스 peak working set MiB | 453.8 | 386.5 |
| 검출/불완전 플래그 | 매회 16개 / false | 매회 16개 / false |

검색 중앙값 약 24% 감소, 전처리 약 50% 감소다. 원시 측정: [변경 전](../data/chip-before-8192.json), [변경 후](../data/chip-after-8192.json). GPU 메모리나 현장 검출률 수치가 아니다. 이전 ADR-016의 512 ROI/9개 시험은 이미지 중앙 교차선 패턴이며 이번 칩 ROI와 다르다.

실제 WPF HWND 드래그로 만든 칩 ROI의 검사 명령은 첫 검증에서 약 5.3초, 최종 배포본에서 약 5.2초였다. ROI 중심 (1027.3511,1027.3511), 크기 1598.9528×1120.2244로 포인터 반올림 때문에 위 고정 입력과 다르며 렌더러도 동시에 실행한다. 벤치마크 수치를 UI 지연으로 대신하지 않는다. 처리 중 상태와 취소 버튼은 바로 나타나지만 즉시 검사 또는 실시간 검사 목표를 달성한 것은 아니다.

재현 명령:

```powershell
dotnet run --project benchmarks/TeachingToolWpf.Matching.Benchmarks -c Release -- artifacts/chip.json 8192 1600 3 1120 shape 1024 1024
artifacts/publish/TeachingToolWpf.exe --inspection-smoke --gpu-debug
```

## 검증 범위

- 기본 8K의 평평한 ROI 학습 실패, 기존 모델 보존/학습 실패 경고, 실행 중 배너/취소, 입력 변경 상태 무효화.
- 실제 HWND에서 테두리·핀을 포함하는 ROI 그리기 → 학습 → 16개 칩 기준점 오차 1px 미만 → DX12 검출 윤곽 픽셀 확인. UI 캡처 `artifacts/chip-ui/artifacts/chip-search-app.png`, 실패 캡처 `chip-training-warning-app.png`.
- 패턴 샘플의 실제 WPF 버튼 바인딩, 파일 읽기, ROI 초기화/학습 모델 보존, 이미지 Undo/Redo. 이어서 두 형상 pose·OpenCV·특징점 토글·네 판정색·빈 검색 영역 NG의 기존 검사 smoke.
- 비정수 이동·각도·배율 정밀화와 큰 원본 이미지 검색, 작은 원형 검색 영역의 기존 수용 기준 유지.
- `IsBusy`를 반전하면 실행 중 상태 테스트가 FAIL한다. 원상복원 후 회귀 검사. 로그 `artifacts/chip-mutation.log`.
- 코드 리뷰에서 샘플 최대 배율 안내 누락을 찾아 수정했다. 알고리즘의 수렴 범위 변경은 위에 명시했다. 검증 완료 여부와 최종 테스트/배포 로그는 [작업 목록](../../tasks/todo.md)에서 관리한다.

실촬영 8K/24K 검출률·처리 시간, 가림/조명/저대비 변화의 비교 통계, 실시간 검사 FPS는 NOT_RUN이다. 기존 ROI 편집/8K 표시 검증과 구별한다.

## SOLID·GRASP 검토

| 원칙 | 이번 변경의 근거 |
|---|---|
| SRP | 전처리/정밀화는 알고리즘, 실행 상태는 매칭 VM, 파일 교체는 기존 coordinator |
| OCP | 공개 검색 계약을 유지하고 원본 정밀화 전처리 경로만 추가 |
| LSP | 새 대체 구현 없음; 기존 취소·입력 검증·원본 좌표 계약 회귀 확인 |
| ISP | 진행 표시 때문에 서비스/Canvas 계약을 확장하지 않음 |
| DIP | 기존 서비스 주입과 값 overlay 유지; Canvas는 샘플 자산/검사 UI를 모름 |
| Information Expert | 모델 단계와 gradient 소유 경계에서 정밀화; UI는 계산하지 않음 |
| Creator | 앱이 샘플 경로, 기존 loader가 이미지 수명, trainer가 모델 생성 소유 |
| Controller | WPF 버튼은 기존 비동기 명령에 위임 |
| Low Coupling | 기존 이미지 교체와 overlay 값 계약 재사용 |
| High Cohesion | startup 검사 smoke는 별도 partial 파일, 이미지/알고리즘 책임 유지 |
| Polymorphism | 기존 학습 서비스의 실제 구현/테스트 대역이 같은 VM 계약 사용 |
| Pure Fabrication | coordinator와 prepared image가 이력/전처리 기술 책임 유지 |
| Indirection | 외부 파일 읽기는 loader, 화면 표시는 범용 GPU overlay를 경유 |
| Protected Variations | 앱 자산 추가가 Core/Canvas 도메인 및 ROI 이력 규칙을 바꾸지 않음 |

MVVM, Command/Memento, 값 기반 렌더 전달을 유지한다. 승인되지 않은 설계 원칙 예외는 없다.

# ADR-059: 세 템플릿 매칭의 선택형 CPU+CUDA와 단계별 코드

- 상태: 사용자 승인에 따른 로컬 구현
- 날짜: 2026-10-16
- 범위: Line2D / Sub-NCC / Directional Chamfer

## 요청

사용자는 알고리즘 코드를 기초 C#을 배운 사람이 따라갈 수 있게 정리하되 성능과 정확도를 유지하도록 요청했다. 세 방식에 기존 GPU 모드가 없음을 알린 뒤, **세 방식용 CPU+CUDA를 새로 추가**하는 것도 명시적으로 승인했다. 이전 로컬 수정·검증 방침을 유지한다.

## 결정

공통 검색을 피라미드 준비, 전체 후보 점수, 피라미드 자세 보정, 원본 검증으로 분리한다. Line2D/Chamfer의 동일한 방향 표본 회전과 보간 점수는 공통 구현으로 합친다. Sub-NCC 표본 선택, Chamfer 공간/방향 거리 전파, 원본 경계 대응은 이름 있는 단계로 드러낸다. CPU SIMD·계산 순서·캐시 상한은 보존한다.

CUDA는 모든 후보 위치의 점수 맵만 계산한다. CPU의 표본과 원래 정밀도를 전달하며, 최종 점수나 후보 예산을 낮추지 않는다. Core에는 선택형 `ICoarseScoreAccelerator`와 점수 전달 계약만 둔다. 실제 장치는 독립 `CpuMatching.Cuda`의 ILGPU1.5.3이 담당한다. 기존 `VisionCompute.ILGPU → VisionAlgorithm → PoseMatch/ONNX` 의존성을 이 독립 비교기에 끌어오지 않는다. 새 패키지 버전을 도입하지 않는다.

App/CLI가 지연 생성 세션을 소유하고 한 검색만 대여한다. 장치 준비·전송·계산 및 대기·수신을 로그로 구별한다. CPU 선택은 장치를 만들지 않는다. GPU 오류/미지원은 명시적인 실패이며 자동 CPU 대체는 하지 않는다. 제출 중 취소/종료는 작업 완료와 버퍼 수명을 보존한다.

WPF는 기존 상세 설정의 실행 장치를 세 방식에도 표시한다. 방식별 CPU/CUDA 선택을 저장하며 템플릿 재학습 없이 전환한다. 기존 탭·숫자 오류·원본 좌표·검색 도형·결과/경고 정책을 보존한다. UI 변경은 선택/주입/로그 연결에 한정한다.

## 유지할 경계

- 최소 점수0.75 및 같은 각도/배율/후보/출력 조건으로 전후 비교한다.
- 사각형 학습4~512px, 마스크 미지원, 검색 여백 포함2Mpx 예산을 유지한다.
- 8K 안의512×512 영역 시험을8K 전체 탐색 합격으로 표현하지 않는다.
- 기존 PoseMatch와 논문 형상·OpenCV·Canvas/ROI 알고리즘은 변경하지 않는다.
- 정확도 합격과 CPU125ms/CUDA80ms 표시 목표를 구분한다. 작은 영역의 CUDA 지연도 숨기지 않는다.
- Git 커밋·푸시, 추가 파일 정리는 이번 요청에 포함하지 않는다.

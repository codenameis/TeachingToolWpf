# ADR-021 — 형상 출력 기본값과 검사 원본 타일 재사용

- 날짜: 2026-10-04
- 상태: 구현·반복 측정·전체 자동 테스트·실제 DX12 앱 검증 완료
- 요청: 논문 기반 형상 매칭이 느리고 일부만 검출되는 현상 확인.

## 재현과 판단

사용자가 남긴 `publish-matching-modes` 앱에서 8192×8192 합성 PCB와 단일 핀 ROI를 확인했다. 중심 (759.518,546.178), 크기 105.827×129.459, 각도 0°, 방향 점수 .72, 특징159개/피라미드3단계/템플릿37개였다. 최대 결과 수16에서16개만 표시하며 출력 생략 경고가 나왔다. 같은 모델의 상한만1000으로 바꾸자256개 모두 검출됐고 후보 예산 경고는 없었다. 실제 앱 단일 실행은5,611.7ms, 읽기/변환3,225.2ms, 검색창64개였다. 원본 상태와 화면은 `artifacts/paper-user-state`에 보관한다.

이번 부분 검출은 출력 상한 때문이다. 후보 검증 예산이 중복 자세에 소모될 가능성은 별도 코드 감사에서 확인했지만 이 입력에서는 누락으로 재현되지 않았다. 이번 수정으로 후보 순서·각도 범위·점수·지지율·NMS·정밀화 조건을 바꾸지 않는다.

## 결정

1. 앱의 논문·기하 형상 기본 출력 상한도256개로 맞춘다. OpenCV와 각각 독립 보관하고 사용자가 정한 값은 유지한다. 라이브러리 `SearchOptions` 기본16개는 바꾸지 않는다. 출력 상한 초과와 후보 잘림의 기존 경고 계약을 유지한다.
2. `MatchingImageReader`가 한 번의 검사 동안 최대16MiB의 원본 Gray8 타일을 LRU로 재사용한다. 키는 level-0 타일 좌표다. reader의 source는 수명 중 고정되며 다른 reader·검사·이미지와 공유하지 않는다. 영구 캐시나 표시 LOD를 쓰지 않는다.
3. 원본 네이티브 타일은 기존 변환식으로 Gray8 버퍼에 복사한 뒤 반환한다. Gray16 상위8bit, RGB 정수 luminance, crop 후 반복2×2 면적 평균 축소를 유지한다. 반환 crop은 별도 소유 배열이다.
4. 캐시 버퍼는 기존 `PixelBuffer` 풀을 사용한다. 예산은 실제 대여 배열의 `Bytes.Length` 합계이며 퇴출/종료 시 반환한다. 취소·변환 실패는 새 버퍼를 반환하고 캐시에 게시하지 않는다. cache hit도 취소를 확인하고 Dispose 후 접근은 거부한다. 단일 worker 읽기·해제 계약을 유지한다.
5. 16MiB는 캐시 소유 배열 한도다. 풀에 반환된 배열, 출력 crop, 알고리즘 작업 공간, 컬렉션과 프로세스 전체 메모리의 상한이 아니다.

## 반복 측정

기준 장비 Ryzen5 5600H / RAM32GB / Windows x64, Release .NET10. CPU 매칭이다. 같은 학습 모델로 워밍업1회 후3회 전체 원본 검색, 매번 새 reader를 열었다. 학습시간은 검색시간에서 제외한다. 전원 모드·발열은 별도 통제하지 않았으므로 작은 차이를 개선으로 해석하지 않는다.

## 검증과 설계 원칙

회귀는 네 픽셀 형식, 홀수 경계 타일, 비영점 crop, 축소2/8/32, 중복 읽기,16MiB 퇴출, 풀 반환, 취소 hit/miss, source 격리, live lease, 반복 Dispose를 검사한다. 메모리 한도를32MiB로 바꾼 변이는 퇴출/반환 테스트2개가 실패했으며 즉시 복원했다. 앱 smoke는 논문 핀 하나 학습→16개 경고→재학습 없이256개 검사와 칩별16개를 확인한다. 최종 자동·실제 DX12 검증 결과는 [작업 목록](../../tasks/todo.md)에 둔다.

SOLID: SRP는 타일 보관과 원본 변환을 분리한다. OCP는 기존 source 계약과 알고리즘을 유지한다. LSP는 원본 픽셀·취소·소유권을 보존한다. ISP는 사용하지 않는 공개 계약을 추가하지 않는다. DIP는 기존 Core source 추상 계약과 앱 reader 경계를 유지한다.

GRASP: Information Expert는 최근 사용/예산을 캐시에 둔다. Creator는 reader가 캐시를 생성·해제한다. Controller는 기존 매칭 서비스다. Low Coupling은 공급자 비의존 픽셀 경계를 유지한다. High Cohesion은 보관 책임을 별도 타입에 둔다. Polymorphism은 기존 `ITileSource`를 사용한다. Pure Fabrication은 LRU의 기술 책임 분리다. Indirection은 원본 reader가 담당한다. Protected Variations는 원본 소스와 매칭 엔진을 격리한다. 원칙 예외는 없다.

# ROI 편집 핸들 크기 설정

2026-10-15. `main`에서 로컬 수정·검증만 진행한다. ROI 선택 시 사용하는 사각 크기 조절 핸들과 원형 회전 핸들 자체의 크기를 설정하는 기능이다.

## 사용법과 계약

- 설정 → **ROI 편집 핸들 크기**에서 50~300%를 25% 간격으로 조절한다. 즉시 적용하며 기본값 100%는 기존 크기·클릭 범위와 같다.
- 사각 핸들, 회전 핸들, 클릭 판정 범위를 같은 배율로 조절한다. 회전 핸들까지의 간격과 선택 이름표 위치도 맞춘다. 화면 DIP 기준이므로 이미지 확대율에 따라 핸들이 커지지 않는다.
- 일반 ROI, 실제 그룹, 메인 편집기의 단일 반복 ROI 셀에 적용한다. 기존 복수 선택의 회전 금지는 유지한다. ROI의 위치·형상·계층과 Undo/Redo는 설정 변경으로 바뀌지 않는다.
- 진행 중인 크기 조절은 핸들 크기 변경으로 취소하거나 확정하지 않는다. 다음 클릭부터 새 클릭 범위를 사용한다.
- `ROI 기본값`은 색·선 두께와 함께 핸들을 100%로 복원한다. 다른 표시 설정처럼 현재 앱 실행 중에만 유지한다.

## 구현과 원칙 검토

설정 VM이 배율을 보관하고 MainWindowViewModel이 기존 입력 컨트롤러에 전달한다. Core의 `HandleGeometry`가 배율 범위와 회전 핸들 위치를 정의한다. 불변 `InteractionOverlay`를 통해 렌더러도 같은 배율을 사용한다. XAML은 바인딩만 추가하며 View 코드 비하인드에 로직을 넣지 않는다. 선택 핸들 몇 개의 좌표·크기만 계산하며 전체 ROI 순회나 새 종속성은 추가하지 않는다.

| 원칙 | 이번 변경의 판단 |
|---|---|
| SRP | 설정·입력 판정·표시를 기존 담당 타입에 유지 |
| OCP | 기존 배율 데이터 전달을 확장하며 제스처 종류나 도메인 분기를 추가하지 않음 |
| LSP | 기존 입력·확정·취소·Undo/Redo 계약을 회귀 검증 |
| ISP | IViewportInput에 설정 전용 메서드를 강제하지 않음 |
| DIP | Core는 WPF/GPU를 참조하지 않으며 앱 VM이 연결 |
| Information Expert | 핸들 위치·유효 배율은 HandleGeometry, 실제 클릭 판정은 입력 담당 |
| Creator | 기존 VM/입력/렌더 생성 경계를 유지; 문서 객체 생성 없음 |
| Controller | 슬라이더는 설정 VM에 바인딩하고 Core가 입력을 해석 |
| Low Coupling | 중립적인 배율 값만 전달하며 View와 렌더러 직접 연결 없음 |
| High Cohesion | ROI 표시 설정·선택 핸들 처리에 한정 |
| Polymorphism | 기존 제스처 계약 유지; 단일 옵션을 위한 새 상속 없음 |
| Pure Fabrication | 기존 표시 스냅샷을 사용하고 불필요한 설정 서비스 없음 |
| Indirection | 기존 VM→입력→표시 스냅샷 경계 재사용 |
| Protected Variations | 배율이 문서·검사·원본 영상·GPU 수명 계약을 바꾸지 않음 |

원칙 예외는 없다.

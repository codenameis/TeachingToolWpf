# 다른 영상·템플릿을 계속 검사하는 작은 ROI 최적화

2026-10-16. 사용자 요청으로 기존 상태를 `efa070f`에 커밋하고 `origin/main`에 정상 푸시한 뒤, 아래 변경은 **커밋·푸시 없이 로컬에 유지**했다. 고정 배치·이전 프레임·동일 픽셀 재사용을 전제로 하지 않는다.

## 변경과 근거

처음 측정한 작은 영역에서 Line2D/Chamfer는 영상 맵 준비, Sub-NCC는 정밀 점수 계산이 큰 비중을 차지했다. 복사·분할·GPU 전송 구조를 바꾸지 않고 각 알고리즘 내부만 수정했다.

- **Line2D:** 축소 방향 응답 맵의 3×3 최대값 계산을 `Vector<float>`로 여러 픽셀씩 처리한다. 이웃 순서, 영상 테두리의 0, 벡터 뒤 남는 픽셀의 기존 스칼라 계산을 유지한다.
- **Sub-NCC:** 회전·배율을 적용한 표본의 실제 최소/최대 좌표를 자세 객체에 보관하고 위치별 유효 범위를 한 번 검사한다. 표본 전체, bilinear 계산과 합산 순서를 유지한다. 이전 전체 8K 실험에서 채택하지 않았던 방법을 이번 작은 ROI 조건에서 재평가하고, 전체 검색도 다시 비교했다.
- **Directional Chamfer:** 공간 거리 전파에서 픽셀의 현재 거리를 지역 변수에 누적하고 한 번 기록한다. 두 방향의 순회와 이웃 비교 순서, `float` 연산, 거리 상한과 양방향 원본 검증은 같다.

공개 API·알고리즘 파라미터·기본 CPU 작업 수 4·후보 묶음·캐시 용량을 바꾸지 않았다. 검색 범위를 줄이거나 낮은 점수 후보를 추가로 버리지 않는다. 각 계산은 기존 알고리즘 소유 클래스 안에 있고 새로운 의존성·관리자·인터페이스는 없다. SOLID/GRASP의 책임·결합 및 수명 경계에 대한 예외는 없다.

## 측정 조건

- 기준 장비 Ryzen 5 5600H / RAM 32GB / Windows x64. Release, CPU 경로다.
- `ken32.png` 원본을 OpenCV Gray8로 읽어 서로 다른 위치에서 32·48·64·96px 정사각 템플릿과 사방 48px 여유의 128·144·160·192px 검색 영상을 추출했다. 명암만 크고 윤곽이 부족한 패치는 기존의 6개 윤곽 학습 조건에 맞지 않아 입력 구성 단계에서 제외했다. 좌표·원본 및 입력 해시는 provenance/report에 기록한다.
- 기존 부품 회전·문자 회전·Kensa 부품·대상 없음 4조건을 더한 **8조건×3방식**을 순환한다. 매 호출마다 matcher를 새로 생성하며 영상과 템플릿을 교체한다. 이전 이미지의 맵/결과는 재사용하지 않는다.
- 모델 생성 + `Find` 전체를 시간에 포함한다. PNG 디코딩·Gray8 변환·대용량 원본에서 ROI 추출·보정·WPF 표시는 제외한다. 입력은 이미 메모리에 있는 영상이다.
- 최소 점수 0.75, ken32 ROI 각도 −30~30°/10°, 배율 1, 피라미드 3, 후보 묶음 2048을 유지한다. 다른 4조건은 기존 데이터의 검색 옵션 그대로다.
- 각 실행의 첫 순회와 추가 3순회를 기록한 뒤 9순회 측정. **이전→이후→이후→이전** 순서로 실행하여 각 조건/방식당 전후 각각 18회 중앙값을 비교한다. 자체 빌드·테스트와 성능 측정은 겹치지 않았다. OS 배경 부하·열 상태까지 고정한 상한 보장은 아니다.

### ken32 작은 영역 결과

단위 ms, 모델 생성 포함 중앙값. 각 셀은 **이전 → 이후**다.

| 템플릿 / 검색 영상 | Line2D | Sub-NCC | Chamfer |
|---|---:|---:|---:|
|32² / 128²|2.27 → 2.12|41.53 → 25.91|16.41 → 14.77|
|48² / 144²|2.77 → 2.12|46.50 → 33.77|14.19 → 11.94|
|64² / 160²|3.20 → 2.43|39.28 → 33.57|19.44 → 16.11|
|96² / 192²|5.20 → 3.97|57.72 → 47.66|32.04 → 27.15|

작은 차이를 모두 개선으로 보지 않는다. Line2D의 32px 조건이나 문자 조건은 변동과 가까우며 모든 입력에서 같은 개선율을 보장하지 않는다.

## 회귀·변동 확인

- 작은 ROI의 24조합에서 첫 실행·준비·측정을 포함한 모든 결과가 전후 일치했다. 검출 목록, 좌표·각도·배율·점수, 후보 수/묶음 수, 평가 횟수, 상한 플래그를 시간과 분리한 SHA-256으로 비교했다.
- 기존 16조건, Kensa 전체 48개, 합성8K 전체 256개, 경계 회전8K 8개의 **19조건×3방식=57조합**도 전후 일치했다. 완전 정답54조합은 누락/추가 없이 위치≤1px·각도≤1°·배율 오차≤0.03을 확인했다. 원본18V의 3조합은 알려진 대상만 확인했다.
- 큰 영역은 각1회 확인이며 8K256개는 Line2D 1910→1686ms, Sub-NCC 21664→17924ms, Chamfer 28644→25793ms였다. 반복 중앙값이나 안정적인 속도 보장으로 표현하지 않는다.
- 일반16조건을 추가로4회 준비+5회 측정했을 때 Line2D의 부분 가림 조건은6.25→7.76ms였다. 준비 시간 자체는2.87→2.43ms로 줄었으며, 해당 조건을 분리하고 순서를 뒤집은25회에서는8.34→6.63ms였다. 원시 기록을 남기고 모든 조건에서 일률적으로 빨라졌다고 주장하지 않는다.
- CPU32 + 실제 CUDA66 + 알고리즘194 = **292테스트 PASS**. 새6테스트는 홀수/짝수 행 폭, 영상 네 모서리 대상, 같은 모델에 다른 빈 영상을 전달한 결과를 확인한다.
- Line2D SIMD의 `Max`를 잠시 `Min`으로 바꾸자 새 Line2D 경계2테스트만 실패하고 다른 방식4테스트는 통과했다. 원래 바이트로 복원한 뒤 최종 Release 빌드와 CPU32/CUDA66을 다시 통과했다.
- 전체 Release 빌드 경고0/오류0. 변경6파일의 공백·스타일·명명 검사 PASS. 저장소 전체 형식 검사는 실행 시점의 기존54파일 위반으로 FAIL이며 대상 밖 파일을 일괄 수정하지 않았다.

## 제약

ken32의4영역은 자기 일치 위치만 알려져 있고 주변 추가 검출에는 전체 정답 라벨이 없다. 예를 들어32px의 Sub-NCC는 전후 모두4개를 반환한다. 현장 오검출0이나 전체 검사 합격을 뜻하지 않는다. 원본 전체530,841,600픽셀 검사·표시, 카메라 입력, 다른CPU·장시간 운영은 미검증이다. CPU125ms/CUDA80ms의 **버튼→표시** 목표 달성으로도 표현하지 않는다.

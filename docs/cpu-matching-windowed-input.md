# 패턴 검색 ROI 자동 지정과 대용량 원본 검사

2026-10-16. [ADR-064](decisions/0064-automatic-search-roi-and-windowed-cpu-matching.md). 변경은 로컬에만 유지한다.

## 사용 동작

1. 학습할 리프 ROI를 선택하고 패턴을 학습한다.
2. 성공하면 검색 여유가 없던 ROI에20px를 자동 지정한다. 기존 검색 여유는 바꾸지 않는다. 오른쪽 속성에서 조정할 수 있고 Undo/Redo가 된다.
3. 기본 검사는 선택 ROI의 검색 범위를 따른다. `ROI 검색 범위 사용 (끄면 전체 이미지)`를 끄면 전체를 검사한다. 사용자가 선택한 전체 검색은 재학습/이미지 갱신으로 자동 해제하지 않는다.
4. Line2D/Sub-NCC/Directional Chamfer는 전체 검색이8K 예산을 넘으면 원본을 작은 창으로 읽는다. ken32를 통째로 `GrayImage`에 넣지 않는다. 시간은 영상·템플릿·각도·배율과 후보 수에 따라 늘어난다.

검색 여유의 이미지 밖 부분은 읽지 않는다. 검색 도형 안의 중심 판정, 원본 해상도 검증, 회전 학습 각도와 화면 좌표 변환은 유지한다. 템플릿 크기·마스크 지원·최대 결과 수 등 기존 기능 조건은 유지한다.

## 검증 범위

- 연속/창 입력 비교: 비정렬 검색 원점, 홀수 크기, 축소 창 경계와 모서리 대상. 위치·각도·점수·후보 수·후보 묶음 수 일치, 전역 결과 상한 검사.
- 가상65,537×32,769 입력: 전체 픽셀 수가 `int`를 넘어도 전체 버퍼를 만들지 않고 축소 격자를 끝까지 순회. 상수 점수 시험이며 실제 대용량 영상 정확도 시험은 아니다.
- 원본 reader: Gray8 원본과1/2/4/16배 반복 평균, 비정렬 ROI 원점, ken32 크기 입력의 끝 타일/화면 좌표, reader 해제.
- CPU/CUDA: 창 경계와 회전 대상에서 같은 결과·후보·평가 수. 기존 연속 입력 회귀도 유지.
- WPF VM: 여섯 모드 ROI 기본값과 명시적 전체 검색 유지, 성공 학습의20px 등록·기존 여유 보존·Undo/Redo·실패 시 문서 보존.
- 기존 전체 검색 회귀는 `UseSelection=false`를 명시하도록 갱신했다. 검출 개수/위치·각도 기대값을 낮추지 않았다.

최종 Release 빌드 경고0/오류0. CPU40·원본 검사113·WPF 연동313·실CUDA72, 총538건 PASS다. 실제 WPF 진단에서도 여섯 모드/두 창 크기의 패널, 학습 후20px 등록, 체크박스의 ROI↔전체 바인딩, Kensa4개 검출과 결과 상한 경고를 통과했다. 추가 안내문 때문에 기본 패널에 생긴 스크롤은 안내를 툴팁으로 옮겨 해소한 뒤 재검증했다.

관련 변경 C#36파일의 형식/스타일 검사는 PASS다. 기존 형식 위반이 있던 `TdcmLatencyRun.cs`는 전체 검사에 포함해 그대로 보고한다. 전체 형식 검사는 기존 파일53개의 위반 때문에 FAIL이다. 관련 없는 파일을 일괄 수정하지 않았다. ken32 전체 정답, 실제 카메라 입력과125/80ms 달성은 이 검증으로 입증하지 않는다.

## 실제 ken32 전체 실행

원본17,280×30,720,530,841,600픽셀. Line2D CPU 전체 검색을 정상 완료했다. 파일 캐시를 먼저 준비하고 아래 조건 그대로 한 번 실행했다. 회귀/빌드 작업 일부와 동시 실행되었으므로 안정적인 성능 기준이나 전후 속도 개선 측정으로 사용하지 않는다.

| 항목 | 결과 |
|---|---:|
| 새 템플릿 학습 |147.5ms|
| 원본 읽기 포함 검색 전체 |644,382.9ms (약10분44초)|
| 원본 창 읽기/변환 누적 |258,590.0ms|
| 읽기를 제외한 검색 경과 |385,788.8ms|
| 후보/묶음 |181,779 / 89|
| 실제 점수 평가 |535,591,684|
| 후보 잘림 |없음|
| 출력 |256개, 결과 상한 초과 경고 유지|
| 알려진 자기 위치 |(14256,5808),0°,점수0.9883737742|
| 프로세스 최대 working set |2,995,666,944bytes (약2.79GiB)|

후보 전체를 검증한 결과이며 최종 출력은 기존256개 상한을 따른다. 한 곳의 자기 위치를 찾은 사실이 전체 검출 정확도는 아니다. Sub-NCC/Chamfer 및 CUDA의 **실제 ken32 전체** 실행과 ken32 버튼→표시는 NOT_RUN이다. 이 경로는 큰 원본을 처리하기 위한 기능이며 빠른 전체 검사 목표를 달성하지 않았다. 맵 창 재생성·원본 읽기와 많은 후보의 정밀 검증이 비용으로 남는다.

[검증 자료](data/cpu-windowed-input-validation.zip)에 실행 JSON·최종538건 TRX·WPF 진단/화면·현재 검증 소스 해시를 보관한다. ken32 원본 파일은 로컬에만 유지한다.

## 재현

```powershell
dotnet build TeachingToolWpf.slnx -c Release --artifacts-path artifacts/sidebar-verified -p:RestorePackagesPath=.packages --no-restore --disable-build-servers -m:1 -p:UseSharedCompilation=false
artifacts/sidebar-verified/bin/TeachingToolWpf.Matching.Benchmarks/release/TeachingToolWpf.Matching.Benchmarks.exe artifacts/windowed-matching/ken32-line2d.json cpu-windowed ken32.png Line2D
```

벤치마크는 ken32의(14208,5760)~(14304,5856),96×96 템플릿을 새로 학습한다. 점수0.75,각도−30~30°,배율1,피라미드3,후보 묶음2048,결과 상한256,CPU 작업4다. 원본 파일 캐시 준비는 별도이며 검색은 원본 읽기/변환을 포함한다. 알려진 템플릿 자기 위치 하나 외 전체 정답은 없다. 창 여백의 추가 점수 계산도 평가 횟수에 포함한다.

## 원칙 검토

새 의존성은 없다. 문서 변경/이력은 기존 EditorSession, 원본 수명/읽기는 VisionInspection, 점수/전역 후보/원본 검증은 CpuMatching에 남긴다. 세 점수 전략과 CPU/CUDA 선택을 재사용하며 기존 연속 입력 호출 계약을 유지한다. 공유 상태는 reader와 맵 캐시의 기존 잠금/용량 규칙으로 보호한다. 일반 알고리즘을 고정 패턴이나 특정 예상 위치에 종속시키지 않는다.

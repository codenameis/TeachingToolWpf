# 기존 그룹 확장·최초 준비·확정 GC 후속 검증

2026-10-15, `main`, 로컬 수정·검증만 진행. 커밋·푸시 없음. [ADR-050](decisions/0050-group-expansion-and-preparation-allocations.md).

## 구현한 동작

- 기존 그룹 하나에 바깥 독립 ROI를 그룹화하면 그 부모의 테두리가 커진다. 추가 ROI/번호를 만들지 않는다.
- 부모의 각도와 내부 ROI 형상·위치를 유지한다. 부모가 원·삼각형·오목 다각형이면 필요할 때 사각형으로 확장한다. 이미 안에 있으면 기존 도형 그대로다.
- 확장 사각형이 상위 모듈·루트의 실제 도형이나 이미지 경계를 넘으면 전체 작업을 거부한다. 상위 그룹 자동 확장은 하지 않는다.
- 성공은 부모 형상+편입 관계를 하나의 이력으로 기록한다. 실패는 문서·선택·이력과 기존 Redo를 유지한다. 기존 계층 깊이·순환/재편입 제한을 유지한다.

## 이전 지연의 원인

이전 `group-input-20261015/verified`의 원본 프레임과 프로파일을 동일 QPC 시간으로 연결했다.

| 이전 관측 | 분해 | 해석 |
|---|---|---|
| 최초 이동69.7095ms 간격 | 그 프레임 CPU2.2699ms, 준비 대기0.0073ms, 패킹0.6376ms, GC0ms | 첫 변환 준비 동안 새 preview가 게시되지 않은 간격. 첫 preview는88.63ms였다. 렌더 한 번의 계산이69.7ms 걸린 것은 아니다. |

| 최초 이동 확정27.2252ms 간격 | 패킹10.059ms, 제출10.4443ms | 새 형상 블록의 최초 GPU 자료 생성 비용도 별도로 남는다. |

`dotnet-trace`의 Windows 스택 샘플과 GC allocation 이벤트를 추가 수집했다. 최초 준비의 약85ms 샘플 구간에서 고정 ROI 색인 생성 약38ms, 변환 선택 생성 약19ms, 이동 색인 약15ms, 회전 제한 약9ms가 관찰되었다. 이는 표본 기반 스레드 시간이며 각 항목에 하위 호출/JIT가 포함되어 정확한 독립 CPU 시간으로 합산하지 않는다.

확정 구간에는 불변 ROI/사전 노드 외에도 GUID 배열·집합 버킷·이력 배열과 공간 변경 목록이 반복 할당되었다. 스택 원본은 `artifacts/group-expansion/trace-before/samples.nettrace`, `samples.speedscope.json`, 타입별 확정 구간 집계는 `trace-commit-allocations.txt`다. 프로파일러 실행의 프레임 수치는 전후 성능 비교에서 제외한다.

## 유지한 작은 최적화

1. 고정 ROI가 소수인 경우에도 준비된 BVH를 필터링한다. 불변 문서의 전체 값 열거와 색인 재생성을 피한다. 정확한 hit·visible·교차·회전 범위·메타데이터 질의를 전체 재구축과 비교했다.
2. 계층의 직접 자식 수로 임시 집합/큐 용량을 확보한다. 큰 배열의 여러 차례 성장·복사를 줄인다.
3. 이력 후보 수를 알면 해당 용량으로 시작한다. 변경 수가 용량과 같으면 불변 배열로 소유권을 넘기고, 일부만 변경되면 실제 길이로 복사한다.
4. 전체 공간 분할의 경계를 갱신하는 refit에서는 쓰지 않는 개별 형상 변경 목록을 만들지 않는다.

불변 문서·정확한 형상·Undo/Redo·취소·공간 블록 identity·GPU fence와 Present(1)을 유지한다. GC 강제 실행/중지, 시작 전 숨은 warmup, 후보 생략, 새 범용 캐시는 추가하지 않았다. 원칙별 검토는 ADR에 기록했다.

## 같은4만 ROI 조건의 재측정

8192×8192, 일반 ROI40,000개+부모3개,4단계, RTX3060 Laptop GPU, VRAM5.9GiB/예산5.1GiB, GPU debug OFF. [기존 시나리오](group-interaction-validation.md)의120Hz 입력·2초 이동/회전·확정 중 탐색·더블클릭을 사용한다. 각 프로세스는 최초1회와 반복3회를 측정한다. 화면 밖 진단 창이며 실제 물리 입력→모니터 지연 시험은 아니다.

동시 검사 프로젝트 편집으로 통합 빌드가 일시적으로 실패하여, 비교 실행에는 검증된 앱을 `artifacts/group-expansion/runtime`에 복사하고 해당 Core만 교체했다. ROI 외 호스트 코드를 비교 중 바꾸지 않았다. 이후 최신 통합 소스 빌드/회귀도 별도로 통과했다. 이 에이전트는 성능 측정과 빌드/테스트를 동시에 실행하지 않았다. 장치 전체의 외부 부하를 통제한 실험은 아니므로 편차를 숨기지 않는다.

단위는 ms, MB는10진수. 확정 시간은 worker 전체 완료까지이며 한 프레임 시간과 다르다. 할당은 각 활성 구간의 프로세스 전체 할당이다.

| 실행 | 최초 preview / 최초 이동 최대 간격 | 이동 확정 중앙값 / 평균 할당 | 회전 확정 중앙값 / 평균 할당 | 준비 후 확정 최대 간격 |
|---|---:|---:|---:|---:|
| before | 113.37 / 88.72 | 163.0 / 31.09MB | 169.7 / 31.07MB | 27.48 |
| filter (색인만) | 78.00 / 57.31 | 306.3 / 30.65MB | 162.9 / 31.14MB | 50.02 |
| allocated (전체 개선) | 86.85 / 67.36 | 142.8 / 25.01MB | 159.6 / 25.45MB | 34.03 |
| allocated-repeat (동일 코드 새 프로세스) | 129.57 / 107.38 | 314.3 / 24.84MB | 286.8 / 24.89MB | 51.23 |

확정 구간 할당은 두 최종 실행에서 약18~20% 줄었고 최초 이동 구간 할당도29.83→17.09/16.81MB로 줄었다. 이 재현되는 할당 감소와 질의 동등성을 근거로 변경을 유지했다. 최초 지연과 프레임 최대값의 일관된 개선은 확인하지 못했다. 한 실행의 빠른 결과만으로69.7ms/25.6ms 스파이크를 해결했다고 표현하지 않는다.

첫 최종 실행은 이동60.01~60.04FPS, 회전59.99~60.04FPS, 더블클릭·탐색60.00~60.01FPS였지만 회전 확정 최저58.56FPS였다. 동일 코드 재실행은 활성 구간54.23~60.18FPS, 최대56.87ms까지 변동했다. **엄격한 평균60FPS 및 모든 활성 프레임16.6667ms 이하 기준은 FAIL**이다. DXGI 표시 주기 추정으로 이 판정을 대체하지 않는다.

두 최종 실행의 더블클릭 선택 완료 평균1.68/3.01ms, 최대2.32/7.16ms. 각각48회 기대한 계층 선택을 검증했다. 모든 이동·회전에서 전체 ROI 값/선택의 Undo→Redo→Undo를 검증했다. 원본 `artifacts/group-expansion/<실행>/report.json`, `frames.csv`, `profile.csv`와 [원본 요약 JSON](group-expansion-results.json)에 최초 실행·GC·입력 대기·해시·나쁜 결과를 모두 남겼다.

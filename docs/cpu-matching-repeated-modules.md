# 반복 모듈 전체 검사 성능 후속

**후속 수정:** 이 문서는 후보 잘림과 Sub-NCC48개 위치 오류를 남겼던 이전 측정이다. 이후 원인 수정·전체 후보 처리·독립 자세 기준과 최적화 결과는 [전체 검색 정확도 검증](cpu-matching-full-search-accuracy.md)을 따른다.

2026-10-16. [ADR-062](decisions/0062-exact-repeated-tile-reuse.md). 현재 상태의 체크포인트 `f86e32d`를 사용자 승인으로 `origin/main`에 푸시했다. 아래 후속 변경은 로컬 수정·검증이며 추가 커밋·푸시는 하지 않았다. **CPU125ms/CUDA80ms 목표는 여전히 FAIL이다.**

## 입력과 기준

- 저장소 `kensa.png`는 **1024×1536**이다. 전체 12모듈의 메모리 패키지 48개를 대상으로 학습 ROI89×52를 사용한다. 개수와 학습한 대상의 자세만 확인하며, 48개 모두의 정밀 라벨을 확보한 현장 전수 검증은 아니다.
- 앱의 **8K 샘플8192×8192**은 2048픽셀 주기의 16모듈·256핀이다. 기존 `ProceduralTileSource`와 `TdcmAccuracy.SamplePins`의 독립 정답을 사용한다. 학습 ROI105.827×129.459, 중심759.518/546.178이다.
- 기존 `samples/CpuMatching.FullImage`는8192×8192에 변환한 패키지 8개를 배치한 별도 합성 데이터다. 밀집 반복 모듈이나 실제 촬영 8K와 구별한다.
- 점수0.75, 후보2048, 출력256, 각도-30~30°/10°간격, 배율1, 피라미드3, NMS반경=학습 ROI 짧은 변×0.6. 전후 동일하며 후보나 검색 위치를 줄이지 않았다.
- Ryzen5 5600H/32GB/RTX3060Laptop, Windows x64, Release. 실제 검사 버튼 Automation Invoke→원본 읽기→계산→게시→DX12 Present/fence→WPF Rendering을 관찰한다. 학습/앱 시작은 제외하고 첫 CUDA 준비는 포함한다. 물리 마우스 입력 대기/모니터 scan-out은 제외한다.

## 남긴 변경과 버린 실험

Line2D의 SIMD 누적 버퍼를 행별로 빌려 기존 최대4작업을 활용한다. 행 내부 float 연산 순서는 같다. 외부 `IRowScore`는 명시적으로 허용하지 않으면 계속 순차 실행한다.

Line2D/Chamfer는 후보 주변의 맵을 준비할 때 같은 크기·모든 픽셀이 동일한 기존 타일을 찾는다. 해시로 후보를 고른 뒤 전체 바이트를 비교한다. 공간 위치별 score/정밀 보정/최종 검증은 그대로 수행한다. 원본/중간 레벨에서만 적용하고 전역 후보 탐색은 모두 수행한다. 기존 최대32항목·맵 크기 추정512MiB 상한을 늘리지 않았다. 실제 촬영 모듈의 노이즈나 결함으로 픽셀이 다르면 재사용하지 않는다.

Sub-NCC의 표본 경계 범위를 자세별로 재사용한 실험은 희소8K CPU 후보 단계3755~3766→3075~3086ms였지만, 반복 모듈의 전체 비용은 개선되지 않았다. 동일 타일 공유 실험에서도 보정 단계가 느려졌고 공유 자세 캐시 경합 가능성을 확인했지만, 실행 환경의 영향과 분리해 원인을 확정하지는 못했다. 두 실험을 모두 제거했고 **Sub-NCC 알고리즘 파일은 체크포인트와 동일**하다. Chamfer의 단일 변수 누적 실험도 측정 전에 원복하여 최종 변경에 포함하지 않았다.

원시 결과·단계별 수치·전후 동일성 검사·소스 해시는 [검증 ZIP](data/cpu-repeated-modules-validation.zip)에 있다. 변경 전 마지막 Chamfer CUDA 모듈 실행에 빌드가 겹쳐 해당 조합의 시간 비교는 양쪽 첫2회만 사용한다. 나머지는 첫 실행을 포함한3회 중앙값이며 최대값/단계별 값도 JSON에 남겼다. 중간 NCC 공유 실험에서 발생한5회의 표시 완료10초 대기 실패는 별도 실패 기록으로 보존하고, 그 대기 시간을 표시 완료 시간으로 사용하지 않는다.

## 정확도와 미해결 항목

- 기본8K에서 Line2D/Chamfer는256개이며 최대 위치 약0.203px·각도 약0.022°다. 그러나 **후보2048 초과 플래그가 있으므로 검색 완료 합격은 아니다.** Kensa 전체의 두 방식도48개를 반환하지만 같은 후보 잘림이 있다.
- Sub-NCC는 기본8K에서256개를 반환하지만 **48개가 위치1px 기준을 넘고 최대 약30.072px**다. 각도와 개수만 보고 합격 처리하지 않는다. 이 실패는 체크포인트에도 존재하며 이번 속도 변경 전후 동일하다. 가느다란 핀에 대한 후보·정밀 보정의 위치 실패를 후속으로 해결해야 한다.
- Kensa 전체의 Sub-NCC는48개·잘림 없음과 알려진 학습 대상의 자세를 확인했다. 전수 위치·각도 정확도 합격을 의미하지 않는다.
- 원본 촬영8K/노이즈·조명 변화/다른PC·장시간은 NOT_RUN이다. 반복 모듈의 바이트 동일성이 성립하지 않으면 맵 공유 이득도 줄어든다.

## 검증과 재현

- PASS: CPU13 + CUDA63 + WPF/검사299 = **375개 테스트**, Release 빌드 경고0/오류0. 변경 C# 파일 공백·스타일·명명 검사 통과. 저장소 전체 형식 검사는 재실행하지 않았으며 이전54개 범위 밖 위반은 그대로다.
- PASS: 새 캐시는 동일 타일4회 준비→2회, 한 픽셀 변경 시3회로 분리하며 결과·평가 수가 같다. 이미지 끝의 다른 크기와 외부 순차 전략도 확인했다.
- PASS: 기존29조건×3방식×2장치=**174건**의 입력 해시·옵션·결과·평가 수·잘림 플래그가 이전과 정확히 같다. CPU/CUDA87조합 일치. 완전 정답168건 합격, 원본18V6건은 알려진 대상만 확인했다. Kensa는10회 준비 뒤3회, 나머지 회귀는10회 준비 뒤1회 측정했으며 첫 실행도 별도 기록했다.
- PASS: 최종 WPF 반복 모듈36회 + 희소8K18회 = **54회** 표시 확인과 전후 결과·평가 수 동일. 모듈 결과는 Line2D/Chamfer 최종 실행24회와 NCC 원복 후 별도 실행12회를 출처와 함께 합산했다. 정확도 합격54회를 뜻하지 않는다.
- FAIL: 반복 모듈의 후보 잘림/NCC 위치 정확도와125/80ms. 희소8K18회는 검출·위치·각도 기준을 통과했지만 시간은 모두 미달이다.

## 설계 검토

| 원칙 | 확인 |
|---|---|
| SRP | 공간 캐시가 동일 픽셀 맵 재사용을 소유하고 진단이 측정을 담당한다. |
| OCP | 기존 점수 전략은 기본 false로 동작을 보존하고 지원 전략만 명시적으로 선택한다. |
| LSP | 기존 순차 행/점수 전략, 취소, 중심 callback 계약을 자동 검증한다. |
| ISP | 행 병렬 허용은 행 점수 계약에만 추가했다. |
| DIP | Core에 WPF/CUDA 의존성을 추가하지 않았다. |
| Information Expert | 픽셀/영역을 가진 지역 캐시에서 동일성을 판단한다. |
| Creator | 행 계산이 대여 버퍼를 반환하고 캐시가 맵 수명을 보관한다. |
| Controller | UI의 검사 흐름과 판정은 바꾸지 않았다. |
| Low Coupling | 알고리즘/진단/표시 경계를 유지한다. |
| High Cohesion | 재사용 판단은 LocalScoreLevel, 행 누적은 Line2D에 남긴다. |
| Polymorphism | 지원하는 점수 구현만 병렬 행 계산을 허용한다. |
| Pure Fabrication | 기존 캐시를 확장하며 별도 관리자 계층을 만들지 않았다. |
| Indirection | 기존 점수 계약과 선택형 CUDA 연결을 유지한다. |
| Protected Variations | 외부 전략의 기본값과 정확한 픽셀 대조로 공유 가능 범위를 제한한다. |

# 세 템플릿 매칭 알고리즘 읽기

같은 패턴을 여러 위치에 대보고 가장 잘 맞는 위치를 찾는 것이 출발점이다. 이 구현은 위치뿐 아니라 각도·배율도 바꾸어 본다. 반복문과 배열, 평균, 삼각함수를 이해한다면 먼저 아래 순서로 읽으면 된다. 복잡한 CUDA 자원 관리는 마지막에 읽어도 된다.

## 공통 순서

진입점은 [PyramidSearch.Find](../src/CpuMatching.Core/PyramidSearch.cs)다. 세 방식은 이 순서를 공유하고 **점수 계산법**만 다르다.

1. `PreparePyramid`: 검색 영상을 자르고, 가로·세로를 절반씩 줄인 영상을 만든다. 큰 영상에서 모든 자세를 정밀하게 검사하는 비용을 줄이기 위해 작은 영상부터 찾는다. 원본 영상은 버리지 않는다.
2. `FindCoarseCandidates`: 지정한 배율과 각도를 차례대로 적용한다. 그 자세로 모든 중심 위치의 점수를 계산한다. 주변보다 좋은 위치만 후보로 남긴다. 후보 상한을 넘으면 검색 불완전 표시를 보존한다.
3. `RefinePyramid`: 후보 주변을 더 세밀하게 확인하면서 원본 해상도로 올라온다. 축소 좌표를 원본으로 돌릴 때 `2*x + 0.5`를 쓰는 이유는 픽셀 **중심**의 위치를 맞추기 위해서다.
4. `VerifyOriginal`: 0.5px, 0.25px 간격으로 자세를 보정하고 원본 점수를 확인한다. Line2D와 Chamfer는 실제 경계 위치로 한 번 더 보정한다. 실제 검색 도형 안에 중심이 있는지도 확인한다.
5. `Suppress`: 같은 대상을 여러 번 찾은 결과를 합치고, 최종 출력 상한을 적용한다. 후보 상한과 결과 상한은 서로 다른 경고다.

‘작은 영상에서 후보가 됐다’는 사실만으로 합격시키지 않는다. 최종 최소 점수는 원본에서 적용한다. [8K 전체 검색 후속](cpu-matching-performance.md)은 같은 점수·검색 간격·후보 예산을 유지한다. Sub-NCC의 축소 영상 위치 위상 누락은 아래의 중간 단계 검증으로 수정했다.

독립된 방향 맵과 후보는 최대4작업으로 나누고, 결과는 원래 후보 번호에 저장한다. 완료 순서가 중복 제거 순서를 바꾸지 않는다. 큰 영상에서는 [LocalScoreLevel](../src/CpuMatching.Core/LocalScoreLevel.cs)이 중간/원본 맵만 필요한 후보 주변에 준비한다. 처음 후보를 찾는 단계는 영상 전체를 검색한다. 템플릿과 거리 전파가 닿는 주변 여백도 함께 읽는다.

## Line2D: 밝기가 바뀌는 방향 비교

[Line2DMatcher](../src/CpuMatching.Line2D/Line2DMatcher.cs)는 템플릿에서 눈에 띄는 윤곽점을 고른다. 장면에는 16방향의 응답 맵을 만든다. 예를 들어 수직 경계의 밝기 변화 방향이 템플릿과 같으면 높은 점수, 반대이면 낮은 점수를 준다.

템플릿을 돌리면 윤곽점 위치와 그 방향을 함께 돌린다. 방향이 두 맵 사이에 있으면 두 응답을 섞는다. 모든 윤곽점 점수의 평균이 해당 자세의 점수다. 원본 위치가 픽셀 사이에 있으면 주변 네 픽셀도 보간한다. 이 공통 계산은 [DirectionalPoseScore](../src/CpuMatching.Core/DirectionalPoseScore.cs)에 있다.

축소 영상에서는 경계를 주변 3×3으로 넓히고 정수 위치로 계산한다. `ScoreRow`는 같은 계산을 CPU SIMD로 여러 픽셀씩 처리한다. 단순한 반복문으로 바꾸면 느려지므로 이 부분은 유지했다. CUDA도 SIMD 구간과 마지막 몇 픽셀의 기존 반올림 순서를 구별한다.

## Sub-NCC: 밝기 무늬 비교

[SubNccMatcher](../src/CpuMatching.SubNcc/SubNccMatcher.cs)는 명암을 직접 비교한다. `SelectPixels`에서 가장 작은 후보 검색 영상은 균일하게 고른 픽셀과 경계 픽셀을 함께 사용한다. 경계만 고르면 모두 비슷한 밝기가 될 수 있다. 중간 단계와 원본 정밀 검사에서는 사각형 내부 픽셀을 모두 쓴다. 작은 원판 무늬의 높은 점수만 따라가면 몇 픽셀 옆으로 잘못 이동할 수 있으므로, 첫 자세 보정은 한 단계 큰 영상에서 수행한다.

점수를 구할 때 템플릿 평균 밝기를 먼저 뺀다. 장면 쪽도 평균 밝기의 영향을 제거한다. 두 무늬의 곱을 더한 값을 각각의 명암 변화량으로 나눈 것이 ZNCC다. 이렇게 하면 단순히 전체가 밝아지는 변화에 덜 민감해진다. 변화량이 거의 없는 영역은 0점을 준다. CUDA도 원래의 `double` 합산과 표본 순서를 유지한다.

## Directional Chamfer: 가까운 윤곽과 방향 비교

[DirectionalChamferMatcher](../src/CpuMatching.DirectionalChamfer/DirectionalChamferMatcher.cs)의 맵에는 처음에 ‘이 방향의 윤곽까지 얼마나 먼가’를 넣는다.

- `SpreadSpatialDistances`: 이웃에서 전파된 거리와 현재 거리 중 작은 것을 고른다. 좌상단에서 한 번, 우하단에서 한 번 훑는다.
- `SpreadAcrossDirections`: 가까운 방향의 윤곽도 사용하되 방향 차이에 비용을 더한다.
- `ConvertDistanceToScore`: 가까울수록 높은 0~1 점수로 바꾼다. 이 맵을 사용한 자세 계산은 Line2D와 같은 `DirectionalPoseScore`를 쓴다.
- `Verify`: **템플릿 윤곽이 장면에 있는지**, **장면의 윤곽이 템플릿으로 설명되는지** 양쪽을 확인한다. 첫 방향만 확인하면 관계없는 조밀한 무늬가 잘 맞는 것으로 나올 수 있기 때문이다. 이전에 수정한 이 검증은 그대로 유지했다.

이 코드는 FDCM에서 착안한 구현이며 논문의 선분 적분 가속 전체를 구현한 것은 아니다.

## 경계로 위치·각도 보정하기

[EdgePoseRefiner](../src/CpuMatching.Core/EdgePoseRefiner.cs)는 각 템플릿 경계점 주변에서 방향이 비슷한 실제 경계를 `FindNearbyEdge`로 찾는다. 경계 사이의 오차를 줄이는 X 이동·Y 이동·회전, 세 보정량을 작은 연립방정식으로 구한다. 큰 오차는 비중을 줄이고, 처음 후보에서 너무 멀어지면 멈춘다. 반복 횟수·허용 범위·계산 순서는 유지했다.

## CPU+CUDA에서 달라지는 한 단계

`FindCoarseCandidates` 안의 **전체 위치 점수 계산**만 CUDA로 보낸다. 한 GPU 스레드가 한 위치를 맡으며, 같은 표본을 같은 순서로 더한다. 영상/방향 맵은 한 검색에서 한 번 전송하고, 각도마다 바뀐 표본 위치와 점수만 오간다. 후보 선택·중복 억제·원본 보정·Chamfer 양방향 검증은 CPU 공통 코드다. 최상위 피라미드가 원본인 작은 템플릿도 지원한다.

[CpuMatching.Cuda](../src/CpuMatching.Cuda/)는 장치 생성·메모리·전송·커널을 소유한다. 세 알고리즘 프로젝트는 CUDA 패키지를 참조하지 않는다. 앱이 `CudaTemplateScoreSession.Rent()`로 한 검색에 실행기를 빌려 주며, CPU를 선택하면 GPU를 초기화하지 않는다. 입력 맵은 대여 동안 변경하지 않는다. 취소는 제출한 GPU 작업을 완료한 뒤 버퍼를 반환한다. 장치 오류를 숨겨 CPU로 자동 전환하지 않는다.

작은 영역에서는 GPU 전송·호출 비용이 계산 절약보다 클 수 있다. GPU 사용 여부와 실제 속도 향상은 구별해야 한다. [사용법·검증·시간 비교](cpu-matching-cuda.md)를 참고한다.

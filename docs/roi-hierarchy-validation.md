# ROI 계층·명명·타입 즉시 적용 검증

**후속 규칙:** 2026-10-15부터 그룹의 이동·회전·크기 변경은 상위 실제 도형 안으로 제한한다. 일반 리프의 생성 후 자유 편집은 유지한다. 버튼은 `ROI 추가/그리기`로 통합하여 그룹 하나 선택 시 연결된 ROI, 그 외에는 독립 ROI를 만든다. `부모 추가/그리기`는 별도로 유지한다. 최신 사용법과 실행 결과는 [전체 View·그룹 경계 기록](views-mvvm-and-group-bounds.md)을 따른다. 아래는 2026-10-14 구현 당시의 기록이다.

2026-10-14. 현재 `main`에서 로컬 수정·검증만 수행한다. 이전 입력 리팩터링과 매뉴얼 작업을 보존했다. 계약은 [ADR-045](decisions/0045-roi-hierarchy-and-explicit-names.md)를 따른다.

## 사용법

1. 독립 도형은 `부모 그리기`, 자식은 부모 하나 선택 후 `자식 그리기`를 사용한다. 자식을 부모 밖으로 걸쳐 그리면 확정하지 않는다. 생성 후 이동·회전·크기 변경은 부모 밖에서도 가능하다.
2. 기존 독립 ROI를 선택해 `연결할 자식 지정`을 누르고, 부모 하나를 선택한 뒤 `선택 부모에 연결`을 누른다. 이미 부모가 있는 ROI는 먼저 다른 부모로 재연결할 수 없다.
3. 부모 하나와 독립 ROI를 그룹화하면 기존 부모에 연결하며 ROI가 추가되지 않는다. 부모가 없거나 부모 여러 개를 함께 묶을 때만 새 외곽 그룹을 만든다. 최대 `RootGroup → ModuleGroup → RoiGroup → Roi`이며 5단계를 만드는 작업은 거부한다. [후속 검증](mvvm-viewport-validation.md).
4. 설정 → ROI 색상과 선 두께에서 자식·ROI 그룹·모듈 그룹·루트 그룹의 기본/선택/다중 선택 색과 두께를 변경한다. 독립 ROI 슬롯은 별도로 유지한다.
5. 속성의 `검색 범위 ROI` 타입 선택 즉시 빨간 점선 범위가 적용된다(초기 양쪽 여유 20px). 여유 숫자·이름·형상은 기존 `변경 적용`으로 확정한다.

- 로그·캡처: `artifacts/roi-hierarchy-20261014/{gpu,warp}/artifacts/smoke.log`, `hierarchy-default.png`, `hierarchy-custom.png`, `explicit-hierarchy-app.png`.

## SOLID·GRASP 검토

| 원칙 | 판단 |
|---|---|
| SRP | 문서 계층 규칙은 Core, 색은 렌더/설정, UI는 요청 전달에 유지 |
| OCP | 기존 ROI 문서/준비 명령 경계를 사용. 신규 공급자 변형을 만들 이유 없음 |
| LSP | 동기/준비 그룹화의 같은 거부 규칙, 취소·실패·Undo/Redo 회귀 유지 |
| ISP | 기존 입력/표시 계약에 사용하지 않는 메서드 강제 없음 |
| DIP | Core에 WPF·GPU 의존성 없음. 앱이 표시와 입력을 조립 |
| Information Expert | 포함 판정은 기하, 계층 높이는 ROI 스냅샷, 이력은 세션 |
| Creator | 기존 세션/그룹 편집이 ID와 부모 관계 생성 |
| Controller | WPF 버튼은 기존 준비→게시 응용 명령에 위임 |
| Low Coupling | 검사 공급자/파일 로더/ROI 데이터 경계 유지 |
| High Cohesion | 그룹 편집·단계 계산·색 설정 책임을 기존 위치에 유지 |
| Polymorphism | 기존 입력 제스처/렌더 경로 유지. 단계를 위해 새 상속 계층을 만들지 않음 |
| Pure Fabrication | 파생 높이/역할 캐시를 스냅샷/렌더 기술 책임에 유지 |
| Indirection | 기존 VM→Core→불변 장면 연결 유지. 범용 중계 계층 추가 없음 |
| Protected Variations | 셰이더 배치는 렌더 내부에서 검사. GPU/WARP 공통 문서 의미 보존 |

원칙 예외 없음. 이름 변경은 의미 보존, 계층/타입 동작 변경은 사용자 요청으로 구별한다.

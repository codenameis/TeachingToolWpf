# PoseMatch 정확도 원인 수정과 남은 실패

2026-10-15, main 로컬 수정·검증. 사용자가 속도보다 정확도를 우선하고 PoseMatch 전체 탐색 유지를 확정했다. 최소 점수0.5, 창512, 스레드4, 자세 보정OFF를 고정했다. 전통적 후보 검색이나 정답 위치를 검색 입력으로 사용하지 않았다.

## 확인한 원인과 수정

`TdcmMatchingService.TrainAsync`는 큰 ROI를36×36으로 줄이면서 출력 픽셀당 원본 한 지점만 bilinear 보간했다. 검색 피라미드의 면적 평균과 달라 얇은 글자/선이 샘플 위상에 따라 사라졌다. 144×144 영상의4픽셀마다 한 줄인 밝은 선으로 재현했으며, 기존 코드는0°/90° 모두 평균 밝기 보존 테스트에 실패했다.

학습 출력 픽셀의 면적을 원본1픽셀 이하 간격으로 분할해 보간값을 평균하도록 수정했다. 원본 ROI의 회전·중심·마스크 거부·원본 reader 수명은 유지한다. 이는 회전 사각형의 정확한 다각형 적분이 아니라 균등 면적 표본화이며, 학습 시간이 증가할 수 있다. 작은 ROI의 확대 시에는 기존 bilinear 표본을 유지한다. 재학습해야 수정된 템플릿이 적용된다.

같은 RTX3060 Laptop PC에서 CPU/CUDA 각각 최초·반복2회 검사했다. 두 장치의 검출 개수·좌표는 같았고 각도는 소수점 수준 차이가 있었다. 아래는 CPU 결과다.

8K는 샘플 생성기의 핀 위치와 고정된 학습 ROI 오프셋(-0.482,-19.322), 명목0°로 계산했다. 예측 각도로 정답 위치까지 회전시키지 않는다. 핀의 일부만 포함한 학습 ROI이므로 핀 중심을 ROI 중심으로 대체하지 않는다. 대칭/부분 윤곽에서의 자세 모호성도 자동 정상 판정으로 숨기지 않는다.

검출-정답 거리로 일대일 연결하고 누락·오검출·중복을 별도로 집계한다. 연결 반경은 Kensa25px/8K60px이며, **허용 정확도는 별도1px/1°**다. 반경은 후보 대응을 위한 값이지 합격 오차가 아니다. 현재 연결 반경 안에서 중복/오검출은0이지만, Kensa28개 중27개와8K110개 전부가 위치 기준에 실패했고 각도는 둘 다 전부 실패했다. 미검출을 제외한 오차임을 유의한다.

증거: [Kensa 전체 로그](posematch-tdcm-accuracy-kensa.json), [8K 전체 로그](posematch-tdcm-accuracy-8k.json). 이전 원본 로그는 덮어쓰지 않고 별도 보존했다.

## 설계 원칙 검토

SOLID: SRP는 학습 표본화와 진단 평가를 각각 기존 서비스/진단에 유지, OCP는 다른 매칭 방식 불변, LSP는 서비스 입력·취소·수명 계약 보존, ISP는 공개 계약 추가 없음, DIP는 기존 원본 loader 주입 유지다.

GRASP: Information Expert는 ROI를 가진 학습 서비스가 역변환, Creator는 기존 서비스가 템플릿 생성, Controller는 VM 유지, Low Coupling은 정답을 검색에 전달하지 않음, High Cohesion은 검증만 진단에 배치, Polymorphism은 기존 서비스 계약 보존(새 변형 없음), Pure Fabrication은 진단 평가의 기술 책임 분리, Indirection은 기존 reader 사용, Protected Variations는 ONNX/CPU/CUDA 경계 불변이다. 원칙 예외 없음. 편집·이력·다른 진행 중 작업은 변경하지 않았다.

# ken32 전체 검색 병목과 결과 보존 최적화

2026-10-16. 원본17,280×30,720의 Line2D CPU 전체 검색을 같은 조건으로 비교한다. 로컬 수정·검증만 진행한다.

## 측정 조건

96×96 템플릿의 원본 영역은(14208,5760)~(14304,5856)이다. 최종 점수0.75, 각도−30~30°/10°, 배율1, 피라미드3, 후보 묶음2048, 결과 상한256, CPU 작업4를 유지한다. 새 템플릿을 매번 학습하며 파일 캐시 준비/PNG 디코딩과 화면 표시는 검색 시간에서 제외한다. 검사 중 원본 창 읽기/변환은 포함한다. 이미지·템플릿·위치를 고정한 제품 최적화는 하지 않는다.

원본 SHA-256은 `3E482155A9A0C86F5E85821B62D8CD2CBF704B89747C4FCCADF40C0EE21C156A`다. 성능 비교는 별도 실행 폴더에서 원본 reader 등 종속 DLL을 고정한다. 공통 매칭과 벤치마크 DLL을 교체하고 Line2D는 기준과 같은 소스로 빌드한다(소스 해시 동일). 공유 작업 폴더의 다른 변경은 성능 개선에 포함하지 않는다. 이 작업의 빌드/테스트와 전체 성능 측정을 겹치지 않지만 다른 프로세스·OS 캐시·열 상태를 완전히 통제한 실험은 아니다.

## 시간이 걸린 곳

기존644.383초는 준비0.002초, 전역 후보48.802초, 피라미드 정밀 보정359.392초, 원본 검증236.092초, 최종 억제0.083초다. **정밀 보정/검증이 약92.4%**다. 원본 창 읽기/변환258.590초는 이 단계들 안에서 발생한 비용이며 별도로 더하지 않는다.

동일 코드의 계측 기준 재실행은676.282초였다. 원본 창 읽기/변환277.947초, 정밀 검색용 맵 읽기358,058회, 맵 생성77,109회였다. 원본/중간/축소 레벨의 맵 생성은61,026/11,912/4,171회이며 생성 누적325.623초였다. 맵 읽기 계측은 reader 잠금 대기까지 포함할 수 있으므로 여러 시간 값을 합산해 전체 경과 시간으로 해석하지 않는다.

20초 관리 스레드 표본에서는 `OrientationLevel.BuildMap`이 주요 계산 함수였고 잠금/작업 대기도 많았다. 쉬고 있는 스레드까지 포함하므로 표본 비율을 CPU 사용률이나 전체 경과 시간의 분해로 표현하지 않는다. 템플릿 특징 추출은 주요 병목이 아니어서 별도 캐시를 추가하지 않았다.

## 적용한 변경

1. **퇴출한 맵의 위치 연결만 제거한다.** `LocalScoreLevel`은 같은 픽셀의 맵을 공유하지만 기존에는 맵 하나를 교체할 때 모든 위치 연결을 비웠다. 남아 있는 맵도 원본 읽기·해시·픽셀 전체 비교를 다시 해야 했다. 교체되는 맵을 가리키는 위치만 제거하고 다른 연결은 보존한다.
2. **후보 하나의 원본 정밀 보정 직후 검증한다.** 기존에는 한 묶음의 원본 보정을 모두 끝내고 검증 단계에서 같은 지역을 다시 순회했다. 제한된 캐시에서 이미 퇴출된 맵을 다시 만들었다. 창 입력에 한해 두 단계를 이어서 계산해 방금 준비한 맵을 재사용한다. 중간/축소 피라미드 탐색은 유지한다.

원본 보정 후 정확히 같은 `(X,Y,Angle,Scale)`로 모인 후보는 기존 `DistinctBy`와 같은 키로 묶는다. 묶음 안의 `ConcurrentDictionary`와 `Lazy`로 검증을 한 번만 수행하고, **원래 후보 순서로 복원한 뒤** 점수 통과/도형 판정/최종 억제를 수행한다. 점수의 누적 순서, 전체 후보, 특징 표본, 각도·배율 범위, 평가 수, CPU 작업4,256px 맵 창 및 기존 캐시 상한을 유지한다. 다른 영상이나 이전 프레임의 결과를 가져오지 않는다.

창 입력의 `Timings.Verification`에는 이제 원본 정밀 보정까지 포함된다. 전후의 Refinement/Verification을 각각 직접 비교하지 않고 두 단계의 합과 전체 시간을 비교한다. 연속 메모리 입력은 기존 단계 경계를 유지한다.

## 실측

## 결과 보존과 검증

외부 벤치마크만 `CpuMatching.Search` 진단을 구독한다. 전역 후보·정밀화 후·원본 검증 후·점수 통과·최종 억제 후의 **모든** X/Y/각도/배율/점수를 순서대로 SHA-256 비교한다. 마지막256개만 비교하는 것으로 후보 보존을 대신하지 않는다. 진단은 검색 조건을 바꾸지 않으며 제품 UI에 측정 기능을 추가하지 않는다.

최종 전체의 후보181,779개/89묶음, 정밀 자세161,735개, 검증161,735개, 점수 통과3,405개, 억제 후1,167개 및 각 단계 전체 해시가 기준과 같다. 평가535,591,684회와 출력256개도 완전히 같다. 후보 절단은 없으며 기존 출력 상한 경고는 유지한다. 알려진 자기 위치(14256,5808),각도0°,점수0.9883737742027242도 동일하다.

- 캐시 회귀는 기존 코드에서 실패하고 수정 후 통과했다. 남아 있는 맵은 재읽지 않고 퇴출된 맵의 다른 위치 연결은 제거하는지 확인한다.
- 새 결합 회귀는 작업자1/4에서12개 후보가4개 자세로 모일 때 검증4회, 평가 수, 결과 및 최종 도형 판정 호출 순서가 같은지 확인한다.
- 최종 Release 빌드 경고0/오류0. CPU46·원본 검사120·WPF315·실CUDA83, 총564건 PASS다. 세 방식의 피라미드1/2/3단계·원본 좌표·축소 위상·창 경계·출력 상한·취소·21억 초과 픽셀 가상 입력을 포함한다. 별도 도형 검사의 OpenCV native 탐색 경로는 설치된 패키지 경로를 테스트 프로세스에만 지정했다.
- 최적화 전 단계에서 기존19조건×3방식=57조합의 전체 결과/점수/후보/평가 해시가 이전 결과와 같았다. Kensa48/48·합성8K256/256·경계 회전8/8을 유지했다. 이 회귀의 시간은 동시 형식 검사/외부 부하가 있어 성능 비교에 사용하지 않는다. 최종 결합 버전의 검증과 구별한다.
- 최종 변경10개 C# 파일의 공백 적용·스타일/명명 검사와 `git diff --check`는 PASS다. 전체 필수 형식 검사는 실행 시점 범위 밖65파일 위반으로 FAIL이었다. 관련 없는 파일은 임의로 고치지 않았다.

[검증 묶음](data/ken32-matching-performance-validation.zip)에 전체 전후 JSON·전량 비교 스크립트·최종564테스트·빌드/형식 결과·프로파일과 입력/소스/실행 DLL 해시를 보존한다. 기존644초 기록과도 최종 결과·후보·평가가 동일한지 확인했다.

## 원칙 검토와 한계

SRP/Information Expert: 맵과 위치 연결의 수명은 기존 캐시, 검색 순서는 기존 공통 검색이 맡는다. OCP/LSP/Polymorphism: 세 점수 전략과 입력 소스·취소·좌표 계약을 유지한다. ISP/DIP/Low Coupling/Indirection/Protected Variations: 공개 검색 계약/의존성을 늘리지 않고 BCL 진단 Observer로 외부 호스트가 구독한다. High Cohesion/Pure Fabrication: 계측/해시/보고서는 벤치마크에 둔다. Creator: 현재 후보 묶음만 검증 공유 객체를 소유한다. Controller: UI/명령/문서 이력은 변경하지 않는다. 성능을 위한 설계 원칙 예외는 없다.

ken32 전체 정답 라벨은 없다. 전후 동일성은 기존 동작 보존의 근거이며 현장 전수 정확도나125/80ms 버튼→표시 목표 달성을 뜻하지 않는다. 결과 상한256 경고를 유지한다. 이번 전체 실측은 Line2D CPU이며 Sub-NCC/Chamfer/CUDA의 ken32 전체 시간·정확도로 일반화하지 않는다.

CHAPTER 04 · IMAGE TILING & SPATIAL ALGORITHMS

이미지 타일링 피라미드와 BVH 공간 탐색 트리

17,280 × 30,720(5.3억 화소) 이미지를 그래픽카드 메모리 폭발 없이 부드럽게 보여주는 다중 해상도 타일 피라미드와, 수만 개의 ROI 중 마우스가 클릭한 도형을 단 몇 번의 비교로 찾아내는 BVH 이진 공간 분할 트리의 원리를 배웁니다.

ALGORITHM 1 · IMAGE TILING & PYRAMID

1. 네이버·구글 지도는 어떻게 지구 전체를 0.1초 만에 띄울까요?

핵심 비결: 이미지를 통째로 불러오지 않고, 가로·세로 512 × 512 픽셀 크기의 정사각형 조각(타일, Tile)으로 바둑판처럼 쪼갠 뒤 현재 모니터 화면에 보이는 조각만 불러옵니다!

만약 5.3억 화소 이미지를 멀리 축소해서(예: 배율 Scale = 0.125, 즉 1/8 크기) 한눈에 보려고 할 때 원본 타일 수천 개를 전부 읽으면 컴퓨터가 멈춰 버립니다.
그래서 가로·세로를 절반(1/2)씩 미리 줄여 놓은 피라미드 층(Level 0, Level 1, Level 2...)을 준비해 둡니다.

📐 핵심 공식 1 — 고1 로그(log2)로 피라미드 층(Level) 고르기
① 레벨 L의 이미지 크기 WL = ⌊W0 + 2L − 12L⌋, HL = ⌊H0 + 2L − 12L⌋
② 현재 화면 배율 S에 딱 맞는 레벨 선택 (TilePlanner) L = clamp(⌊log2(1S)⌋,  0,  Lmax)
③ 화면에 보이는 타일 번호 범위 (TileSize = 512) colmin = ⌊xmin512⌋, colmax = ⌊xmax512⌋

예를 들어 화면을 1/4 배율(S = 0.25)로 축소하면 1 / S = 4이고, log2(4) = 2이므로 자동으로 Level 2(1/4 축소본) 타일을 선택합니다.
또한 그래픽카드 메모리가 무한정 늘어나지 않도록, 논리 타일 캐시 예산을 256MiB로 정해 두고 가장 오래 안 쓴 타일부터 지우는 LRU(Least Recently Used) 퇴출 규칙을 사용합니다.

ALGORITHM 2 · BVH SPATIAL INDEX

2. 스무고개로 도형 찾기: BVH 이진 공간 트리

스무고개 원리: 10,000개의 ROI 중 마우스가 클릭한 도형을 찾으려고 1번부터 10,000번까지 다 물어보면 너무 느립니다.
대신 "왼쪽 반쪽에 있니, 오른쪽 반쪽에 있니?" 하고 큰 상자부터 물어보면 틀린 쪽 절반(5,000개)을 한 번에 건너뛸 수 있습니다!

이처럼 도형들을 감싸는 바깥 사각형(AABB, Axis-Aligned Bounding Box)을 반씩 묶어 나무 모양으로 만든 자료구조를 BVH(Bounding Volume Hierarchy)라고 부릅니다.
10,000개의 도형이 있어도 log2(10000) ≈ 14번 안팎의 상자 확인만으로 클릭된 도형을 즉시 찾아냅니다.

🌳 인터랙티브 실험실: BVH 공간 트리 가지치기 (Pruning)
캔버스 위에서 마우스를 움직여 보세요. 마우스가 없는 쪽 그룹은 내부 ROI를 아예 검사하지 않고 통째로 건너뜁니다!
src/VisionCanvas.Core/Geometry/RoiSpatialIndex.cs & BvhNodePath.cs & src/VisionCanvas.Core/Editing/RoiIdSet.cs O(log N) BVH 가지치기 탐색, 1-based BvhNodePath(_valueMinusOne), RoiIdSet 영속 델타 
// 1. BVH 트리 가지치기 탐색 (O(log N)): 부모 상자와 안 겹치면 하위 수천 개 노드를 통째로 건너뜀!
private static void QueryNode(Node? node, BoundsD queryBounds, List<Guid> results)
{
    if (node is null || !node.Bounds.Intersects(queryBounds)) return;

    if (node.LeafEntries is { } entries)
    {
        foreach (var entry in entries)
            if (entry.Bounds.Intersects(queryBounds))
                results.Add(entry.Id);
        return;
    }
    QueryNode(node.Left, queryBounds, results);
    QueryNode(node.Right, queryBounds, results);
}

// 2. default(0)에서도 루트(Value=1) 불변식을 유지하는 BvhNodePath와 O(log Δ) RoiIdSet
public readonly record struct BvhNodePath
{
    private readonly uint _valueMinusOne;
    public static BvhNodePath Root => default;
    public uint Value => _valueMinusOne + 1;
    public BvhNodePath LeftChild() => new(Value << 1);
    public BvhNodePath RightChild() => new((Value << 1) | 1);
}
ALGORITHM 3 · BISECTION & FIDUCIAL ALIGNMENT

3. 이분 탐색 경계 클램핑과 계층별 마크 보정

마지막으로, 실제 산업 현장에서 꼭 필요한 두 가지 기하 알고리즘을 정리해 봅시다.

① 이분 탐색 경계 제한 (RoiMotionBounds)

회전된 다각형 ROI를 드래그할 때 이미지 밖으로 삐져나가지 않게 막으려면 어디까지 이동할 수 있을까요?
이동 비율 t ∈ [0, 1] 구간을 반씩 쪼개어 검사하는 이분 탐색(Bisection)을 20회 반복하면, 1 / 220 ≈ 0.000001 정밀도로 이미지 테두리에 딱 붙는 최대 이동량을 구할 수 있습니다.

② 계층별 마크 보정 (FiducialAlignment)

카메라 앞에 놓인 기판(PCB)이 살짝 밀리거나 돌아갔을 때, 기준 마크(Fiducial) 1점을 찍으면 (dx, dy) 평행이동을 구하고, 2~4점을 찍으면 회전각 dθ까지 계산합니다.
RoiAlignmentMap은 전체 기판 → 모듈 → 개별 ROI 그룹의 보정값을 합성하여 원래 티칭 좌표에 단 한 번 적용합니다.

CHAPTER 01 · HIGH SCHOOL MATH TO C# STRUCT

고등학교 1학년 수학으로 만드는 2D 기하 엔진

"그래픽 엔진 수학"이라고 하면 어렵게 느껴지지만, 실제로는 중학교 피타고라스 정리, 고1 일차함수, 그리고 삼각비(sin, cos) 딱 세 가지만 있으면 충분합니다.
이 세 가지 공식이 VisionGeometry 프로젝트의 C# 코드로 어떻게 바뀌는지 하나씩 따라가 봅시다.

STEP 0 · WARM-UP PREREQUISITES

0. 워밍업: 수학 공식을 보기 전에 꼭 알아야 할 2가지 기초

잠깐! 바로 수식부터 보면 어지럽습니다. 먼저 ① 왜 컴퓨터 화면은 Y축이 아래로 내려가는지, 그리고 ② 왜 C#에서 class 대신 readonly record struct를 쓰는지부터 1분 만에 감을 잡아 봅시다!

① 수학 교과서 좌표계 vs 모니터 화면 좌표계

학교 수학 시간의 그래프는 왼쪽 아래가 (0, 0)이고 위로 갈수록 +Y가 커지죠?
하지만 모든 컴퓨터 모니터와 카메라 사진은 공책 글씨를 읽듯이 '왼쪽 맨 위 모서리'가 원점 (0, 0)이고, 아래로 내려갈수록 +Y가 커집니다! 이 차이 때문에 각도 +θ는 시계 방향 회전이 됩니다.

② 왜 class 대신 readonly record struct를 쓸까요?

마우스를 움직일 때 점 (X, Y) 계산은 1초에 수백만 번 일어납니다. 만약 점을 class로 만들면 힙(Heap) 메모리에 쓰레기가 쌓여 가비지 컬렉터(GC) 때문에 화면이 뚝뚝 끊깁니다.
반면 readonly record struct는 함수가 끝나면 즉시 사라지는 초고속 스택(Stack) 메모리에 놓이고, == 비교와 with 복사 문법까지 자동으로 만들어 줍니다!

STEP 1 · POINT & VECTOR

1. 점(Point)과 화살표(Vector), 그리고 내적·외적 한 걸음씩 유도하기

한 줄 요약: 화면 위의 위치를 나타내면 '점(Point)'이고, 한 점에서 다른 점으로 향하는 이동량(방향과 거리)을 나타내면 '벡터(Vector)'입니다.

도착점 B(x₂, y₂)에서 출발점 A(x₁, y₁)를 빼면(B - A), A에서 B로 향하는 화살표 벡터 (Δx, Δy) = (x₂ - x₁, y₂ - y₁)이 만들어집니다.

① 두 점 사이의 거리와 LengthSquared

중학교 2학년 때 배운 피타고라스 정리 c2 = a2 + b2 입니다!
단순히 "마우스가 반지름 6픽셀 안에 들어왔니?"만 비교할 때는 계산이 느린 루트(Math.Sqrt)를 씌우지 않고 거리의 제곱(dx*dx + dy*dy <= 36)끼리 비교하면 훨씬 빠릅니다.

② 내적 (Dot Product) = 그림자 길이

위에서 손전등을 수직으로 비췄을 때 한 화살표가 다른 화살표 바닥에 만드는 그림자 길이입니다.
계산식은 A.X * B.X + A.Y * B.Y이며, 도형이 부모 벽에 부딪혀 벽을 따라 미끄러질 거리(Wall Sliding)를 구할 때 핵심으로 쓰입니다.

③ 2D 외적 (Cross Product) = 좌우 방향 판별기

두 화살표가 이루는 평행사변형의 넓이이자, 시계 방향(+)으로 꺾였는지 반시계 방향(-)으로 꺾였는지 알려주는 나침반입니다.
계산식은 A.X * B.Y - A.Y * B.X이며, 다각형 선분이 8자로 꼬였는지 검사할 때 쓰입니다.

📐 핵심 공식 1 — 거리·내적·외적 (PointD 구조체)
거리d = √(Δx)2 + (Δy)2 | 내적A · B = AxBx + AyBy | 외적A × B = AxBy − AyBx

🔢 실제 숫자 대입 연습: 점 A(10, 20)과 B(13, 24)가 있을 때 Δx = 3, Δy = 4이므로 거리 제곱은 3² + 4² = 25이고 실제 거리는 √25 = 5픽셀입니다!

src/VisionGeometry/PointD.cs 불변(readonly) 2D 좌표 구조체 
public readonly record struct PointD(double X, double Y)
{
    public static PointD operator +(PointD a, PointD b) => new(a.X + b.X, a.Y + b.Y);
    public static PointD operator -(PointD a, PointD b) => new(a.X - b.X, a.Y - b.Y);

    // 내적: 두 벡터가 얼마나 같은 방향인지 계산
    public static double Dot(PointD a, PointD b) => (a.X * b.X) + (a.Y * b.Y);

    // 외적: 회전 방향(부호)과 평행사변형 넓이 계산
    public static double Cross(PointD a, PointD b) => (a.X * b.Y) - (a.Y * b.X);

    // 제곱근(Sqrt) 없이 빠르게 거리 비교할 때 사용
    public double DistanceSquaredTo(PointD other)
    {
        double dx = X - other.X;
        double dy = Y - other.Y;
        return (dx * dx) + (dy * dy);
    }
}
STEP 2 · VIEWPORT TRANSFORM & ZOOMAT

2. 일차함수로 이해하는 화면 확대·축소 (ZoomAt)

왜 중요할까요? 지도 앱에서 마우스 커서를 특정 건물 위에 두고 휠을 굴리면, 그 건물이 마우스 커서 밑에 딱 붙어 있는 채로 주변만 확대됩니다.
이 마법이 바로 고1 일차함수입니다!

원본 이미지 좌표 Pimg를 화면 픽셀 좌표 Pscr로 바꾸는 식은 기울기가 S(배율, Scale)이고 y절편이 T(이동량, Offset)인 일차함수 y = Sx + T와 똑같습니다.

📐 핵심 공식 2 — 정변환 · 역변환 · 마우스 기준 줌(ZoomAt)
① 이미지 → 화면 (정변환) Pscr = Pimg × S + T
② 화면 → 이미지 (역변환) Pimg = Pscr − TS
③ 마우스 고정 줌(ZoomAt): 배율이 S → S'으로 바뀔 때, 커서 아래 이미지 점 Pimg가 화면 커서 위치 Pcursor에 그대로 남으려면 새 이동량 T'은 다음과 같습니다.
T' = Pcursor − (Pimg × S')
src/VisionGeometry/ViewportTransform.cs 마우스 커서 고정 줌(ZoomAt) 구현 
public readonly record struct ViewportTransform(double Scale, double OffsetX, double OffsetY)
{
    public PointD ImageToScreen(PointD imagePt) =>
        new((imagePt.X * Scale) + OffsetX, (imagePt.Y * Scale) + OffsetY);

    public PointD ScreenToImage(PointD screenPt) =>
        new((screenPt.X - OffsetX) / Scale, (screenPt.Y - OffsetY) / Scale);

    public ViewportTransform ZoomAt(PointD screenAnchor, double newScale)
    {
        // 1. 줌 하기 직전, 마우스 커서 아래에 있던 이미지 좌표를 구합니다.
        PointD anchorImage = ScreenToImage(screenAnchor);

        // 2. 새 배율(newScale)에서도 그 이미지 좌표가 같은 화면 위치에 오도록 Offset을 역산합니다.
        double newOffsetX = screenAnchor.X - (anchorImage.X * newScale);
        double newOffsetY = screenAnchor.Y - (anchorImage.Y * newScale);

        return new ViewportTransform(newScale, newOffsetX, newOffsetY);
    }
}
STEP 3 · 2D ROTATION & INVERSE HIT-TEST

3. 삐딱하게 돌아간 상자(ROI)를 클릭했는지 어떻게 알까요?

발상의 전환: 30도 기울어진 사각형 안에 마우스가 들어왔는지 직접 계산하려면 부등식이 아주 복잡해집니다.
대신 마우스 좌표를 반대 방향(-30도)으로 되돌려 놓으면 반듯한 사각형 검사가 됩니다!

점 (x, y)를 원점 기준으로 각도 θ만큼 회전시키는 공식은 삼각비 cos θ와 sin θ로 이루어집니다.
그리고 반대 방향(−θ)으로 되돌릴 때는 cos(−θ) = cos θ, sin(−θ) = −sin θ 성질 덕분에 부호 하나만 바꾸면 즉시 역변환이 완성됩니다.

📐 핵심 공식 3 — 2D 회전 정변환과 역변환 (RigidTransform2D & RoiGeometry)
✏️ 한 걸음씩 유도하기: 가로 단위벡터 (1, 0)을 θ만큼 돌리면 (cos θ, sin θ)가 되고, 세로 단위벡터 (0, 1)을 θ만큼 돌리면 (-sin θ, cos θ)가 됩니다. 따라서 점 (x, y)를 회전한 위치는 두 벡터에 각각 x와 y를 곱해 더한 값입니다!
정변환 (+θ 회전 후 이동) x' = x cos θ − y sin θ + Tx, y' = x sin θ + y cos θ + Ty
역변환 (이동 제거 후 −θ 역회전, Δx = x' − Tx, Δy = y' − Ty) x = Δx cos θ + Δy sin θ, y = −Δx sin θ + Δy cos θ
src/VisionGeometry/RigidTransform2D.cs 정회전(Transform) 및 역회전(InverseTransform) 구현 
public readonly record struct RigidTransform2D(double Dx, double Dy, double DTheta)
{
    // 정변환: 원점 기준 +DTheta 회전 후 (Dx, Dy) 평행이동
    public PointD Transform(PointD p)
    {
        double c = Math.Cos(DTheta), s = Math.Sin(DTheta);
        return new PointD((p.X * c) - (p.Y * s) + Dx, (p.X * s) + (p.Y * c) + Dy);
    }

    // 역변환: (Dx, Dy) 이동을 먼저 빼고 -DTheta 역회전 (기울어진 도형 히트테스트의 핵심!)
    public PointD InverseTransform(PointD p)
    {
        double rx = p.X - Dx, ry = p.Y - Dy;
        double c = Math.Cos(DTheta), s = Math.Sin(DTheta);
        return new PointD((rx * c) + (ry * s), (-rx * s) + (ry * c));
    }
}

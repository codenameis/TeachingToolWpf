CHAPTER 02 · OS WINDOW HANDLE & HARDWARE VECTOR

HWND, IntPtr, 그리고 SIMD 벡터 가속

C#과 WPF만 공부했을 때 가장 생소하게 느껴지는 세 단어가 바로 HWND, IntPtr(또는 nint), 그리고 SIMD입니다.
운영체제(Windows)와 그래픽카드, CPU 하드웨어를 직접 다루기 위해 꼭 필요한 이 세 가지 개념을 비유와 함께 명쾌하게 풀어봅니다.

CONCEPT 1 · HWND & INTPTR

1. HWND와 IntPtr(nint)은 무엇인가요?

일상 비유: 아파트 관리실(Windows 운영체제)은 각 세대를 부를 때 '철수네 집' 같은 이름 대신 '101동 502호'라는 고유 번호표를 씁니다.
이 번호표가 바로 HWND이고, 번호표를 C# 변수에 담는 그릇이 IntPtr(nint)입니다.

그래픽카드(DirectX 12, Vulkan, wgpu)한테 "이 사각형 영역에 그림을 그려줘!"라고 명령하려면, 그래픽카드가 알아들을 수 있는 Windows 운영체제의 진짜 창 번호(Handle to a Window, HWND)를 건네주어야 합니다.

그런데 WPF의 일반 버튼이나 그리드는 운영체제 입장에서는 별도의 창이 아니라, 큰 창 하나 안에 그려진 그림일 뿐입니다.
그래서 VisionCanvas는 WPF의 HwndHost를 상속받아, 캔버스 영역만을 위한 진짜 Win32 자식 창(ViewportWindow)을 만들고 그 창 번호(IntPtr)를 그래픽카드에 연결합니다.

① HWND (Handle to a Window)

Windows가 화면의 각 창을 식별하기 위해 발급하는 64비트 정수 번호표입니다.
마우스 캡처(SetCapture), 커서 변경, 그래픽카드 스왑체인 연결이 모두 이 번호표를 기준으로 동작합니다.

② IntPtr 과 nint

메모리 주소나 운영체제 핸들(번호표)을 담는 C#의 특수 정수 타입입니다.
32비트 컴퓨터에서는 4바이트, 64비트 컴퓨터에서는 8바이트 크기로 자동 조절되며, 최신 C#에서는 nint라는 짧은 키워드로도 똑같이 쓸 수 있습니다.

CONCEPT 2 · WNDPROC & BIT UNPACKING

2. 마우스 좌표는 왜 비트 연산(&, >>)으로 꺼낼까요?

핵심 원리: Windows 운영체제는 마우스가 움직일 때마다 숫자 하나(lParam) 안에 가로 좌표(X)와 세로 좌표(Y)를 반씩 합쳐서 배달해 줍니다.

Windows가 보내주는 WM_MOUSEMOVE 메시지의 lParam을 열어보면, 아래쪽 16비트(하위 2바이트)에는 X 좌표가 들어 있고, 그 위쪽 16비트(상위 2바이트)에는 Y 좌표가 나란히 들어 있습니다.
도시락통 하나에 밥과 반찬을 칸막이로 나누어 담은 셈이지요.

📐 핵심 공식 — lParam 32비트에서 (X, Y) 꺼내기 (ViewportWindow.cs)
하위 16비트(X 좌표)short x = (short)(v & 0xFFFF); 상위 16비트(Y 좌표)short y = (short)((v >> 16) & 0xFFFF);
⚠️ 왜 int가 아니라 꼭 (short)로 먼저 변환할까요?

마우스를 드래그한 채로 창 왼쪽이나 위쪽 바깥으로 나가면 좌표가 음수(예: -15px)가 됩니다.
16비트 부호 있는 정수인 short로 캐스팅해야만 0xFFF1 같은 비트 패턴이 양수 65521로 잘못 읽히지 않고 정확한 음수 -15로 복원됩니다!

src/VisionCanvas.Host/Controls/ViewportWindow.cs Win32 메시지 루프 및 좌표 언패킹 
protected override IntPtr WndProc(
    IntPtr hwnd, int msg, IntPtr wParam, IntPtr lParam, ref bool handled)
{
    switch (msg)
    {
        case NativeMethods.WM_LBUTTONDOWN:
            // 창 밖으로 드래그해도 마우스 신호를 놓치지 않도록 캡처
            NativeMethods.SetCapture(hwnd);
            ForwardMouseDown(UnpackPoint(lParam));
            handled = true;
            break;

        case NativeMethods.WM_MOUSEMOVE:
            ForwardMouseMove(UnpackPoint(lParam));
            handled = true;
            break;
    }
    return IntPtr.Zero;
}

private static PointD UnpackPoint(IntPtr lParam)
{
    long v = lParam.ToInt64();
    short x = (short)(v & 0xFFFF);
    short y = (short)((v >> 16) & 0xFFFF);
    return new PointD(x, y);
}
CONCEPT 3 · SIMD VECTOR256

3. SIMD란 무엇인가요? (CPU의 8차선 고속도로)

비유로 이해하기: 일반 for 반복문이 1차선 도로에서 자동차를 한 대씩 통과시키는 것이라면, SIMD(Single Instruction, Multiple Data)는 8차선·16차선 톨게이트에서 명령 한 번으로 여러 픽셀을 동시에 통과시키는 기술입니다.

최신 CPU 안에는 256비트(32바이트) 크기의 넓은 계산 그릇인 Vector256 레지스터가 들어 있습니다.
여기에 32비트 정수(int) 8개 또는 16비트 픽셀(ushort) 16개를 나란히 담고 + 명령을 내리면, 단 한 번의 CPU 클럭으로 8개~16개의 계산이 동시에 끝납니다.

실제로 VisionCanvas는 5.3억 화소(ken32.png) 이미지의 다중 해상도 피라미드를 만들 때 Vector256 정수 SIMD를 사용하여 축소 시간을 1.659초에서 1.127초로 줄였습니다.

🚀 인터랙티브 비교: 일반 for문 vs SIMD Vector256
버튼을 눌러 CPU 1클럭당 처리되는 픽셀 개수를 비교해 보세요.
src/VisionCanvas.Host/Imaging/BoxResampler.cs & experiments/VisionImaging.Pyramid/TrianglePyramid.cs Vector256<int> SIMD 8픽셀 동시 반올림 평균 구현 
using System.Runtime.InteropServices;
using System.Runtime.Intrinsics;

public static void AverageRowSimd(ReadOnlySpan<int> rowA, ReadOnlySpan<int> rowB, Span<int> dst)
{
    int i = 0;
    if (Vector256.IsHardwareAccelerated)
    {
        Vector256<int> ones = Vector256.Create(1);
        for (; i <= dst.Length - 8; i += 8)
        {
            Vector256<int> va = Vector256.LoadUnsafe(ref MemoryMarshal.GetReference(rowA.Slice(i, 8)));
            Vector256<int> vb = Vector256.LoadUnsafe(ref MemoryMarshal.GetReference(rowB.Slice(i, 8)));
            // 8개의 32비트 정수를 동시에 더하고 오른쪽 시프트(>> 1, 즉 ÷2) 수행!
            Vector256<int> avg = (va + vb + ones) >> 1;
            avg.CopyTo(dst.Slice(i, 8));
        }
    }
    for (; i < dst.Length; i++)
    {
        dst[i] = (rowA[i] + rowB[i] + 1) >> 1;
    }
}

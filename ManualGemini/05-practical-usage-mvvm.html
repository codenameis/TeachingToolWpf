CHAPTER 05 · PRACTICAL WPF MVVM INTEGRATION

내 WPF 앱에 VisionCanvas 붙이기 (실전 사용법)

내부 원리를 이해했으니, 이제 실제 사용하는 개발자 입장에서 VisionCanvas를 내 WPF MVVM 프로젝트에 어떻게 조립하고 제어하는지 알아봅니다.
samples/VisionCanvas.MvvmSample에 들어 있는 표준 패턴을 그대로 따라가면 실수 없이 깔끔하게 연동할 수 있습니다.

STEP 1 · MVVM ROLES

1. App · ViewModel · View는 각각 무엇을 맡을까요?

핵심 원칙: ViewModel이 그래픽카드(GPU)나 Win32 창(HWND)을 직접 알면 안 됩니다!
ViewModel은 순수 C# 객체인 EditorSession만 들고 있고, View가 그 세션을 캔버스 컨트롤에 연결해 줍니다.

① App.xaml.cs (조립·수명)

앱이 켜질 때 EditorSession과 ImageCoordinator를 생성해 ViewModel에 주입하고, 앱이 꺼질 때 GPU/타일 자원을 안전하게 정리(Dispose)합니다.

② EditorViewModel (상태·명령)

EditorSession을 속성으로 노출하고, 도구 선택, Undo/Redo, 이미지 열기, 1억 ROI 추가 등의 ICommand를 제공합니다.

③ EditorView (화면·입력 전달)

XAML에 배치된 캔버스 컨트롤에 Session을 연결하고, 외부 목록에서 요청한 화면 이동(FocusRoi, FitImage)을 호출합니다.

samples/VisionCanvas.MvvmSample/ViewModels/EditorViewModel.cs ViewModel에서 EditorSession과 ImageCoordinator 다루기 
public sealed class EditorViewModel : INotifyPropertyChanged
{
    private readonly ImageCoordinator _imageCoordinator;

    public EditorViewModel(EditorSession session, ImageCoordinator imageCoordinator)
    {
        Session = session;
        _imageCoordinator = imageCoordinator;
    }

    public EditorSession Session { get; }

    // 새 이미지와 문서를 비동기로 준비한 뒤 캔버스에 한 번에 교체
    public async Task LoadImageFileAsync(string filePath, CancellationToken ct)
    {
        PreparedDocument prepared = await Session.PrepareDocumentAsync(filePath, ct);
        await _imageCoordinator.LoadDocumentAsync(prepared, ct);
    }

    public void Undo() => Session.Undo();
    public void Redo() => Session.Redo();
}
STEP 2 · INPUT MODES & NAVIGATION

2. 검사 중 입력 잠금과 외부 ROI 목록 맞춤 보기

실제 검사 장비에서는 티칭(편집) 화면과 자동 검사(Run) 화면의 입력 권한이 달라야 합니다.
검사 도중에 작업자가 실수로 ROI를 드래그해서 옮기면 큰일 나기 때문이지요! VisionCanvas는 이를 위해 두 가지 스위치를 구분해서 제공합니다.

속성 / 메서드 동작 설명 언제 사용하나요?
InteractionController.IsEnabled = false 마우스·키보드 입력을 완전히 차단하고, 진행 중이던 드래그 프리뷰/캡처를 즉시 취소합니다. (단, 카메라 실시간 영상 게시는 계속 유지!) 무인 자동 검사 중 조작을 완전히 잠글 때
InteractionController.NavigationOnly = true ROI 이동·크기 변경·삭제는 막고, 마우스 휠 줌과 화면 패닝(이동)만 허용합니다. 검사 결과를 확대해서 관찰만 하고 싶을 때
FocusRoi(roiId) / FocusBounds(rect) 현재 선택 상태나 Undo 이력을 전혀 바꾸지 않고 해당 ROI가 화면 중앙에 오도록 부드럽게 줌·이동합니다. 오른쪽 ROI 목록이나 불량 목록을 클릭했을 때
FitImage() 선택 상태나 Undo 이력을 건드리지 않고 전체 이미지가 창 안에 딱 맞게 배율을 맞춥니다. '전체 보기' 버튼을 눌렀을 때
STEP 3 · KEYBOARD NUDGE & 100M ROI

3. 방향키 1px 미세 이동과 1억 ROI 압축 배치

⌨️ 방향키 1px / Shift + 방향키 10px

마우스로 1픽셀 단위를 정밀하게 맞추기 힘들 때는 ROI를 선택한 뒤 키보드 방향키(↑↓←→)를 누르면 정확히 1px씩 이동합니다.
Shift 키를 누른 채 방향키를 누르면 10px씩 빠르게 이동합니다.

🚀 1억 ROI(100,020,001셀) 추가와 개별 편집

샘플의 1억 ROI 버튼을 누르면 일반 객체 1억 개를 메모리에 할당하는 대신, 공통 Core의 압축 배치(10001 × 10001 = 100,020,001셀)를 추가합니다.
그러면서도 개별 셀 포인터 이동·크기 조절·회전·삭제와 5천만 셀 부분 복붙(총 1.5억 개), Undo/Redo가 그대로 동작합니다.

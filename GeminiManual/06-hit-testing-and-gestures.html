      CHAPTER 06 · 2단계: 겹쳐진 ROI 선택과 스파게티 if-else 없는 드래그 상태 머신

      06장 · 마우스 히트테스트(RoiHitTester)와 입력 제스처 상태 머신(InteractionController)

      05장에서 우리는 수만 개의 일반 ROI와 1억 개의 반복 셀을 순식간에 검색하는 자료구조를 만들었습니다.
      그런데 큰 부모 모듈 상자 안에 작은 자식 핀 상자가 포개져 있을 때 마우스를 클릭하면 둘 중 누구를 먼저 선택해야 할까요?
      또 마우스 드래그가 화면 밀기(Pan), 도형 이동(Move), 8방향 크기 조절(Resize), 회전(Rotate), 새 도형 그리기(Draw), 고무줄 다중 선택(Marquee) 중 무엇인지 어떻게 수백 줄짜리 if-else 없이 깔끔하게 처리할 수 있을까요?

      1단계 · 마우스 클릭과 드래그를 처리하는 2가지 핵심 아이디어

      Step 1 · 문제 이해와 일상 비유
      클릭 판정 (Hit Test)

      겹쳐 있을 때는 '작은 도형(자식)'부터 선택한다!

      큰 부모 상자 안에 있는 작은 자식 핀을 클릭했을 때 큰 부모가 매번 가로채 버리면 자식을 영원히 선택할 수 없습니다. 그래서 RoiHitTester는 면적이 작은 도형을 1순위로 선택합니다.

      손잡이 판정 (Handles)

      이미 선택된 도형의 9개 손잡이(8방향 크기 + 1개 회전)가 최우선!

      도형이 선택되면 모서리에 8개 크기 조절 손잡이와 머리 위 회전 손잡이가 나타납니다. 마우스를 누를 때 이 손잡이(6 DIP 반경)가 가장 먼저 잡혀야 합니다.

      드래그 상태 머신

      거대한 if-else 대신 IGesture 카트리지 갈아끼우기!

      InteractionController는 마우스를 누르는 순간 알맞은 IGesture 객체를 딱 하나 꽂아두고, 드래그 중에는 무조건 _activeGesture.Update(dip) 한 줄만 호출합니다!

      일상 비유로 감 잡기 · 게임기 팩 갈아끼우기(IGesture)와 돋보기 배율 보정(3.0 / Zoom)

      파인만 학습법 (Feynman Analogy)

      🎮 비유 1 · 스파게티 리모컨 대신 게임기 카트리지(IGesture) 갈아끼우기

      초보자가 그림판 프로그램을 만들 때 가장 많이 하는 실수가 OnMouseMove 함수 하나 안에 if (isMoving) ... else if (isResizing) ... else if (isRotating) ...를 500줄씩 나열하는 것입니다.
      대신 게임기 본체(InteractionController)에는 Update(진행), Commit(완료), Cancel(취소) 단 3개의 버튼만 있는 슬롯(IGesture 인터페이스)을 만들어 둡니다. 마우스로 이동을 시작하면 '이동 팩(MoveGesture)'을 꽂고, 회전 손잡이를 잡으면 '회전 팩(RotateGesture)'을 꽂으면 본체 코드는 단 5줄로 끝납니다!

      🔍 비유 2 · 사진을 축소해도 손잡이가 똑같이 잘 잡히는 비결 (Tolerance / Zoom)

      모니터 화면에서 사람 손으로 클릭하기 편한 오차 범위는 약 3~6 픽셀(DIP)입니다.
      만약 사진이 0.1배로 작게 축소되어 있을 때 사진 기준으로 3픽셀만 허용하면, 모니터 화면에서는 0.3픽셀이라는 바늘구멍을 찍어야 해서 클릭이 불가능해집니다! 그래서 화면 허용 거리 3.0 DIP를 현재 확대 배율 Zoom으로 나눈 값(3.0 / Zoom)을 이미지 허용 반경으로 씁니다.

      2단계 · 워밍업: 이 장을 시작하기 위한 4가지 기초 개념

      Step 2 · 필수 사전지식 먼저 다지기

      개념 1 · 인터페이스 다형성 IGesture와 Null Object 패턴(NoGesture)

      인터페이스는 "이 자리에 꽂히는 모든 클래스는 반드시 이 함수 3개를 가지고 있어야 한다"는 약속입니다. 그리고 아무것도 드래그하지 않는 평소에는 null 대신 빈 깡통 객체인 NoGesture.Instance를 넣어두면 귀찮은 if (_activeGesture != null) 검사조차 필요 없습니다! 

      public interface IGesture
{
    void Update(PointD screenDip); // 마우스 이동 시
    void Commit();                 // 마우스 버튼 뗄 때 확정
    void Cancel();                 // Esc 키 누를 때 취소
}

      개념 2 · 히트 우선순위 손잡이(1순위) → 작은 도형(2순위) → 큰 부모 도형(3순위)

      마우스 왼쪽 버튼을 누르는 순간(PointerDown) 다음 순서로 검사합니다:

      • 1순위 (핸들): 현재 선택된 도형의 8방향 크기 조절 핸들이나 상단 회전 핸들(6 DIP 이내)을 눌렀는가?
      • 2순위 (도형 & 1억 셀): 마우스 점 안에 들어온 도형 후보들을 모아 면적(Area)이 작은 순서대로 정렬해 가장 작은 자식 도형을 선택! (단, Alt 키를 누른 채 클릭하면 겹친 도형들을 차례대로 순환 선택!)

      개념 3 · 9개 핸들 좌표 정규화 로컬 좌표 [-0.5, +0.5]로 핸들 위치 찍기

      03장에서 만든 ToWorld(u, v) 함수 덕분에, 도형이 아무리 기울어져 있어도 8방향 크기 조절 핸들의 위치를 1줄로 구할 수 있습니다!

      • 4개 모서리: 좌상단 (-0.5, -0.5), 우상단 (+0.5, -0.5), 우하단 (+0.5, +0.5), 좌하단 (-0.5, +0.5)
      • 4개 변 중앙: 상단 (0, -0.5), 우측 (+0.5, 0), 하단 (0, +0.5), 좌측 (-0.5, 0)

      개념 4 · 반대편 모서리 고정 리사이즈 왜 기울어진 상자 크기를 늘릴 때 중심이 함께 이동할까?

      오른쪽 변 핸들(East)을 잡고 오른쪽으로 20픽셀 늘릴 때, 왼쪽 변(West)은 그 자리에 가만히 고정되어 있어야 자연스럽습니다.
      왼쪽 변은 고정된 채 가로 폭만 +20 늘어나면, 상자의 정중앙(Center)은 그 절반인 +10픽셀만큼 회전된 오른쪽 방향으로 이동하게 됩니다!

      3단계 · 한 걸음씩 수식 유도하기: 배율 불변 허용 반경, 회전 핸들, 반대편 고정 리사이즈

      공식 1 · 배율 불변 허용 반경 & 면적 정렬 배율 불변 히트 허용 반경 εimg 와 후보 정렬 규칙
      (식 6.1)
      ✏️ 한 걸음씩 유도하기:
      1) 원본 이미지에서 길이가 εimg 인 선분은 02장의 뷰포트 배율 s(Zoom)를 거치면 모니터 화면에서 s · εimg 크기로 보입니다.
      2) 이 화면 크기가 항상 일정한 εscr (도형은 3.0 DIP, 핸들은 6.0 DIP)가 되려면 s · εimg = εscr 이어야 하므로, 양변을 s로 나누면 εimg = εscr / s 가 됩니다!
      3) 그리고 마우스 점에 여러 도형이 동시에 걸렸을 때는 작은 자식 도형이 큰 부모 도형에 가려지지 않도록 면적 Area(A) < Area(B) 오름차순으로 정렬하고, 면적이 같다면 나중에 그려진 도형(ZOrder가 큰 도형)을 우선 선택합니다.
      이미지 공간 히트 반경 εimg = εscrs = 3.0 DIPZoom
      후보 A가 B보다 우선 선택될 조건 (A ≺ B) Area(A) < Area(B) 또는 (Area(A) = Area(B)  ∧  ZOrder(A) > ZOrder(B))

      초간단 숫자 대입: 핸들 클릭 허용 거리가 모니터 기준 6 DIP일 때,
      • 사진을 2배 확대(Zoom = 2)하면 사진 픽셀 기준 허용 반경은 6 ÷ 2 = 3 픽셀이 되고,
      • 사진을 0.5배 축소(Zoom = 0.5)하면 6 ÷ 0.5 = 12 픽셀로 자동 조절되어, 확대하든 축소하든 마우스로 핸들을 잡는 손맛이 100% 똑같아집니다!
      공식 2 · 회전 손잡이 위치 회전된 ROI의 상단 회전 핸들(Rotate Handle) 월드 좌표
      (식 6.2)
      ✏️ 한 걸음씩 유도하기:
      1) 회전하지 않은 상자의 위쪽 방향 단위벡터는 (0, -1)입니다.
      2) 이 벡터를 01장 (식 1.4) 회전 공식에 대입해 θ만큼 돌리면: x' = 0·cos θ − (−1)·sin θ = sin θ, y' = 0·sin θ + (−1)·cos θ = −cos θ 가 됩니다! 즉, 기울어진 상자 머리 위로 수직으로 뻗어 나가는 단위 법선 벡터는 ntop = (sin θ, −cos θ) 입니다.
      3) 따라서 상단 중앙 점 ToWorld(0, -0.5)에서 ntop 방향으로 24.0 / Zoom 픽셀만큼 전진하면 항상 상자 머리 위 24 DIP 거리에 회전 손잡이가 놓입니다!
      상단 중앙 핸들ptop = ToWorld(0, −0.5), 상단 외향 법선 단위벡터ntop = (sin θ, −cos θ)
      회전 핸들 월드 좌표 prot = ptop + drots · ntop (단, 기본 drot = 24.0 DIP)
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 중심이 (100, 100)이고 높이가 40(반높이 20)인 안 기울어진 상자(θ = 0°, Zoom = 1)의 회전 손잡이 위치는?
      • 상단 중앙 점은 (100, 80)이고, n_top = (sin 0°, -cos 0°) = (0, -1) 이므로 위로 24 픽셀 더 올라간 (100, 56) 위치에 동그란 회전 손잡이가 달립니다!
      공식 3 · 반대편 모서리 고정 리사이즈 기울어진 도형의 핸들을 끌 때 반대편 모서리를 고정하는 로컬 스케일링 수식
      (식 6.3)
      ✏️ 한 걸음씩 유도하기:
      1) 드래그 시작 시점의 도형 중심을 c0, 크기를 (W0, H0), 회전각을 θ라고 합시다.
      2) 현재 마우스 위치 p를 시작 중심 기준 로컬 픽셀 오프셋으로 역회전합니다: dlocal = (p − c0).InverseRotate(θ).
      3) 원래 도형의 왼쪽·오른쪽·위·아래 로컬 경계는 l = −W0/2, r = +W0/2, t = −H0/2, b = +H0/2 입니다.
      4) 예를 들어 오른쪽 핸들(East)을 끌면 왼쪽 경계 l은 고정한 채 오른쪽 경계 r만 마우스 로컬 위치 dlocal,x로 바꿉니다 (최소 폭 4px 보장).
      5) 그러면 새로운 가로·세로 크기는 W' = r − l, H' = b − t 가 되고, 로컬 중심 이동량 ((l+r)/2, (t+b)/2)를 다시 θ만큼 정방향 회전해 c0에 더하면 반대편 모서리가 1픽셀도 흔들리지 않고 크기가 조절됩니다!
      W' = r − l, H' = b − t, c' = c0 + Rotateθ(l + r2,  t + b2)

      켄트 백 Composed Method · InteractionController.PointerDown 호출 트리
      HitSelectable CC = 5 PointerDown CC = 4
      InteractionController.PointerDown(PointD screenDip, bool rightButton, bool altCycle)
      Branch A HitHandle() → ResizeGesture / RotateGesture 이미 선택된 ROI의 8방향 크기 핸들이나 회전 핸들을 잡았으면 즉시 리사이즈/회전 제스처를 시작합니다.

      코드 1 · RoiHitTester & IGesture 상태 머신 완성본 src/VisionCanvas.Core/Interaction/InteractionController.cs 
      using System;
using System.Collections.Generic;
using System.Collections.Immutable;
using VisionCanvas.Core.Editing;
using VisionCanvas.Core.Geometry;
using VisionGeometry;

namespace VisionCanvas.Core.Interaction;

public enum RoiHandleKind { None, NorthWest, North, NorthEast, East, SouthEast, South, SouthWest, West, Rotate }

public static class RoiHitTester
{
    public const double HandleRadiusDip = 6.0;
    public const double RotateOffsetDip = 24.0;

    // 1순위: 현재 선택된 도형의 8방향 크기 조절 핸들 + 상단 회전 핸들 히트 판정
    public static RoiHandleKind HitHandle(RoiGeometry g, ViewportTransform viewport, PointD screenDip)
    {
        PointD imgPt = viewport.ScreenToImage(screenDip);
        double tolImg = HandleRadiusDip / viewport.Zoom;

        // (식 6.2) 상단 회전 핸들 위치 검사
        PointD topCenter = g.ToWorld(0.0, -0.5);
        PointD upNormal = new(Math.Sin(g.RotationRadians), -Math.Cos(g.RotationRadians));
        PointD rotHandle = topCenter + (upNormal * (RotateOffsetDip / viewport.Zoom));
        if (imgPt.DistanceTo(rotHandle) <= tolImg) return RoiHandleKind.Rotate;

        // 8방향 크기 조절 핸들 위치 검사
        ReadOnlySpan<(RoiHandleKind Kind, double U, double V)> handles =
        [
            (RoiHandleKind.NorthWest, -0.5, -0.5), (RoiHandleKind.North, 0.0, -0.5),
            (RoiHandleKind.NorthEast, +0.5, -0.5), (RoiHandleKind.East,  +0.5, 0.0),
            (RoiHandleKind.SouthEast, +0.5, +0.5), (RoiHandleKind.South, 0.0, +0.5),
            (RoiHandleKind.SouthWest, -0.5, +0.5), (RoiHandleKind.West,  -0.5, 0.0)
        ];

        foreach (var (kind, u, v) in handles)
        {
            if (imgPt.DistanceTo(g.ToWorld(u, v)) <= tolImg) return kind;
        }
        return RoiHandleKind.None;
    }

    // 2순위: (식 6.1) BVH로 후보를 찾고 면적(Area)이 작은 자식 도형부터 정렬해 반환!
    public static Guid? HitRoi(DocumentState doc, ViewportTransform viewport, PointD screenDip, bool altCycle = false)
    {
        PointD imgPt = viewport.ScreenToImage(screenDip);
        List<Guid> candidates = doc.SpatialIndex.QueryPoint(imgPt);
        var hits = new List<Roi>();

        foreach (Guid id in candidates)
        {
            if (doc.Rois.TryGetValue(id, out Roi? roi) && roi.Geometry.Contains(imgPt))
                hits.Add(roi);
        }
        if (hits.Count == 0) return null;

        // 작은 면적(자식 ROI)이 1순위, 면적이 같으면 ZOrder 내림차순!
        hits.Sort((a, b) =>
        {
            double areaA = a.Geometry.Width * a.Geometry.Height;
            double areaB = b.Geometry.Width * b.Geometry.Height;
            int cmp = areaA.CompareTo(areaB);
            return cmp != 0 ? cmp : b.ZOrder.CompareTo(a.ZOrder);
        });

        return hits[0].Id;
    }
}

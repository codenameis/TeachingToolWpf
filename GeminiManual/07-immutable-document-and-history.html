      CHAPTER 07 · 2단계: 스레드 안전성과 완벽한 Undo/Redo를 보장하는 불변(Immutable) 아키텍처

      07장 · 불변 문서(DocumentState)와 드래그 프리뷰 · Undo/Redo · 그룹 편집(RoiGroupEditor)

      06장에서 우리는 마우스 드래그를 처리하는 제스처(MoveGesture, ResizeGesture 등)를 만들었습니다.
      그런데 자식 ROI 1,000개가 달린 모듈 그룹을 마우스로 드래그하는 동안, 매 프레임마다 1,000개의 ROI 객체를 새로 만들고 BVH 트리를 재구축하면 화면이 뚝뚝 끊깁니다.
      또 백그라운드 렌더 스레드가 도형을 그리는 도중에 UI 스레드가 ROI 목록을 고치면 프로그램이 뻗어버립니다(Race Condition).
      어떻게 불변 스냅샷(DocumentState)과 경량 변환 프리뷰(RoiTransformPreview)로 60FPS 반응 속도와 완벽한 Undo/Redo를 동시에 잡았는지 밑바닥부터 구현해 봅시다!

      1단계 · 드래그 중에는 0.001ms 만에 반응하고 마우스를 떼면 Undo에 기록되는 3박자

      Step 1 · 문제 이해와 일상 비유
      1박자 · 확정 문서

      확정된 문서는 DocumentState가 불변(Immutable)으로 보관!

      한 번 만들어진 DocumentState는 절대 내부가 바뀌지 않습니다. 따라서 백그라운드 렌더 스레드가 락(lock) 없이 읽어도 100% 안전합니다.

      2박자 · 드래그 프리뷰

      드래그 중에는 RoiTransformPreview 숫자만 바꾼다 (O(1))!

      마우스를 끄는 동안에는 원본 문서를 안 고치고, '선택된 도형들이 (dx, dy)만큼 이동 중'이라는 가벼운 프리뷰 표지만 교체하여 BVH 재구축 비용을 0으로 만듭니다.

      3박자 · 커밋 & Undo

      마우스 버튼을 뗄 때(PointerUp) 딱 1번 새 문서를 만들고 Undo에 저장!

      마우스를 놓는 순간에만 이전 DocumentState를 EditHistory 스택에 밀어 넣고 변경이 반영된 새 DocumentState로 교체합니다.

      일상 비유로 감 잡기 · 투명 셀로판지(RoiTransformPreview)와 타임머신 사진첩(EditHistory)

      파인만 학습법 (Feynman Analogy)

      📝 비유 1 · 백과사전 위에 투명 셀로판지를 덮고 그리기 (RoiTransformPreview)

      두꺼운 백과사전(DocumentState)에서 그림 하나를 옆으로 옮길 때, 마우스를 1mm 움직일 때마다 백과사전 1,000페이지를 새로 인쇄(BVH 트리 재구축 + Undo 저장)하면 컴퓨터가 멈추겠죠?
      대신 드래그하는 동안에는 백과사전 위에 투명 셀로판지(RoiTransformPreview) 한 장을 얹어놓고 셀로판지만 스르륵 움직여 보여줍니다. 그리고 마우스 버튼을 딱 놓는 순간(Commit)에만 새 백과사전을 딱 1번 인쇄해 책꽂이(Undo 스택)에 꽂는 것입니다!

      ⏪ 비유 2 · 만약 드래그 중 PointerMove마다 Undo에 넣으면 어떻게 될까?

      초보자가 흔히 저지르는 실수입니다! 마우스를 1초만 끌어도 PointerMove가 100번 호출되어 Undo 스택에 1px씩 움직인 기록 100개가 쌓입니다.
      그러면 사용자가 Ctrl+Z를 한 번 눌렀을 때 원래 자리로 돌아가지 않고 겨우 1픽셀 뒤로만 가서, Ctrl+Z를 100번 연타해야 하는 버그가 생깁니다! Preview(드래그 중)와 Commit(마우스 뗄 때)을 분리하면 드래그 1번이 정확히 Undo 1칸이 됩니다.

      개념 2 · 2단계 상태 전이 SetTransformPreview vs CommitTransformPreview

      EditorSession은 확정된 문서 Document와 임시 프리뷰 ActivePreview 두 개의 프로퍼티를 가집니다.

      • 드래그 중(PointerMove): ActivePreview만 교체 (비용 O(1), Undo 기록 안 함)
      • 드래그 완료(PointerUp): ActivePreview를 Document에 합쳐 확정하고 ActivePreview = null로 비움 (Undo 1회 기록!)

      개념 3 · Undo/Redo 스택 규칙 새 편집 시 Redo 비우기 & 거부된 편집 시 Redo 보존

      EditHistory는 _undoStack(과거)과 _redoStack(미래) 두 개의 리스트를 관리합니다.

      • 성공한 새 편집(Push): 현재 문서를 _undoStack에 넣고 _redoStack.Clear()로 미래 이력을 비웁니다.
      • 거부된 편집(예: 작은 이미지 로드 실패, 순환 참조 거부): 문서가 바뀌지 않았으므로 기존 _redoStack을 절대 지우지 않고 그대로 보존합니다!

      개념 4 · 부모-자식 그룹 규칙 순환 참조 금지(CreatesCycle)와 부모 자동 확장

      도형 A를 부모 B의 자식으로 넣을 때(Attach), 만약 B가 이미 A의 자식이라면 A ↔ B 무한 루프(Cycle)가 생깁니다! 이를 막고, 자식이 부모 상자 밖에 있으면 부모 상자를 자동으로 넓혀 자식을 품어줍니다.

      using System;
using System.Collections.Generic;
using System.Collections.Immutable;
using VisionCanvas.Core.Geometry;
using VisionGeometry;

namespace VisionCanvas.Core.Editing;

public sealed record Roi(
    Guid Id,
    string Name,
    RoiGeometry Geometry,
    Guid? ParentId = null,
    bool IsGroup = false,
    long Order = 0);

// 1. 드래그 도중 원본 문서를 건드리지 않고 이동·회전·크기 변화량만 들고 있는 O(1) 프리뷰
public sealed record RoiTransformPreview(
    ImmutableHashSet<Guid> MovingIds,
    PointD TranslationDelta,
    double RotationDeltaDegrees = 0.0,
    PointD? RotationPivot = null,
    Guid? SingleOverrideId = null,
    RoiGeometry? SingleOverrideGeometry = null)
{
    public RoiGeometry Apply(Roi roi)
    {
        if (SingleOverrideId == roi.Id && SingleOverrideGeometry is { } g) return g;
        if (!MovingIds.Contains(roi.Id)) return roi.Geometry;

        RoiGeometry geom = roi.Geometry;
        if (RotationPivot is { } pivot && Math.Abs(RotationDeltaDegrees) > 1e-7)
        {
            return geom.RotateAround(pivot, RotationDeltaDegrees);
        }

        return geom.Translate(TranslationDelta);
    }
}

// 2. 한 시점의 모든 ROI 사전, 영속 BVH 스냅샷(RoiSnapshot), 선택 집합(RoiIdSet)을 담은 불변 문서
public sealed class DocumentState
{
    public ImmutableDictionary<Guid, Roi> Rois { get; }
    public RoiIdSet Selection { get; }
    public RoiSpatialIndex SpatialIndex { get; }

    public DocumentState(
        ImmutableDictionary<Guid, Roi> rois,
        RoiIdSet selection)
    {
        Rois = rois;
        Selection = selection;
        var entries = new List<RoiSpatialIndex.Entry>(rois.Count);
        foreach (Roi r in rois.Values)
            entries.Add(new RoiSpatialIndex.Entry(r.Id, r.Geometry.Bounds, r.Geometry.Area, r.Order));
        SpatialIndex = new RoiSpatialIndex(entries);
    }

    public static DocumentState Empty { get; } =
        new(ImmutableDictionary<Guid, Roi>.Empty, RoiIdSet.Empty);

    public DocumentState WithRoi(Roi roi) => new(Rois.SetItem(roi.Id, roi), Selection);
    public DocumentState WithRois(ImmutableDictionary<Guid, Roi> rois) => new(rois, Selection);
    public DocumentState WithSelection(RoiIdSet selection) => new(Rois, selection);
}

// 3. 최대 32단계의 과거(Undo)와 미래(Redo) 스냅샷 스택 관리기
public sealed class EditHistory
{
    private readonly List<DocumentState> _undo = new();
    private readonly List<DocumentState> _redo = new();
    private const int MaxDepth = 32;

    public int UndoCount => _undo.Count;
    public int RedoCount => _redo.Count;

    public void Push(DocumentState previousState)
    {
        if (_undo.Count >= MaxDepth) _undo.RemoveAt(0);
        _undo.Add(previousState);
        _redo.Clear(); // 새로운 역사가 쓰여졌으므로 미래(Redo) 스택 초기화!
    }

    public bool TryUndo(DocumentState current, out DocumentState restored)
    {
        if (_undo.Count == 0) { restored = current; return false; }
        restored = _undo[^1];
        _undo.RemoveAt(_undo.Count - 1);
        _redo.Add(current);
        return true;
    }

    public bool TryRedo(DocumentState current, out DocumentState restored)
    {
        if (_redo.Count == 0) { restored = current; return false; }
        restored = _redo[^1];
        _redo.RemoveAt(_redo.Count - 1);
        _undo.Add(current);
        return true;
    }
}

      updates.AddRange(children.Select(c => c with { ParentId = parentId })); 검증을 통과한 자식 도형들에 with { ParentId = parentId }로 부모 ID를 부여해 불변 문서 스냅샷으로 단 한 번에 업데이트합니다.

      6단계 · 방금 만든 코드의 설계 원리: 불변 상태와 프리뷰 분리가 만드는 압도적 최적화

      SOLID 원칙 GRASP 패턴
      GRASP · Indirection (간접성 패턴)

      RoiTransformPreview가 제스처와 무거운 문서 상태 사이를 완충

      드래그 제스처가 무거운 DocumentState를 직접 흔들지 않고 가벼운 RoiTransformPreview 객체 하나만 바꾸도록 간접 계층을 두어 드래그 비용을 O(1)로 만들었습니다.

      SOLID · SRP (단일 책임 원칙)

      문서 데이터(DocumentState) · 이력 스택(EditHistory) · 세션 조율(EditorSession) 분리

      스냅샷 보관, Undo/Redo 스택 관리, 현재 선택 및 프리뷰 조율 책임을 3개 클래스로 명확히 분리했습니다.

      GRASP · Creator (창조자 패턴)

      EditorSession이 검증된 명령을 바탕으로 새 DocumentState 스냅샷을 생성

      아무 클래스나 문서를 고칠 수 없고, 오직 EditorSession만이 부모-자식 계층 규칙을 검증한 뒤 새 DocumentState를 만들어 교체합니다.

      SOLID · OCP & 불변 스냅샷(Memento)

      복잡한 역연산 코드 없이 스냅샷 교체만으로 100% 완벽한 Undo/Redo

      각 명령마다 취소 코드를 따로 짤 필요 없이 불변 DocumentState 참조만 스택에 넣었다 빼면 되므로, 1억 개 배치 편집이든 폴리곤 변형이든 Undo 버그가 절대 생기지 않습니다.

      💡 이 구조가 어떻게 60FPS 최적화를 달성할까요?
      드래그 중(PointerMove)에는 BVH 트리 재구축도, 딕셔너리 복사도 전혀 하지 않고 숫자 2개(TranslationDelta.X, Y)만 바꿉니다. 덕분에 수만 개 ROI가 있어도 드래그 중 CPU 소요 시간은 0.01ms 미만입니다!

      CLASS DIAGRAM 07장 불변 문서 상태(DocumentState) · 실시간 프리뷰 · Undo/Redo 클래스 다이어그램

      드래그 중 O(1) 반응을 보장하는 RoiTransformPreview와 불변 스냅샷 기반 EditHistory의 클래스 구조입니다.

      SEQUENCE DIAGRAM 07장 시퀀스 다이어그램 · 드래그 중 Preview 갱신과 PointerUp 커밋 및 Undo 복원 흐름

      PointerMove 중에는 RoiTransformPreview만 바뀌고, PointerUp에서 딱 한 번 DocumentState와 EditHistory가 갱신되는 타임라인입니다.

      7단계 · 07장 마무리 셀프 체크 & 다음 장으로 가는 징검다리

      셀프 체크 Q1 · Undo를 한 상태에서 사용자가 새로운 도형을 추가하면 Redo 스택은 어떻게 되어야 하고, 반대로 작은 이미지 거부처럼 편집이 실패했을 때 Redo 스택은 어떻게 되어야 할까요?

      정답: 새로운 도형 추가가 성공했을 때는 새로운 역사가 시작되었으므로 Redo 스택을 깨끗이 비워야(Clear) 하고, 편집 요청이 거부(Reject)되어 문서가 바뀌지 않았을 때는 기존 Redo 스택을 절대 날리지 않고 그대로 보존해야 합니다!

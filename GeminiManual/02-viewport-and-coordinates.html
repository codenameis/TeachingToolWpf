      CHAPTER 02 · 1단계: 모니터 화면 픽셀과 8K 카메라 원본 픽셀을 잇는 다리

      02장 · 좌표계와 뷰포트 변환 직접 만들기 (BoundsD, ViewportTransform)

      01장에서 우리는 점 하나를 표현하는 PointD(X, Y)를 직접 만들었습니다.
      그런데 사용자가 모니터 화면의 (340, 190) 위치를 마우스로 클릭했을 때, 그곳이 원본 8K 카메라 사진의 몇 번 픽셀인지 어떻게 알 수 있을까요?
      또 마우스 휠을 굴려 확대할 때 마우스 커서가 가리키던 사진 속 지점이 엉뚱한 곳으로 도망가지 않고 커서 아래에 딱 고정되게(Cursor-Anchored Zoom) 만들려면 어떤 방정식이 필요할까요?
      중학교 1차 함수 y = ax + b 하나로 이 문제를 완벽히 풀어 봅시다!

      1단계 · 왜 '화면 좌표'와 '사진 좌표'를 분리해야 할까요?

      Step 1 · 문제 이해와 일상 비유
      왜 분리할까?

      화면은 계속 움직이지만 사진 데이터는 변하면 안 됩니다

      사용자가 마우스로 화면을 이리저리 밀거나(Pan) 휠로 10배 확대(Zoom)하더라도, 기판 위 부품 ROI가 저장된 '원본 사진 픽셀 위치(예: 1500, 2400)'는 절대 바뀌면 안 됩니다.

      누가 통역할까?

      양방향 통역사 ViewportTransform

      ViewportTransform 구조체는 현재 확대 배율(Zoom)과 화면이 밀린 거리(PanX, PanY) 숫자 3개만 들고, 사진 좌표 ↔ 모니터 화면 좌표를 양방향으로 즉시 통역합니다.

      어떤 수학을 쓸까?

      중학교 1차 함수 y = s·x + t 와 역함수

      사진 좌표에 배율 s를 곱하고 밀림 t를 더하면 화면 좌표가 되고, 반대로 화면 좌표에서 t를 빼고 s로 나누면 원래 사진 좌표가 됩니다!

      일상 비유로 감 잡기 · 왜 그냥 배율만 키우면 내가 보던 사진이 도망갈까?

      파인만 학습법 (Feynman Analogy)

      📌 비유 1 · 책상 위 지도에 압정 꽂고 확대하기 (ZoomAt의 원리)

      책상 위에 놓인 고무 지도를 2배로 늘린다고 상상해 보세요. 만약 지도의 왼쪽 위 모서리 (0, 0)에 압정을 꽂아두고 고무 지도를 2배로 잡아당기면, 내가 자세히 보려고 손가락을 짚고 있던 '서울 시청' 위치는 오른쪽 아래로 멀리 도망가 버립니다!
      서울 시청이 내 손가락 밑에서 도망가지 않게 하려면 어떻게 해야 할까요? 내 손가락 끝(마우스 커서 위치)에 압정을 꽂은 채로, 지도가 늘어난 만큼 지도 원점을 왼쪽 위로 반대로 당겨(새 PanX, PanY 보정) 주어야 합니다.

      🔍 비유 2 · 일반 모니터(100%)와 고해상도 노트북(150%)의 눈금 차이 (DIP)

      똑같은 15인치 화면인데 픽셀이 촘촘한 4K 노트북에서는 기본 픽셀(px) 단위로 사각형 손잡이를 그리면 깨알처럼 작아져서 마우스로 잡기가 힘듭니다.
      그래서 윈도우 배율(DpiScale, 예: 150% = 1.5)로 나눈 논리 픽셀(DIP, Device-Independent Pixel)을 사용하면 어떤 모니터에서든 사람 눈에 똑같은 크기(예: 6 DIP)로 보입니다!

      2단계 · 워밍업: 이 장을 시작하기 위한 3가지 기초 개념

      Step 2 · 필수 사전지식 먼저 다지기

      수식과 코드를 작성하기 전에, 이 장에서 사용할 3가지 기초 재료(물리 픽셀 vs DIP, 축 정렬 상자 BoundsD, 1차 함수 역산)를 먼저 가볍게 익혀 봅시다.

      개념 1 · 화면 단위 물리 픽셀(px) vs 논리 픽셀(DIP)과 DpiScale

      윈도우 설정에서 디스플레이 배율을 150% (DpiScale = 1.5)로 설정하면, 논리 화면 좌표 1 DIP는 실제 모니터 물리 픽셀 1.5개에 해당합니다. 

      // 1) Win32 마우스 메시지(물리 픽셀) → 논리 화면 좌표(DIP) 변환
PointD screenDip = new(clientPixelX / DpiScale, clientPixelY / DpiScale);

// 2) 논리 화면 좌표(DIP) → GPU 렌더 타겟 물리 픽셀(px) 변환
double gpuPixelX = screenDip.X * DpiScale;

      VisionCanvas.Core는 모니터 해상도에 흔들리지 않도록 항상 화면 논리 좌표(DIP)와 원본 이미지 픽셀 좌표(Image px) 두 가지만 깔끔하게 다룹니다.

      개념 2 · 중학교 1차 함수 y = s·x + t 를 x 에 대해 풀기(역함수)

      중학교 2학년 때 배운 일차함수 y = s · x + t 가 뷰포트 변환의 전부입니다!

      • 기울기 s (Zoom): 원본 사진 1픽셀이 화면에서 몇 DIP 크기로 보이는가? (예: 2배 확대면 s = 2)
      • 절편 t (PanX, PanY): 사진의 왼쪽 위 모서리 (0, 0)이 현재 모니터 화면의 어디에 놓여 있는가?
      • 역함수 구하기: 양변에서 t를 빼면 y − t = s · x 이고, 양변을 s로 나누면 x = (y − t) / s 가 됩니다!

      개념 3 · 경계 상자 반듯한 사각형 영역을 담는 BoundsD(Left, Top, Right, Bottom)

      화면 영역이나 이미지 영역처럼 축에 나란한(기울어지지 않은) 사각형 범위는 왼쪽(Left), 위쪽(Top), 오른쪽(Right), 아래쪽(Bottom) 숫자 4개로 표현합니다. 이를 축 정렬 경계 상자(AABB, Axis-Aligned Bounding Box)라고 부릅니다. 

      // 두 사각형 상자 A와 B가 조금이라도 겹치는지(Intersects) 1줄 판정법:
// "A의 오른쪽 끝이 B의 왼쪽 끝보다 오른쪽에 있고, A의 왼쪽 끝이 B의 오른쪽 끝보다 왼쪽에 있으며..."
bool isOverlapping = Right >= b.Left && Left <= b.Right && Bottom >= b.Top && Top <= b.Bottom;

      개념 4 · 값 범위 제한 Math.Clamp(값, 최소, 최대)

      사용자가 마우스 휠을 끝없이 굴려서 확대 배율 s가 0이 되거나 음수가 되면, 나눗셈 (y - t) / s에서 0으로 나누기 오류(DivideByZero / NaN)가 발생합니다!
      따라서 Math.Clamp(targetZoom, 0.01, 64.0)처럼 배율이 항상 0.01배 ~ 64배 안전한 범위 안에만 머물도록 가두어 줍니다.

      3단계 · 한 걸음씩 수식 유도하기: 정방향·역방향 변환과 커서 고정 줌(ZoomAt)

      이제 원본 사진 속 점 pimg = (xi, yi)와 모니터 화면 점 pscr = (xs, ys)를 연결하는 3가지 핵심 공식을 한 줄씩 유도해 봅시다.

      공식 1 · 일차함수와 역함수 ImageToScreen 정방향 변환과 ScreenToImage 역방향 변환
      (식 2.1)
      ✏️ 한 걸음씩 유도하기 (중2 일차함수):
      1) 원본 사진 좌표 xi를 s배 확대하면 원점으로부터의 거리가 s · xi가 됩니다.
      2) 여기에 사진 전체가 화면 오른쪽으로 밀린 거리 tx(PanX)를 더하면 모니터 화면 좌표 xs = s · xi + tx 가 완성됩니다! (ImageToScreen)
      3) 반대로 모니터 화면 좌표 xs를 클릭했을 때 원본 사진 좌표 xi를 찾으려면? 방금 한 계산을 거꾸로 되돌려서 tx를 먼저 빼고 s로 나누면 됩니다: xi = (xs − tx) / s (ScreenToImage).
      정방향 ImageToScreen pscr = s · pimg + t ⟺ (xs, ys) = (s · xi + tx,  s · yi + ty)
      역방향 ScreenToImage pimg = pscr − ts ⟺ xi = xs − txs, yi = ys − tys
      기호 및 변수 정의 (Symbol & Domain Legend)
      수식 기호 수학적 의미 정의역 · 단위 C# 코드 대응
      pimg = (xi, yi) 원본 카메라 영상 내부의 픽셀 좌표 (좌상단 원점) [0, W] × [0, H] (Image px) PointD imagePoint
      pscr = (xs, ys) 뷰포트 컨트롤 화면 위의 논리 픽셀 좌표 가로·세로 숫자 쌍 (X, Y) (단위: DIP) PointD screenPoint
      s 화면 확대 배율 (원본 1픽셀이 화면에서 차지하는 DIP 크기) [0.01, 64.0] (배율) double Zoom (또는 Scale)
      t = (tx, ty) 이미지 원점 (0, 0)이 모니터 화면에서 놓인 평행이동 오프셋 가로·세로 숫자 쌍 (X, Y) (단위: DIP) double PanX, PanY
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 사진 속 좌표 (100, 50)을 2배 확대(Zoom = 2)하고 화면을 오른쪽으로 30, 아래로 10만큼 밀었다면(PanX = 30, PanY = 10)?
      • 모니터 화면 좌표 X = 100 × 2 + 30 = 230, Y = 50 × 2 + 10 = 110 이 됩니다!
      • 반대로 모니터 (230, 110)을 마우스로 클릭했을 때 원본 사진 위치를 찾으려면? 더했던 30을 먼저 빼고 2로 나누면 (230 − 30) ÷ 2 = 100, (110 − 10) ÷ 2 = 50으로 원래 사진 좌표 (100, 50)이 정확히 되돌아옵니다!
      공식 2 · 불변점 방정식 마우스 커서 위치 고정 확대(ZoomAt) 방정식 유도
      (식 2.2)
      ✏️ 한 걸음씩 유도하기 (확대 전후 사진 좌표가 같아야 한다는 조건 세우기):
      1) 사용자가 모니터 화면의 pcursor 위치에 마우스를 올린 채 휠을 굴려 배율을 sold에서 snew로 바꿉니다.
      2) 휠을 굴리기 직전, 마우스 커서 바로 밑에 있던 원본 사진 속 점 a는 (식 2.1)의 역변환에 의해 a = (pcursor − told) / sold 입니다.
      3) 핵심 아이디어: 배율이 snew로 바뀐 뒤에도 이 사진 속 점 a를 화면으로 변환했을 때 여전히 같은 마우스 위치 pcursor에 찍혀야 합니다! 즉, pcursor = snew · a + tnew 가 성립해야 합니다.
      4) 이 식에서 우리가 구하고 싶은 새로운 화면 밀림 값 tnew만 남기고 우변의 snew · a를 이항하면 tnew = pcursor − snew · a 가 유도됩니다!
      1단계 · 줌 이전 커서 아래 불변점 추출 a = pcursor − toldsold
      2단계 · 배율 변경 후에도 a가 동일 커서에 매핑될 조건 pcursor = snew · a + tnew
      ∴ 최종 해 · 새로운 평행이동 오프셋 tnew = pcursor − snew · a
      기호 및 변수 정의 (Symbol & Domain Legend)
      수식 기호 수학적 의미 정의역 · 단위 C# 코드 대응
      pcursor 마우스 휠을 굴리는 순간 커서의 화면 고정 좌표 가로·세로 숫자 쌍 (X, Y) (DIP) PointD screenAnchor
      a 확대 전후로 커서 바로 밑에 고정되어야 할 이미지 앵커 좌표 가로·세로 숫자 쌍 (X, Y) (Image px) PointD imageAnchor = ScreenToImage(screenAnchor)
      sold, snew 변경 전 배율과 Math.Clamp를 거친 변경 후 배율 [MinZoom, MaxZoom] Zoom, clampedZoom
      tnew 앵커 점 a가 도망가지 않도록 역산된 새 Pan 좌표 가로·세로 숫자 쌍 (X, Y) (DIP) panX, panY
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 현재 Zoom = 2, PanX = 30인 상태에서 모니터 화면 X = 230 위치에 마우스를 올린 채 배율을 2배 → 4배로 키운다면?
      • 1단계: 현재 마우스(230) 바로 아래에 있는 사진 픽셀 번호는 (230 − 30) ÷ 2 = 100번 픽셀입니다.
      • 2단계: 사진이 4배로 커지면 100번 픽셀은 원점에서 100 × 4 = 400만큼 떨어진 곳으로 늘어납니다. 이 점이 모니터 230 위치에 그대로 있으려면? 새 밀림 값 PanX = 230 − 400 = −170으로 당겨 주면 마우스 아래 100번 픽셀이 1픽셀도 안 흔들리고 그 자리에 딱 고정됩니다!
      공식 3 · 화면 중앙 맞춤 이미지 전체 또는 특정 ROI를 화면 정중앙에 꽉 차게 맞추는 Fit 수식
      (식 2.3)
      ✏️ 한 걸음씩 유도하기 (가로 비율과 세로 비율 중 어느 쪽에 맞춰야 할까?):
      1) 가로×세로가 (W_img, H_img)인 사진을 (W_view, H_view) 크기의 모니터 창 안에 잘리지 않게 다 넣으려고 합니다.
      2) 가로가 딱 차게 만드는 배율은 sx = Wview / Wimg 이고, 세로가 딱 차게 만드는 배율은 sy = Hview / Himg 입니다.
      3) 둘 중 더 큰 배율을 고르면 사진의 다른 한쪽이 창 밖으로 잘려 나갑니다! 따라서 사진 전체가 잘리지 않고 다 보이려면 반드시 둘 중 더 작은 값 s = min(sx, sy)를 선택해야 합니다.
      4) 배율 s를 정한 뒤, 크기가 s · Wimg가 된 사진을 창 정중앙에 놓으려면 남는 여백 (W_view - s * W_img)를 정확히 반(÷ 2)으로 나누어 왼쪽 여백(PanX)으로 주면 됩니다!
      s = min(WviewWimg,  HviewHimg), tx = Wview − s · Wimg2, ty = Hview − s · Himg2
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 가로 1000, 세로 500인 사진을 가로 800, 세로 600인 모니터 창에 맞추려면?
      • 가로 배율 후보 = 800 ÷ 1000 = 0.8, 세로 배율 후보 = 600 ÷ 500 = 1.2 → 둘 중 작은 값인 s = 0.8 선택!
      • 0.8배 줄어든 사진 크기는 800 × 400이므로, 가로 여백 PanX = (800 − 800) ÷ 2 = 0, 세로 위아래 여백 PanY = (600 − 400) ÷ 2 = 100으로 놓으면 정중앙에 예쁘게 들어갑니다!

      4단계 · 인터랙티브 실험실: 마우스 휠 고정 줌(ZoomAt) & 드래그 패닝 시뮬레이터

      인터랙티브 실험실 · 마우스 휠 고정 줌(ZoomAt) & 드래그 패닝(Pan) 시뮬레이터
      캔버스 위에서 마우스 휠을 굴려 확대/축소하고, 드래그하여 Pan과 Image 좌표 변화를 확인하세요
      노란 조준선이 가리키는 이미지 좌표 (imgX, imgY)가 휠 확대 중에도 절대 도망가지 않는 것을 확인하세요!

      5단계 · 밑바닥부터 직접 구현하기: BoundsD와 ViewportTransform 전체 코드

      이제 3단계에서 유도한 수식들을 C# readonly record struct 코드로 그대로 옮겨 적어 봅시다.

      코드 1 · 축 정렬 경계 상자 BoundsD & 카메라 변환기 ViewportTransform 완성본 src/VisionGeometry/ViewportTransform.cs 
      using System;

namespace VisionGeometry;

/// <summary>
/// 축에 나란한 사각형 영역(Axis-Aligned Bounding Box)을 표현하는 불변 값 타입입니다.
/// </summary>
public readonly record struct BoundsD(double Left, double Top, double Right, double Bottom)
{
    public double Width => Right - Left;
    public double Height => Bottom - Top;
    public PointD Center => new((Left + Right) * 0.5, (Top + Bottom) * 0.5);

    // 점 p가 상자 내부(경계선 포함)에 들어왔는지 검사합니다.
    public bool Contains(PointD p) =>
        p.X >= Left && p.X <= Right && p.Y >= Top && p.Y <= Bottom;

    // 두 상자가 1픽셀이라도 서로 겹치는지(교차하는지) 검사합니다.
    public bool Intersects(BoundsD b) =>
        Right >= b.Left && Left <= b.Right && Bottom >= b.Top && Top <= b.Bottom;

    // 상자 사방을 margin만큼 넓힌 새 상자를 반환합니다.
    public BoundsD Inflate(double margin) =>
        new(Left - margin, Top - margin, Right + margin, Bottom + margin);
}

/// <summary>
/// 원본 이미지 픽셀 좌표계와 화면 논리 좌표계(DIP)를 양방향으로 통역하는 불변 카메라 구조체입니다.
/// </summary>
public readonly record struct ViewportTransform(double Zoom, double PanX, double PanY, double DpiScale = 1.0)
{
    public const double MinZoom = 0.01;
    public const double MaxZoom = 64.0;

    // (식 2.1) 정방향: 원본 이미지 픽셀 → 모니터 화면 DIP
    public PointD ImageToScreen(PointD imagePoint) =>
        new((imagePoint.X * Zoom) + PanX, (imagePoint.Y * Zoom) + PanY);

    // (식 2.1) 역방향: 모니터 화면 DIP → 원본 이미지 픽셀
    public PointD ScreenToImage(PointD screenPoint) =>
        new((screenPoint.X - PanX) / Zoom, (screenPoint.Y - PanY) / Zoom);

    // 화면을 (deltaDipX, deltaDipY)만큼 평행이동한 새 뷰포트를 반환합니다.
    public ViewportTransform PanBy(double deltaDipX, double deltaDipY) =>
        this with { PanX = PanX + deltaDipX, PanY = PanY + deltaDipY };

    // (식 2.2) 마우스 커서 위치(screenAnchor) 아래의 이미지 지점을 고정한 채 배율을 변경합니다.
    public ViewportTransform ZoomAt(PointD screenAnchor, double targetZoom)
    {
        double clampedZoom = Math.Clamp(targetZoom, MinZoom, MaxZoom);
        PointD imageAnchor = ScreenToImage(screenAnchor);
        double newPanX = screenAnchor.X - (imageAnchor.X * clampedZoom);
        double newPanY = screenAnchor.Y - (imageAnchor.Y * clampedZoom);
        return this with { Zoom = clampedZoom, PanX = newPanX, PanY = newPanY };
    }

    // (식 2.3) 원본 이미지(imageWidth x imageHeight) 전체를 뷰포트 창 정중앙에 맞춥니다.
    public static ViewportTransform Fit(
        double imageWidth, double imageHeight,
        double viewWidthDip, double viewHeightDip,
        double dpiScale = 1.0)
    {
        double scaleX = viewWidthDip / Math.Max(1.0, imageWidth);
        double scaleY = viewHeightDip / Math.Max(1.0, imageHeight);
        double zoom = Math.Clamp(Math.Min(scaleX, scaleY), MinZoom, MaxZoom);
        double panX = (viewWidthDip - (imageWidth * zoom)) * 0.5;
        double panY = (viewHeightDip - (imageHeight * zoom)) * 0.5;
        return new ViewportTransform(zoom, panX, panY, dpiScale);
    }
}
      핵심 코드 구문 무슨 역할을 하며 왜 이렇게 작성했을까요?
      Right >= b.Left && Left <= b.Right ... 두 사각형이 안 겹치려면 한쪽이 완전히 왼쪽·오른쪽·위·아래에 있어야 합니다. 그 반대 조건을 쓰면 단 4번의 부등호 비교만으로 겹침 여부를 즉시 알아냅니다.
      ImageToScreen(PointD imagePoint) (식 2.1)의 정방향 수식 x * Zoom + PanX를 그대로 구현합니다. ROI 도형을 모니터 화면에 그릴 때 사용합니다.
      ScreenToImage(PointD screenPoint) (식 2.1)의 역방향 수식 (x - PanX) / Zoom을 구현합니다. 마우스로 클릭한 화면 위치가 사진의 몇 번 픽셀인지 찾을 때 사용합니다.
      this with { PanX = PanX + deltaDipX, ... } C# record struct의 비파괴 복사(with 식) 문법입니다. 기존 구조체를 덮어쓰지 않고, Zoom과 DpiScale은 그대로 유지한 채 PanX, PanY만 바뀐 새 구조체를 만듭니다.
      Math.Clamp(targetZoom, MinZoom, MaxZoom) 배율이 너무 작아져 0이 되거나 무한히 커지는 것을 막아 ScreenToImage의 나눗셈이 언제나 안전하게 동작하도록 보장합니다.
      PointD imageAnchor = ScreenToImage(screenAnchor); (식 2.2)의 1단계입니다. 배율을 바꾸기 전에 먼저 현재 마우스 커서 아래에 놓인 원본 이미지 픽셀 좌표를 구해 기억해 둡니다.
      screenAnchor.X - (imageAnchor.X * clampedZoom) (식 2.2)의 2단계입니다. 새 배율(clampedZoom)을 적용한 뒤에도 imageAnchor가 screenAnchor 위치에 그대로 머물도록 새 PanX, PanY를 역산합니다.
      Math.Min(scaleX, scaleY) (식 2.3)에서 가로 맞춤 배율과 세로 맞춤 배율 중 더 작은 쪽을 택해 사진이 화면 밖으로 잘리지 않게 합니다.

      6단계 · 방금 만든 코드의 설계 원리: 왜 좌표 변환을 ViewportTransform 하나로 모았을까?

      SOLID 원칙 GRASP 패턴

      처음 프로그램을 짤 때는 마우스 클릭 이벤트 함수마다 직접 (mouseX - panX) / zoom 수식을 복사해서 붙여넣기 쉽습니다.
      방금 우리가 만든 것처럼 ViewportTransform 클래스로 분리하면 어떤 강력한 장점이 생길까요?

      GRASP · Information Expert (정보 전문가)

      배율(Zoom)과 위치(Pan)를 가진 객체가 변환 공식도 직접 책임진다

      Zoom, PanX, PanY, DpiScale 데이터를 모두 들고 있는 전문가가 바로 ViewportTransform이므로, 화면↔이미지 변환 공식과 ZoomAt 계산을 이 구조체 안에 캡슐화했습니다.

      SOLID · SRP (단일 책임 원칙)

      카메라 렌즈 수식 계산과 마우스 드래그 상태 관리의 분리

      ViewportTransform은 오직 '카메라 좌표 변환 수학'만 수행하고, 마우스 버튼을 누른 채 화면을 끌고 다니는 상태 관리는 06장에서 배울 PanGesture가 별도로 담당합니다.

      GRASP · Low Coupling (낮은 결합도)

      클릭 판정기·렌더러·타일 계산기가 똑같은 변환 객체를 공유

      클릭 판정기(RoiHitTester), 장면 조립기(ScenePainter), 타일 계산기(TilePlanner)가 모두 동일한 ViewportTransform을 받아 쓰므로, 화면에 그려진 위치와 마우스가 클릭되는 위치가 0.001픽셀도 어긋나지 않습니다.

      SOLID · 불변성 (Immutability)

      줌/패닝 시 기존 값을 덮어쓰지 않고 새 ViewportTransform 반환

      ZoomAt()이나 PanBy()는 기존 구조체를 수정하지 않고 with 식으로 새 구조체를 반환하므로, 백그라운드 렌더링 스레드가 화면을 그리는 도중에 배율이 반쪽만 바뀌는 화면 깨짐 버그가 원천 차단됩니다.

      💡 왜 이 구조가 초고속 최적화에 유리할까요?
      8K~32K 거대 이미지를 확대할 때 수억 개의 이미지 픽셀을 다시 계산하는 게 아니라, ViewportTransform의 숫자 3개(Zoom, PanX, PanY)만 바꾸어 GPU와 타일 계산기에 넘기므로 32K 영상도 0.001ms 만에 즉시 확대/이동됩니다!

      CLASS DIAGRAM 02장 카메라 뷰포트(ViewportTransform)와 주변 클래스들의 연결 구조

      방금 우리가 작성한 ViewportTransform을 앞으로 만들 InteractionController, PanGesture, TilePlanner가 어떻게 함께 사용하는지 보여주는 설계도입니다.

      SEQUENCE DIAGRAM 02장 시퀀스 다이어그램 · 마우스 휠 확대(ZoomAt) 시 커서 위치 고정 호출 순서

      사용자가 마우스 휠을 굴릴 때 마우스 아래 이미지 좌표(anchorImg)를 먼저 구하고 새 Pan을 역산하는 시간 순서입니다.

      7단계 · 02장 마무리 셀프 체크 & 다음 장으로 가는 징검다리

      셀프 체크 Q1 · ScreenToImage(ImageToScreen(p))를 실행하면 어떤 값이 나와야 정상일까요?

      정답: 원본 사진 좌표 p를 모니터 화면 좌표로 바꿨다가(× Zoom + Pan) 다시 역함수로 되돌렸으므로((화면 - Pan) ÷ Zoom), 원래 사진 좌표 p가 오차 없이 그대로 나와야 합니다! 실제 단위 테스트에서도 이 왕복 항등식(Round-trip Identity)으로 뷰포트 코드를 검증합니다.

      셀프 체크 Q2 · 다음 장(03장)에서는 무엇을 만들게 되나요?

      징검다리: 이제 마우스가 원본 사진의 몇 번 픽셀을 가리키는지 정확히 알게 되었습니다! 다음 03장에서는 사진 위에 사각형(Rectangle), 원/타원(Circle), 삼각형(Triangle), 자유 다각형(Polygon) 등 4가지 ROI 도형을 그리고 회전시키는 RoiGeometry 엔진을 직접 만들어 봅니다.

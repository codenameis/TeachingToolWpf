      Step 2 · 필수 사전지식 먼저 다지기

      개념 1 · CPU SIMD Vector256<int>가 어떻게 8배 빠를까?

      최신 CPU 코어 안에는 32비트(4바이트) 정수 하나만 담는 일반 그릇 말고도, 256비트(32바이트 = 32비트 정수 8개)를 한꺼번에 담는 거대한 와이드 레지스터가 들어 있습니다.
      C#의 System.Runtime.Intrinsics.Vector256을 쓰면 덧셈 기호(+) 한 번에 픽셀 8개가 동시에 더해집니다! 

      // 32비트 정수 8개를 한 번에 더하고 오른쪽 시프트(>> 1, 즉 ÷2)를 동시에 수행!
Vector256<int> avg8 = (vecA + vecB + Vector256.Create(1)) >> 1;

      개념 2 · 고1 로그(Logarithm) 밑이 2인 로그 log2(x)

      고등학교 1학년 수학에서 배우는 log2(x)는 "2를 몇 번 거듭제곱해야 x가 되는가?"를 묻는 함수입니다!

      • 축소 배율이 s = 0.5 (1/2 크기) → 1 / s = 2 = 2¹ 이므로 log₂(2) = 1층(Level 1)!
      • 축소 배율이 s = 0.25 (1/4 크기) → 1 / s = 4 = 2² 이므로 log₂(4) = 2층(Level 2)!
      • 축소 배율이 s = 0.125 (1/8 크기) → 1 / s = 8 = 2³ 이므로 log₂(8) = 3층(Level 3)!

      개념 3 · GPU Instancing 도형 4,096개를 드로우콜 1번으로 찍어내기

      그래픽카드(GPU)에게 "사각형 1개 그려라"를 4,096번 따로 시키면 CPU↔GPU 통신 비용 때문에 느려집니다.
      대신 4,096개 도형의 (중심 X, Y, 가로 W, 세로 H, 회전각 θ, 색상) 배열을 GPU 메모리(VRAM) 버퍼 하나에 통째로 올려두고 DrawInstanced(4096) 단 한 번만 호출하면 GPU 코어 수천 개가 동시에 달려들어 0.05ms 만에 다 그려냅니다!

      개념 4 · GPU Fence 왜 GPU 메모리를 지울 때 번호표(Fence)를 확인할까?

      CPU가 GPU에게 "3번 블록 버퍼를 그려라"라고 명령을 내린 직후, GPU가 아직 그리는 중인데 CPU가 그 버퍼를 지워버리면(Dispose) 그래픽카드가 멈춥니다(Device Removed)!
      그래서 매 프레임마다 번호표(frameFenceValue = 101, 102...)를 붙이고, GPU가 "102번 프레임 다 그렸어!"라고 완료 신호를 보낸 뒤에만 안 쓰는 버퍼를 안전하게 치웁니다(RetireBlock).

      3단계 · 한 걸음씩 수식 유도하기: 타일 피라미드 LOD 공식과 SIMD 반올림 평균 수식

      공식 1 · 밑이 2인 로그와 가시 타일 구간 화면 배율 s 에 따른 최적 피라미드 레벨 L 과 가시 타일 행·열 범위
      (식 9.1)
      ✏️ 한 걸음씩 유도하기:
      1) 피라미드의 L번째 층(Level L) 이미지는 원본(Level 0)보다 가로·세로가 2L배 축소되어 있습니다. 즉 Level L의 픽셀 1개는 원본 이미지의 2L × 2L 영역을 대표합니다.
      2) 현재 모니터 배율이 s (예: s = 0.25)일 때, 화면 1픽셀에는 원본 이미지의 1 / s 픽셀(예: 1 / 0.25 = 4픽셀)이 들어갑니다.
      3) 따라서 2L ≈ 1 / s 가 되도록 양변에 밑이 2인 로그(log2)를 씌우면 L = ⌊log2(1 / s)⌋ 가 됩니다!
      4) 레벨 L에서 타일 1장(T = 512px)이 덮는 원본 이미지 폭은 T · 2L 이므로, 현재 화면 가시 구간 [xmin, xmax]를 T · 2L 로 나누면 화면에 걸치는 타일 열 번호 구간이 바로 구해집니다!
      피라미드 레벨 선택 L = clamp(⌊log2(1s)⌋,  0,  Lmax) (레벨 L의 축소 비율: 2L)
      레벨 L 가시 타일 범위 (T = 512 px) c ∈ [⌊xminT · 2L⌋,  ⌊xmaxT · 2L⌋]

      초간단 숫자 대입: 32K 초대형 사진을 화면에 0.25배(1/4 크기)로 축소해서 보고 있고, 현재 화면에 원본 좌표 0 ~ 4096 구간이 보인다면?
      • 1 ÷ 0.25 = 4 = 2² 이므로 피라미드 Level 2(1/4 축소본)를 선택합니다!
      • Level 2에서 512px 타일 1장은 원본 사진의 512 × 4 = 2048px 폭을 덮으므로, 4096 ÷ 2048 = 딱 2장(0열, 1열)의 타일만 GPU로 그리면 끝납니다!
      공식 2 · 비트 정확도(Bit-Exact) 정수 SIMD 축소 부동소수점 오차 없는 정수 반올림 평균과 Vector256<int> 8픽셀 병렬 처리
      (식 9.2)
      ✏️ 한 걸음씩 유도하기:
      1) 두 정수 밝기 값 A와 B의 평균을 낼 때 그냥 정수 나눗셈 (A + B) / 2를 하면 0.5가 무조건 버려져 이미지가 단계마다 어두워집니다.
      2) 소수 첫째 자리 0.5에서 정확히 반올림하려면 나누기 전에 1을 먼저 더한 뒤 2로 나누면 됩니다(오른쪽 1비트 시프트 >> 1): (A + B + 1) >> 1.
      3) 이 수식을 Vector256<int>에 적용하면 CPU 코어 하나가 클럭 한 번에 픽셀 8개의 반올림 평균을 비트 단위까지 100% 동일하게(Bit-Exact) 계산해 피라미드 생성 시간을 크게 단축합니다!
      정수 반올림 평균 Avg(A, B) = ⌊A + B + 12⌋ = (A + B + 1) ≫ 1

      using System;
using System.Collections.Generic;
using System.Runtime.Intrinsics;
using VisionGeometry;

namespace VisionCanvas.Rendering;

public static class TilePlanner
{
    public const int TileSize = 512;

    // 1. (식 9.1) 현재 뷰포트 배율(Zoom)에 맞는 최적 피라미드 레벨 L을 선택합니다.
    public static int SelectLevel(double zoom, int maxLevel)
    {
        if (zoom >= 1.0) return 0;
        int level = (int)Math.Floor(Math.Log2(1.0 / zoom));
        return Math.Clamp(level, 0, maxLevel);
    }

    // 2. (식 9.2) Vector256 SIMD를 이용해 픽셀 8개씩 동시에 반올림 평균을 구합니다!
    public static void AverageRowSimd(ReadOnlySpan<int> rowA, ReadOnlySpan<int> rowB, Span<int> dst)
    {
        int i = 0;
        if (Vector256.IsHardwareAccelerated)
        {
            Vector256<int> ones = Vector256.Create(1);
            for (; i <= dst.Length - 8; i += 8)
            {
                Vector256<int> va = Vector256.LoadUnsafe(ref System.Runtime.InteropServices.MemoryMarshal.GetReference(rowA.Slice(i, 8)));
                Vector256<int> vb = Vector256.LoadUnsafe(ref System.Runtime.InteropServices.MemoryMarshal.GetReference(rowB.Slice(i, 8)));
                Vector256<int> avg = (va + vb + ones) >> 1; // 8개 픽셀 동시 반올림 평균!
                avg.CopyTo(dst.Slice(i, 8));
            }
        }
        // 8개 단위로 떨어지지 않는 나머지 꼬리 픽셀 처리
        for (; i < dst.Length; i++)
        {
            dst[i] = (rowA[i] + rowB[i] + 1) >> 1;
        }
    }
}

      if (_entries.TryGetValue(key, out Entry? entry)) { ... uploadRoleChanges(...); } GPU 캐시 적중(Cache Hit) & 4B 역할 분리: 불변 BVH 블록 참조(region.Identity)가 같으면 64바이트 형상 버퍼는 재사용하고, 선택 상태가 바뀌었을 때만 4바이트 역할 버퍼(uploadRoleChanges)만 가볍게 갱신합니다!
      if (!canPrepareNewDetail) { _lastDetails.TryGetValue(region.Identity, out ...); } 4ms 상세화 예산 방어: 이번 프레임 상세 준비 예산(4ms)을 넘겼다면 마우스가 멈추지 않도록 직전 LOD 버퍼(_lastDetails)를 임시로 보여주고 다음 프레임에 상세화합니다.

      6단계 · 방금 만든 코드의 설계 원리: GPU 메모리 최적화와 멀티 렌더러(DX12/Vulkan/wgpu/Skia) 아키텍처

      SOLID 원칙 GRASP 패턴
      GRASP · Pure Fabrication (순수 가공물)

      타일 계산기(TilePlanner)와 공통 VRAM 블록 캐시(RoiBlockCache<TBlock>) 분리

      도메인 모델(Roi, GrayImage)에 GPU 버퍼 코드를 섞지 않고, 오직 렌더링 최적화를 위한 전용 가공 클래스(TilePlanner, RoiBlockCache, RoiPipeline)를 두었습니다.

      SOLID · SRP (단일 책임 원칙)

      64B 형상 버퍼(RoiInstance)와 4B 역할 버퍼(Role)의 물리적 분리

      1억 개 ROI 중 일부를 클릭해 선택(Selected)할 때 64바이트 형상 데이터를 다시 업로드하지 않도록, 불변 형상(64B)과 선택·활성 역할(4B uint) 버퍼를 분리해 UploadRoleChanges만 호출합니다.

      GRASP · Protected Variations (변화로부터의 보호)

      DX12 / Vulkan / wgpu / Skia 4대 렌더러가 동일한 VisionCanvas.Host 캐시 공유

      공통 TilePlanner, BoxResampler, RoiBlockCache<TBlock>를 VisionCanvas.Host에서 공유하고, 실제 그래픽 API 명령어(HLSL/SPIR-V/WGSL/Skia)만 각 백엔드 안에 캡슐화했습니다.

      SOLID · OCP (개방-폐쇄 원칙)

      3단계 캐시 조회(Hit → 4ms Budget Fallback → Pack & Upload)와 128MiB 아레나 퇴출

      RoiBlockCache.GetOrUpload 내부에서 상세 준비 예산(4ms)과 128MiB 아레나 페이지 단위 LRU 퇴출(EvictInactive)을 처리해 렌더 루프를 단순하게 유지합니다.

      렌더러 프로젝트 기반 그래픽 API 핵심 특징 및 적합한 환경 참조 문서
      VisionCanvas Direct3D 12 + Direct2D/DirectWrite Windows 기본 고성능 GPU 경로, HLSL 인스턴싱 셰이더 및 D2D 텍스트 오버레이 본 매뉴얼 08~09장
      VisionCanvas.Vulkan Vulkan 1.2+ (SPIR-V) 명시적 커맨드 버퍼·펜스 제어, 크로스플랫폼 규격 GPU 파이프라인 manual/vulkan/README.md
      VisionCanvas.Wgpu WebGPU Native (WGSL, DX12 백엔드) 모던 WebGPU API 및 WGSL 셰이더 기반, 깔끔한 바인드 그룹 아키텍처 manual/wgpu/README.md
      VisionCanvas.Skia SkiaSharp (전용 스레드 CPU Raster) GPU 드라이버 문제나 원격 데스크톱/구형 PC에서도 동작하는 CPU 래스터 렌더러 docs/skia-canvas-performance.md

      CLASS DIAGRAM 09장 GPU 타일 피라미드 캐시 · RoiBlockCache<TBlock> · RoiPipeline 클래스 다이어그램

      8K~32K 대용량 영상 타일링과 1억 개 ROI 하드웨어 가속을 담당하는 VisionCanvas.Host 및 백엔드 GPU 파이프라인 클래스 구조입니다.

      SEQUENCE DIAGRAM 09장 시퀀스 다이어그램 · RoiBlockCache.GetOrUpload 3단계 GPU 캐시 & 4B 역할 갱신 흐름

      불변 BVH 블록 참조(region.Identity)를 비교해 캐시 적중 시 64B 형상은 재사용하고 4B 역할만 갱신하며, 4ms 예산 초과 시 직전 LOD 버퍼로 폴백하는 순서입니다.

      7단계 · 09장 마무리 셀프 체크 & 마지막 10장으로 가는 징검다리

      셀프 체크 Q1 · 화면을 0.25배(1/4 크기)로 축소해서 볼 때 원본(Level 0) 대신 몇 단계 축소된 피라미드 이미지(Level L)를 쓰면 딱 맞을까요?

      정답: 1 / 0.25 = 4 = 2² 이므로, 가로·세로를 1/4로 줄여둔 Level 2 이미지를 가져오면 픽셀 낭비 없이 딱 맞게 그릴 수 있습니다!

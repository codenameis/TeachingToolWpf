      01장 · 컴퓨터 화면 좌표계, struct 메모리, 그리고 2D 벡터와 회전

      우리의 첫 번째 목표는 화면 위의 점 하나를 나타내는 PointD, 반듯한 네모 상자를 나타내는 BoundsD, 그리고 도형을 회전시키는 RigidTransform2D 세 가지를 직접 만드는 것입니다.
      행렬이나 어려운 공식이 갑자기 튀어나오지 않도록, 컴퓨터 모니터의 좌표축 방향부터 시작해 C# struct 메모리 원리와 고1 삼각비 유도 과정까지 차근차근 밟아 올라갑니다.

      1단계 · 출발점 이해하기: 학교 수학 공책과 컴퓨터 모니터는 무엇이 다를까?

      가장 먼저 알아야 할 화면 상식
      차이점 ① · 원점 (0, 0)과 Y축 방향

      왼쪽 맨 위가 (0, 0)이고, 아래로 내려갈수록 Y가 커진다!

      학교 수학 시간에는 원점 (0, 0)이 한가운데에 있고 위로 올라갈수록 Y가 커집니다. 하지만 모든 컴퓨터 모니터와 디지털 사진은 옛날 브라운관 TV가 맨 위 왼쪽 줄부터 아래로 주사선을 그렸던 전통 때문에 왼쪽 맨 위 모서리가 (0, 0)이고, 오른쪽으로 갈수록 X가 커지며, 아래로 내려갈수록 Y가 커집니다!

      차이점 ② · 왜 int가 아니라 double일까?

      100배 확대해도 덜덜 떨리지 않는 소수점 좌표 (Sub-pixel)

      만약 좌표를 정수(int)로만 저장하면, 사진을 20배 확대해서 도형을 천천히 움직일 때 100 → 101처럼 1픽셀 단위로 뚝뚝 끊기며 계단처럼 튱니다. 반면 실수(double)로 100.375처럼 소수점까지 정밀하게 저장하면 아무리 확대하고 회전해도 오차 없이 매끄럽게 움직입니다.

      차이점 ③ · 점(Point)과 화살표(Vector)

      숫자 두 개 (X, Y)는 '위치'도 되고 '이동 화살표'도 된다!

      PointD(100, 50)은 원점에서 가로 100, 세로 50에 찍힌 '점(위치)'을 뜻하기도 하고, 마우스를 오른쪽으로 +100, 아래로 +50만큼 끌었다는 '이동 화살표(벡터)'를 뜻하기도 합니다. 그래서 점 + 이동량 = 새 점이라는 산수가 그대로 성립합니다.

      일상 비유로 미리 감 잡기 · 손전등 그림자(내적)와 압정 꽂고 돌리기(피벗 회전)

      일상 비유 워밍업

      비유 1 · 내적(Dot Product)은 '손전등 그림자 길이'다!

      수식에서 내적(p · u)이라는 말이 나오면 겁먹지 말고 '그림자 길이'라고 바꿔 읽으세요!
      바닥에 놓인 자(축 u) 위로 공중의 막대기(벡터 p)에 수직으로 손전등을 비췄을 때, 바닥 자 위에 맺히는 그림자의 길이가 몇 칸인가를 구하는 아주 단순한 곱셈·덧셈입니다.

      비유 2 · 도형을 제자리에서 돌리려면 '가운데에 압정을 꽂아야' 한다!

      기본 회전 공식(x cos θ - y sin θ)은 무조건 화면 왼쪽 맨 위 구석 (0, 0)에 압정을 꽂고 돌립니다. 그냥 돌리면 화면 한가운데 있던 상자가 큰 원을 그리며 화면 밖으로 날아갑니다!
      그래서 ① 상자 중심점(Pivot)을 원점 (0, 0)으로 잠시 데려왔다가(point - Pivot), ② 돌린 다음, ③ 원래 중심점 자리로 다시 돌려놓아야(+ Pivot) 상자가 제자리에서 빙글 돕니다.

      2단계 · C# 문법 워밍업: 왜 class 대신 readonly record struct를 쓸까?

      코드를 읽기 전에 꼭 알아야 할 C# 문법 4가지

      학교나 기초 강의에서는 모든 것을 class로 만들지만, 1초에 수백만 번 계산되는 좌표 PointD를 class로 만들면 프로그램이 심하게 버벅입니다. 그 이유를 컴퓨터 메모리 구조로 먼저 이해해 봅시다.

      비교 항목 일반 class (참조 타입 = 복도 사물함) readonly record struct (불변 값 타입 = 내 책상 위 포스트잇)
      메모리 저장 위치 멀리 있는 힙(Heap) 사물함에 데이터를 넣고, 변수에는 사물함 번호표(주소)만 들고 다닙니다. CPU가 지금 바로 읽는 스택(Stack) 책상 위나 배열 칸 안에 숫자 (X, Y)가 직접 들어갑니다.
      10만 번 계산할 때 new PointClass()를 10만 번 부르면 일회용 사물함이 10만 개 생겨나고, 청소부(가비지 컬렉터, GC)가 청소하느라 화면이 뚝뚝 멈춥니다. 사물함을 전혀 만들지 않고 책상 위 숫자만 바로 계산하므로 청소할 쓰레기(힙 할당)가 0바이트입니다!
      값 변경 규칙 누군가 내 사물함 열쇠를 복사해 가서 안의 숫자를 몰래 바꾸면 내 화면도 같이 망가집니다(버그 위험). readonly가 붙어 있어 한 번 적힌 숫자는 절대 못 바꿉니다. 멀티스레드에서도 100% 안전합니다.

      문법 1 한 줄로 완성하는 readonly record struct

      예전 C#에서는 X, Y 프로퍼티와 생성자, == 비교 함수를 30줄에 걸쳐 직접 짜야 했습니다.
      최신 C#에서는 아래 단 한 줄만 적으면 컴파일러가 생성자와 값 비교(a == b)까지 자동으로 만들어 줍니다. 

      // 단 한 줄로 불변 X, Y 속성과 생성자, == 비교가 완성됩니다!
public readonly record struct PointD(double X, double Y);

      문법 2 원본은 지켜주고 원하는 값만 바꾼 새 복사본 뽑기: with

      불변 객체는 roi.Width = 200;처럼 원본을 직접 고칠 수 없습니다(그래야 Ctrl+Z로 예전 상태를 되돌릴 수 있으니까요!).
      대신 with를 쓰면 원본은 그대로 둔 채 중괄호 안의 속성만 바뀐 새 복사본을 찰칵 찍어냅니다. 

      // original은 그대로 보존되고, Center만 이동된 새 객체 moved가 만들어집니다.
RoiGeometry moved = original with { Center = original.Center + delta };

      문법 3 Null 검사와 변수 꺼내기를 동시에: is { } 와 switch 식

      if (hit is { } point)는 한국어로 읽으면 "만약 hit가 비어있지(null) 않다면, 그 안의 진짜 값을 꺼내어 point라고 부르자!"라는 뜻입니다.
      또한 switch 식(=>)을 쓰면 수학의 조건부 함수처럼 깔끔하게 값을 계산할 수 있습니다. 

      double area = shape switch
{
    RoiShape.Rectangle => w * h,
    RoiShape.Circle    => Math.PI * (w * 0.5) * (h * 0.5),
    _                  => 0.0 // 그 외의 경우(_)
};

      문법 4 if 중첩 지옥을 없애는 보호절 (Guard Clause)

      if 안에 또 if를 넣어 오른쪽으로 깊게 들어가는 코드는 읽기가 너무 힘듭니다.
      계산할 필요가 없는 예외 상황(예: 회전 각도가 0도일 때)은 함수 맨 위에서 바로 return해서 내보내는 것을 보호절(Guard Clause)이라고 부릅니다. 

      // 각도가 0도에 가까우면 무거운 삼각함수(sin, cos)를 부르지 않고 즉시 반환!
if (Math.Abs(RotationRadians) <= 1e-12)
{
    return Pivot + shifted;
}

      3단계 · 고1 수학으로 한 줄씩 유도하기: 점·거리·그림자·나침반·회전 공식

      이제 도형을 움직이고 돌리는 데 필요한 4가지 수학 공식을 하나씩 만들어 봅시다.
      외우려고 하지 마세요! "왜 이런 식이 나왔는지" 유도 과정을 따라 읽고 바로 아래의 실제 숫자 대입 예제를 보면 중학생도 10초 만에 이해할 수 있습니다.

      공식 1 · 중2 피타고라스 정리 두 점 사이의 이동 화살표(변위 벡터)와 직선 거리
      (식 1.1)
      ✏️ 한 걸음씩 유도하기:
      1) 마우스를 시작점 a = (ax, ay)에서 끝점 b = (bx, by)까지 끌었다면, 가로로 움직인 양은 Δx = bx − ax이고 세로로 움직인 양은 Δy = by − ay입니다.
      2) 가로 밑변이 Δx이고 세로 높이가 Δy인 직각삼각형의 빗변 길이는 중학교 때 배운 피타고라스 정리(밑변² + 높이² = 빗변²)에 의해 √(Δx² + Δy²)이 됩니다!
      3) 실전 최적화 팁: 컴퓨터 CPU에게 루트(Math.Sqrt) 계산은 덧셈·곱셈보다 느립니다. 그래서 단순히 "거리가 5픽셀 이하인가?"만 비교할 때는 양변을 제곱해 Δx² + Δy² ≤ 25 (LengthSquared <= 25)로 비교하면 루트 계산을 아예 생략할 수 있습니다!
      Δ = b − a = (bx − ax,  by − ay), ‖Δ‖2 = √Δx2 + Δy2
      기호 및 변수 정의 (Symbol & Domain Legend)
      수식 기호 수학적 의미 정의역 · 단위 C# 코드 대응
      a, b 2차원 평면 위의 시작점과 끝점 위치 가로·세로 숫자 쌍 (X, Y) [단위: 픽셀 또는 DIP] PointD a, PointD b
      Δ = (Δx, Δy) 점 a에서 점 b로 향하는 이동 화살표(변위 벡터) 가로·세로 숫자 쌍 (X, Y) PointD delta = b - a
      ‖Δ‖2 두 점 사이의 직선 거리 (피타고라스 빗변 길이) 0 이상의 실수 delta.Length (Math.Sqrt)
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 시작점 a = (10, 20)에서 끝점 b = (13, 24)까지 마우스를 끌었다면?
      • 가로 이동량 Δx = 13 − 10 = 3, 세로 이동량 Δy = 24 − 20 = 4
      • 두 점 사이 직선 거리 = √(3² + 4²) = √(9 + 16) = √25 = 5 픽셀! (중학교 때 배운 3:4:5 직각삼각형 그대로입니다!)
      공식 2 · 그림자 길이 재기 (내적) 벡터의 내적(Dot Product) — 기울어진 기준 축 위로 드리운 그림자 길이
      (식 1.2)
      ✏️ 왜 내적이 필요할까요? (단계별 이해):
      1) 상자가 반듯하게 서 있을 때는 마우스 점 p = (7, 5)가 가로로 몇 칸 갔는지 보려면 그냥 X좌표 7을 읽으면 됩니다. 이는 가로 방향 단위 화살표 u = (1, 0)과 7×1 + 5×0 = 7을 계산한 것과 같습니다.
      2) 그렇다면 상자가 각도 θ만큼 비스듬히 기울어져 있어서, 상자의 가로축 방향 화살표가 u = (ux, uy) = (cos θ, sin θ)가 되었다면 어떨까요?
      3) 이때도 똑같이 가로 성분끼리 곱하고(px ux) 세로 성분끼리 곱해서 더하면(py uy), 기울어진 축 u 위로 수직 손전등을 비췄을 때 맺히는 정확한 그림자 길이(정사영 길이, ‖p‖ cos α)가 나옵니다!
      p · u = px ux + py uy = ‖p‖ ‖u‖ cos α
      기호 및 변수 정의 (Symbol & Domain Legend)
      수식 기호 수학적 의미 정의역 · 판정 의미 C# 코드 대응
      p = (px, py) 측정하려는 대상 벡터 (예: 도형 중심에서 마우스까지의 화살표) 가로·세로 숫자 쌍 (X, Y) [단위: 픽셀] PointD p = point - center
      u = (cos θ, sin θ) 길이가 1인 기준 방향 화살표 (예: 기울어진 상자의 가로축) 길이 ‖u‖ = 1인 단위 벡터 new PointD(Math.Cos(rad), Math.Sin(rad))
      p · u 축 u 방향으로 드리운 그림자 길이 (양수면 앞쪽, 음수면 반대쪽) 실수 (double) PointD.Dot(p, u)
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 기준 화살표 u가 오른쪽 가로 방향 (1, 0)이고, 마우스 점 p가 (7, 5)라면?
      • 내적 p · u = (7 × 1) + (5 × 0) = +7! (오른쪽 방향으로 딱 7칸 갔다는 뜻)
      • 만약 마우스 점 p가 왼쪽인 (−4, 5)라면? (−4 × 1) + (5 × 0) = −4! (부호가 음수이므로 기준 화살표 반대쪽으로 4칸 갔다는 뜻입니다!)
      공식 3 · 좌회전/우회전 나침반 (외적) 2D 외적(Cross Product) — 선분이 어느 쪽으로 꺾였는지 알려주는 판별식
      (식 1.3)
      ✏️ 왜 엇갈려 곱해 뺄까요? (ax by − ay bx):
      1) 두 화살표 a = (ax, ay)와 b = (bx, by)의 기울기를 비교해 봅시다. b가 a보다 더 아래쪽(시계 방향)으로 꺾여 있다는 것은 기울기 by / bx > ay / ax라는 뜻입니다.
      2) 양변에 분모를 곱해 이항하면 바로 ax by − ay bx > 0이 됩니다!
      3) 따라서 이 값 하나만 계산해 보면 두 선분이 서로 교차하는지(03장 다각형 8자 꼬임 검사)를 나눗셈(0으로 나누기 위험) 없이 즉시 판별할 수 있습니다!
      Cross(a, b) = ax by − ay bx = ‖a‖ ‖b‖ sin α
      기호 및 변수 정의 (Symbol & Domain Legend)
      수식 기호 수학적 의미 부호 판정 기준 (화면 Y↓ 기준) C# 코드 대응
      Cross(a, b) 두 벡터가 만드는 평행사변형의 부호 있는 넓이 양수(+): 시계 방향, 음수(−): 반시계 방향, 0: 평행 (a.X * b.Y) - (a.Y * b.X)
      🔢 고1 학생도 3초 만에 이해하는 실제 숫자 대입 예제
      초간단 숫자 대입: 정면 오른쪽 화살표 a = (1, 0) 기준에서 점 b = (1, 3)이 어느 쪽으로 꺾였는지 확인해 볼까요?
      • 외적 = (1 × 3) − (0 × 1) = +3 (양수)!
      • 컴퓨터 화면에서는 아래쪽이 +Y이므로, 결과가 양수(+)면 정면 화살표보다 오른쪽 아래(시계 방향)로 꺾여 있다는 뜻입니다.
      공식 4 · 고1 삼각비(sin, cos) 회전 도형을 +θ만큼 돌리는 회전 공식과 −θ만큼 되돌리는 역회전 공식
      (식 1.4)
      ✏️ 행렬을 몰라도 10초 만에 이해하는 고1 삼각비 유도 과정:
      1) 가로로 1칸 간 점 (1, 0)을 각도 θ만큼 돌리면 어디로 갈까요? 반지름이 1인 원 위의 점이므로 (cos θ, sin θ)가 됩니다.
      2) 세로로 1칸 간 점 (0, 1)을 똑같이 θ만큼 돌리면, X축은 왼쪽(−)으로 가고 Y축은 줄어들어 (−sin θ, cos θ)가 됩니다.
      3) 그렇다면 가로로 x칸, 세로로 y칸 간 점 (x, y)를 돌리면? 1번에 x배, 2번에 y배를 해서 더해주면 끝납니다!
         👉 새 가로 x' = x cos θ − y sin θ,   새 세로 y' = x sin θ + y cos θ
      4) 반대로 원래 자리로 되돌리는 역회전(−θ)은 각도에 −θ를 넣으면 됩니다. 삼각함수에서 cos(−θ) = cos θ이고 sin(−θ) = −sin θ이므로, 가운데 부호(−와 +) 두 개만 서로 맞바꾸면 즉시 역회전 공식이 완성됩니다!
      정방향 회전 +θ x' = x cos θ − y sin θ, y' = x sin θ + y cos θ
      역방향 회전 −θ x = x' cos θ + y' sin θ, y = −x' sin θ + y' cos θ

      완성 코드 1 · 점/벡터(PointD)와 반듯한 상자(BoundsD) src/VisionGeometry/PointD.cs 
      using System;

namespace VisionGeometry;

public readonly record struct PointD(double X, double Y)
{
    public double LengthSquared => (X * X) + (Y * Y);
    public double Length => Math.Sqrt(LengthSquared);
    public bool IsFinite => double.IsFinite(X) && double.IsFinite(Y);

    public static double Dot(PointD a, PointD b) => (a.X * b.X) + (a.Y * b.Y);
    public static double Cross(PointD a, PointD b) => (a.X * b.Y) - (a.Y * b.X);

    public static PointD operator +(PointD a, PointD b) => new(a.X + b.X, a.Y + b.Y);
    public static PointD operator -(PointD a, PointD b) => new(a.X - b.X, a.Y - b.Y);
    public static PointD operator *(PointD a, double s) => new(a.X * s, a.Y * s);
    public static PointD operator /(PointD a, double s) => new(a.X / s, a.Y / s);
}

public readonly record struct BoundsD(double Left, double Top, double Right, double Bottom)
{
    public double Width => Math.Max(0.0, Right - Left);
    public double Height => Math.Max(0.0, Bottom - Top);
    public PointD Center => new((Left + Right) * 0.5, (Top + Bottom) * 0.5);

    public bool Contains(PointD pt) =>
        pt.X >= Left && pt.X <= Right && pt.Y >= Top && pt.Y <= Bottom;

    public bool Intersects(BoundsD other) =>
        Left <= other.Right && Right >= other.Left && Top <= other.Bottom && Bottom >= other.Top;
}
      완성 코드 2 · 2D 강체 회전·이동 변환기 (RigidTransform2D) src/VisionGeometry/RigidTransform2D.cs 
      using System;

namespace VisionGeometry;

public readonly record struct RigidTransform2D(
    PointD Translation,
    double RotationRadians,
    PointD Pivot)
{
    public static readonly RigidTransform2D Identity = new(new PointD(0, 0), 0.0, new PointD(0, 0));

    public PointD Apply(PointD point)
    {
        // 1단계: 평행이동을 적용한 뒤 회전 중심(Pivot)을 원점 (0, 0)으로 당겨옵니다.
        var shifted = point + Translation - Pivot;

        // 보호절(Guard Clause): 회전 각도가 0이면 삼각함수 계산 없이 즉시 반환!
        if (Math.Abs(RotationRadians) <= 1e-12)
        {
            return Pivot + shifted;
        }

        // 2단계: (식 1.4) 2D 정방향 회전 공식 적용
        var cos = Math.Cos(RotationRadians);
        var sin = Math.Sin(RotationRadians);
        var rotated = new PointD(
            (shifted.X * cos) - (shifted.Y * sin),
            (shifted.X * sin) + (shifted.Y * cos));

        // 3단계: 다시 회전 중심(Pivot) 위치를 더해 원래 자리로 돌려놓습니다.
        return Pivot + rotated;
    }
}
      단계 C# 실제 코드 고1 눈높이 한 줄 해부 설명
      1 public readonly record struct PointD(double X, double Y) 힙 메모리 할당이 전혀 없는 불변 값 구조체로 선언하여, 1초에 수백만 번 계산해도 가비지 컬렉터(GC) 멈춤이 발생하지 않습니다.
      2 public double LengthSquared => (X * X) + (Y * Y); public double Length => Math.Sqrt(LengthSquared); 거리 제곱(LengthSquared)을 먼저 만들어 두면, 단순 거리 비교에서는 느린 Math.Sqrt를 생략할 수 있고 진짜 길이가 필요할 때만 Length를 부릅니다.
      3 public static PointD operator -(PointD a, PointD b) => new(a.X - b.X, a.Y - b.Y); 연산자 오버로딩 덕분에 Subtract(a, b)처럼 길게 쓰지 않고 수학 책처럼 b - a로 두 점 사이의 이동 화살표를 구합니다.
      4 public bool Intersects(BoundsD other) => Left <= other.Right && Right >= other.Left && Top <= other.Bottom && Bottom >= other.Top; 두 사각형이 겹치는지 확인하는 조건입니다. 내 왼쪽이 상대방 오른쪽보다 왼쪽에 있고, 내 오른쪽이 상대방 왼쪽보다 오른쪽에 있으면 가로로 겹칩니다!
      5 var shifted = point + Translation - Pivot; 도형을 제자리에서 돌리기 위해, 먼저 회전 중심점(Pivot)을 빼서 도형 중심을 원점 (0, 0)으로 잠시 데려옵니다.
      6 if (Math.Abs(RotationRadians) <= 1e-12) { return Pivot + shifted; } 켄트 백의 보호절(Guard Clause): 회전 각도가 거의 0도(10⁻¹² 이하)라면 Math.Cos, Math.Sin을 부르지 않고 즉시 결과를 돌려줍니다.
      7 var rotated = new PointD( (shifted.X * cos) - (shifted.Y * sin), (shifted.X * sin) + (shifted.Y * cos)); return Pivot + rotated; 원점 기준으로 (x cos θ - y sin θ, x sin θ + y cos θ) 회전을 수행한 뒤, 아까 뺐던 Pivot을 다시 더해 원래 중심 자리로 복구합니다.
      완성 코드 3 · 내적(Dot)과 외적(Cross)으로 마크 회전각을 구하는 FiducialAlignment.cs src/VisionGeometry/FiducialAlignment.cs

      방금 배운 내적(dot)과 외적(cross)이 실제 반도체·PCB 검사에서 어떻게 쓰일까요? 카메라에 찍힌 기판의 기준 마크(1~4점) 위치가 살짝 틀어졌을 때, FiducialAlignment.TryFindRotation은 기준 중심에서의 벡터 from과 검출 중심에서의 벡터 to의 내적 합과 외적 합을 구한 뒤 Math.Atan2(cross, dot) 단 한 줄로 최소제곱 회전 보정각 angle을 계산합니다! 

      // src/VisionGeometry/FiducialAlignment.cs 핵심 발췌: 1점은 XY 이동, 2~4점은 최소제곱 XYθ 강체 보정
var dot = 0d;
var cross = 0d;
for (var i = 0; i < reference.Length; i++)
{
    var from = inherited.ApplyVector(reference[i] - referenceCenter);
    var to = detected[i] - detectedCenter;
    dot += (from.X * to.X) + (from.Y * to.Y);       // 내적 합 (cos 비례)
    cross += (from.X * to.Y) - (from.Y * to.X);     // 외적 합 (sin 비례)
}
angle = Math.Atan2(cross, dot) * 180 / Math.PI;     // tan(θ) = sin(θ)/cos(θ) 역삼각함수로 최적 회전각 산출!

      GRASP · Information Expert (정보 전문가)

      데이터를 가진 구조체가 계산 함수도 직접 가진다

      BoundsD가 스스로 Left, Top, Right, Bottom 숫자를 가지고 있으므로, 점이 상자 안에 들어왔는지(Contains)나 두 상자가 겹치는지(Intersects)를 외부 도우미 클래스가 아닌 BoundsD 자신이 직접 계산합니다.

      SOLID · SRP (단일 책임 원칙)

      점(PointD) · 사각 영역(BoundsD) · 회전 변환(RigidTransform2D) 역할 분리

      하나의 거대한 Math 유틸리티 클래스에 모든 함수를 다 때려넣지 않고, '점 하나', '사각 영역', '이동+회전 변환'이라는 딱 하나의 책임만 갖는 3개의 작은 구조체로 나누었습니다.

      GRASP · High Cohesion (높은 응집도)

      연산자 오버로딩(+, -, *)으로 수식과 코드를 1:1 일치

      PointD 안에 덧셈(+)과 뺄셈(-)을 정의해 두었기 때문에, b - a처럼 칠판에 적은 산수 식 그대로 C# 코드를 읽을 수 있습니다.

      SOLID · OCP (개방-폐쇄 원칙)

      불변 값 타입(readonly record struct)을 통한 안전한 확장

      내부 값을 아무나 몰래 바꿀 수 없게 막아두었기 때문에, 멀티스레드 렌더링 중에도 값이 깨질 걱정 없이 새로운 도형 연산을 안전하게 추가할 수 있습니다.

      💡 왜 struct(값 타입)로 짜면 최적화가 될까요?
      만약 PointD를 일반 class로 만들면, 10만 개 꼭짓점을 회전시킬 때마다 힙(Heap) 메모리에 쓰레기 객체가 10만 개씩 생겨서 가비지 컬렉터(GC) 때문에 화면이 뚝뚝 끊깁니다.
      readonly record struct로 짜면 메모리 할당이 0바이트라 60FPS가 유지됩니다!

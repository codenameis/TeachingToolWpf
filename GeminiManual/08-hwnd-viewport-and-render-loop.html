      왜 WPF 기본 도형은 멈출까?

      WPF 기본 컨트롤은 도형 하나마다 무거운 UI 객체(Visual Tree)를 만들고 레이아웃을 계산합니다. 그래서 WPF 창 안에 그래픽카드가 직접 그림을 쏘는 전용 유리창(HWND)을 뚫어야 합니다.

      파인만 학습법 (Feynman Analogy)

      🪧 비유 1 · 운영체제가 발급해 주는 '유리창 관리 번호표' (HWND와 IntPtr)

      WPF 프로그램 창이라는 큰 아파트 거실 벽에 '그래픽카드(DirectX 12 / Vulkan / wgpu)가 직접 레이저로 그림을 쏘는 전용 유리창'을 하나 뚫었다고 상상해 보세요.
      Windows 운영체제(관리사무소)는 이 유리창에 0x001A04F2번 같은 고유 관리 번호표(Handle to a Window = HWND)를 붙여주는데, C#에서 이 64비트 번호표를 담는 변수 상자 이름이 바로 IntPtr (또는 nint)입니다!

      🎞️ 비유 2 · 만화 영화 투명 셀화 필름 6장 겹치기 (화가 알고리즘, Painter's Algorithm)

      만화 영화를 만들 때 맨 아래에 '배경 풍경(1층)'을 깔고, 그 위에 투명 필름으로 '등장인물(3층)'을 얹고, 맨 위에 '말풍선과 조준선(4~6층)'을 얹으면 아래 그림 위에 위 그림이 자연스럽게 덮어써집니다.
      이처럼 뒤에 있는 것부터 앞에 있는 순서대로 차곡차곡 겹쳐 그리는 기법이 ScenePainter.Build의 핵심 원리입니다!

      Step 2 · 필수 사전지식 먼저 다지기

      개념 1 · HWND와 IntPtr 윈도우 핸들(HWND) = 운영체제가 발급하는 '화면 땅문서 번호'

      Windows 운영체제는 보안을 위해 일반 프로그램이 화면 메모리를 마음대로 건드리지 못하게 막고, 대신 창을 만들면 정수 번호표(식별자, Handle)를 하나 내어줍니다.

      • HWND: Handle to a Window(창 번호표)의 약자입니다.
      • IntPtr: C#에서 운영체제의 주소나 번호표(64비트 윈도우에서는 8바이트 정수)를 담는 전용 타입입니다. 즉 IntPtr _hwnd는 "그래픽카드야, 내 그림을 몇 번 창에 출력해 줘!"라고 알려줄 때 쓰는 방 번호입니다.

      개념 2 · HwndHost 왜 WPF 안에 HwndHost로 자식 창을 뚫어야 할까?

      WPF는 기본적으로 MainWindow 전체에 딱 1개의 HWND만 만들고, 그 안의 버튼이나 <Canvas>는 운영체제가 모르는 WPF 내부 그림으로 처리합니다.
      반면 Direct3D 12, Vulkan, wgpu의 고속 화면 출력기(SwapChain)는 반드시 자신만의 전용 HWND 번호표를 요구합니다! 그래서 WPF 레이아웃 한가운데에 독립된 자식 윈도우 핸들(Child HWND)을 분양받아 끼워 넣는 클래스가 바로 HwndHost입니다.

      개념 3 · WndProc 운영체제가 창과 대화하는 우체통 함수: WndProc

      HWND 창이 만들어지면 Windows 운영체제는 그 창 위에서 마우스가 움직이거나 키보드가 눌릴 때마다 4개의 숫자 묶음으로 된 우편물을 WndProc 함수로 배달합니다:

      • IntPtr hwnd: "몇 번 창에 도착한 우편물인가?" (방 번호)
      • int msg: "무슨 사건인가?" (예: 0x0201 = 왼쪽 마우스 눌림, 0x0200 = 마우스 이동)
      • IntPtr wParam: "보조 정보 1" (Shift/Ctrl 키 상태, 마우스 휠 회전량 등)
      • IntPtr lParam: "보조 정보 2" (마우스 가로 X좌표와 세로 Y좌표가 위아래 16비트씩 합쳐진 숫자!)

      개념 4 · SwapChain & Channel 더블 버퍼링(SwapChain)과 최신 프레임 우체통(Channel)

      화면에 직접 도형을 그리면 그려지는 과정이 깜빡거리며 보입니다(Tearing). 그래서 GPU는 뒷면 도화지(Back Buffer)에 조용히 그림을 다 그린 뒤 완성되는 순간 앞면 화면(Front Buffer)과 순식간에 맞바꾸기(Swap / Present)를 합니다.
      이때 UI 스레드가 GPU를 기다리지 않도록 비동기 우체통(Channel<RenderFrameRequest>)에 최신 요청 1개만 넣어 백그라운드 RenderWorker 스레드를 깨웁니다!

      3단계 · 한 걸음씩 수식 유도하기: Win32 lParam 비트 분해와 음수 좌표 함정 피하기

      운영체제가 WndProc로 보내주는 lParam 숫자 하나 안에는 마우스 가로 좌표(X)와 세로 좌표(Y)가 16비트(2바이트)씩 나란히 붙어 있습니다. 이를 안전하게 꺼내는 공식을 유도해 봅시다!

      공식 1 · 비트 마스크(&)와 시프트(>>) Win32 lParam 패킹 정수에서 부호 있는 (X, Y) 추출 및 DIP 변환
      (식 8.1)
      ✏️ 한 걸음씩 유도하기 (왜 반드시 (short)로 변환해야 할까요?):
      1) 32비트 정수 L의 오른쪽(하위) 16비트 칸에는 가로 좌표 X가, 왼쪽(상위) 16비트 칸에는 세로 좌표 Y가 들어 있습니다.
      2) 하위 16비트만 남기려면 16진수 마스크 0xFFFF(이진수로 하위 16자리가 모두 1)와 비트 AND(&) 연산을 합니다: L & 0xFFFF.
      3) 상위 16비트에 있는 Y를 꺼내려면 먼저 오른쪽으로 16칸 밀어낸 뒤(L >> 16) 똑같이 & 0xFFFF를 씌웁니다.
      4) ⚠️ 가장 중요한 함정: 사용자가 도형을 드래그하다가 마우스를 창 왼쪽 바깥으로 끌고 나가면 마우스 좌표가 음수(예: −10px)가 됩니다! 16비트 음수 −10(0xFFF6)을 그냥 32비트 int로 읽으면 +65526이라는 거대한 양수로 둔갑해 도형이 화면 오른쪽 끝으로 날아갑니다!
      5) 따라서 반드시 부호 있는 16비트 정수 (short)로 먼저 캐스팅해 음수 부호를 살린 뒤 모니터 배율 DpiScale로 나누어 주어야 합니다!
      xpx = (short)(L & 0xFFFF), ypx = (short)((L ≫ 16) & 0xFFFF)

      xpxddpi , ypxddpi

      using System;
using System.Runtime.InteropServices;
using System.Threading;
using System.Threading.Channels;
using System.Threading.Tasks;
using System.Windows.Interop;
using VisionCanvas.Core.Editing;
using VisionCanvas.Core.Interaction;
using VisionGeometry;

namespace VisionCanvas.Controls;

public sealed class Dx12Viewport : HwndHost
{
    private const int WsChild = 0x40000000;
    private const int WsVisible = 0x10000000;
    private const int WmLButtonDown = 0x0201;
    private const int WmLButtonUp   = 0x0202;
    private const int WmMouseMove   = 0x0200;
    private const int WmMouseWheel  = 0x020A;

    private IntPtr _hwnd;
    private double _dpiScale = 1.0;
    private readonly InteractionController _controller;

    // 1. WPF가 화면에 이 컨트롤을 배치할 때 자식 윈도우 핸들(HWND)을 생성합니다.
    protected override HandleRef BuildWindowCore(HandleRef hwndParent)
    {
        int width  = Math.Max(1, (int)Math.Ceiling(Math.Max(ActualWidth, 1.0) * _dpiScale));
        int height = Math.Max(1, (int)Math.Ceiling(Math.Max(ActualHeight, 1.0) * _dpiScale));

        _hwnd = CreateWindowEx(
            0, "STATIC", string.Empty,
            WsChild | WsVisible,
            0, 0, width, height,
            hwndParent.Handle, IntPtr.Zero, IntPtr.Zero, IntPtr.Zero);

        return new HandleRef(this, _hwnd);
    }

    protected override void DestroyWindowCore(HandleRef hwnd)
    {
        if (hwnd.Handle != IntPtr.Zero) DestroyWindow(hwnd.Handle);
    }

    // 2. (식 8.1) lParam 32비트 패킹 정수에서 부호 있는 (short) X, Y를 꺼내 DIP로 변환합니다.
    private PointD ToDip(IntPtr lParam)
    {
        long raw = lParam.ToInt64();
        int pxX = unchecked((short)(raw & 0xFFFF));
        int pxY = unchecked((short)((raw >> 16) & 0xFFFF));
        return new PointD(pxX / _dpiScale, pxY / _dpiScale);
    }

    // 3. 운영체제가 HWND 창으로 보낸 마우스/키보드 우편물을 해독합니다.
    protected override IntPtr WndProc(IntPtr hwnd, int msg, IntPtr wParam, IntPtr lParam, ref bool handled)
    {
        switch (msg)
        {
            case WmLButtonDown:
                SetFocus(_hwnd);
                SetCapture(_hwnd); // 창 밖으로 드래그해도 마우스 이벤트를 놓치지 않게 캡처!
                _controller.PointerDown(ToDip(lParam), rightButton: false);
                RequestRender();
                handled = true;
                break;

            case WmMouseMove:
                _controller.PointerMove(ToDip(lParam));
                RequestRender();
                handled = true;
                break;

            case WmLButtonUp:
                ReleaseCapture();
                _controller.PointerUp(ToDip(lParam));
                RequestRender();
                handled = true;
                break;

            case WmMouseWheel:
                int wheelDelta = unchecked((short)((wParam.ToInt64() >> 16) & 0xFFFF));
                _controller.MouseWheel(ToDip(lParam), wheelDelta);
                RequestRender();
                handled = true;
                break;
        }
        return IntPtr.Zero;
    }

    private void RequestRender() { /* Channel에 최신 프레임 그리기 요청 전송 */ }

    [DllImport("user32.dll", CharSet = CharSet.Unicode)]
    private static extern IntPtr CreateWindowEx(
        int exStyle, string className, string windowName, int style,
        int x, int y, int width, int height,
        IntPtr hwndParent, IntPtr hMenu, IntPtr hInstance, IntPtr lpParam);

    [DllImport("user32.dll")] private static extern bool DestroyWindow(IntPtr hwnd);
    [DllImport("user32.dll")] private static extern IntPtr SetCapture(IntPtr hwnd);
    [DllImport("user32.dll")] private static extern bool ReleaseCapture();
    [DllImport("user32.dll")] private static extern IntPtr SetFocus(IntPtr hwnd);
}

      GRASP · Indirection (간접성 / 비동기 채널)

      UI 스레드와 GPU 스레드 사이를 Channel<RenderFrameRequest>로 분리

      UI 스레드가 직접 GPU 함수를 호출하면 그래픽카드가 바쁠 때 마우스 커서까지 멈춥니다. 비동기 채널(우체통)을 사이에 두어 두 스레드가 서로 기다리지 않게 분리했습니다.

      GRASP · Pure Fabrication (순수 가공물)

      장면 조립만 전담하는 ScenePainter 클래스

      GPU 드로우콜을 쏘는 코드와 '무엇을 어떤 순서(6단계)로 그릴지' 결정하는 코드를 분리하기 위해 ScenePainter라는 장면 조립 전용 클래스를 만들었습니다.

      SOLID · SRP (단일 책임 원칙)

      창 관리(Dx12Viewport) · 스레드 루프(RenderWorker) · 장면 설계도(SceneFrame) 분리

      Dx12Viewport는 Win32 HWND 생성과 마우스 메시지만 처리하고, ScenePainter는 불변 설계도인 SceneFrame만 만들며, 실제 GPU 출력은 RenderWorker가 맡습니다.

      SOLID · DIP & Protected Variations

      SceneFrame 덕분에 DX12·Vulkan·wgpu·Skia가 똑같은 장면 조립 로직 공유

      ScenePainter가 특정 그래픽카드 API에 종속되지 않고 순수 데이터 묶음(SceneFrame)을 만들어주므로, 어떤 렌더러에서도 똑같은 화면이 그려집니다.

      💡 이 구조가 왜 60FPS 최적화의 핵심일까요?
      UI 스레드는 마우스 입력 처리에만 100% 집중하고, 무거운 6단 레이어 조립과 GPU 업로드는 백그라운드 RenderWorker 스레드에서 병렬로 돌아가며, 불변 스냅샷(DocumentState)을 넘기므로 스레드 락(lock) 대기 시간이 0ms입니다!

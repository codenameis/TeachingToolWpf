      CHAPTER 04 · 1단계: 자식 ROI가 부모 도형 벽을 뚫고 나가지 못하게 막는 연속 충돌 수학

      04장 · 부모-자식 경계 충돌과 이동·회전 한계 방정식 (RoiMotionBounds, RoiGroupBounds)

      03장에서 우리는 사각형·원·삼각형·폴리곤을 표현하는 RoiGeometry를 만들었습니다.
      실제 반도체·PCB 검사에서는 모듈(부모 ROI) 안에 리드 핀(자식 ROI)들이 계층 구조로 들어갑니다.
      사용자가 자식 ROI를 마우스로 빠르게 드래그하거나 회전할 때 부모 벽 밖으로 뚫고 나가면 안 되며, 벽에 딱 멈추거나 벽면을 타고 매끄럽게 미끄러져야(Wall Sliding) 합니다.
      이 장에서는 40회 이분법(스무고개), 내적을 이용한 벽면 슬라이딩, 그리고 삼각방정식 A cos θ + B sin θ = C를 한 걸음씩 유도하고 전체 C# 코드로 구현합니다!

      1단계 · 자식 도형이 부모 상자 벽에 부딪혀 미끄러지는 물리 엔진의 3단계

      Step 1 · 문제 이해와 일상 비유
      1단계 · 포함 검사

      자식이 부모 안에 완전히 들어있는가? (ContainsGeometry)

      자식 도형의 꼭짓점(또는 원의 16방향 끝점)들이 모두 부모 도형의 Contains(p)를 통과하는지 확인합니다.

      2단계 · 벽 접촉점 찾기

      몇 % 지점에서 부모 벽에 딱 닿는가? (40회 이분법)

      마우스를 100픽셀 끌었을 때 벽을 뚫고 나간다면, 절반씩 쪼개어 확인하는 스무고개(이분법)를 40번 반복해 벽에 딱 닿는 비율 t*를 찾습니다.

      3단계 · 벽면 슬라이딩

      남은 마우스 힘으로 벽을 따라 미끄러지기 (내적 정사영)

      벽에 닿은 뒤 남은 이동 벡터 r을 부모 벽 방향 단위화살표 u에 내적(Dot)하여 벽면을 타고 부드럽게 미끄러지게 만듭니다.

      일상 비유로 감 잡기 · 40회 스무고개(이분법)와 미닫이문 미끄러지기(슬라이딩)

      파인만 학습법 (Feynman Analogy)

      🎯 비유 1 · 스무고개 40번으로 머리카락 1조분의 1 오차까지 벽 찾기 (이분법)

      1부터 100 사이의 숫자를 맞출 때 "50보다 크니?" → "75보다 작니?"처럼 절반씩 범위를 줄이면 스무 번(220 ≈ 100만) 안에 무조건 맞출 수 있죠!
      이를 40번 반복하면 구간 크기가 1 / 240 ≈ 0.0000000000009 (약 1조분의 1)로 줄어들어, 어떤 모양의 도형이든 부모 벽에 딱 닿는 순간을 오차 없이 찾아냅니다.

      🚪 비유 2 · 방바닥에서 상자를 벽 쪽으로 대각선으로 밀 때 (벽면 슬라이딩)

      상자를 북동쪽(오른쪽 위 대각선)으로 밀다가 오른쪽 세로 벽에 딱 부딪혔다고 상상해 보세요. 상자가 그 자리에서 아예 얼어붙으면 조작감이 매우 답답합니다.
      실제 물리 세계처럼 오른쪽으로 벽을 뚫으려는 힘은 벽에 막혀 사라지고, 위쪽(북쪽)으로 밀던 힘만 살아남아 세로 벽을 타고 위로 스르륵 미끄러지게 해주는 것이 바로 ConstrainTranslation입니다!

      2단계 · 워밍업: 이 장을 시작하기 위한 4가지 기초 개념

      Step 2 · 필수 사전지식 먼저 다지기

      개념 1 · 비율 t 출발점(0)에서 도착점(1)까지의 이동 비율 t ∈ [0, 1]

      자식 도형을 이동 벡터 Δ = (Δx, Δy)만큼 옮길 때, 비율 t (0 ≤ t ≤ 1)를 곱한 t · Δ는 전체 이동 경로 위의 중간 지점을 뜻합니다.

      • t = 0.0: 아직 출발하지 않은 원래 자리 (무조건 부모 안쪽이므로 안전!)
      • t = 0.5: 마우스가 끈 거리의 딱 절반(50%)만큼 이동한 자리
      • t = 1.0: 마우스 커서가 있는 최종 희망 도착지

      개념 2 · 터널링 방지 왜 도착점(t = 1)만 검사하면 얇은 벽을 뚫고 지나갈까?

      사용자가 마우스를 재빠르게 휘두르면 한 프레임 만에 이동 거리 delta가 500픽셀이 될 수도 있습니다. 만약 다각형의 움푹 들어간 벽 너비가 20픽셀이라면, 중간 경로를 안 보고 도착점만 검사했을 때 벽을 순간이동으로 건너뛰는 터널링(Tunneling) 버그가 발생합니다.
      그래서 FitsTranslationStep은 이동 구간을 잘게 나누어 경로 중간중간도 모두 부모 안에 들어있는지 꼼꼼히 확인합니다.

      개념 3 · 내적 정사영 남은 힘 r을 벽 방향 단위벡터 u로 투영하기

      01장에서 배운 내적(Dot)이 여기서 가장 빛을 발합니다! 벽의 시작점과 끝점을 빼서 길이로 나눈 길이가 1인 벽 방향 화살표 u를 만든 뒤, 남은 이동 벡터 r과 내적하면: 

      // 벽 방향으로 미끄러질 거리(스칼라) = r.Dot(u)
// 벽 방향으로 미끄러질 2D 이동 벡터 = u * r.Dot(u)
PointD slideVector = u * r.Dot(u);

      개념 4 · 삼각함수 합성 A cos θ + B sin θ = C 푸는 법

      자식 도형의 꼭짓점이 중심 주위를 회전할 때 좌표는 (cos θ, sin θ)로 변하고, 부모의 직선 벽 방정식에 대입하면 항상 A cos θ + B sin θ = C 모양이 됩니다.
      여기서 직각삼각형의 빗변 R = √(A2 + B2)과 각도 φ = atan2(B, A)를 쓰면 좌변이 R cos(θ − φ) = C 로 합쳐져서 역코사인 Math.Acos(C / R) 한 번으로 정확한 충돌 각도 θ가 구해집니다!

      3단계 · 한 걸음씩 수식 유도하기: 40회 이분법 · 벽면 슬라이딩 · 회전 한계각

      공식 1 · 40회 이분 탐색 40회 이분법(Bisection)을 이용한 최대 무충돌 이동 비율 t* 탐색
      (식 4.1)
      ✏️ 한 걸음씩 유도하기:
      1) 만약 희망 이동량 전체(t = 1)로 이동해도 부모 안에 들어있다면 이분법을 할 필요 없이 바로 t* = 1.0을 반환합니다.
      2) 만약 t = 1에서 부모 밖으로 나간다면, 안전한 하한을 lo = 0.0, 충돌하는 상한을 hi = 1.0으로 놓습니다.
      3) for 루프를 40번 돌면서 딱 절반 지점 mid = (lo + hi) * 0.5로 이동시켜 봅니다.
      4) mid까지 가는 동안 부모 안에 안전하게 들어있다면 안전한 하한을 끌어올리고(lo = mid), 밖으로 삐져나간다면 상한을 낮춥니다(hi = mid).
      5) 40번 반복이 끝난 뒤의 lo 값은 실제 벽 접촉 비율 t*와 차이가 최대 1 / 240 이하이면서 절대 부모 밖으로 나가지 않는 가장 큰 안전 비율이 됩니다!

      • 1회차(mid = 0.5): 절반인 50픽셀 가봄 → 안 부딪힘(OK)! 안전 하한 lo = 0.5로 상승 (남은 범위: 50~100)

      공식 2 · 벽면 슬라이딩 부모 벽면 방향 단위벡터 u 위로의 잔여 이동량 슬라이딩 투영 (ConstrainTranslation)
      (식 4.2)
      ✏️ 한 걸음씩 유도하기:
      1) (식 4.1)로 구한 1차 직선 이동량 Δdirect = t*Δ 만큼 먼저 자식을 벽 바로 앞까지 이동시킵니다.
      2) 아직 쓰지 못하고 남은 마우스 이동 벡터는 r = Δ − Δdirect = (1 − t*)Δ 입니다.
      3) 부모 도형의 각 변(벽면) 방향 단위벡터 ui에 남은 힘 r을 내적하여 벽을 따라 미끄러지는 후보 벡터 Δslide, i = (r · ui)ui 를 구합니다.
      4) 각 벽면 슬라이딩 후보에 대해서도 다시 TranslationFraction을 곱해 그 벽 끝 모서리를 뚫지 않도록 안전하게 잘라준 뒤, 가장 많이 미끄러질 수 있는 방향을 최종 채택합니다!
      잔여 이동 벡터r = (1 − t*) Δ, 벽면 단위벡터ui = vi+1 − vi‖vi+1 − vi‖2
      벽면 슬라이딩 후보 벡터 Δslide, i = (r · ui) ui

      초간단 숫자 대입: 벽에 닿고 나서도 마우스가 대각선으로 r = (+40, +30)만큼 더 밀고 있는데, 오른쪽 세로 벽(방향 단위벡터 u = (0, 1))에 막혔다면?
      • 벽 방향 내적 = (40 × 0) + (30 × 1) = 30!
      • 슬라이딩 벡터 = u × 30 = (0, 30) → 즉 벽을 뚫는 가로 힘(+40)은 깔끔하게 사라지고, 세로 벽을 따라 아래로 +30픽셀만큼 스르륵 미끄러집니다!
      공식 3 · 회전 한계 각도 회전 접촉 방정식 A cos θ + B sin θ = C 의 해석적 근과 이분 탐색
      (식 4.3)
      ✏️ 한 걸음씩 유도하기:
      1) 자식 꼭짓점이 중심 주위를 각도 θ로 회전할 때 위치는 cos θ와 sin θ의 일차 결합으로 표현됩니다.
      2) 이 꼭짓점이 부모의 직선 변 위에 놓일 조건(내적 = 상수)을 정리하면 A cos θ + B sin θ = C 형태가 됩니다.
      3) 양변을 R = √(A2 + B2)로 나누고 cos φ = A/R, sin φ = B/R (즉, φ = atan2(B, A))로 치환하면 코사인 덧셈정리 cos(θ − φ) = cos θ cos φ + sin θ sin φ 에 의해 좌변이 단 하나의 코사인 항 cos(θ − φ) = C / R 로 합쳐집니다!
      4) 따라서 접촉 후보 각도는 θ = φ ± arccos(C / R) 두 개뿐이며, 이와 함께 회전 각도 구간에도 40회 이분법을 적용하면 어떤 도형이든 회전 한계각을 완벽하게 구할 수 있습니다.
      방정식A cos θ + B sin θ = C, 합성 진폭R = √A2 + B2, 위상각φ = atan2(B, A)
      |C| ≤ R 일 때 cos(θ − φ) = CR ⟹ θ1, 2 = φ ± arccos(CR)

      초간단 숫자 대입: 만약 A = 3, B = 4, C = 2.5 라면?
      • 합성 진폭 R = √(3² + 4²) = 5 이고, |2.5| <= 5 이므로 회전하다가 반드시 벽과 만납니다!
      • C / R = 2.5 ÷ 5 = 0.5 이고 arccos(0.5) = 60° (π/3 rad) 이므로, 위상각 φ에서 양쪽으로 ±60° 떨어진 두 각도에서 정확히 벽과 접촉합니다!

      이제 3단계에서 유도한 40회 이분법(TranslationFraction), 벽면 슬라이딩(ConstrainTranslation), 회전 한계 탐색(RotationLimit & AddRotationRoots) 전체 코드를 직접 작성해 봅시다.

      코드 1 · 부모-자식 포함 판정, 40회 이분법, 벽면 슬라이딩 전체 구현 src/VisionGeometry/RoiMotionBounds.cs 
      using System;
using System.Collections.Immutable;
using VisionCanvas.Core.Geometry;

namespace VisionGeometry;

public static class RoiMotionBounds
{
    private const int BisectionIterations = 40;
    private const double Epsilon = 1e-9;

    // 1. 자식 도형(child)의 모든 샘플 끝점이 부모 도형(parent) 내부에 들어있는지 검사합니다.
    public static bool ContainsGeometry(RoiGeometry parent, RoiGeometry child)
    {
        foreach (PointD pt in SampleBoundaryPoints(child))
        {
            if (!parent.Contains(pt)) return false;
        }
        return true;
    }

    // 2. (식 4.1) 40회 이분법으로 부모 벽에 딱 닿는 최대 무충돌 이동 비율 t* in [0, 1]을 구합니다.
    public static double TranslationFraction(RoiGeometry parent, RoiGeometry child, PointD delta)
    {
        if (FitsTranslationStep(parent, child, delta, 1.0)) return 1.0;

        double lo = 0.0, hi = 1.0;
        for (int i = 0; i < BisectionIterations; i++)
        {
            double mid = (lo + hi) * 0.5;
            if (FitsTranslationStep(parent, child, delta, mid))
                lo = mid;
            else
                hi = mid;
        }
        return lo;
    }

    // 3. (식 4.2) 직선 접촉점까지 이동한 뒤, 남은 변위(remainder)를 부모 벽면으로 정사영해 미끄러지게 합니다!
    public static PointD ConstrainTranslation(RoiGeometry parent, RoiGeometry child, PointD delta)
    {
        double t = TranslationFraction(parent, child, delta);
        PointD direct = delta * t;
        if (t >= 1.0 - 1e-6) return delta;

        RoiGeometry atWall = child with { X = child.X + direct.X, Y = child.Y + direct.Y };
        PointD remainder = delta - direct;

        PointD bestSlide = new(0, 0);
        double bestLenSq = 0.0;

        foreach (PointD wallDir in GetParentWallDirections(parent))
        {
            // (식 4.2) 남은 힘을 벽 방향 단위벡터 wallDir에 내적(Dot)하여 정사영!
            PointD projected = wallDir * remainder.Dot(wallDir);
            double slideT = TranslationFraction(parent, atWall, projected);
            PointD candidate = projected * slideT;
            if (candidate.LengthSquared > bestLenSq)
            {
                bestLenSq = candidate.LengthSquared;
                bestSlide = candidate;
            }
        }
        return direct + bestSlide;
    }

    // 4. (식 4.3) 자식 도형을 회전시킬 때 부모 벽에 부딪히지 않는 최대 회전 변화량(deltaRad)을 구합니다.
    public static void AddRotationRoots(
        double a, double b, double c,
        double startAngle, double desiredDelta,
        System.Collections.Generic.List<double> candidates)
    {
        double r = Math.Hypot(a, b);
        if (r <= Epsilon || Math.Abs(c) > r + Epsilon) return;

        double ratio = Math.Clamp(c / r, -1.0, 1.0);
        double baseAngle = Math.Atan2(b, a);
        double delta = Math.Acos(ratio);

        candidates.Add(baseAngle + delta);
        candidates.Add(baseAngle - delta);
    }

    private static bool FitsTranslationStep(RoiGeometry parent, RoiGeometry child, PointD delta, double fraction)
    {
        PointD step = delta * fraction;
        RoiGeometry moved = child with { X = child.X + step.X, Y = child.Y + step.Y };
        return ContainsGeometry(parent, moved);
    }

    private static ImmutableArray<PointD> GetParentWallDirections(RoiGeometry parent)
    {
        PointD c0 = parent.ToWorld(-0.5, -0.5);
        PointD c1 = parent.ToWorld(+0.5, -0.5);
        PointD c2 = parent.ToWorld(+0.5, +0.5);
        PointD e0 = c1 - c0;
        PointD e1 = c2 - c1;
        return ImmutableArray.Create(
            e0 / Math.Max(1e-6, e0.Length),
            e1 / Math.Max(1e-6, e1.Length));
    }

    private static ImmutableArray<PointD> SampleBoundaryPoints(RoiGeometry g) =>
        g.Shape switch
        {
            RoiShape.Rectangle => ImmutableArray.Create(
                g.ToWorld(-0.5, -0.5), g.ToWorld(+0.5, -0.5),
                g.ToWorld(+0.5, +0.5), g.ToWorld(-0.5, +0.5)),
            _ => ImmutableArray.Create(
                g.ToWorld(-0.5, 0), g.ToWorld(+0.5, 0),
                g.ToWorld(0, -0.5), g.ToWorld(0, +0.5),
                g.ToWorld(-0.3535, -0.3535), g.ToWorld(+0.3535, -0.3535),
                g.ToWorld(+0.3535, +0.3535), g.ToWorld(-0.3535, +0.3535))
        };
}
      행 / 핵심 코드 초보자 눈높이 한 줄 설명
      if (FitsTranslationStep(..., 1.0)) return 1.0; 마우스가 움직인 최종 위치(1.0)가 이미 부모 안쪽이라면, 40번 루프를 돌 필요 없이 즉시 1.0(100% 이동 허용)을 반환해 속도를 높입니다.
      double mid = (lo + hi) * 0.5; (식 4.1)의 이분 탐색입니다. 안전 구간(lo)과 충돌 구간(hi)의 딱 가운데 비율(mid)을 시험해 2−40 정밀도로 벽 위치를 좁혀 갑니다.
      PointD remainder = delta - direct; 벽 바로 앞(direct)까지 이동하고 나서 아직 소모하지 못한 잔여 마우스 이동 벡터 r을 구합니다.
      PointD projected = wallDir * remainder.Dot(wallDir); (식 4.2)의 핵심입니다! 잔여 이동 벡터 remainder를 부모 벽의 단위 방향 벡터 wallDir와 내적(Dot)하여 벽면을 따라 미끄러지는 성분을 추출합니다.
      double r = Math.Hypot(a, b); (식 4.3)의 삼각함수 합성 진폭 R = √(A2 + B2)을 구합니다. Math.Abs(c) > r이면 360°를 다 돌아도 그 벽과 안 만나므로 건너뜁니다.
      double ratio = Math.Clamp(c / r, -1.0, 1.0); 부동소수점 미세 오차로 c / r이 1.0000000000000002가 되어 Math.Acos가 NaN을 반환하는 참사를 막기 위해 [-1, +1]로 안전하게 클램프합니다.

      6단계 · 방금 만든 코드의 설계 원리: 왜 움직이는 제스처와 충돌 보정을 분리했을까?

      SOLID 원칙 GRASP 패턴

      만약 MoveGesture 안에 부모 벽 충돌 수식 200줄을 다 집어넣었다면, ResizeGesture나 키보드 방향키 이동(TryNudgeSelection)에서는 그 코드를 어떻게 재사용할 수 있었을까요?

      GRASP · Pure Fabrication (순수 가공물)

      충돌 보정만 전담하는 RoiMotionBounds와 RoiGroupBounds 분리

      마우스 제스처 클래스가 복잡한 충돌 수식을 직접 계산하지 않도록, 계층 구조 검사(RoiGroupBounds)와 이동·회전 한계 계산(RoiMotionBounds)이라는 전용 가공 클래스를 분리했습니다.

      SOLID · SRP (단일 책임 원칙)

      MoveGesture는 '마우스 델타 계산'만, RoiMotionBounds는 '벽 충돌 보정'만!

      덕분에 마우스 드래그 이동(MoveGesture)뿐 아니라 키보드 방향키 1px/10px 미세 이동(TryNudgeSelection)에서도 똑같은 ConstrainTranslation을 그대로 재사용합니다.

      GRASP · High Cohesion (높은 응집도)

      켄트 백 스타일의 3단계 함수 분해 (TranslationFraction → ConstrainTranslation)

      복잡한 미끄러짐 물리 연산을 ① 1차 접촉점 찾기, ② 남은 힘 계산, ③ 부모 벽면으로 정사영하기의 짧은 함수들로 쪼개어 누구나 한눈에 읽을 수 있습니다.

      SOLID · OCP (개방-폐쇄 원칙)

      도형 모양에 상관없이 ContainsGeometry 하나로 통일

      자식이 사각형이든 원이든 폴리곤이든 ContainsGeometry가 03장의 Contains를 이용해 똑같이 판정하므로, 새 도형이 추가되어도 이분법 충돌 코드는 고칠 필요가 없습니다.

      💡 왜 40회 이분법이 최적화에 유리할까요?
      회전된 타원과 회전된 다각형이 부딪히는 정확한 공식을 대수 방정식으로 풀려면 코드가 수천 줄이 되고 예외 케이스에서 깨지기 쉽습니다. 반면 40회 이분법은 단 40번의 반복(약 0.0005ms)으로 모든 도형 조합의 충돌 지점을 10−12 정밀도로 보장합니다!

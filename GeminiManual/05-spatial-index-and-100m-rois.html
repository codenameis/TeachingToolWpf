      CHAPTER 05 · 2단계: 수만~수억 개 ROI를 단일 영속 트리와 비트 경로로 다루는 비결

      05장 · 영속 공간 색인(RoiSpatialIndex, BvhNodePath)과 대용량 차분 집합(RoiIdSet)

      01장~04장에서 우리는 기하 엔진(VisionGeometry)의 도형 수식을 모두 완성했습니다.
      이제 도형이 1개가 아니라 수만~수백만 개의 일반 ROI와 반복 격자 셀이 동시에 화면에 놓이는 상황을 해결할 차례입니다.
      별도의 예외용 자료구조를 중복해서 만들지 않고, 단 하나의 영속 이진 트리(RoiSpatialIndex)와 64비트 경로(BvhNodePath), 그리고 차분 집합(RoiIdSet)만으로 검색·부분 수정·전체 이동·GPU 블록 캐싱까지 일관되게 처리하는 클린 아키텍처를 밑바닥부터 정복해 봅시다!

      1단계 · 어떻게 단일 일반 ROI 구조만으로 대규모 격자와 개별 편집을 동시에 잡을까?

      Step 1 · 문제 이해와 일상 비유
      핵심 1 · 영속 BVH 트리

      도형 1개를 고칠 때 트리 전체를 다시 안 만들고 바뀐 줄기만 교체! (BvhNodePath)

      각 ROI가 트리 루트에서 잎(Leaf)까지 내려가는 이진수 길찾기 번호(BvhNodePath)를 기억하므로, 도형 1개를 옮겨도 나머지 99.9% 서브트리 노드는 그대로 재사용합니다.

      핵심 2 · 정렬 없는 Refit & Filter

      전체 이동은 RefitGeometry, 부분 선택은 Filter로 재정렬 비용 0!

      수만 개 그룹을 통째로 이동할 때는 공간 분할 순서를 유지한 채 상자 크기만 다시 맞추고(RefitGeometry), 선택 집합은 Filter로 기존 트리 구조를 그대로 추려냅니다.

      핵심 3 · 차분 선택 집합

      대량 선택 위에서 Ctrl+클릭 1개 토글을 O(1)로 처리하는 RoiIdSet!

      대량 선택 본체는 FrozenSet<Guid>에 얼려 두고, Ctrl+클릭으로 추가·해제한 소수 ID만 _added / _removed에 기록해 복사 비용을 없앱니다.

      일상 비유로 감 잡기 · 스무고개 지도 찾기(BVH)와 이진수 주소표(BvhNodePath)

      파인만 학습법 (Feynman Analogy)

      🗺️ 비유 1 · 전국 편의점 5만 개 중 내 옆 편의점 찾기 (RoiSpatialIndex BVH 트리)

      내가 지금 '서울 강남구'에 서 있는데, 내 발밑에 편의점이 있는지 찾으려고 제주도·부산·강원도 편의점 5만 개 주소를 1번부터 끝까지 다 읽어보는 것(foreach 전체 순회, O(N))은 너무나 비효율적입니다.
      BVH 이진 트리는 전국을 '북쪽 절반 / 남쪽 절반' 큰 상자로 계속 반씩 나누어 둔 지도책입니다. 내가 서울에 있다면 '남쪽 절반 상자'는 아예 펼치지도 않고 통째로 건너뛰므로(가지치기, Pruning), 단 15~20번의 확인만으로 내 발밑의 도형을 찾아냅니다!

      🧭 비유 2 · 루트는 1, 왼쪽은 0, 오른쪽은 1을 붙이는 이진수 길찾기 번호 (BvhNodePath)

      트리에서 특정 도형이 있는 잎 노드로 찾아 내려갈 때, 루트 노드를 이진수 1로 시작해 왼쪽 갈래로 갈 때마다 뒤에 0을 붙이고(RawValue << 1), 오른쪽 갈래로 갈 때마다 뒤에 1을 붙입니다((RawValue << 1) | 1).
      예를 들어 루트(1) → 왼쪽(0) → 오른쪽(1)으로 내려간 노드의 주소는 이진수 0b101(십진수 5)입니다! 이 64비트 숫자 하나만 있으면 포인터 배열 없이도 루트에서 해당 잎 노드까지 비트 시프트만으로 정확히 찾아가 그 경로의 노드만 새로 교체(Copy-on-Write)할 수 있습니다!

      2단계 · 워밍업: 이 장을 시작하기 위한 4가지 기초 개념

      Step 2 · 필수 사전지식 먼저 다지기

      개념 1 · 시간복잡도 O(N) vs O(log N) vs O(1) 이란?

      도형 개수 N이 늘어날 때 컴퓨터가 해야 하는 계산 횟수가 어떻게 늘어나는지 나타내는 표기법입니다.

      • O(N) (전체 순회): 도형이 10만 개면 10만 번 다 확인해야 함 (마우스 이동 시 화면 멈춤!)
      • O(log N) (이진 트리 BVH): 한 번 확인할 때마다 대상이 절반씩 줄어들어, 10만 개여도 약 17번만 확인하면 끝!
      • O(1) (수식 역산): 도형이 100개든 1억 개든 나눗셈 단 1번으로 끝!

      개념 2 · 고1 등차수열 an = a0 + n · d 와 내림 함수 Math.Floor

      첫째항이 X0이고 공차(간격)가 Sx인 등차수열에서 c번째 칸(0번부터 시작)의 시작 위치는 X(c) = X0 + c · Sx 입니다.
      반대로 마우스 좌표 px가 몇 번째 칸 c에 속하는지 구하려면? X0를 빼고 간격 Sx로 나눈 뒤 소수점을 버리면(내림, Math.Floor) 됩니다: 

      int col = (int)Math.Floor((px - OriginX) / StepX);

      개념 3 · 몫과 나머지 2차원 (row, col) ↔ 1차원 번호 k 변환

      가로 열 개수가 Columns(예: 10,001)인 바둑판에서 (row, col) 칸에 고유 번호 k 하나를 붙이려면: 

      // (row, col) → 1차원 고유 번호 k (주의: 1억 개는 int 범위를 넘을 수 있어 long 사용!)
long k = ((long)row * Columns) + col;

// 반대로 1차원 번호 k → (row, col) 복원 (나눗셈 몫과 나머지!)
int row = (int)(k / Columns);
int col = (int)(k % Columns);

      개념 4 · 희소 사전(Sparse Dictionary) ImmutableDictionary와 ImmutableHashSet

      1억 칸 배열을 만들면 메모리가 터지지만, 실제로 변화가 생긴 셀 번호 k만 저장하는 사전(Dictionary)을 쓰면 10개를 고쳤을 때 딱 10개 분량의 메모리만 씁니다! 이를 희소(Sparse) 저장소 또는 Flyweight 패턴이라고 부릅니다.

      3단계 · 한 걸음씩 수식 유도하기: 1억 셀 격자 인덱싱과 화면 가시 범위 클리핑

      공식 1 · 등차수열 역산 RepeatedRoiGrid의 O(1) 정방향 위치 계산과 역방향 마우스 히트 셀 조회
      (식 5.1)
      ✏️ 한 걸음씩 유도하기:
      1) 0행 0열 셀의 왼쪽 위 시작점을 (X0, Y0), 셀 가로·세로 간격(피치)을 (Sx, Sy), 각 셀의 크기를 (Wc, Hc)라고 합시다.
      2) r행 c열 셀의 왼쪽 위 모서리 좌표는 등차수열 공식에 의해 X(c) = X0 + c · Sx,  Y(r) = Y0 + r · Sy 입니다.
      3) 이제 사용자가 마우스로 (px, py)를 클릭했을 때, 이 점이 몇 행 몇 열 근처인지 역산합니다: c = ⌊(px − X0) / Sx⌋,  r = ⌊(py − Y0) / Sy⌋.
      4) 마지막으로 구한 (r, c)가 격자 범위(0 ≤ r < Nrow, 0 ≤ c < Ncol) 안에 있고, 셀과 셀 사이 빈틈(Gap)이 아니라 실제 셀 상자 [X(c), X(c) + Wc] 안에 들어왔는지 확인하면 단 한 번의 나눗셈으로 1억 개 중 클릭된 셀을 찾아냅니다!
      1) 1차원 인덱스 k ↔ 2차원 격자 (r, c) k = r · Ncol + c ⟺ r = ⌊kNcol⌋, c = k mod Ncol
      2) 정방향 셀 위치 X(c) = X0 + c · Sx, Y(r) = Y0 + r · Sy
      3) 역방향 마우스 히트 후보 (r, c) 역산 c = ⌊px − X0Sx⌋, r = ⌊py − Y0Sy⌋

      • 마우스로 (165, 73)을 클릭했다면 몇 행 몇 열일까요?
      • 열 번호 col = Floor((165 − 100) ÷ 20) = Floor(3.25) = 3열!

      공식 2 · 가시 영역 클리핑 현재 모니터 화면(visibleBounds)에 보이는 행·열 구간 [r_min..r_max, c_min..c_max] 산출
      (식 5.2)
      ✏️ 한 걸음씩 유도하기:
      1) 화면을 확대한 상태에서 1억 개 셀을 매 프레임 다 그리려고 하면 GPU도 멈춥니다.
      2) 02장의 ScreenToImage로 현재 모니터 화면의 왼쪽 끝(L), 위쪽 끝(T), 오른쪽 끝(R), 아래쪽 끝(B) 이미지 좌표를 구합니다.
      3) 이 화면 상자 [L, R] × [T, B]와 겹치는 최소·최대 열 번호 c_min, c_max와 행 번호 r_min, r_max만 부등식으로 구하면, 현재 모니터에 실제로 보이는 셀만 콕 집어서 그릴 수 있습니다!
      cmin = clamp(⌊L − X0 − WcSx⌋,  0,  Ncol − 1), cmax = clamp(⌊R − X0Sx⌋,  0,  Ncol − 1)

      5단계 · 밑바닥부터 직접 구현하기: BvhNodePath, RoiSpatialIndex, RoiIdSet 전체 코드

      이제 루트부터 잎 노드까지의 경로를 64비트 정수로 부호화하는 BvhNodePath, 이를 이용해 바뀐 경로만 교체하는 영속 RoiSpatialIndex, 그리고 대용량 선택 위에서 O(1) 토글을 지원하는 RoiIdSet을 직접 작성해 봅시다.

      using System;
using System.Collections.Frozen;
using System.Collections.Generic;
using System.Collections.Immutable;
using System.Numerics;
using VisionGeometry;

namespace VisionCanvas.Core.Geometry;

// 1. 루트(1)부터 잎(Leaf)까지 내려가는 이진 경로를 비트열로 부호화한 값 객체 (default도 항상 유효한 Root == 1!)
public readonly record struct BvhNodePath
{
    public const int MaxSupportedHeight = 48;
    private const int MaxDepth = 62;
    private readonly ulong _valueMinusOne;

    private BvhNodePath(ulong rawValue)
    {
        ArgumentOutOfRangeException.ThrowIfZero(rawValue);
        _valueMinusOne = rawValue - 1;
    }

    public static BvhNodePath Root => default;
    public ulong RawValue => _valueMinusOne + 1;
    public int Depth => BitOperations.Log2(RawValue);
    public BvhNodePath Left => new(RawValue << 1);
    public BvhNodePath Right => new((RawValue << 1) | 1UL);
    public ulong FirstStepBit => Depth == 0 ? 0UL : 1UL << (Depth - 1);
    public bool IsRightBranch(ulong stepBit) => (RawValue & stepBit) != 0;
}

// 2. 대량 선택(FrozenSet)과 Ctrl+클릭 소수 편집(_added/_removed)을 결합한 영속 집합
public sealed class RoiIdSet
{
    private readonly FrozenSet<Guid> _items;
    private readonly ImmutableHashSet<Guid> _added;
    private readonly ImmutableHashSet<Guid> _removed;

    public static RoiIdSet Empty { get; } = new(FrozenSet<Guid>.Empty, [], []);
    public int Count => _items.Count + _added.Count - _removed.Count;

    private RoiIdSet(FrozenSet<Guid> items, ImmutableHashSet<Guid> added, ImmutableHashSet<Guid> removed)
        => (_items, _added, _removed) = (items, added, removed);

    public static RoiIdSet CreateRange(IEnumerable<Guid> ids)
        => ids is RoiIdSet set ? set : new(ids.ToFrozenSet(), [], []);

    public bool Contains(Guid item)
        => _added.Contains(item) || (_items.Contains(item) && !_removed.Contains(item));

    public RoiIdSet Add(Guid item)
        => Contains(item) ? this
         : _items.Contains(item) ? new(_items, _added, _removed.Remove(item))
         : new(_items, _added.Add(item), _removed);

    public RoiIdSet Remove(Guid item)
        => !Contains(item) ? this
         : _items.Contains(item) ? new(_items, _added, _removed.Add(item))
         : new(_items, _added.Remove(item), _removed);
}

// 3. 영속 BVH 공간 색인 트리 (바뀐 경로만 교체하고 최대 2,048개 단위 GPU 공간 블록을 제공)
public sealed class RoiSpatialIndex
{
    public readonly record struct Entry(Guid Id, BoundsD Bounds, double Area, long Order);

    private sealed record Node(
        BoundsD Bounds, int Count, int Height, double MaxArea,
        Entry[]? Entries, Node? Left, Node? Right);

    private readonly Node _root;
    private readonly ImmutableDictionary<Guid, BvhNodePath> _locations;

    public RoiSpatialIndex(IReadOnlyList<Entry> entries)
    {
        var copy = new Entry[entries.Count];
        for (int i = 0; i < entries.Count; i++) copy[i] = entries[i];
        var paths = ImmutableDictionary.CreateBuilder<Guid, BvhNodePath>();
        _root = copy.Length == 0
            ? new Node(default, 0, 0, 0, [], null, null)
            : Build(copy, 0, copy.Length, BvhNodePath.Root, paths);
        _locations = paths.ToImmutable();
    }

    private static Node Build(
        Entry[] items, int start, int count,
        BvhNodePath path, ImmutableDictionary<Guid, BvhNodePath>.Builder paths)
    {
        if (count <= 8)
        {
            var leaf = items.AsSpan(start, count).ToArray();
            foreach (var entry in leaf) paths[entry.Id] = path;
            return CreateLeaf(leaf);
        }

        BoundsD bounds = items[start].Bounds;
        for (int i = start + 1; i < start + count; i++)
            bounds = Union(bounds, items[i].Bounds);

        bool horizontal = bounds.Width >= bounds.Height;
        Array.Sort(items, start, count, Comparer<Entry>.Create((a, b) =>
            horizontal ? a.Bounds.Center.X.CompareTo(b.Bounds.Center.X)
                       : a.Bounds.Center.Y.CompareTo(b.Bounds.Center.Y)));

        int mid = count / 2;
        return CreateBranch(
            Build(items, start, mid, path.Left, paths),
            Build(items, start + mid, count - mid, path.Right, paths));
    }

    private static Node CreateLeaf(Entry[] entries)
    {
        BoundsD bounds = entries.Length == 0 ? default : entries[0].Bounds;
        double maxArea = 0;
        foreach (var e in entries)
        {
            bounds = Union(bounds, e.Bounds);
            maxArea = Math.Max(maxArea, e.Area);
        }
        return new Node(bounds, entries.Length, 0, maxArea, entries, null, null);
    }

    private static Node CreateBranch(Node left, Node right) =>
        new(Union(left.Bounds, right.Bounds),
            left.Count + right.Count,
            1 + Math.Max(left.Height, right.Height),
            Math.Max(left.MaxArea, right.MaxArea),
            null, left, right);

    private static BoundsD Union(BoundsD a, BoundsD b) =>
        new(Math.Min(a.Left, b.Left), Math.Min(a.Top, b.Top),
            Math.Max(a.Right, b.Right), Math.Max(a.Bottom, b.Bottom));
}
      핵심 코드 구문 초보자 눈높이 한 줄 설명
      private readonly ulong _valueMinusOne;
      public ulong RawValue => _valueMinusOne + 1;      		 C# 구조체의 기본값(default(BvhNodePath))은 내부 필드가 모두 0이 됩니다. 이때 _valueMinusOne + 1 트릭을 쓰면 초기화하지 않은 기본값도 언제나 유효한 루트 노드(RawValue == 1)가 되도록 도메인 불변식을 보장합니다!
      public BvhNodePath Left => new(RawValue << 1);
      public BvhNodePath Right => new((RawValue << 1) | 1UL);      		 왼쪽 자식으로 내려갈 때는 비트를 왼쪽으로 한 칸 밀어 0을 붙이고, 오른쪽 자식으로 내려갈 때는 | 1UL로 1을 붙여 트리 경로를 64비트 정수 하나에 압축합니다.
      public bool Contains(Guid item) => _added.Contains(item) || (_items.Contains(item) && !_removed.Contains(item)); RoiIdSet의 핵심입니다. 수만 개 전체 선택(_items)에서 Ctrl+클릭으로 도형 1개를 뺄 때, 거대한 집합을 복사하지 않고 작은 _removed 집합에만 추가해 O(1)에 처리합니다.
      bool horizontal = bounds.Width >= bounds.Height; 트리가 한쪽으로 길쭉해지지 않도록, 상자의 가로가 더 길면 세로선으로 자르고 세로가 더 길면 가로선으로 잘라 균형 잡힌 이진 트리를 만듭니다.
      RefitGeometry & Filter (실제 RoiSpatialIndex.cs) 전체 ROI를 함께 평행이동·회전할 때는 공간 순서가 바뀌지 않으므로 재정렬 없이 RefitGeometry로 상자만 갱신하고, 선택 부분 트리는 Filter로 원래 블록 정체성을 보존합니다.
      Blocks(BoundsD bounds, int maximumCount = 2048) 트리에서 2,048개 이하의 ROI를 가진 서브트리 노드를 RoiSpatialBlock으로 꺼내어 09장의 GPU 블록 캐시(RoiBlockCache)가 노드 참조 주소(Identity)로 즉시 재사용하게 합니다!

      6단계 · 방금 만든 코드의 설계 원리: 어떻게 단일 BVH 구조로 대용량 편집과 GPU 캐싱까지 통합했는가?

      SOLID 원칙 GRASP 패턴
      GRASP · Pure Fabrication (순수 가공물)

      검색 속도를 O(N)에서 O(log N)으로 줄이는 영속 RoiSpatialIndex

      DocumentState가 수만 개 ROI를 일렬로 뒤지지 않도록, 비트 경로(BvhNodePath) 기반 영속 이진 트리 가공물(RoiSpatialIndex)을 두었습니다.

      GRASP · Information Expert (정보 전문가)

      비트 연산으로 트리 경로를 스스로 추적하는 BvhNodePath

      깊이(BitOperations.Log2)와 좌/우 분기 판정(IsRightBranch(stepBit))을 BvhNodePath 값 구조체가 직접 계산하여 힙 할당 없이 경로를 추적합니다.

      SOLID · SRP (단일 책임 원칙)

      전체 공간 색인(RoiSnapshot.Spatial)과 선택 부분 색인(RoiSelectionSnapshot) 분리

      문서 전체의 BVH는 RoiSnapshot이 보유하고, 현재 선택된 도형들의 부분 BVH와 통계는 RoiSelectionSnapshot이 지연(Lazy) 생성해 책임을 나눕니다.

      GRASP · Low Coupling & Structural Sharing

      불변 서브트리 참조(RoiSpatialBlock.Identity)를 GPU 캐시 키로 직접 활용

      편집되지 않은 서브트리 노드는 메모리 주소(object Identity)가 그대로 유지되므로, 09장의 RoiBlockCache가 해시 계산조차 없이 참조 비교 한 번으로 GPU 버퍼를 재사용합니다!

      💡 왜 별도의 예외 배치 클래스를 없애고 영속 BVH + 차분 집합으로 통일했을까요?
      일반 ROI와 반복 격자 ROI가 100% 동일한 Roi 레코드와 RoiSpatialIndex를 쓰기 때문에, 개별 이동·회전·삭제·그룹화·마스크·복붙·Undo/Redo에서 예외 분기 버그가 원천적으로 사라지고, BvhNodePath 경로 복사와 RoiBlockCache(2,048개 블록 캐싱) 덕분에 대용량에서도 빠른 응답성을 유지합니다!

      CLASS DIAGRAM 05장 영속 공간 색인(RoiSpatialIndex · BvhNodePath) 및 선택 스냅샷 클래스 다이어그램

      영속 이진 트리 RoiSpatialIndex와 비트 경로 BvhNodePath, GPU 블록 단위 RoiSpatialBlock, 그리고 차분 선택 집합 RoiIdSet의 구조입니다.

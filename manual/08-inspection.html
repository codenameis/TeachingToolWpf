학습은 여기서 신경망 학습이 아니다

“컴퓨터에게 이 부품을 찾아 달라고 하려면 무엇을 알려줘야 할까요?” 책에서 찾고 싶은 문장 일부를 메모해 놓고 같은 부분을 찾듯, 기준 부품의 밝기나 윤곽 방향을 원본에서 뽑아 보관합니다. 여기서 ‘학습’은 이 기준을 만드는 전통적 패턴 티칭입니다. 신경망을 훈련하거나 딥러닝 가중치를 내려받는 과정은 아닙니다.

학습 ROI
원본·마스크→불변 모델→후보 검색·원본 검증→판정·표시

모델과 학습 조건을 함께 저장합니다. 마스크·형상·학습 조건이 바뀌면 기존 모델로 검사해도 되는지 확인해야 합니다. 이 앱은 해당 변경에서 재학습 전 검사를 막습니다.

기준 만들기와 합불 판정은 다른 질문입니다

티칭은 ‘무엇을 찾을 것인가’, 검색은 ‘어디에 비슷한 것이 있는가’, 판정은 ‘찾은 것이 요구조건을 만족하는가’를 다룹니다. 위치 점수가 높아도 수량이나 치수가 기준과 다르면 제품 판정은 달라질 수 있습니다. Canvas는 이 검사 정책을 정하지 않고 전달받은 윤곽과 색을 표시합니다.

화면을 확대하거나 보간한 픽셀 대신 원본 픽셀·실제 ROI 도형·제외 마스크로 기준을 만들어야 합니다. 그렇지 않으면 화면 배율에 따라 학습 정보가 달라집니다. 학습 마스크를 바꿨는데 모델을 그대로 두면 ‘기준이라고 저장한 정보’와 ‘현재 요청한 기준’이 달라지므로 재학습이 필요합니다.

정규화 상관: 밝기 모양 비교

“같은 부품인데 조명 때문에 모든 값이 밝아졌다면 다른 부품일까요?” 세 칸이 [10,20,30]인 기준과 [30,50,70]인 후보를 보세요. 숫자 자체는 다르지만 ‘어두움→중간→밝음’의 변화 모양은 같습니다. 전체 밝기와 변화 크기를 걷어낸 뒤 이 모양을 비교하는 것이 아래 NCC 식의 목적입니다.

OpenCV 기본 경로는 CCoeffNormed를 사용합니다. 아래 식은 마스크 없는 위치 하나의 개념식입니다. 실제 마스크가 있으면 유효 영역과 가중 규칙을 구현에 맞춰야 합니다.

T¯=∑i=1nTinI¯=∑i=1nIinNCC=∑i=1n(Ti−T¯)·(Ii−I¯)∑i=1n(Ti−T¯)2·∑i=1n(Ii−I¯)2T 평균 = Σ(i=1..n)Ti/n; I 평균 = Σ(i=1..n)Ii/n; NCC = Σ[(Ti−T평균)(Ii−I평균)] / √(Σ(Ti−T평균)² · Σ(Ii−I평균)²)

바로 위 수식에서 쓰인 기호

기호 / 읽는 법뜻과 단위코드·예시에서 찾기
TT티: 학습 템플릿의 밝기 표본. 밝기 단위Ti는 i번째 유효 표본. 윗줄은 평균
ii아이: 대응하는 표본이나 점의 번호합 기호에서는1부터n까지
nn엔: 실제 합에 넣은 대응 표본 수, 개수마스크 밖·padding을 유효 표본으로 세지 않음
II아이: 비교할 원본 후보의 밝기 표본. T와 같은 밝기 단위학습과 같은 순서/마스크의 위치를 비교
NCCNCC평균을 뺀 두 밝기 패턴의 정규화 상관. 단위 없음분모가0이면 이 수식은 정의되지 않음

T는 템플릿 픽셀, I는 후보 위치의 픽셀, n은 비교 개수, 위 막대는 평균입니다. 먼저 평균을 빼 전체 밝기 차이를 줄이고, 두 신호의 길이로 나눠 크기 영향을 줄입니다. 분모가 0이 아닌 경우 이론적으로 −1~1입니다. 상수 영상은 분모가 0이므로 API의 예외적 처리와 입력 검증을 확인해야 합니다.

T=[10,20,30],I=[30,50,70]T=[10,20,30], I=[30,50,70]이면 평균은 20과 50입니다. 평균 제거 후 [−10,0,10], [−20,0,20], 분자는 400, 분모는 200×800=400√(200×800)=400이므로 NCC=1NCC=1입니다. 반대로 순서를 뒤집은 I=[70,50,30]I=[70,50,30]은 −1입니다. ‘점수 0.9’가 현장 성공 확률 90%라는 뜻은 아닙니다.

일반적인 고정 크기 템플릿 이동 검색은 회전·크기 변화까지 자동으로 해결하지 않습니다. 이 앱의 OpenCV 방식은 학습 각도·크기를 유지한 평행 이동으로 읽습니다.

실제 OpenCV 호출 · OpenCV 공식 설명

긴 분수는 ‘평균 빼기 → 함께 변하는 양 → 크기로 나누기’입니다

아래 계산은 마스크 없는 위치 하나의 개념식입니다. T는 기준 템플릿, I는 같은 위치 순서로 놓은 후보 픽셀, n은 비교 개수입니다. T 위의 막대는 평균입니다. 아래첨자 i는 i번째 칸이지 곱셈이 아닙니다. Σ는 모든 칸에 같은 계산을 해서 더하라는 뜻입니다. 실제 OpenCV 경로는 CCoeffNormed를 쓰며 마스크가 있으면 그 유효 영역·가중 규칙을 따릅니다.

  1. 평균: T 평균은 (10+20+30)3=20,I(10+20+30)/3=20, I 평균은 (30+50+70)3=50(30+50+70)/3=50입니다. 각 값에서 자기 평균을 빼면 ‘자기 영상에서 평균보다 얼마나 어둡고 밝은가’가 남습니다.
  2. 분자:(−10)×(−20)+0×0+10×20=400(−10)×(−20)+0×0+10×20=400입니다. 둘 다 평균보다 어둡거나 둘 다 밝으면 양수를 더합니다. 반대로 변하면 음수를 더합니다.
  3. 분모: T 편차의 제곱합은 100+0+100=200,I100+0+100=200, I는 400+0+400=800400+0+400=800입니다. 이 두 크기를 곱하고 제곱근을 취하면 160,000=400√160,000=400입니다.
  4. 결과:400400=1400/400=1입니다. 후보의 변화 폭이 기준의 두 배여도, 크기로 나누었기에 같은 변화 모양으로 비교됩니다.

후보를 [70,50,30]으로 뒤집으면 편차가 [20,0,−20]입니다. 분자는 −400, 분모는 그대로 400이므로 −1입니다. 후보가 [50,50,50]처럼 평평하면 편차가 모두 0이라 분모가 0입니다. 이 경우를 ‘어떤 부품과도 완벽히 같다’고 해석하면 안 됩니다. 입력 검사와 라이브러리의 예외 처리를 확인해야 합니다.

비유의 한계: 전체에 같은 밝기 변화·양의 배율이 적용된 이상적인 예입니다. 일부 그림자, 포화, 잡음, 회전, 크기 변화까지 이 식이 자동으로 없애 주지는 않습니다. 0.9는 이 계산의 유사도이지 현장 검출 성공률 90%가 아닙니다.

using System.Collections.Immutable;
using System.Diagnostics;
using System.Runtime.InteropServices;
using OpenCvSharp;

namespace VisionAlgorithm.OpenSrc.PatternMatching.Imaging;

/// <summary>Mat과 네이티브 호출 수명은 이 경계에만 둔다. 호출 중 취소되어도 반환 후 자원을 해제한다.</summary>
internal static class OpenCvTemplateMatcher
{
    public static CorrelationResult Search(GrayImage image, CorrelationTemplate template, SearchOptions options, CancellationToken token)
    {
        options.Validate();
        if ((long)image.Width * image.Height > CorrelationTemplate.MaximumSearchPixels)
        {
            throw new ArgumentException("OpenCV 검색 창은 16 Mpx 이하여야 합니다.");
        }
        token.ThrowIfCancellationRequested();
        if (image.Width < template.Width || image.Height < template.Height)
        {
            return new([], false, 0);
        }
        var timer = Stopwatch.StartNew();
        var pixels = new byte[checked(image.Width * image.Height)];
        for (var row = 0; row < image.Height; row++)
        {
            token.ThrowIfCancellationRequested();
            image.Pixels.Span.Slice(row * image.Stride, image.Width).CopyTo(pixels.AsSpan(row * image.Width));
        }
        using var source = Mat.FromPixelData(image.Height, image.Width, MatType.CV_8UC1, pixels, image.Width);
        using var pattern = Mat.FromPixelData(template.Height, template.Width, MatType.CV_8UC1, template.Pixels);
        using var mask = template.Mask.Length == 0 ? null : Mat.FromPixelData(template.Height, template.Width, MatType.CV_8UC1, template.Mask);
        using var response = new Mat();
        // OpenCV 4.13: CCOEFF_NORMED의 마스크 수식과 원본 크기 결과 맵.
        // https://docs.opencv.org/4.13.0/df/dfb/group__imgproc__object.html
        if (mask is null)
        {
            Cv2.MatchTemplate(source, pattern, response, TemplateMatchModes.CCoeffNormed);
        }
        else
        {
            Cv2.MatchTemplate(source, pattern, response, TemplateMatchModes.CCoeffNormed, mask);
        }
        token.ThrowIfCancellationRequested();
        var width = response.Width;
        var height = response.Height;
        var scores = new float[checked(width * height)];
        Marshal.Copy(response.Data, scores, 0, scores.Length);
        // 마스크 정규화의 0 분모는 NaN/Inf일 수 있다. 유효 후보로 승격하지 않는다.
        for (var y = 0; y < height; y++)
        {
            token.ThrowIfCancellationRequested();
            for (var x = 0; x < width; x++)
            {
                var index = (y * width) + x;
                if (!float.IsFinite(scores[index]) || !(options.Region?.Contains(x + template.ReferencePoint.X, y + template.ReferencePoint.Y) ?? true) ||
                    (scores[index] >= options.MinimumScore && OverlapsMask(image, template, x, y, token)))
                {
                    scores[index] = float.NegativeInfinity;
                }
            }
        }
        var peaks = new PriorityQueue<(int X, int Y, float Score), (float Score, int Order)>();
        var truncated = false;
        for (var y = 0; y < height; y++)
        {
            token.ThrowIfCancellationRequested();
            for (var x = 0; x < width; x++)
            {
                var index = (y * width) + x;
                if (scores[index] < options.MinimumScore || !IsMaximum(scores, width, height, x, y))
                {
                    continue;
                }
                peaks.Enqueue((x, y, scores[index]), (scores[index], -index));
                if (peaks.Count > options.MaximumCandidates)
                {
                    peaks.Dequeue();
                    truncated = true;
                }
            }
        }
        var selected = peaks.UnorderedItems.Select(value => value.Element)
            .OrderByDescending(value => value.Score).ThenBy(value => value.Y).ThenBy(value => value.X)
            .Select(peak => new CorrelationMatch(new(peak.X + template.ReferencePoint.X, peak.Y + template.ReferencePoint.Y),
                Math.Clamp(peak.Score, -1, 1))).ToImmutableArray();
        return new(selected, truncated, timer.Elapsed.TotalMilliseconds);
    }

    private static bool OverlapsMask(GrayImage image, CorrelationTemplate template, int left, int top, CancellationToken token)
    {
        if (image.ExcludedPixels.IsEmpty)
        {
            return false;
        }
        for (var y = 0; y < template.Height; y++)
        {
            token.ThrowIfCancellationRequested();
            for (var x = 0; x < template.Width; x++)
            {
                if ((template.Mask.Length == 0 || template.Mask[(y * template.Width) + x] != 0) &&
                    image.ExcludedPixels.Span[((top + y) * image.Width) + left + x] != 0)
                {
                    return true;
                }
            }
        }
        return false;
    }
    internal static double Overlap(ImagePoint first, ImagePoint second, CorrelationTemplate template)
    {
        var intersection = Math.Max(0, template.Width - Math.Abs(first.X - second.X)) * Math.Max(0, template.Height - Math.Abs(first.Y - second.Y));
        return intersection / ((2d * template.Width * template.Height) - intersection);
    }

    private static bool IsMaximum(float[] scores, int width, int height, int x, int y)
    {
        var index = (y * width) + x;
        for (var row = Math.Max(0, y - 1); row <= Math.Min(height - 1, y + 1); row++)
        {
            for (var column = Math.Max(0, x - 1); column <= Math.Min(width - 1, x + 1); column++)
            {
                var other = (row * width) + column;
                if (scores[other] > scores[index] || (scores[other] == scores[index] && other < index))
                {
                    return false;
                }
            }
        }
        return true;
    }
}

형상 검색: 방향이 있는 특징점

“밝기 자체 대신 부품의 선 모양을 비교할 수 없을까요?” 윤곽 위치에 ‘어느 쪽으로 밝아지는가’라는 작은 화살표를 붙인다고 생각하세요. 같은 위치에 비슷한 방향의 화살표가 모이면 같은 형상일 가능성을 평가할 수 있습니다. 다만 방향 하나만 맞는 것으로 최종 검출을 결정하지는 않습니다.

형상 방식은 윤곽 위치와 기울기 방향을 사용합니다. 두 단위 방향 u,v의 내적 u·v=cos⁡(Δθ)u·v = cos(Δθ)는 방향이 같으면 1, 직각이면 0, 반대면 −1입니다. 대비 극성을 무시할지에 따라 부호를 다루는 정책이 달라질 수 있습니다. 이 값 하나가 앱의 최종 점수식 전체는 아닙니다.

현재 경로는 방향 응답맵 기반 피라미드 후보 → 연속 gradient 방향 검증 → robust point-to-line 정밀화입니다. 거친 단계에서 대략적인 위치를 찾고, 원본 crop에서 자세히 판정합니다. 논문 기반과 자체 기하 방식은 별도 모델·설정이며 자체 기하만 추가 윤곽 품질 평가를 연결합니다. 원 논문 전체 재현이나 상용 matcher와 동등함을 뜻하지 않습니다.

RMS=∑i=1ndi2n=d12+d22+⋯+dn2n대응점 거리 RMS = √(Σ(i=1..n)di²/n) = √((d₁²+d₂²+…+dₙ²)/n)

기호 / 읽는 법뜻과 단위코드·예시에서 찾기
RMSRMS거리 제곱의 평균에 제곱근을 취한 값, 원본 px평균 거리와 다른 통계
ii아이: 대응하는 표본이나 점의 번호합 기호에서는1부터n까지
nn엔: 실제 합에 넣은 대응 표본 수, 개수마스크 밖·padding을 유효 표본으로 세지 않음
dd디: 대응점 사이 거리, 원본 pxdi는 i번째 거리. 6장의 DPI 배율과 다름

dᵢ는 대응한 점 사이의 원본 거리(px)입니다. 거리 [1,2,2]라면 RMS=3≈1.732pxRMS=√3≈1.732px입니다. 큰 오차에 더 민감합니다. point-to-line의 잔차는 선의 법선 방향 거리이며 유클리드 대응 거리와 같은 항이라고 가정하면 안 됩니다.

ClutterRatio는 불필요 윤곽 개수의 비율 판단, ClutterEnergyRatio/ClutterPenaltyRatio는 강도와 감점에 관련된 서로 다른 값입니다. 최종 점수와 원래 방향 점수를 나누어 봅니다. 자세한 실행식은 ShapeMatcher와 설정 안내에서 확인합니다.

    public MatchResult RefineCandidate(GrayImage image, ShapeModel model, MatchPose initial, double candidateScore,
        SearchOptions options, CancellationToken cancellationToken = default)
    {
        options.Validate();
        ValidateGeometricPolicy(model, options);
        var preprocessor = GetPreprocessor(options);
        if (!double.IsFinite(initial.X) || !double.IsFinite(initial.Y) || !double.IsFinite(initial.Angle) ||
            !double.IsFinite(initial.Scale) || !double.IsFinite(candidateScore) || candidateScore is < 0 or > 1 ||
            initial.X < 0 || initial.Y < 0 || initial.X > image.Width || initial.Y > image.Height ||
            !ContinuousVerifier.Allowed(initial, model, options))
        {
            throw new ArgumentException("정밀화 초기 자세 또는 후보 점수가 모델의 유효 범위를 벗어납니다.", nameof(initial));
        }
        var prepared = PreparedSearchImage.CreateForRefinement(image, model.Options.MinimumGradient, model.Levels.Length,
            cancellationToken, options.TiledPreprocessing, preprocessor, RequiresEdges(model, options), model.FineDetail is not null && options.ClutterWeight > 0);
        var timer = Stopwatch.StartNew();
        var pose = initial;
        VerifiedScore? verification = null;
        if (options.Verify)
        {
            // 위치가 정해진 후보의 원본 검증에는 전체 응답맵 검색을 다시 수행하지 않는다.
            for (var level = model.Levels.Length - 1; level >= 0; level--)
            {
                var factor = model.Levels[level].Factor;
                var local = pose with
                {
                    X = pose.X / factor,
                    Y = pose.Y / factor
                };
                var result = ContinuousVerifier.Optimize(prepared.Gradients[level], model, local, options, cancellationToken, level);
                pose = result.Pose with
                {
                    X = result.Pose.X * factor,
                    Y = result.Pose.Y * factor
                };
                verification = result.Score;
            }
        }
        var candidate = new PoseCandidate(pose, candidateScore, 0, verification);
        return CompleteCandidates(prepared, model, options, new([candidate], false, 0), timer.Elapsed.TotalMilliseconds, cancellationToken);
    }

    internal static MatchResult CompleteCandidates(PreparedSearchImage image, ShapeModel model, SearchOptions options,
        CandidateBatch batch, double candidateTime, CancellationToken cancellationToken)
    {
        var timer = Stopwatch.StartNew();
        var eligible = !image.ExcludedPixels.IsEmpty && model.PixelMask is { } mask
            ? batch.Candidates.Where(candidate => !mask.Overlaps(image, candidate.Pose, model.Bounds, cancellationToken)).ToList()
            : batch.Candidates;
        var candidates = VerificationCandidateScheduler.Select(eligible, model, options.MaximumVerifiedCandidates, cancellationToken);
        var detail = options.Verify && options.ClutterWeight > 0 ? model.FineDetail : null;
        if (detail is not null && image.Original is null)
        {
            throw new ArgumentException("작은 형상 세부 검증에는 retainOriginal 전처리가 필요합니다.", nameof(image));
        }
        var verified = new ShapeMatch?[candidates.Length];
        Parallel.For(0, candidates.Length, new ParallelOptions
        {
            MaxDegreeOfParallelism = options.MaximumParallelism,
            CancellationToken = cancellationToken
        }, i =>
        {
            var candidate = candidates[i];
            var pose = candidate.Pose;
            var score = candidate.Verification ?? new VerifiedScore(candidate.Score, 0, 0);
            if (options.Verify && candidate.Verification is null)
            {
                (pose, score) = ContinuousVerifier.Optimize(image.Gradients[0], model, pose, options, cancellationToken);
            }
            if (pose.X < 0 || pose.Y < 0 || pose.X > image.Width || pose.Y > image.Height ||
                (options.Verify && (score.Score < options.MinimumScore || score.Support < options.MinimumSupport)))
            {
                return;
            }
            verified[i] = new(pose, candidate.Score, score.Score, score.Support, score.Quadrants,
                new(RefinementStatus.Disabled, pose, double.NaN, double.NaN, 0, 0, true));
            if (detail is not null)
            {
                var refined = options.Refine ? detail.Optimize(image.Original!, model, pose, options, cancellationToken)
                    : (Pose: pose, Score: detail.Score(image.Original!, pose, model.Options.Polarity));
                var directional = ContinuousVerifier.Score(image.Gradients[0], model, refined.Pose);
                verified[i] = verified[i]! with
                {
                    Pose = refined.Pose,
                    Score = directional.Score,
                    Support = directional.Support,
                    SupportedQuadrants = directional.Quadrants,
                    DetailConsistency = refined.Score
                };
            }
        });
        var verificationTime = timer.Elapsed.TotalMilliseconds;
        timer.Restart();
        var matches = new List<ShapeMatch>();
        foreach (var match in verified)
        {
            cancellationToken.ThrowIfCancellationRequested();
            if (match is null)
            {
                continue;
            }
            var final = detail is null && options.Refine && options.Verify ? PointToLineRefiner.Refine(image, model, match, options, cancellationToken) : match;
            final = final with
            {
                DirectionScore = final.Score
            };
            if (model.PixelMask?.Overlaps(image, final.Pose, model.Bounds, cancellationToken) == true)
            {
                continue;
            }
            if (!(options.Region?.Contains(final.Pose.X, final.Pose.Y) ?? true) ||
                final.Pose.X < 0 || final.Pose.Y < 0 || final.Pose.X > image.Width || final.Pose.Y > image.Height ||
                (options.Verify && (final.Score < options.MinimumScore || final.Support < options.MinimumSupport)))
            {
                continue;
            }
            if (options.Verify && options.EvaluateGeometry && model.GeometryModel is not null)
            {
                var quality = GeometricQualityEvaluator.Evaluate(image.Gradients[0], model, final.Pose,
                    options.GeometricTolerancePixels, cancellationToken);
                if (quality.Coverage < options.MinimumCoverage || quality.FitErrorPixels > options.MaximumFitErrorPixels ||
                    quality.ClutterRatio > options.MaximumClutterRatio)
                {
                    continue;
                }
                final = final with
                {
                    Geometry = quality,
                    ClutterRatio = quality.ClutterRatio,
                    ClutterPenaltyRatio = quality.ClutterEnergyRatio
                };
            }
            if (options.ClutterWeight > 0)
            {
                var clutter = final.Geometry is { } geometry
                    ? new ClutterMeasurement(geometry.ClutterRatio, geometry.SceneEdges, geometry.ClutterEnergyRatio)
                    : GeometricQualityEvaluator.EvaluateClutter(image.Gradients[0], model,
                        final.Pose, options.GeometricTolerancePixels, cancellationToken);
                final = final with
                {
                    ClutterRatio = clutter.Ratio,
                    ClutterPenaltyRatio = clutter.EnergyRatio,
                    Score = final.DirectionScore * (1 - (options.ClutterWeight * clutter.EnergyRatio)) *
                        (1 - (options.ClutterWeight * (1 - (final.DetailConsistency ?? 1))))
                };

                {
                    continue;
                }

내적은 두 화살표가 같은 방향으로 향하는 정도입니다

단위 방향은 길이를 1로 맞춘 화살표입니다.u=(1,0),v=(1,0). u=(1,0), v=(1,0)이면 내적은 1×1+0×0=11×1+0×0=1입니다.v=(0,1). v=(0,1)이면 0,v=(−1,0)0, v=(−1,0)이면 −1입니다. Δθ는 두 방향의 각도 차이이고 cos는 이를 같은 값으로 표현합니다. 길이를 1로 맞추지 않으면 밝기 변화의 크기까지 곱에 섞입니다.

RMS는 왜 제곱하고 다시 제곱근을 구할까요?

  1. 대응점 거리 d=[1,2,2]pxd=[1,2,2]px를 제곱하면 [1,4,4]px2[1,4,4]px²입니다. 큰 거리의 영향이 더 커집니다.
  2. 세 개의 평균은 (1+4+4)3=3px2(1+4+4)/3=3px²입니다.
  3. 제곱근을 취하면 3≈1.732px√3≈1.732px로 다시 거리 단위가 됩니다. n은 대응 개수이며 0이면 평균을 계산할 수 없습니다.

단순 거리 평균은 53≈1.667px5/3≈1.667px로 다릅니다. RMS를 계산한다고 대응이 올바른지까지 보장되는 것도 아닙니다. 또한 점과 점의 유클리드 거리와 점에서 선으로 내린 수선의 거리는 서로 다른 값입니다. 현재 기하 품질의 대응 거리와 정밀화의 point-to-line 잔차를 같은 측정으로 기록하지 않습니다.

검출 좌표와 중복 제거

“잘라낸 영상에서 찾은 위치를 원본에 그렸더니 왼쪽 위로 몰려요.” 종이의 일부를 잘라 따로 놓으면 그 조각 안의 주소가 새로 0부터 시작합니다. 조각 안 위치를 원본에 그릴 때는 어디에서 잘랐는지 되돌려야 합니다. 축소했다면 줄인 비율도 되돌립니다.

NMS(Non-Maximum Suppression)는 겹치는 후보 중 대표를 고르는 단계입니다. 개념적인 상자 겹침 지표 IoU는 교집합 면적합집합 면적교집합 면적 / 합집합 면적입니다. 이것은 도형 포함 판정이나 최종 표시 경계가 아닙니다. 실제 화면에는 학습한 도형을 검출 pose로 옮긴 경계를 그립니다.

crop 원점과 축소 비율의 계산 순서

회전 없는 crop 원점이 원본 (100,200)이고, 축소 영상의 한 픽셀 간격이 원본 4px라고 합시다. 축소 좌표계의 점 (10,20)을 같은 좌표 원점 규약으로 되돌리면 먼저 (40,80), 그 뒤 원점을 더해 (140,280)입니다.(10+100,20+200). (10+100,20+200)에 4를 곱하면 원본 원점까지 확대해 버립니다. 실제 리샘플러의 픽셀 중심 규약은 별도로 따라야 합니다. 회전 ROI에는 2장의 중심·회전 변환도 필요합니다. 앱 결과의 Angle은 원본 이미지 기준 절대각이고, 검색 회전 범위는 학습 ROI 대비 편차입니다.

상자 겹침의 IoU도 작게 계산해 봅시다. 두 상자의 면적이 각각 100px2100px²이고 겹친 면적이 50px250px²이면, 합집합은 100+100−50=150px2100+100−50=150px²입니다. 겹친 부분을 두 번 세지 않도록 한 번 빼는 것입니다.IoU=50150=13. IoU=50/150=1/3이고 면적 단위는 약분됩니다.50200. 50/200으로 계산하면 잘못된 분모입니다.

NMS는 여러 후보가 같은 대상을 중복 보고하는 일을 줄이는 절차입니다. 겹친 두 물체가 항상 같은 물체라는 뜻은 아니므로 겹침 기준은 검출 정책의 일부입니다. 이 상자는 후보 정리에 쓰며 실제 화면의 검출 도형을 대신하지 않습니다.

상태해석
완료된 검색에서 조건 불충족검사 정책에 따라 불량 판단 가능
취소·예외·시간 초과완전한 검사 결과가 아님
Truncated후보/탐색 예산 때문에 검색이 잘림
MatchLimitExceeded출력 결과 개수 상한 초과

불완전 검색을 제품 NG로 바꾸지 않습니다. 정상 LimeGreen, 불량 Tomato, 경고 Orange, 사용자 확인 Gold의 판정은 앱이 정하고 Canvas는 전달받은 색·윤곽을 그립니다. 검사 실행·결과는 편집 Undo 스택에 넣지 않습니다.

검사 CPU 125ms/CUDA 80ms 목표와 표시 16.67ms 프레임 예산은 별개입니다. 기존 8K 서비스 실측 CPU 261.7ms/CUDA 227.3ms는 새 목표 미달입니다. 이 수치는 버튼→원본 읽기→게시→표시 완료의 전체 시간을 대신하지 않습니다.
직접 확인: 검색 예산을 줄여 빨라졌는데 일부 부품이 사라졌다. 성능 개선인가?

같은 정확성·완전성 계약을 만족하지 않으므로 그대로 성능 개선 성공으로 부를 수 없습니다. 후보가 줄어 검출을 놓쳤는지 확인하고 Truncated를 알립니다. 동일 입력·같은 검출 조건·전체 비용으로 비교해야 합니다.

이 장의 기호를 먼저 읽는 표

기호는 이 장 안에서의 뜻입니다. 같은 글자라도 다른 장에서는 다른 양을 가리킬 수 있습니다. 아래첨자는 성분·번호를, 윗줄은 평균을 뜻합니다. 합 기호는 표시한 시작 번호부터 끝 번호까지 항을 모두 더하라는 지시입니다. 절댓값은 부호를 버린 크기, 제곱근은 제곱하면 안의 값이 되는 음이 아닌 수입니다.

기호 / 읽는 법뜻과 단위코드·예시에서 찾기
TT티: 학습 템플릿의 밝기 표본. 밝기 단위Ti는 i번째 유효 표본. 윗줄은 평균
II아이: 비교할 원본 후보의 밝기 표본. T와 같은 밝기 단위학습과 같은 순서/마스크의 위치를 비교
ii아이: 대응하는 표본이나 점의 번호합 기호에서는1부터n까지
nn엔: 실제 합에 넣은 대응 표본 수, 개수마스크 밖·padding을 유효 표본으로 세지 않음
NCCNCC평균을 뺀 두 밝기 패턴의 정규화 상관. 단위 없음분모가0이면 이 수식은 정의되지 않음
uu유: 길이를1로 맞춘 첫 방향 벡터, 단위 없음실제 픽셀 위치와 다른 데이터
vv브이: 길이를1로 맞춘 둘째 방향 벡터u와 방향을 비교
ΔΔ델타: 뒤따르는 양의 차이라는 표시Δθ는 두 방향의 각도 차이
θθ세타: 방향각, 삼각함수에는 rad각도 차이의 cos로 내적 해석
dd디: 대응점 사이 거리, 원본 pxdi는 i번째 거리. 6장의 DPI 배율과 다름
RMSRMS거리 제곱의 평균에 제곱근을 취한 값, 원본 px평균 거리와 다른 통계
coscos코사인: 주어진 각도의 가로 방향 기여를 계산. 각도 입력은 rad수학 연산

책을 덮고, 동료에게 설명해 보세요

본문을 가리고, 다음 상황의 이유를 자기 말로 설명해 보세요.

설명할 상황:T=[10,20,30],I=[30,50,70]T=[10,20,30], I=[30,50,70]의 NCC가 1인 이유를 “정규화해서요”라는 말 없이 설명하세요. 그 결과로 회전한 부품이나 모든 실제 촬영에서도 찾는다고 말할 수 있는지도 설명하세요.

설명 예시와 스스로 확인할 기준

“각자 평균 20·50을 빼면 [−10,0,10]과 [−20,0,20]이 돼. 같은 순서로 어둡고 밝아져서 곱의 합이 400이고, 변화 크기로 나누는 분모도 400이어서 1이야. 이 예에서는 밝기와 대비만 달라졌어. 회전·잡음·포화 같은 다른 변화까지 검증한 것은 아니야.”

막혔다면: NCC 표에서 각 칸의 부호를 먼저 비교하세요. 분자가 함께 변하는 정도, 분모가 크기라는 뜻을 숫자와 연결하세요. 다시 읽은 뒤 예시를 닫고 한 번 더 설명합니다.

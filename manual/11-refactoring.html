11. 이번 리팩터링과 검증

범위와 증거를 읽는 예시

가정과 변경 범위

요청은 C# 문법을 막 배운 개발자가 리뷰할 수 있는 가독성, SOLID·GRASP 유지, 성능 보존입니다. 기존 main 작업 트리의 대량 ROI·DX12 변경을 기준으로 삼았습니다. 기존 클래스의 역할·공개 API·알고리즘·GPU 수명 구조를 바꾸지 않고 학습의 출발 경로를 정리했습니다. 저장소 전체의 모든 복잡한 코드를 재작성한 것은 아닙니다.

대상바꾼 표현보존한 계약
EditHistory.cs이미 별개였던 DocumentEdit, HistoryStep, PreparedHistoryStep을 별도 파일로 이동. 책임 주석namespace·타입·서명·전후 차이·예산·검증·캐시·이력 순서
TilePlanner원본 좌표/타일 범위/제외 끝이 드러나는 지역 이름과 설명LOD 선택·계산 순서·타일 순서·할당 방식
ViewportTransform / RigidTransform2D단위·확대 anchor·회전/역변환 수식과 단계 주석연산 순서·오차·배율 제한·구조체 값
RoiGeometry도형명 switch 읽기 순서와 회전 경계의 반너비/반높이 명칭실제 포함 판정·AABB 식·불변 형상
manual오프라인 HTML, 실험 5개, 본문 실제 코드16곳, C# 실습 2개 전체 코드제품 실행에 문서/예제 의존성을 추가하지 않음

실행 명령 비교가 말해 주는 것

Release 빌드의 관련 타입과 생성된 하위 타입에서 151개 메서드 본문을 추출했습니다. 파일 이동으로 바뀔 수 있는 메타데이터 토큰은 대상 타입·멤버 이름으로 해석한 뒤, IL 명령·피연산자·지역 변수 형식·예외 구성·스택 정보를 비교했습니다. 모두 일치했습니다. 이는 이번 변경에서 추가 실행 연산·복사·할당이 생기지 않았다는 근거입니다.

소스 이름·파일 위치·PDB·메타데이터 배치가 달라지므로 DLL 전체 해시가 같아야 한다는 뜻은 아닙니다. 동일 IL 비교를 GPU 실측이나 모든 하드웨어에서의 절대 시간 동일성 보장으로 확대하지 않습니다. 이 작업에서는 새 8K/24K 장시간 프레임 벤치마크를 수행하지 않았으며 기존 성능 미달을 유지합니다.

최종 명령·건수·HTML/실습 확인 범위는 검증 기록에 정리합니다. 작업 도중 발생한 도구 연결 실패와 최종 재실행 결과도 구별합니다.

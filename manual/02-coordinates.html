02. 좌표·확대·회전

수식을 작은 단계로 나누어 읽기

같은 점에 세 가지 주소가 있다

이미지의 부품 위치는 원본 px, WPF 레이아웃은 DIP, 모니터에 실제로 찍는 위치는 물리 px로 셉니다. DIP는 96분의 1인치를 기준으로 하는 논리 단위입니다. 150% 배율에서 DPI 계수 d=1.5라면 100 DIP는 150 물리 px입니다. ROI 형상에는 원본 좌표를 저장하여 화면 확대와 무관하게 같은 부품을 가리킵니다.

원본 px× Scale + Offset →화면 DIP× DPI 계수 →물리 px
s=z·p+op=s−ozs = z·p + o; p = (s − o)/z

p는 원본 점, s는 화면 점, z는 배율(DIP/px), o는 화면 이동량(DIP)입니다. x와 y에 같은 식을 각각 씁니다. p=(100,50), z=2, o=(20,10)이면 s=(220,110)입니다. 반대로 (220−20)/2=100, (110−10)/2=50입니다. Scale=0으로 나누는 입력은 허용하면 안 됩니다.

마우스 아래를 고정하고 확대하기

배율만 바꾸면 이미지가 원점 기준으로 커져 마우스 아래의 부품이 도망갑니다. 기존 화면 anchor a 아래의 원본 점 p를 먼저 구합니다. 새 배율 z′에서 그 점을 다시 a에 놓도록 이동량 o′를 구합니다.

p=a−ozo′=a−z′·pp = (a − o)/z; o′ = a − z′·p

기존 z=1, o=0, 마우스 a=100이면 p=100입니다. 2배 확대 후 o′=100−2×100=−100이어야 화면 위치가 100으로 유지됩니다. ViewportTransform.ZoomAt은 이 식과 배율 상한·하한을 적용합니다. Fit의 0.92는 화면 여백을 위한 비율입니다.

회전은 두 성분을 섞는 계산

각도는 C# UI에서 도(degree), Math.Sin/Math.Cos에서 라디안(radian)을 씁니다. 한 바퀴 360°가 2π rad이므로 rad=degree×π180rad = degree × π/180입니다. cos는 가로 방향 몫, sin은 세로 방향 몫으로 생각하세요. 0°에서 cos=1, sin=0, 90°에서 cos≈0, sin=1입니다.

x′=xcos⁡θ−ysin⁡θy′=xsin⁡θ+ycos⁡θR⁡(θ)=[cos⁡θ−sin⁡θsin⁡θcos⁡θ]p′=c+R⁡(θ)(p−c)+tx′ = x cos θ − y sin θ; y′ = x sin θ + y cos θ; R(θ) = [cos θ, −sin θ; sin θ, cos θ]; p′ = c + R(θ)(p − c) + t

R(θ)는 위 두 줄을 묶어 부르는 회전 행렬입니다. c는 회전 중심, t는 회전 뒤 이동량입니다. 점에서 c를 빼고 → 회전하고 → c를 더하고 → t를 더합니다. 이 영상 좌표는 y가 아래로 증가하므로 양의 각도는 화면에서 시계 방향입니다. 수학책의 y가 위인 그림과 구별하세요.

실험: 중심 (160,110) 주위의 점 (230,110)

30°: 원본 회전 결과 약 (220.62,145.00). 배율은 형상을 바꾸지 않습니다.

화면 확대는 도형을 편집하지 않습니다. 반면 ROI 자체를 회전하면 문서의 형상이 바뀌어 이력에 남습니다. 역변환은 먼저 t와 c를 빼고 −θ로 회전한 뒤 c를 더합니다. 코드에서는 sin의 부호를 바꾸어 계산합니다.

ROI 내부와 AABB는 다른 질문

ROI(Region of Interest)는 관심 영역입니다. 회전 사각형 안에 마우스가 있는지 보려면 마우스를 ROI의 로컬 좌표로 역회전합니다. 그 뒤 |x|≤W2|x| ≤ W/2와 |y|≤H2|y| ≤ H/2를 검사합니다. 원은 중심과의 거리 제곱이 r² 이하인지, 폴리곤은 실제 변과 내부를 검사합니다.

AABB 반너비=W|cos⁡θ|+H|sin⁡θ|2AABB 반높이=W|sin⁡θ|+H|cos⁡θ|2AABB 반너비 = (W|cos θ| + H|sin θ|)/2; AABB 반높이 = (W|sin θ| + H|cos θ|)/2

AABB는 축과 평행한 바깥 상자입니다. 빠르게 후보를 거르는 데 쓰지만 실제 도형보다 넓습니다. AABB가 겹친다고 실제 도형이 겹치거나 포함되는 것은 아닙니다. RoiGeometry.Bounds와 Contains를 구별하여 읽으세요. width=100, height=20, angle=90°의 AABB 크기는 약 20×100입니다.

직접 확인: c=(10,10), p=(20,10), θ=90°, t=(3,0)의 결과는?

p−c=(10,0), 회전하면 (0,10), c를 더하면 (10,20), t를 더하면 (13,20)입니다. sin/cos는 부동소수점이라 극히 작은 오차가 있을 수 있습니다. 정확히 ==로 비교하기보다 오차 허용 범위를 정해 테스트합니다.

수식이 실제 C#이 되는 자리

ImageToScreen은 곱한 뒤 더하고, ScreenToImage는 뺀 뒤 나눕니다. ZoomAt은 마우스 아래 원본 좌표를 먼저 구한 후 새 Offset을 역산합니다. with는 기존 값을 바꾸지 않고 일부 필드만 다른 새 값을 만듭니다.

ViewportTransform 전체 구현

현재 저장소 코드 · 파일 전체 · src/VisionGeometry/ViewportTransform.cs

namespace VisionGeometry;

/// <summary>원본 이미지 좌표와 뷰포트 DIP 좌표를 변환한다. 물리 픽셀/DPI 변환은 호스트가 담당한다.</summary>
public readonly record struct ViewportTransform(double Scale, PointD Offset)
{
    public static ViewportTransform Identity => new(1, new(0, 0));

    public PointD ImageToScreen(PointD point) => (point * Scale) + Offset;

    public PointD ScreenToImage(PointD point) => (point - Offset) / Scale;

    public ViewportTransform Pan(PointD delta) => this with { Offset = Offset + delta };

    public ViewportTransform ZoomAt(PointD anchor, double factor)
    {
        if (!double.IsFinite(factor) || factor <= 0)
        {
            throw new ArgumentOutOfRangeException(nameof(factor));
        }

        var scale = Math.Clamp(Scale * factor, 0.00001, 128);
        // anchor 아래의 원본 좌표가 확대 후에도 같은 화면 위치에 오도록 Offset을 역산한다.
        return new(scale, anchor - (ScreenToImage(anchor) * scale));
    }

    public static ViewportTransform Fit(double imageWidth, double imageHeight, double viewWidth, double viewHeight)
    {
        if (imageWidth <= 0 || imageHeight <= 0 || viewWidth <= 0 || viewHeight <= 0)
        {
            return Identity;
        }

        // 두 축 모두 들어가는 배율에 여백을 두고, 남은 공간의 절반만큼 이동해 중앙에 둔다.
        var scale = Math.Min(viewWidth / imageWidth, viewHeight / imageHeight) * 0.92;
        return new(scale, new(
            (viewWidth - (imageWidth * scale)) / 2,
            (viewHeight - (imageHeight * scale)) / 2));
    }
}

# 메인 편집기의 1억 ROI 통합 — 승인 범위

2026-10-13 사용자 정정: 별도 시험 창이 아니라 현재 TeachingToolWpf의 편집 화면에서1억 개를 선택·복사·붙여넣기해야 한다. 반복 격자라도 각 ROI의 개별 선택·편집과 이력을 유지한다. 사용자는 아래 공통 문서 확장을 승인했다. 구현 결정은 [ADR-042](../docs/decisions/0042-main-editor-repeated-rois.md), 완료/미달은 [검증](../docs/main-editor-repeated-roi-validation.md)으로 구별한다.

## 코드에서 확인한 차이

- 일반 `DocumentState`는 `ImmutableDictionary<Guid, Roi>`와 `ImmutableHashSet<Guid>` 선택을 사용한다. `RoiClipboard.Copy`는 선택/자손을 개별 ROI 배열로 만들고, 붙여넣기는 각각 새 ID/도형/문서 변경 이력을 만든다.
- 현재 `RepeatedRoiSession`은 공통 격자 pose와 개별 수정만 저장하며, 선택은 전체 또는 단일 정수 ID다. 부분 다중 선택·클립보드가 없고 일반 문서의 통합 이력과 분리돼 있다.
- 창을 메인 viewport에 옮기는 것만으로 일반 편집기의1억 개 부분 선택/복사·붙여넣기가 성립하지 않는다. 기존 컨테이너에1억 개를 펼치는 방식은 메모리·전수 순회 비용을 다시 만든다.

## 제안하는 최소 확장 경계

1. 우선 기존 일반 ROI30만 개에서 빈 선택→15만/20만 부분 선택 병목을 별도로 측정·개선한다. 기존 ID/계층/이력/회전 제한은 유지한다. 이 작업은 기존 권한 안에서 진행한다.
2. 1억 개는 기존 Core의 공통 문서에 반복 배치를 압축 상태로 연결한다. 선택은 셀 범위와 개별 예외를 표현하고, 복사는 불변 배치/선택 참조를 공유하며 붙여넣기는 새 배치 ID·pose를 만든다. 각 셀의 정체성과 개별 수정은 보존한다.
3. 메인 입력·선택 표시·목록/속성·클립보드·통합 Undo/Redo가 이 문서 표현을 소비하게 한다. 별도 창 또는 동일 창 안의 기능이 단절된 시험 모드로 대체하지 않는다.
4. 렌더 장치/영상 읽기/검사 알고리즘은 교체하지 않는다. 다만 문서 계약에 연결된 계층·필터·마스크·검사 경계는 호환성 영향 검토가 필요하다. 이 기능을 조용히 제거하거나 지원된 것으로 표시하지 않는다.

2~4는 수개 렌더 파일의 국소 수정 범위를 넘는 공통 문서/편집 계약 변경이다. **2026-10-13 사용자 답변: “공통 문서 확장까지 진행”으로 이 범위를 승인했다.** 로컬 변경·검증만 진행하고 단계별로 검증한다. 원칙 완화는 제안하지 않으며, 현재 승인된 예외도 없다.

검증 기준은 실제 메인 창에서 빈 선택→15만/20만 및1억 배치의 부분/전체 선택, 복사·붙여넣기, 수정·Undo/Redo, 중간 취소, 오래된 비동기 결과 배제다. 작업 완료 시간과 UI 대기/프레임 간격을 따로 측정하고, WARP60FPS 목표 미달을 평균 FPS로 숨기지 않는다.

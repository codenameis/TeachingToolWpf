# 독립 이상 감지 관제 앱 구현

2026-10-16 사용자 확정: 관제실형 HTML을 기준으로 새 프로젝트와 새 컨트롤을 만들고 실제 영상 입력·정상 학습·이상 감지까지 구현한다. 로컬 수정·검증만 수행한다.

## 구현 경계

- `VisionAnomaly`: WPF와 분리한 영상 파일/USB/RTSP 입력, 정상 특징 학습, 추론, 모델 저장/읽기, 알람 상태.
- `VisionAnomaly.Controls`: 기존 VisionCanvas DX12를 사용하는 재사용 영상 관제 컨트롤. 원본 크기 표시, 원본 좌표의 관심 영역/이상 후보 표시. 앱·알고리즘 구현을 역참조하지 않는다.
- `AnomalyMonitor`: 별도 WPF MVVM 앱. 최대4개 영상, 선택 영상 설정·정상 수집·모델 관리, 알람 확인/정상 기록 및 증거 저장. App이 조립/종료를 소유한다.
- 별도 솔루션과 테스트. 기존 TeachingToolWpf의 검사 기능/판정은 변경하지 않는다.

## 알고리즘과 한계

외관은 ImageNet ResNet18의 layer2/3 특징에 국소 평균, 고정 채널 축소, 정상 패치 메모리 및 최근접 거리를 사용하는 PatchCore 착안 구현이다. 원논문의 WideResNet50, 전체 coreset, 재가중 점수를 그대로 재현했다고 표현하지 않는다. 백본은 고정하며 정상 학습은 메모리와 임계값 산출이다. 카메라마다 정상 영상이 필요하고 정상 수집에 이상이 섞이면 정상 기준이 오염된다.

움직임은 Farneback optical flow의 영역별 속도·방향 정상 통계와 시간 지속 조건을 사용한다. 자세/행동 의미를 이해하는 AI-VAD 전체 구현이 아니다. 모든 종류의 이상을 찾는다는 보장은 하지 않는다.

입력은 원본 해상도로 수집·표시하고 선택 영역은224×224로 분석한다. 미세 결함과 작은 원거리 객체가 소실될 수 있다.8K 입력 지원과8K 원본 세부 검사·60FPS 달성은 다르다. 실제 측정 전 성능/현장 정확도 합격을 주장하지 않는다.

## 수명·검증 계약

수집/추론은 UI 밖에서 실행한다. 프레임 버퍼를 명시적으로 반환하고 표시/추론 대기열은 최신1개만 유지한다. 소스/영역 변경 시 정상 모델을 무효화한다. 중지/취소/종료 시 네이티브 호출이 끝난 뒤 해제한다. 연결 끊김·파일 끝·미학습·오류는 정상/제품 NG로 표시하지 않는다.

정상 수집과 확인 결과를 분리하며 알람을 정상으로 기록해도 자동 재학습하지 않는다. 이벤트에는 발생 프레임·시각·점수·영역·모델 식별을 보존한다. 파일 입력은 미디어 시각, 실시간 입력은 단조 시각으로 움직임을 계산한다. 낮은 검사 빈도로 놓친 짧은 이상은 검출 보장 대상이 아니다.

## 검증 순서

1. 사전학습 특징 ONNX 변환과 PyTorch 출력 대조, C# 실제 추론.
2. 정상 학습·외관/움직임 이상·임계값·모델 저장/읽기·취소/수명 테스트.
3. 영상 파일을 실제 디코딩하여 학습→검사→알람/증거 저장.
4. 실제 WPF 컨트롤 렌더링/명령/바인딩/상태·종료 검증. USB/RTSP는 실제 장치·주소가 없으면 미검증으로 기록.

참고: [PatchCore 공식 구현](https://github.com/amazon-science/patchcore-inspection), [Torchvision ResNet18](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet18.html), [OpenCV VideoCapture](https://docs.opencv.org/4.x/d8/dfe/classcv_1_1VideoCapture.html).

# 기하 형상 매칭 확장 계획

기준: 2026-10-04 사용자 요청 “cognex patmax 같은걸 만들어 보자”. [ADR-019](../docs/decisions/0019-geometric-match-quality.md)의 자체 C# 구현이며 PatMax의 내부 알고리즘 복제나 동일 성능 보증이 아니다. 기존 [패턴 매칭 계획](pattern-matching-plan.md)의 전통적 CPU/원본 입력/독립 검사 레시피 경계를 유지한다.

## 1차 — 측정 가능한 윤곽 검증과 오검출 억제

1. 기존 기본 설정의 회귀 기준을 먼저 고정한다. 전체 360° 범위의 비정수 각도 9개, 균일 배율 .8–1.2, 반대비, 경계 상자 오른쪽 25% 가림, 주변 윤곽, 복합 변화, 유사 도형/빈 영상, 극성 반전을 사용한다. 정답 개수·중복·위치 .75px 이내·각도 1.5° 이내·배율 .025 이내·후보 잘림을 각각 검증한다. 25% 경계 상자 가림을 특징점 25% 가림이라고 표현하지 않는다.
2. 최종 실제 pose에서 선택 윤곽 특징 대응 비율·대응 위치 RMS 오차·학습에 없는 윤곽 비율을 계산한다. 희소 특징/전체 학습 윤곽의 목적을 구분하고 정확한 학습 마스크와 극성·원본 픽셀 단위를 유지한다.
3. 사용자가 위 지표의 검사 기준을 설정하고 결과에서 확인한다. 기존 방향 점수와 support, 검색 완전성, 정밀화 상태도 함께 남긴다. 설정 변경과 오래된 결과, OpenCV 전환, 검사 중 조작을 회귀한다.
4. 오답과 정답이 기존 방향 점수에서 겹치는 사례를 새 명시적 품질 기준으로 검증한다. fixture를 약하게 바꾸거나 예산 잘림을 숨겨 통과시키지 않는다. 기본 설정과 새 검사 profile의 결과를 따로 기록한다. 별도 계측에서 필요한 raw 후보가 2,239/2,219개, 유사 도형의 검증 후보가 160개였으므로 선택형 확대 예산은 4,096/256개로 둔다. 기존 기본 예산 2,048/64와 경고는 유지한다.
5. 기존 8K 합성 칩 16개 및 회전 폴리곤의 앱 학습→검사→실제 DX12 표시를 재확인한다. 품질값/점선/닫힌 검출선/검사 판정이 일치하는 화면을 남긴다. 합성 시험과 현장 영상을 구분한다.

최초 baseline은 18개 중 15개 PASS/3개 FAIL이다. 주변 윤곽과 복합 변화는 정확한 위치를 찾았지만 후보 예산을 초과했다. 유사 폐직사각형은 방향 점수 약 .831로 오검출했고 검증 후보 제한도 초과했다. 가림 정답도 약 .831이므로 점수 상향만으로 구분하지 않는다. 원시 근거는 `artifacts/geometric-robustness-baseline.log`다. 변경 후 결과는 실제 재검증 뒤 [작업 목록](todo.md)에 기록한다.

## 2차 — 현장 데이터와 학습 품질

- 실제 대상의 정상품/유사 오답/가림/반사/초점·노출 변화 데이터를 고정 dataset으로 구성하고 학습/기준 선택/최종 평가 영상을 분리한다. 실물 데이터가 없어 현재 NOT_RUN이다.
- 반복 무늬·대칭에서 기준점/각도 모호성, 유효 특징 분포와 대비, 추천 피라미드·각도 간격을 학습 품질 보고로 제공한다. 성능 목표는 데이터 크기·대상 수·각도/배율 범위별로 결정한다.
- 다중 인스턴스, 가까운 대상, ROI 경계, 8K/24K 원본 검사의 p50/p95·메모리·UI 지연을 계측하고 측정 병목에 따라 후보 검색을 개선한다. 실시간 FPS 미정이며 단일 합성 검사로 충족 선언하지 않는다.
- 가림 허용과 오검출 억제의 tradeoff를 독립 평가하고 결함 판정과 위치 검출을 분리한다.

## 3차 — 추가 변형과 제품화

- 비균일 배율/affine, 제한된 국소 변형, CAD/다중 패턴 학습은 별도 수용 기준과 정답 데이터를 만든 후 구현한다. 1차의 대응 허용 반경으로 이 기능을 대체하지 않는다.
- 학습 mask 편집, 레시피/모델 자산 저장·버전 호환·재로드, ROI와 통합 Undo/Redo, 반복 사용의 메모리/취소/종료 검증을 완료한다.
- 결과를 소비하는 공정의 기대 개수·위치/각도 공차·최종 판정 규칙을 앱 계층에 추가한다. Canvas에는 공급자/공정 규칙을 넣지 않는다.
- Cognex/Halcon 비교는 사용 가능한 정식 SDK/장비와 동일 dataset/옵션에서 수행한다. 현재 라이선스/SDK 비교는 NOT_RUN이다.

각 단계는 관련 자동 검증, 코드 규칙 검사, 실제 앱 실행 증거가 있어야 완료로 기록한다. 전체 로드맵은 1차 구현 완료와 구별한다.

# 8K 형상 검사 500 ms 수용 기준과 실행 계획

> 2026-10-05 후속: 논문 방식의 현행 목표는 [버튼 기준 CPU 125 ms / CUDA 80 ms 미만 재계획](paper-shape-125ms-plan.md)으로 대체한다. 이 문서는 기존 두 방식의 500 ms 구현·실측 이력이며 아래 PASS를 새 기준의 달성으로 해석하지 않는다. 자체 기하 방식의 기존 상태와 미완료 항목은 보존한다.

2026-10-05 사용자 확정: 앱의 8192×8192 PCB 샘플부터 확실히 해결한다. 논문 기반·자체 기하 형상 모두 전체 검출, 사선에 따른 점수 구분, CPU 500 ms 이내, GPU는 CPU보다 빨라야 한다. 최종 v4 일반 앱 수동 검사는 첫 CPU 459.0 ms/준비 후 GPU 375.0 ms, 각각 256개로 PASS다. 서비스 benchmark 32회와 정상 표시 WPF 서비스 16회, 전체 테스트 878개도 PASS다. 최초 CUDA 준비 포함 사용·숨김 창 명령·별도 파일은 미달 범위를 유지하고 v1/v2 첫 실패도 보존한다. 조건과 시간 경계는 [실측](../docs/shape-500ms-validation.md)을 따른다.

## 고정 조건

- 앱 원본 `sample:8192:8192`, 핀 하나의 ROI 중심 `(759.518,546.178)`, 크기 `105.827×129.459`, 각도 0. 전체 이미지의 정답 256개를 일대일로 찾고 위치 오차 1 px 이하, 중복·미할당·누락 0.
- 회전 범위 ±180°, 간격 10°, 배율 1, 최소 점수 .72, 지지 .6, 추가 윤곽 가중치 1. 후보 2048/검증 64/거친 검증 256, 결과 256. 정확성 기준과 예산을 속도 달성을 위해 낮추지 않는다.
- 사선이 지나는 독립된 기하 정답 열(1,6)의 64핀과 나머지 192핀을 구별한다. 점수로 그룹을 나누지 않으며, 깨끗한 핀의 최저 점수와 사선 핀의 최고 점수 차이를 기록한다. 표시상 차이가 명확한 .02 이상을 회귀 기준으로 둔다.
- Release, 실제 Ryzen 5 5600H/RTX 3060 Laptop에서 측정. 전체 `SearchAsync` 호출 시간을 사용하며 원본 reader 개방·샘플 원본 생성·전처리·후보 검색·원본 최종 검증·결과 조립·GPU lease 반환을 포함한다. 앱/CLI 소유 세션의 최초 CUDA 장치·커널 준비와 종료는 검사 밖에서 관리하고 준비 시간을 별도 공개한다. 학습과 이미지 파일 가져오기도 별도다. 장치 준비를 포함한 최초 GPU 사용이 500 ms라고 표현하지 않는다.
- 첫 검색과 반복 검색을 구별한다. 최소 3회 반복의 중앙값·최대값을 공개하며 500 ms 초과 실행을 평균으로 숨기지 않는다. GPU도 같은 조건과 최종 결과로 비교한다. 장치 초기화 정책을 바꾸면 최초 준비 비용과 이후 검사 비용을 함께 기록한다.
- 샘플 통과는 실제 촬영 전체의 성능 보장이 아니다. 별도 Gray8 파일 핀, 큰 ROI, 회전·배율·잡음 사례의 기존 정확성 회귀를 보존한다.

## 순서

1. 기존 최종 DLL을 별도 보관하고 동일 입력 baseline, 단계별 원가와 결과를 고정한다.
2. 원본 읽기와 샘플 생성, 거친 창 병렬 처리, 정확한 SIMD 평활화·gradient·방향맵으로 중복 비용을 줄인다. 최대 작업 영상·캐시·취소·소유권 계약을 유지한다.
3. GPU에는 중립 계약으로 방향 확산·템플릿 점수 일괄 계산을 맡긴다. 실제 integer 점수와 최종 pose/score를 CPU와 비교한다. 전처리·원본 최종 검증의 CPU 처리는 명시된 혼합 실행 정책으로 둔다.
4. 전체 검출·점수 구분·500 ms·GPU 가속을 하나의 benchmark에서 검증하고 실제 앱으로 재검사한다. 실패한 목표는 FAIL로 유지한다.
5. 전체 관련 테스트·포맷·빌드·설계 원칙 검토, 사용자에게 측정 결과와 실제 앱 화면을 제공한다.

원칙 예외는 적용하지 않는다. 새로운 후보 절단이나 검출 기능 축소를 성능 개선으로 포장하지 않는다.

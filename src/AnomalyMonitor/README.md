# WATCH · 실제 영상 이상 감지

HTML 관제실 시안을 별도 WPF 앱으로 구현했다. 영상 연결 → 정상 수집 → 감시 → 알람 확인을 수행한다. 기존 TeachingToolWpf 앱과 독립 실행하며, 커밋·푸시 없이 로컬 구현·검증한 작업이다.

## 실행

Windows x64, .NET 10 Desktop Runtime, Visual C++ 2022 x64 Runtime이 필요하다. 저장소 루트에서:

```powershell
dotnet build AnomalyMonitor.slnx -c Release
dotnet run --project src/AnomalyMonitor -c Release --no-build
```

빌드 후 `src/AnomalyMonitor/bin/Release/net10.0-windows/AnomalyMonitor.exe`로도 실행한다. 동봉한 ONNX 특징 모델을 CPU로 실행하므로 Python 설치나 추가 가중치 다운로드는 필요하지 않다. DX12 표시 장치를 사용할 수 없으면 기존 Canvas의 WARP 경로를 사용한다.

## 동봉 영상으로 바로 확인

1. 왼쪽 **CAM 01**을 선택한다.
2. 오른쪽 **영상 설정 → 연결 → 영상 파일 찾아 열기**에서 `samples/AnomalyMonitor.Data/inspection.avi`를 연다.
3. **정상 기준 → 모델 불러오기**에서 같은 폴더의 `normal-model.json`을 연다.
4. 가운데 아래 **감시 시작**을 누른다. 영상은 연결 즉시 재생되므로 11초 전에 감시를 시작한다. 늦었다면 다시 연결하고 모델을 불러온다.
5. 11~12.5초 외관 변화, 16~19.5초 속도 변화 구간을 확인한다. 알람을 선택하면 해당 프레임의 원본 이미지·점수·모델 ID가 표시된다.

동봉 모델은 **합성 컨베이어 정상 영상 전용**이다. 현장 CCTV나 다른 제품 영상의 정상 모델로 사용하지 않는다. 샘플 설명과 재생성은 [데이터 안내](../../samples/AnomalyMonitor.Data/README.md)를 참고한다.

## 자신의 영상으로 정상 기준 만들기

1. 파일, USB 카메라 번호(예: `0`), 또는 RTSP/HTTP(S) 영상 주소를 연결한다. 웹페이지 주소 대신 영상 스트림 주소가 필요하다.
2. 이상이 없는 구간에서 **정상 기준** 탭을 연다. 관심 영역은 원본 영상 크기에 대한 X/Y/너비/높이의 백분율이다. 기본값은 전체 화면이다.
3. 수집 프레임 수를 30~200으로 정하고 **현재 영상으로 정상 수집 시작**을 누른다. 기본 60프레임이며 실제 소요 시간은 분석 속도에 따라 달라진다.
4. 정상 기준 준비가 끝나면 모델을 저장하고 **감시 시작**을 누른다. 조명·위치·제품 등 허용할 정상 변화를 수집에 포함한다.
5. 알람 배율은 0.5~5.0이며 **배율 적용** 시 반영된다. 높이면 더 큰 변화에서 알람이 난다. 점수는 불량 확률이 아니다.

새 소스를 연결하면 이전 모델을 해제한다. 같은 해상도라도 촬영 위치가 다르면 새 정상 기준을 만든다. 다른 해상도의 모델과 다른 특징 추출기로 만든 모델은 거부한다. 관심 영역 숫자 편집은 다음 수집 시작에 적용되며 이미 만든 모델의 영역을 조용히 바꾸지 않는다.

파일 끝·연결 실패·일시정지·미학습은 정상 판정과 구별한다. 파일 재생 끝에서는 다시 연결한 뒤 모델을 명시적으로 불러온다. USB·RTSP 연결 코드가 있지만 이번 검증은 실제 영상 파일로 수행했으며 실물 카메라/서버 연결은 미검증이다.

## 알람과 기록

- 외관: 분석한 한 프레임에서도 기준을 넘으면 기록한다.
- 움직임: 속도·방향 변화가 최소 2개 분석 프레임, 0.6초 이상 지속될 때 기록한다. 1초보다 긴 입력 간격은 이전 시간 상태와 연결하지 않는다.
- 같은 이상은 연속 중복 기록을 억제한다. 기준의 80% 아래로 3프레임 연속 회복한 뒤 다시 기록할 수 있다.
- **이벤트 확인 완료 / 정상 상황으로 기록**은 검토 상태만 저장한다. 자동 재학습하지 않는다.
- 증거 JPEG와 JSON은 `%LOCALAPPDATA%/WatchAnomalyMonitor/Events`에 저장한다. JSON에는 프레임 번호·영상 시각·발생 시각·종류·점수·원본 좌표 영역·모델 ID·확인 상태가 들어간다.
- 화면 목록은 최근 200건이다. 디스크 기록은 자동 삭제하지 않는다. 소리·메일·외부 알림·NVR 녹화는 포함하지 않는다.

## 현재 검출 범위

**외관은 PatchCore에서 착안한 정상 패치 거리**, **움직임은 Farneback optical flow 정상 통계**다. 정상 영상으로 패치 메모리·임계값·속도 분포를 학습하며 ResNet18 백본 가중치는 고정한다. 원논문 재현이나 모든 행동의 의미를 이해하는 모델은 아니다.

관심 영역을 **224×224**로 변환해 분석한다. 원본은 유지하여 DX12 표시와 증거 저장에 사용하지만, 축소로 사라지는 미세 결함·원거리 작은 객체는 놓칠 수 있다. 분석 후 최소 200ms를 기다리고 최신 프레임을 가져온다. 처리 사이에 사라진 이상은 검출하지 못하며 건너뛴 프레임 수를 화면에 표시한다. 표시 영상은 위치 표시와 대응하는 분석 프레임이다.

4개 입력을 독립 구성할 수 있다. 4채널 8K 실시간 처리나 60FPS·현장 정확도는 검증하지 않았다. 실사용 전 해당 장면의 정상/이상 영상으로 누락·오검출과 적절한 관심 영역을 확인해야 한다. 현재 결과는 [검증 기록](../../docs/anomaly-monitor-validation.md)을 따른다.

## 프로젝트 구성

| 프로젝트 | 책임 |
|---|---|
| `VisionAnomaly` | 영상 입력, 특징 추출, 정상 모델, 추론, 알람 조건, 기록, 세션 수명 |
| `VisionAnomaly.Controls` | 재사용 `CameraMonitorControl`, `AlarmTimelineControl`; 앱/알고리즘을 역참조하지 않음 |
| `AnomalyMonitor` | 화면 상태·명령·파일 대화상자·조립과 종료 |

컨트롤 사용법은 [별도 안내](../VisionAnomaly.Controls/README.md), 구조 결정은 [ADR-058](../../docs/decisions/0058-independent-anomaly-monitor.md)에 있다.

```powershell
dotnet test tests/VisionAnomaly.Tests -c Release
dotnet test tests/AnomalyMonitor.Tests -c Release
```

두 검증은 순서대로 실행한다. 첫 검증은 동봉 영상을 재생성하며, 두 번째 검증은 실제 STA 창과 DX12/WARP를 사용하므로 대화형 Windows 세션이 필요하다. 관련 라이선스는 [고지](../../THIRD-PARTY-NOTICES.md)에 있다.
